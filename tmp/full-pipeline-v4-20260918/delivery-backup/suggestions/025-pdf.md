## 需修改或注意的问题

1. **关键路径遗漏：告知动作存在却不可达。** [SKILL.md:47](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:47)要求无法安装时说明缺少的依赖及本地安装方法。`block_023/ir_044` 确实保存该动作，却没有任何入边；主流程安装分支 `block_009/010 → block_007` 直接渲染，没有安装不可行/失败的出口。应补上真实条件到告知动作的路径。这修正了旧初审“没有该操作”的表述：缺的是触发与可达性。

2. **依赖安装缺少适用条件与主流程关系。** [SKILL.md:27](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:27)限定 install if missing。`block_018–022` 是另一独立组件，按 uv 可用性选择安装器，却没有缺依赖判断，也没有主入口可达路径。建议表达仅缺包时进入该组件及完成后的继续关系；不要为了连通而让每次任务都执行安装。

3. **数据流缺口：汇合后要求仅某分支产生的值。** [SKILL.md:18](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:18)和 [SKILL.md:19](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:19)描述创建与提取用途。`block_017/ir_033` 无论哪条任务路径到达，都列入提取支的 `result_003/result_004`；创建或纯视觉复核路径未产生它们。建议总结只消费当前任务实际产生的结果，或明确条件选择，不要求固定 phi 操作。`ir_009` 的 resolve 和 `ir_029` 的 merge 已有选择意图，不应仅因列出候选值就一律判同类错误。

4. **交付动作的输入可更明确。** [SKILL.md:24](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:24)和 [SKILL.md:65](D:/projects/SkillFlow/packages/skill-ir/experiments/semantics_baseline/frozen/corpus/inputs/upstream/pdf/SKILL.md:65)要求最终产物和交付门槛。`block_017` 名称含交付，实际 `ir_033/ir_034` 生成并返回说明，未把最终 PDF 路径作为明确返回/交付输入。建议让最终产物的定位也可追踪；当前判断为交付表达不足，不据此断言文件没有生成。
