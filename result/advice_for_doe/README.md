# 新版 DOE 需要什么，以及这 30 份评审如何使用

**先定义新版 DOE 的判断目标，再决定需要补哪些过程证据。** 本轮将 30 份原评审压缩另存，保留相同编号和主名；原评审、Skill ZIP、CFG PNG 均保留。下述是本轮提出的需求草案，不代表已经实现或经共同确认的最终接口。

已经明确的原则是：DOE 适配当前 Skill-IR 的语义表达；不沿用旧 DOE 的输入字段、评分公式或阈值来要求 IR 改形。**语义回溯负责 Skill 与 IR 的通用双向保真，不做成 DOE 专用检查。** 压缩只改变本轮阅读和处理问题的优先级，不删除一般语义问题，也不把模型结果提升为标准答案。

**1. 新版 DOE 的目标**

针对一项具体任务，识别哪些原始数据及其派生内容，在什么条件下被什么操作读取、处理、传递或持久保存，到达什么对象；再判断这种使用、可见范围或保留方式，是否超出了任务需要或明确允许的范围。只有 Skill 包而没有具体任务/运行环境时，应输出带条件的候选与缺失证据，不能给出确定的实际泄露结论。

建议以“一份数据或相关派生内容，经一段处理过程，在某条件下到达一个使用/接收位置”为分析对象。下面是需要回答的问题，不是要求往 IR 中增加同名字段：

| 必须回答的问题 | 需要的证据 | 应避免的误判 |
| --- | --- | --- |
| 数据是什么，从哪里来？ | 原始文件/字段/上下文/服务结果；路径与实际内容的区别；派生内容与原来源的关系 | 有文件路径就认定已上传文件；将工具标识当业务载荷 |
| 数据经过什么处理？ | 读取、筛选、转换、汇总、脱敏、编码、拼接等真实操作及输入输出；适用约束 | 有 summarize 就自动视为最小化；Base64 编码就视为已去敏 |
| 哪些数据实际可能进入该操作？ | 显式输入、文件副作用、脚本边界的输入输出、可用性、条件与来源对应 | 把所有可用上下文当作本次工具调用的参数；把互斥分支数据当作同时使用 |
| 到达哪里，谁能看到或继续使用？ | 工具/API/模型提供方、站点/工作区/对象、用户输出、本地文件；接收者、可见范围和保留方式 | 所有 external_resource 都是外发；预览链接天然私有；本地落盘天然越界 |
| 在什么条件下发生？ | 当前任务选择、批准、筛选、缺省、重试、回退、dry-run；历史示例与当前行为的区别 | “可能”写成“必然”；限制只当背景文字；看到代码中有 API 就认为所有模式都联网 |
| 为什么需要，是否超量？ | 当前用户任务、明确授权/禁令、接收对象需要什么、是否有原文支持的更少数据方案 | 已授权就视为任意内容都必要；仅凭敏感程度断定超量；凭空假设可替代服务或无损脱敏方法 |

敏感性与任务必要性分别判断：非敏感数据也可能多传，敏感数据也可能是完成已授权任务所需。外部写入和权限使用是重要过程证据，但一个未经请求的写操作不自动等于数据过度暴露，需要继续看其内容、接收范围和任务依据。

**2. 当前 IR 能提供什么，分析层还要做什么**

当前 IR 已保存基本块、开放操作名、输入/输出引用、控制边条件、各层约束以及相关 metadata；完整性校验检查结构和引用连通性。[当前 IR 说明](D:/projects/SkillFlow/packages/skill-ir/README.md:205)

新版分析层需要在这些事实之上解释操作效果、追踪数据来源和处理历史、识别可能的接收边界，并保留推断依据与不确定性。辅助分析和判断可以外置，先不修改生产 IR。脚本中的读取、网络调用或落盘需要有边界摘要及源码依据；源码只存在于 metadata 中，并不代表已经完成了效果识别，但也不能直接算作提取遗漏。不得为了分析方便把脚本内部行为重复插入主流程。

下列三类信息不能混在一起：

- **IR 中可直接核对的事实：**操作、引用、条件、限制、实际源码和命令。
- **分析得到的结论：**可能来源、派生关系、操作效果和候选数据流；注明证据、适用条件及未决部分。
- **任务/环境提供的事实：**本次目标、授权、真实配置、接收者可见范围、数据属性、日志/上下文收集方式和运行记录。Skill 没有说明的内容留为未知。

外置人工评审和冻结事实标注仅用于离线复核、评测与误差分析，不混入 Skill 输入，不作为常规提取或被测 DOE 的事实来源。若后续用这些样例调 Prompt，应明确作为开发材料，并用独立留出样例验证；不能再将同一批的提升描述为独立泛化结果。

**3. 必须适配的当前 IR 语义**

- **可用不等于消费，消费不等于跨界。** 数据在某处可用，只表示有可能被后续使用；是否实际进入参数、文件内容或模型上下文，需要额外依据。若运行器会自动携带历史上下文，应独立描述该传播机制，不能从 CFG 可达性推断所有历史数据都被带入。
- **合流保留可能来源。** 单分支产出在合流后引用可以合法；多输入列表本身不证明所有值必须同时出现。保留分支相关性，避免把多个条件路径拼成一条不存在的实际执行路径。[当前校验边界](D:/projects/SkillFlow/packages/skill-ir/README.md:243)
- **高层操作允许表达逐项处理与条件。** each、suggest_or_apply、if_missing 等语义可以在操作和约束中表达，不要求为了 DOE 增加固定 loop、phi 或判断节点。无法解释来源绑定时报告未决，不用猜测补齐。
- **独立片段不是默认每次执行的动作。** 当前校验将无前驱块也作为根；识别片段的适用条件或调用关系，不因未接到声明入口就宣称不存在，也不自动串接全部根。
- **副作用没有 result 也可能真实存在。** 写文件、更新 issue、部署可由命令和操作语义证明；同名文件的生产/消费还需按执行顺序和路径条件核对，不能仅靠同名认定同一版本。
- **约束的范围与效力要保留。** 区分全局、块、操作限制，区分声明应当遵守与图中已表示的控制；条件不明或源码/文档冲突时同时保留证据。语义未定不能变成默认允许或默认禁止。

现有可选 availability 分析可提供可能/保证可用结果，但不是完整条件求解、效果传播或暴露审计；结构检查通过也不证明原文没有整段遗漏。[后续分析边界](D:/projects/SkillFlow/packages/skill-ir/README.md:248)

**4. 第一阶段的输出应当能支持人工判断**

建议输出可追溯的候选：样例与所选轮次、数据原来源及派生关系、相关操作/路径条件、内容与接收对象、当前任务/限制依据、缺失证据及判断理由。证据位置应能定位到源文件和实际 IR 标识。现在不固定 JSON 接口，也不先设计一个总分来压缩未知。

分析状态至少区分：在给定假设下的可能行为、有证据支持的条件性判断、无法判断的未知/冲突。真实运行观察另行标识，不能混进静态推断。报告“超出任务需要”必须说明多出的数据、接收者/用途/保留范围，以及依据；报告“未发现超出”也必须说明分析覆盖和假设，不能将没有找到候选等同完整证明安全。

第一阶段建议收集有依据的网络传输、模型/工具输入、用户可见输出和持久化位置，**先保留事件事实，再按任务和边界政策判断**。本地文件、stdout 或进入当前模型上下文本身不自动定性为过度暴露。最终政策仍需明确：是否评估运行器自动携带的上下文；哪些本地保留/输出算跨界；纯静态分析是否允许接收具体任务与运行配置。这些选择目前是需求待定项，本轮没有假称它们已经共同冻结。

**6. 后续顺序与完成标准**

先明确上述判断范围和外部证据来源；用这 30 个选定 CFG 检验分析层能否解释关键链路，把“源文缺信息”“IR 漏/错转换”“下游尚不会消费已保留的语义”分别归因。只对确认的漏/错转换反馈 Prompt，避免把下游解释能力不足都当作提取问题。

随后推进独立的通用语义回溯：由只看到 IR 的回译过程重建描述，再双向比对源文，检查遗漏和无依据新增，并结合确定性引用/来源检查。回溯覆盖一般过程、条件和约束；DOE 的优先级不裁掉这层语义范围。新版 DOE 的效果识别与处理历史分析可以据此并行设计，但不能声称回译相似度已经保证了暴露判断正确。

验证新版 DOE 时，至少应能区分 N06 的正文变化、Q06 的缺省值、F06 的返回字段、D06 的交付目标；排除 N05/Q05/F05/D05 的历史副作用；保留凭据用途、批准门控、建议/应用以及 dry-run/API 的差异。互斥来源不交叉拼接、独立片段不无条件串行、文件路径不冒充正文。对源文冲突和任务信息缺失输出可定位的未知，不编造标准答案。以上是后续验收需求，本轮尚未实现 DOE 或语义回溯测试。

本目录共 30 份一一对应的压缩评审和本说明。复用最早结构有效的既有结果：015/F03 为第 3 次，其余为第 1 次；没有重新调用模型、执行 Skill 脚本或改动生产 Prompt、IR 模型与提取 pipeline。
