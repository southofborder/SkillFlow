# Procrastination — Starting, and Why It Is Not Laziness

Scope: the task is known, the time exists, and it still does not begin. Procrastination is an emotion-regulation move — the brain trading a future cost for immediate relief — not a time-management failure, which is why time-management answers bounce off it.

**Before diagnosing**, read `## Friction`, `## How They Work` and `## Tasks` in `~/Clawic/data/productivity/memory.md`. The same task stalling for three weeks is a different problem from a bad afternoon, and only the file knows which one this is.

## Diagnose the Avoided Feeling

Six feelings produce identical behavior. The fix differs completely, so ask "what is unpleasant about starting this?" before offering any technique.

| Feeling | Tell | Fix |
|---|---|---|
| Ambiguity | Cannot say what the first action is; the task is a noun | Decompose until the first step is physical and 2 minutes long |
| Fear of judgment | Perfectionism on the visible parts, endless polishing of the invisible ones | Set the quality tier out loud (A/B/C, `overload.md`) and ship the ugly draft to one safe reader |
| Boredom | Task is clear, easy, and repellent | Shrink and pair: 15 minutes with a timer, plus something sensory; batch with similar dull work |
| Resentment | "Why is this mine?" | The real move is renegotiation or delegation, not motivation (`delegation.md`) |
| Overwhelm | Every task feels equally impossible, not just this one | Not procrastination — go to `overload.md` |
| Depletion | Wanted to, sat down, nothing came | Not procrastination — go to `energy.md`, and check Red Flags |

The question that finds it fastest: "If it were already done, what would you feel?" Relief points at fear, indifference at resentment, nothing at depletion.

## The Start Protocol

Designed so the hardest version still works on a bad day.

1. **Name the first physical action.** Not "write the report" — "open the file and read yesterday's last paragraph". If you cannot name it in one line, that is the ambiguity case.
2. **Shrink until it is embarrassing.** Two minutes, one paragraph, one email, two push-ups. The point is not the two minutes; it is that starting and continuing are different problems and only the first one is blocked.
3. **Remove the setup.** File open, tools ready, tab loaded — done at the end of the previous session, so the future self arrives at a running start rather than a cold one.
4. **Start visibly worse than you would like.** Explicit permission to produce a bad first version is the highest-yield intervention for perfectionist stalling, because the fear is of the artifact, not the work.
5. **Ten minutes, then choose.** Committing to ten minutes with a real option to stop is honest, so the brain accepts it; committing to "just start" and secretly meaning four hours is what it learned to refuse.
6. **If still nothing after three attempts, escalate the diagnosis.** The task is either wrong, not yours, or blocked by something unnamed. Three failed starts is data, not a character verdict.

## Implementation Intentions

The most reliably supported starting device (Gollwitzer): a plan in the form **"When <specific cue>, I will <specific action> at <place>."**

- Vague: "I'll write more this week." Specific: "When I sit down after the school run at 16:00, I open the draft and write one paragraph at the kitchen table."
- The cue must be something that will unambiguously happen — an existing routine, a time, a place — not a feeling. "When I feel motivated" is not a cue; it is a wish with a clock.
- Pair it with a coping intention for the predictable obstacle: "If chat is open when I sit down, I close it before I open the draft."
- One at a time. Stacking three intentions on one cue reliably produces zero.

## Deadlines That Actually Work

- **External and dated beats self-imposed**; self-imposed and public beats private; private and vague does nothing. Ariely and Wertenbroch's finding is the useful part: people who set their own spaced deadlines outperform those with none, and still underperform evenly spaced imposed ones. So manufacture externality: a reviewer expecting the draft, a meeting where it is presented, a person who will ask.
- **Spacing matters more than the final date.** One deadline at the end produces one panic; three checkpoints produce three starts.
- **A deadline with no consequence is a date.** Name what actually happens on the day — someone reads it, the slot is lost, the price changes.
- **Panic productivity works and bills later.** Deadline-driven work skips revision and recovery, and the error rate is invisible until it is not. Treat a stated preference for pressure as a real preference with a price (`Where Experts Disagree` in SKILL.md), not a virtue.

## Chronic Avoidance of One Item

One item stuck across three or more weekly reviews is a decision, not a task. Force it:

1. **Do it now, small**: a 25-minute timer on its first physical action, in this session.
2. **Or delegate it**, with decision rights and a date (`delegation.md`).
3. **Or kill it**, and tell whoever is waiting. A dead item announced costs a message; a dead item hidden costs the trust of the whole list.
4. **Or schedule it with an external witness** — the only remaining move if it must be you and it must happen.

Never leave it as "next week" a fourth time. The fourth carry-over is what teaches the user that their own list is fiction, and that lesson contaminates every other item on it.

## Planning as Avoidance

Replanning, reorganizing, tool-shopping and researching methods are the highest-status forms of procrastination: they feel like work, produce artifacts, and never risk judgment.

Tells: the system changes more often than the output ships; three planning sessions and no started item; a new app in the last month (`tools.md`); the review keeps producing structural improvements instead of finished work.

Counter: one plan per horizon, one review per cadence, and a hard rule that no structural change is allowed while an item is stuck — fix the stuck item first, then change the system if it still seems necessary. It rarely does.

## What to Write Down

- A recurring avoidance pattern — which type of task, which feeling, what unblocked it — goes to `## Friction`, and what worked to `## How They Work`. This pair is what lets a later session skip straight to the intervention that already works for this person.
- A carried-over item that got killed or delegated updates `## Tasks` and `## Commitments`, and gets named in the current `reviews/<year>.md` entry.
- An implementation intention the user commits to is a cadence-shaped thing: if it recurs, it becomes a `## Habits` row with its trigger and minimum version (`habit-building.md`).
- If avoidance clusters on a specific person's requests or a specific kind of work, that is a `## Friction` line with a name in it — and often the real fix is in `delegation.md`, not here.
