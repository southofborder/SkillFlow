# Flavors — Which Parser You Are Actually Writing For

There is no "Markdown". There is CommonMark (a spec), GFM (CommonMark plus five extensions, plus a sanitizer), and roughly a dozen dialects that predate or ignore both. Every rule in this skill is conditional on which one renders the file.

**Before writing or fixing anything**, read `## Render Targets` in `~/Clawic/data/markdown/memory.md` (or `targets.md` if `## Boxes` points there): the destinations already identified and, in the `Confirmed refuses` column, what each one was **observed** rejecting. That column outranks any table in this skill, because it was measured on their content.

## The Genealogy

- **Markdown.pl (2004)** — the original, ambiguous, no spec. Its behaviors survive in old parsers: 4-space nesting, no tables, HTML passthrough.
- **CommonMark (2014→)** — the spec that resolved the ambiguities with 600+ test cases. No tables, no strikethrough, no task lists, no footnotes. Reference implementation `cmark`.
- **GFM** — CommonMark + tables, strikethrough, task lists, autolink literals, and a disallowed-raw-HTML rule; github.com adds footnotes, alerts, math, Mermaid and a sanitizer on top of the spec, so "GFM the spec" and "what github.com renders" are not the same set.
- **markdown-it** — CommonMark-compliant, plugin-driven, the engine behind VS Code preview, VitePress, and many CMSs. `html: false` by default in libraries, `true` in most CLI wrappers.
- **remark / MDX** — the JavaScript AST toolchain; `remark-gfm` adds the GFM extensions, MDX adds JSX (`mdx.md`).
- **Python-Markdown** — extension-based (`tables`, `footnotes`, `attr_list`, `toc`), 4-space nesting, the base under MkDocs.
- **kramdown** — Jekyll's default: IALs (`{: .class}`), `{#id}`, footnotes, definition lists.
- **Goldmark** — Hugo's, CommonMark + GFM, **raw HTML dropped unless `unsafe: true`**.
- **Pandoc** — the superset with the largest extension set and the only one that treats Markdown as one format among forty (`conversion.md`).

## Differences That Change What You Type

- **List nesting**: CommonMark/GFM accept 2 spaces after `- `; Python-Markdown wants 4. Writing 4 satisfies both (SKILL.md Rule 3).
- **A list interrupting a paragraph**: legal in CommonMark for bullets and for ordered lists starting at `1.`; not in older parsers. A blank line makes the question disappear.
- **Underscores inside words**: CommonMark and GFM do not treat `snake_case_name` as emphasis; Markdown.pl-era parsers do. `*` **does** work intraword everywhere, so `2*3*4` italicizes in all of them.
- **Hard breaks**: CommonMark accepts both `\` and two trailing spaces; Markdown.pl-era parsers have no `\`, and there two trailing spaces are the canonical break. `<br>` is the fallback for when those spaces get stripped, and `raw_html` decides whether you may use it (SKILL.md Rule 6).
- **Heading ids**: derived by rule and the rules differ — GitHub strips punctuation and lowercases; Python-Markdown's `toc` slugifies differently and appends `_1` (not `-1`) for duplicates; Pandoc drops leading digits. Never copy an anchor between targets (`links.md`).
- **HTML blocks**: CommonMark ends an HTML block at a blank line, so Markdown inside a `<div>` is parsed as Markdown **only after** a blank line; Python-Markdown needs `markdown="1"` on the element instead.
- **Line endings**: CRLF is tolerated by parsers and hated by diffs; a lone CR (old Mac paste) breaks several parsers outright.
- **Tabs**: expanded to the next 4-column stop before block parsing in CommonMark; in YAML frontmatter a tab is a syntax error.

## The Portable Intersection

When the target is unknown, or the document will travel through several: ATX headings with a space, `-` bullets at 4-space nesting, blank lines around every block, fenced code with a language, inline links with angle-bracketed destinations when they contain anything odd, `**bold**` and `*italic*`, no tables (or a table plus a plain-text fallback below it), no footnotes, no callouts, no raw HTML, no emoji shortcodes, Unicode emoji only where it carries no meaning.

This costs expressiveness and buys the guarantee that no target silently drops content. Announce it in one line rather than quietly downgrading a document the user expected to be rich.

## Testing a Construct in 30 Seconds

Cheaper than any table, including this one: take the smallest snippet that contains the construct, render it in the real target — push a gist, save a preview branch, paste one message, run the site's dev server — and look. Do it once per target per construct, then write the answer into the boxes named below, so nobody pays again.

**Write the result of every such test**: the target and its parser go in `## Render Targets` of `~/Clawic/data/markdown/memory.md`, and anything it refused goes in that row's `Confirmed refuses` column, with a one-line explanation in `## Quirks` naming the target (`memory-template.md`). Once the section passes ~15 targets it splits to `targets.md` with the same headings. An untested assumption about a parser is the most expensive kind of guess in this domain: it is discovered by a reader, not by a build.
