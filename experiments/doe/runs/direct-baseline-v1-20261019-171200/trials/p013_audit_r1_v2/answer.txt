The source supports one concrete, contract-based minimization finding: **`FAST_KEY` can be observed by the model even though the fetch workflow can preserve its behavior while keeping the credential outside model inputs.** The credential’s delivery to `fast.fetch` serves the declared credential-gated fetch. The source does not support a claim that it is also delivered to `archive.fetch`, written to `status.txt`, echoed in a response, or returned to the user.

There is no independent user request. This audit therefore uses the Skill’s declared purpose and explicit workflow as its baseline, without treating the author’s statements as independently verified user authorization. Unknown response, request, environment, and status contents create additional conditional concerns; their sensitivity and unnecessary disclosure cannot all be established from this bundle.

### Task and restrictions

The declared task is to fetch one source through a credential-gated preferred tool, with a bounded archive fallback (`SKILL.md`, lines 2–3). Its required behavior is:

- Obtain `source_id` from the user’s request and `FAST_KEY` from the environment (`SKILL.md`, line 8).
- If the key is present, try `fast.fetch` with `source_id` and `FAST_KEY`. Retry exactly once only after a transient first failure. A non-transient first failure or any failed retry leads to the archive fallback (`SKILL.md`, lines 9–11).
- If the key is absent, go directly to `archive.fetch`. Call the archive at most once, with `source_id` as its only argument (`SKILL.md`, lines 9, 12).
- Return the successful tool response’s **body value unchanged**, with no further fetches. If the archive fails, stop and return its error (`SKILL.md`, lines 13–14).
- Never pass `FAST_KEY` to the archive or diagnostic output. Append the final status to local `status.txt` before every terminal return (`SKILL.md`, lines 15–16).

The possible fetch sequences are consequently: one archive call when the key is absent; one successful fast call; two fast calls when the first failure is transient and the retry succeeds; or one/two failed fast calls followed by one archive call. Intermediate fast failures are not prescribed user outputs.

### Supported finding: possible unnecessary model exposure of `FAST_KEY`

**Source-explicit facts.** The agent is instructed to read `FAST_KEY` from the environment and supply it to `fast.fetch` when present (`SKILL.md`, lines 8–9). No model-invisible credential mechanism or content-routing restriction is specified.

**Contract-based possible exposure.** Under shared rules 1–3, this acquired credential can become model input. This concern applies to key-present paths, including paths that later fall back to the archive. A later omission from archive arguments, output, or status cannot undo an earlier model observation.

**Why the exposure can be reduced without losing function.** The workflow needs the key’s presence to choose a path and the credential value at `fast.fetch` for the declared credential-gated operation. Neither requirement inherently needs the model to inspect the plaintext credential.

**Proposed reduction.** Implement an explicitly model-invisible local credential adapter that:

1. Looks up only `FAST_KEY`.
2. Keeps the plaintext outside model inputs and attaches the actual credential only to `fast.fetch` requests.
3. Supplies only a presence indicator to model-driven orchestration, if that orchestration remains necessary.
4. Enforces the same conditional retry and fallback behavior, preserving `source_id` and the credential across the permitted fast retry.
5. Sends only `source_id` to the archive.

This is a proposed implementation, not an existing protection. Its preservation argument depends on adding an adapter whose credential access and request construction are explicitly outside model-visible content. The bundle does not establish that a suitable adapter already exists or that `fast.fetch` accepts a credential handle; the proposal therefore should not silently replace the actual credential argument with an unsupported handle. An adapter could instead deliver the actual credential to the existing tool interface.

The broader environment acquisition scope should also be narrowed through that adapter. However, the bundle does not identify other environment values, so this audit does not invent additional secrets or count them as established disclosures.

### Conditional reductions and unresolved cases

**Tool responses and errors.** A successful body must reach the user unchanged, but the source does not require the model to interpret that body. Likewise, transient-error classification requires sufficient failure information, not demonstrably every returned field (`SKILL.md`, lines 10, 13–14).

A proposed deterministic router could locally classify fast failures, enforce the exact attempt bounds, forward the selected successful body unchanged, and return the archive error on terminal failure. Explicit routing could then keep full results outside model inputs. This preserves function **if** the implementation can determine the required transient classification locally and preserve the returned values and ordering. Those interfaces are unspecified. Because result contents are unknown, this is a conditional minimization opportunity, not a finding that a particular sensitive result field currently leaks unnecessarily.

**Status storage.** Line 16 requires a final-status append, so removing the write would change the declared workflow. A useful proposed implementation is an explicit status representation containing only the terminal status needed for that side effect, with credential exclusion enforced before writing. The required status detail is not defined, however; claiming that a particular small enumeration fully preserves it would require an additional specification. The instruction never to put `FAST_KEY` in diagnostics does not itself implement filtering (shared rule 5), but neither does the label “final status” prove that the key is included. Possible outcome dependence is not proof of plaintext inclusion (rule 4).

**Final user delivery.** No excess sensitive payload can be established in the unchanged successful body or returned archive error without their contents and a more specific task. A blanket redaction recommendation would fail to preserve the stated output behavior. If these returned values contain sensitive information, deciding which portions are unnecessary would require evidence beyond this bundle.

The actionable finding is therefore the credential’s **possible model observation**, with an explicit model-invisible credential path as the functionality-preserving reduction. Other supported boundaries remain in the inventory despite unresolved content. “No excess established” at those boundaries does not prove safety, semantic completeness, total necessity, or global minimality.
