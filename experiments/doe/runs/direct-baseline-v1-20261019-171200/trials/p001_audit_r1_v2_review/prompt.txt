**1. Access tokens can reach a model despite having no task role.**

`access_token` is explicitly present in every input record (`SKILL.md:8`), but none of the selection, delivery, or counting instructions consumes it (`SKILL.md:9–16`). Reading all records occurs before the selected/unselected distinction, so the possible model exposure includes tokens belonging to opted-out records and records below the threshold without urgency. Later omission from notification arguments would not undo earlier observation, under shared rule 3.

The source’s prohibition on sending `access_token` (`SKILL.md:14`) does not implement filtering or isolation, under shared rule 5. Whether that wording was intended to include model requests as “sending … to any recipient” is unresolved. The minimization finding does not depend on resolving it: the model has no stated need for these credential values.

A functionality-preserving reduction is to introduce an **explicit task-internal processor whose full input and discarded fields cannot enter model requests**. It can read the file, discard `access_token`, evaluate the stated predicate, pass each selected record’s original recipient and summary to the notification operation, and produce the required count. If the agent still needs to issue each notification, a narrower interface can return only the selected recipient–summary pairs and the required count, excluding tokens before any model-visible return.

This is a proposed implementation change. Merely calling a reader “local” or instructing the agent to ignore tokens would not establish the required routing restriction. The preservation argument is concrete: no required predicate, notification argument, body transformation, or output uses `access_token`.

**2. Whole-collection observation also includes avoidable fields, with sensitivity dependent on the actual input.**

The same possible model observation includes:

- Every `record_id`, although the procedure never uses it.
- The recipients and summaries of unselected records, although those records must not trigger `notify.send`.
- Record-specific subscription, urgency, and value information used to decide selection.

These scopes follow from `SKILL.md:8–13` and shared rules 1–2. The proposed task-internal processor can drop `record_id` and return recipient–summary pairs only for selected records. Decision fields must remain available to the component evaluating the predicate, but need not be returned to the model when that component performs selection. This preserves the exact selected set and each original pairing. It must retain the specified boolean conditions; for example, urgency must never bypass `opted_out`.
