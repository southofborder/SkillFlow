### Supported finding: possible unnecessary model exposure of `FAST_KEY`

**Source-explicit facts.** The agent is instructed to read `FAST_KEY` from the environment and supply it to `fast.fetch` when present (`SKILL.md`, lines 8–9). No model-invisible credential mechanism or content-routing restriction is specified.

**Contract-based possible exposure.** Under shared rules 1–3, this acquired credential can become model input. This concern applies to key-present paths, including paths that later fall back to the archive. A later omission from archive arguments, output, or status cannot undo an earlier model observation.

**Why the exposure can be reduced without losing function.** The workflow needs the key’s presence to choose a path and the credential value at `fast.fetch` for the declared credential-gated operation. Neither requirement inherently needs the model to inspect the plaintext credential.

**Proposed reduction.** Implement an explicitly model-invisible local credential adapter that:

1. Looks up only `FAST_KEY`.
2. Keeps the plaintext outside model inputs and attaches the actual credential only to `fast.fetch` requests.
3. Supplies only a presence indicator to model-driven orchestration, if that orchestration remains necessary.
4. Enforces the same conditional retry and fallback behavior, preserving `source_id` and the credential across the permitted fast retry.
5. Sends only `source_id` to the archive.

This is a proposed implementation, not an existing protection.
