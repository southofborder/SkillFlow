**Static control flow and element scope.** Define:

```text
eligible(r) =
    (r.opted_out == false)
    AND
    ((r.urgent == true) OR (r.score >= 80))

C1  Read records.json locally and obtain its records array.
C2  Retain each eligible record, preserving source order.
C3  For each retained record r:
        notify.send(to=r.recipient, body=r.summary), once.
C4  Set n to the number of retained records.
C5  Write receipt.json with {"selected_count": n}, once.
C6  Display {"selected_count": n} to the coordinator, once.
```

This follows the stated ordering in `SKILL.md:8–12`. The parentheses keep the opt-out check outside the urgency/score alternative. There is no branch that permits urgency to bypass an opt-out (`SKILL.md:9`).

**Minimization conclusions and preservation limits.**

1. **No staff triage note reaches a supported exposure boundary.** Every note enters D1, and the P-401/P-402 notes remain in D2, but both versions stay in the controller’s explicitly private ephemeral memory. The patient body expression selects only `r.summary`; the summary and triage note are expressly separate fields (`SKILL.md:8–10,14–15`; `CONTRACTS.md:13–21,25–27`). Thus T5 is respected at delivery. It would be incorrect to describe all acquired notes as model-observed, sent to patients, or written to the receipt.

2. **The source does not establish that acquiring every field is task-necessary.** Eligibility needs the predicate fields; delivery needs the selected record’s address and unchanged summary; the receipt needs the selected count. The independent task does not require triage notes as inputs. Nevertheless, unnecessary acquisition within the explicit private local controller is not, by itself, a supported unnecessary exposure at a receiving, model, or storage boundary (shared rule 7). The bundle provides no field-limited read interface from which to claim a specific acquisition reduction is already available.

3. **The selected clinical payload is required in its current form at the patient recipient.** The summary text includes each patient’s identifier, but T3 requires the summary to remain unchanged. Redacting that identifier, paraphrasing the result, omitting part of the summary, combining the two summaries, or replacing delivery with a count would violate an affirmative task requirement. Using each corresponding address is necessary to maintain the required recipient pairing. This is a payload-specific justification, not an exemption for every field of a selected record.

4. **P-403 and P-404 produce no patient delivery.** P-403’s urgency and high score do not bypass its opt-out; P-404 fails both positive alternatives. Their acquired summaries and addresses remain local. They are not included in B1/B2, and the count payload does not serialize them (`records.json:22–37`; `SKILL.md:9–12`).

5. **The persistent and coordinator-visible payloads are limited to the requested count.** B3/B4 receive D5, not D2. There is no basis for propagating the selected patients’ plaintext fields into the receipt or reply merely because the count depends on selection. Both operations are positively requested, and neither has an established excess field.

6. **The analytics vendor receives no supported workflow payload.** Its ability to receive and retain data is documented, but no call path from C1–C6 invokes `metrics.publish` (`CONTRACTS.md:37–39`; `SKILL.md:8–12`). Treating that service as an actual recipient would manufacture an exposure.

There is consequently no established excess for which a corrective payload reduction is warranted. A local projection that retains only selected `(recipient, summary)` pairs and the count could reduce subsequent private controller state, but it would not undo the initial full acquisition, and the current contract does not make that private state an exposure. It would therefore be an optional state-minimization change, not a demonstrated fix for an exposure found here.

The conclusion depends on the explicit local-isolation and exact-delivery contracts. Notification-interface deployment, request retention, failure handling, and any field-limited acquisition capability remain unresolved. Those gaps do not support inventing extra recipients or protections, and they prevent treating “no excess established” as a proof of safety, complete necessity, semantic completeness, or global minimality.
