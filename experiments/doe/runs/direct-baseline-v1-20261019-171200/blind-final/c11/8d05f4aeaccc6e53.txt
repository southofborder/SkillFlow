### Supported finding and concrete correction

**Pass the masked version to the drafting model.** The source creates an appropriate reduced version but then explicitly passes the unchanged original (`SKILL.md:9–10`). Because `mask_fields` creates a fresh object without modifying its input, this is not an ambiguity about whether masking happened in place (`CONTRACTS.md:30–34`).

The unnecessary payload comprises:

- `customer_email`, classified as confidential contact information.
- `session_key`, classified as a confidential active-session credential.

Both reach the same external provider, are observed by its model, and remain in its retained request on every execution of the described sequence. The finding follows from the unnecessary **payload**, even though the drafting action itself is required. It does not depend merely on the recipient being external or on the user’s prohibition: the source independently establishes that the public fields suffice and that exact replacements preserve those fields.

The proposed replacement for step 3 is:

```text
draft_v3 = draft_model.compose(
    ticket=redacted_v2,
    style="one sentence; preserve any quoted error_text verbatim"
)
```

This preserves function because the documented transform:

- Keeps `product`, `error_text`, and `requested_fix` unchanged.
- Supplies the two exact placeholders the user specified.
- Preserves the ticket’s field structure.
- Requires no additional model call or saved memory.

The existing one-sentence style and single `user.reply` can remain. Keeping the documented local cleanup is compatible with this correction, although cleanup cannot substitute for sending the correct version. Moving the working-variable assignment before the call would also work **only if the call actually passes that masked variable**; changing an unused variable alone would not address the defect.

For this fixture, neither original confidential value occurs in `error_text`, so cleanup does not alter the quoted public error (`ticket.json:3, 5–6`; `CONTRACTS.md:42–44`). The proposed request correction also preserves that error text directly.

### Limits and unresolved cases

The source does not provide the actual returned draft. It establishes that the model uses the public issue fields for a one-sentence note, but it does not specify every possible returned character. The cleanup removes complete occurrences of the original email and session key; it does not establish removal of every possible fragment, encoding, or paraphrased disclosure. Conversely, receiving the original request is not evidence that the model’s response contains those confidential values. Those output possibilities remain unresolved, rather than additional established findings (shared rules **4** and **8**).

The controller contract expressly excludes implicit model observations and unmentioned logging or telemetry. Accordingly, local loading, masking, assignment, and cleanup must not be inflated into further disclosures. The definition of `context.save` likewise does not establish that memory was saved.

The supported correction removes the original confidential values from all three established provider-side consequences—delivery, model observation, and request retention—while preserving the specified public inputs, placeholders, recipient, one-sentence format, and single requester output. No excess is established at the remaining boundaries; that limited conclusion does not prove universal output safety or global minimality.
