# Historical context for the three revised full-chain pilot answers

This is a qualitative background comparison, not a controlled comparison, gold standard, semantic assessment, or score. The revised first answers articulate a source-supported **conditional minimization opportunity at model observation** for cases 001 and 013 that the inspected historical deterministic DOE results do not affirmatively establish. They do not reveal an omitted model-observation boundary: both historical results already contain the relevant boundary and credential sensitivity. For case 010, no concrete sensitive-data difference is defensible. No historical partial result is treated as a model semantic failure.

## Scope and comparability

The direct materials inspected were the frozen `cases/{001,010,013}/source_bundle.txt` and only `trials/p001_chain_r1_v2/answer.txt`, `p010_chain_r1_v2/answer.txt`, and `p013_chain_r1_v2/answer.txt`. Historical files were located by explicit file search under `latest-prompts-pipeline-v1-20261018-124304` (001/010) and `case-013-rerun-v1-20261019-105450` (013). The comparison uses their visible run reports, manifests, corresponding English source packages, and formal DOE reports/results. It does not evaluate every historical annotation or derivation. No reference/gold material, blind packets, assessor files, hidden reasoning, credentials, or other agent sessions were read. No model or network call was made and no historical artifact was changed.

The historical pipeline used newly sampled source-only Task extraction followed by annotation/review and deterministic propagation/DOE over retained historical CFGs; it did not re-extract the graph. It requested `deepseek-v4-flash`, effort `max`. The direct full-chain answers instead reason from the source bundle and their supplied shared static-analysis contract. Model identity is not matched by this review, and the task format, graph availability, stages, and output types differ; these factors prevent causal attribution of differences to either method. See the historical [three-case report, lines 7–15](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/report.md:7), [manifest, lines 5–8 and 75–84](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/manifest.json:5), and [013 rerun report, lines 3–5 and 35](D:/projects/SkillFlow/experiments/doe/runs/case-013-rerun-v1-20261019-105450/report.md:3).

All three historical DOE states are explicitly `partial`. Their reported counts concern declared ranges, not measured leaks. The direct answers are also static, conditional analyses, not execution evidence. No independent user task was supplied, so both source interpretation and any preservation argument concern the Skill's declared function rather than independently verified user authorization.

## Case 001: unused credentials in acquired records

**Source facts.** Each acquired event record names `access_token`, but selection uses `opted_out`, `urgent`, and `value`; each selected notification uses the same record's recipient and unchanged summary. Sending the token is prohibited; the final local write contains a processed-record count. The source does not define that count precisely. These facts appear in [source bundle, physical lines 9–17, embedding `SKILL.md:8–16`](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/cases/001/source_bundle.txt:9).

**Historical reported state.** The historical DOE report records six sinks, one declared sensitive scope, and four `no_excess_established` comparisons, with partial demand analysis ([report, lines 5–30](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/cases/001/doe/report.md:5)). Its acquisition-stage `model_observe` row already carries the credential-bearing data: the row references `sensitivity_3084fdb16e4a9ed8aeda`, whose declaration is each record's `access_token`. Its conclusion is withheld because relevant limitations prevent supported excess, not because it proves token necessity ([result, lines 195–246](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/cases/001/doe/doe-result.json:195); [credential scope, lines 405–421](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/cases/001/doe/doe-result.json:405)).

**Direct claim.** The revised answer identifies possible early model observation of tokens from selected and unselected records, distinguishes it from the narrower notification payload, and proposes an isolated local exclusion step before model-visible return. It preserves the predicate, record pairing, original summaries, per-record calls, and count obligation while retaining the count ambiguity ([answer, lines 101–118](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p001_chain_r1_v2/answer.txt:101); [lines 138–165](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p001_chain_r1_v2/answer.txt:138)).

**Inference.** This is a defensible additional minimization argument in the direct narrative: the named credential has no stated computational role, and removing it from a proposed model-visible version need not change the specified notification values. It is not a newly discovered historical flow or demonstrated false-negative model judgment. The historical result intentionally abstained under global limitations. The proposed isolation interface is absent from the source; its feasibility and exact behavior are premises of the reduction, not existing protections or proven semantic equivalence.

**Source facts.** The linked workflow requires one search with unchanged `term`, optional arguments included unchanged only when present, `total` written locally, and `items` returned unchanged. Neither concrete contents nor sensitive classifications are supplied ([source bundle, physical lines 19–39, embedding `references/workflow.md:3–23`](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/cases/010/source_bundle.txt:19)).

**Historical reported state.** The report records twelve sinks but zero sensitivity declarations or range comparisons, explicitly limits coverage to declared ranges, and remains partial ([report, lines 3–33](D:/projects/SkillFlow/experiments/doe/runs/latest-prompts-pipeline-v1-20261018-124304/cases/010/doe/report.md:3)). That is an evidence boundary, not a finding that request/response data are nonsensitive.

**Direct claim.** The revised answer likewise declines an unconditional sensitive-over-exposure finding. It describes possible whole-request and actual response observation, preserves the exact optional-argument semantics, and proposes a local executor only conditionally on sensitive content, avoidable model routing, an isolation interface, and compatible return delivery ([answer, lines 1–3](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p010_chain_r1_v2/answer.txt:1); [lines 98–127](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p010_chain_r1_v2/answer.txt:98)).

**Inference.** No concrete historical sensitive-data omission or over-conservative semantic claim is established. The direct narrative adds a useful conditional implementation proposal, but absent sensitivity and return-recipient evidence it cannot turn the historical empty declaration set into a demonstrated missed DOE. Ordinary return remains distinct from established user delivery.

## Case 013: credential use at the preferred tool versus model observation

**Source facts.** `FAST_KEY` gates the preferred fetch and is an explicit argument to that fetch, including the single transient-error retry. The archive accepts only `source_id`; successful body values remain unchanged, archive failure returns its error, and every terminal path appends a final status. The key is prohibited at the archive and diagnostic output. Status representation and transient classification are unspecified ([source bundle, physical lines 9–17, embedding `SKILL.md:8–16`](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/cases/013/source_bundle.txt:9)).

**Historical reported state.** The rerun retains separate preferred-call parameter demands and archive `source_id`-only arguments, one credential declaration, sixteen sinks, and ten `no_excess_established` comparisons. Its report explicitly says this does not prove field necessity, prohibition compliance, or absence of DOE ([rerun report, lines 12–27](D:/projects/SkillFlow/experiments/doe/runs/case-013-rerun-v1-20261019-105450/report.md:12)). The key-acquisition `model_observe` row already exists and states that preservation demand retains the property or conservatively overlapping range, expressly disclaiming irreplaceability ([result, lines 56–118](D:/projects/SkillFlow/experiments/doe/runs/case-013-rerun-v1-20261019-105450/cases/013/doe/doe-result.json:56)).

**Direct claim.** The revised answer separates credential delivery needed by `fast.fetch` from possible plaintext observation by the coordinating model. It proposes a model-invisible broker that preserves key presence, original credential binding, retry cardinality, fallback triggers, and archive arguments. It labels the broker and routing as proposals and does not infer credential plaintext in responses or final status from dependency alone ([answer, lines 87–104](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p013_chain_r1_v2/answer.txt:87); [lines 120–128](D:/projects/SkillFlow/experiments/doe/runs/direct-baseline-v1-20261019-171200/trials/p013_chain_r1_v2/answer.txt:120)).

**Inference.** This exposes a useful limit of the historical conservative output: preserving a credential's required use by one receiver does not establish that a different receiver must inspect it. The direct first answer supplies that receiver-specific, conditional reduction argument. It does not refute the historical abstention, which already disclaims irreplaceability, and it does not demonstrate a historical model error. Broker feasibility, routing isolation, presence semantics, and transient classification still require implementation evidence. Neither version supports a claim that the archive or status file receives credential plaintext.

## Research implication

The defensible qualitative difference is **actionable, conditional receiver-specific minimization reasoning in the direct first answers**, most clearly for named credentials in 001 and 013. The inspected historical results retain those exposure paths but stop at partial deterministic comparisons. There is no supported new exposure-boundary discovery, demonstrated historical semantic failure, or evidence that the direct approach is more accurate overall. A future controlled comparison would need matched models, inputs, runtime assumptions, and evaluable output obligations; these historical artifacts cannot supply that control.
