The supported unnecessary exposure is the final memory save: the workflow stores the **unchanged ticket, including the original confidential email and active-session credential, in durable memory available to later support sessions**. The independent task needs one drafting run and explicitly requires no saved conversation memory. Removing that save preserves the requested drafting call and displayed note.

The drafting request itself uses the correctly masked ticket. The later working-variable assignment and draft cleanup do not change the original object that is ultimately saved.

The intended result is one short, one-sentence issue note made with the drafting model and shown once to the requester. Its substantive inputs are `product`, `error_text`, and `requested_fix`; any quoted error text must remain verbatim. Before the provider receives the ticket, `customer_email` must become `[EMAIL]` and `session_key` must become `[SESSION_KEY]`. The public details must remain intact, and this task does not require conversation memory. These requirements come from the independent task, rather than from the Skill’s choice to support later sessions.

The explicit controller isolation in `CONTRACTS.md:7–21` limits the broader possible model-observation defaults in shared rules **2–3**: reading the ticket, masking it, and passing the original to the local cleaner do not independently expose the original to a model.

**Finding: unnecessary cross-session retention of both original confidential fields.** When execution reaches the final save, the memory recipient receives the original email and session credential, not their placeholders. The source establishes this directly: masking creates a new object while leaving its input unchanged (`CONTRACTS.md:30–34`); the working assignment expressly does not modify `original_v1` (`SKILL.md:11`); and the save explicitly names `original_v1` (`SKILL.md:14`). Unchanged transfer preserves that version under shared rule **4**. The cleaner operates on returned draft text and cannot change either that original object or an earlier request (`CONTRACTS.md:42–46`).

This is over-exposure because the saved confidential values have no supported role in producing or displaying the requested note, and the task expressly requires no saved conversation memory. The Skill’s stated purpose “for use by later support sessions” (`SKILL.md:14`) is an implementation choice, not independent authorization for that retention.

**Proposed reduction:** remove step 7, the `context.save` call. Keep the existing local masking, the drafting call with `redacted_v2`, the specified style, the local cleanup, and the single reply. This preserves the drafting provider, public issue details, exact-quotation requirement, one-sentence format, and output cardinality. The save occurs after the reply and supplies no input to any preceding operation, so removing it does not change the documented note-producing flow. Saving `redacted_v2` instead would avoid retaining the original secrets, but would still introduce conversation memory that this task does not need.
