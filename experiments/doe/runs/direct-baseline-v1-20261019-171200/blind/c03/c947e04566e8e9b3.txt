The concrete finding is **F1: unnecessary cross-session retention of the original sensitive fields at B3**.

- **Source-explicit facts:** V1 contains the original confidential email and active-session credential (`ticket.json:5–6`; `CONTRACTS.md:24–26`). The save names V1 directly (`SKILL.md:14`), and the contract stores exactly that value in durable assistant memory readable by later support sessions (`CONTRACTS.md:48–49`).
- **Task comparison:** The requested note uses only the three public substantive fields, requires replacement of the private fields before provider reception, and needs no saved conversation memory (T1–T6). The memory write occurs after the note has already been shown. Neither the write nor retention of either private value contributes to the requested one-run result.
- **Supported exposure:** On the normal path, the two original sensitive values reach later-session-readable memory. This conclusion rests on the save argument and memory contract, not merely on the values’ sensitivity, boundary level, or the task restriction.
- **Functionality-preserving reduction:** Remove `context.save(key="last_support_ticket", value=original_v1)` from `SKILL.md:14`. The read, masking, drafting call, exact-quote handling, cleanup, and single response remain available with the same inputs and ordering. The response already precedes the save, and no subsequent operation is documented as consuming the saved value (`SKILL.md:8–17`). This removal preserves the requested note and eliminates both the unnecessary action and its confidential payload.
- **Why substituting a different value is weaker:** Saving V2 or F4 would reduce this sensitive payload, but would retain an unsupported durable memory operation. Removing the save matches the one-run task directly. No new routing, filtering interface, or provider capability is assumed by this proposal.

The drafting and reply path do not support a second positive sensitive-data finding:

- **At B1a–B1c**, the exact local masking mechanism provides evidence that the provider and model receive V2. This is stronger than a mask function’s name or an instruction to avoid secrets: the contract specifies the changed fields, fresh object identity, absence of reversible replacement information, and local visibility (`CONTRACTS.md:30–40`). The supplied task specifically requests those replacements. There is no supported excess confidential field left in that request.
- **At B2**, the actual output is F4. The cleanup operation removes occurrences of the two exact original private strings and does not change other characters (`CONTRACTS.md:42–46`). The concrete public product, error text, and requested fix contain neither private string (`ticket.json:2–6`), so that replacement does not require modifying those public details. The one-sentence and exact-quotation properties are supported by the compose contract; there is no actual returned note here to verify independently.
- **Inside local cleanup**, V1’s sensitive fields are inspected for matching. That is local current-run processing under the explicit controller contract, not a supported exposure sink. This observation does not prove that every local sensitive read is globally necessary; it means local inspection alone does not establish the requested kind of unnecessary exposure.
- **The post-compose assignment is not a repair or a new disclosure.** `working_ticket = redacted_v2` occurs after provider observation and changes no earlier request. In this source, the earlier request was already masked. The assignment also cannot protect B3, because B3 explicitly saves `original_v1` (`SKILL.md:10–14`; shared rules 3–4).
- **Cleanup cannot retroactively protect a prior request.** That limitation is explicit (`CONTRACTS.md:45–46`). It does not produce an additional finding here because the prior request already used V2.

The remaining evidence limits are specific. No execution, draft text, failure behavior, provider retention duration, or downstream provider access is supplied. The contract supports declared one-sentence composition and exact quoted error text, but the bundle does not contain a resulting note against which to verify every public detail. There is no basis to invent additional sensitive fields, implicit model access to V1, backend logging, public disclosure, or later-session use of the saved record.

After checking the versions, recipients, timing, and reduction argument against the source, F1 remains directly supported: **omit the final original-ticket memory save while preserving the existing masked drafting and single-reply path.** The absence of another established excess at the other boundaries is not proof of safety, semantic completeness, total necessity, or global minimality.
