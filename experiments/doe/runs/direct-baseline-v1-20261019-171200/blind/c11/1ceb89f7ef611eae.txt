**Task-related judgments and reductions.**

**J1 — Supported excess: both original confidential values at B1–B3.**  
This finding follows from the actual payload and a documented task-preserving alternative, rather than from sensitivity or a prohibition alone.

The task requires replacement before provider reception. The only substantive drafting inputs required are the three public issue fields. The source already constructs R2 before composition, and R2 preserves those public fields exactly. Nevertheless, composition passes the unmodified O1. Thus the provider receives and retains the original confidential contact information and session credential, and the model observes them. [U2–U3; SKILL.md:8–11; CONTRACTS.md:25–40]

Using the drafting model is required. Sending these two original values is not. No necessary sensitive use of either original value is established at the external provider, model-observation, or retained-request points.

Replace step 3 with:

```text
draft_v3 = draft_model.compose(
    ticket=redacted_v2,
    style="one sentence; preserve any quoted error_text verbatim"
)
```

This uses an existing documented interface and an existing concrete version. Its preservation argument is specific:

- R2 has the same field structure and unchanged `product`, `error_text`, and `requested_fix` values, so the required issue details remain available to the drafting model. [CONTRACTS.md:30–32]
- The two confidential fields contain exactly the required placeholders before provider reception. [CONTRACTS.md:30–34; U3]
- The model and exact style argument remain the same, preserving the documented one-sentence drafting and verbatim-quotation behavior. [SKILL.md:10; CONTRACTS.md:36–40]
- The current local cleanup and one final reply remain available. Cleanup can still use O1 privately; the provider does not need O1 for that operation. [SKILL.md:12–13; CONTRACTS.md:42–50]
- No conversation-memory save or additional call is introduced.

For the concrete fixture, neither original confidential string occurs in the public error or other public issue values. Consequently, the existing exact-string cleanup does not require changing those public input details. [ticket.json:2–6; CONTRACTS.md:42–44]

In a corrected run, the retained request would contain R2 and S instead of O1 and S. This preserves the documented drafting function and required input details; it does not promise an identical generated sentence or prove the semantic quality of an unseen output. It also does not erase any hypothetical request previously delivered.

**J2 — Later masking-related actions do not repair the earlier exposure.**  
R2 exists before the call but is not sent. Assigning W afterward does not mutate O1, and W is unused by subsequent specified steps. Cleaning D3 changes returned text only. None of these operations modifies the request already received, the model’s earlier observation, or the provider’s retention of that request. [SKILL.md:9–12; CONTRACTS.md:42–46; shared rule **3**]

**J3 — Public fields and style have supported task roles.**  
The three public fields are required issue inputs, and the style implements the required output form and quotation constraint. Their inclusion in the drafting request has a clear task basis. No sensitive-data excess is established for them. The placeholders also have a direct basis in U3. [U1–U3, U5; CONTRACTS.md:27–32, 36–40]

This does not establish that provider retention is independently needed by the user. Retention is documented service behavior. No source-supported retention-control interface is supplied, so a claim that retention can be disabled while preserving this service’s function would require an additional premise.

**J4 — Possible sensitive influence, but insufficient evidence for an additional output disclosure at B4.**  
D3 comes from a call whose model observes O1. Its opaque content therefore retains possible input influence. That is not evidence that it contains the original email, key, a fragment, or a derived representation. Response dependence does not prove plaintext inclusion. [CONTRACTS.md:36–40; shared rules **4**, **8**]

The cleanup guarantees replacement of occurrences of the two complete original strings. It leaves other characters unchanged. Accordingly:

- A complete original email or session-key string occurring in D3 is replaced before B4.
- A partial or transformed sensitive representation is not covered by the documented exact-string replacement mechanism.
- The source provides no concrete output establishing that such a residual representation exists.

The correct judgment at B4 is therefore **no additional sensitive excess established, with possible residual influence unresolved**. Passing R2 at the earlier call removes the supported original-value input path to the drafting model and avoids relying on downstream cleanup to undo that path.

**J5 — No additional local or memory exposure finding.**  
The complete local read and cleanup’s use of O1 are not proved necessary merely because they are implemented. However, their stated routing is private and ephemeral, and they create no separate exposure sink. A field-only acquisition interface is not documented, so such an interface should not be assumed as an immediately available repair. The demonstrated B1–B3 reduction requires no acquisition change. [CONTRACTS.md:7–24, 42–45; shared rules **1–3**, **7**]

No saved conversation memory occurs. The source-defined provider retention must not be relabeled as assistant conversation memory, nor should the unused definition of `context.save` create an exposure finding. [CONTRACTS.md:36–38, 48–49; SKILL.md:8–16]

**Consistency and evidence limits.** The principal finding uses source-explicit facts: the original ticket contains two confidential values; masking creates a separate object; the call passes the original object; the model observes its fields; and the provider retains the request. The source also explicitly isolates local processing. These facts support the external excess without adding implicit local model calls, public dissemination, third-party forwarding, telemetry, or further storage systems.

The repair’s preservation argument rests on documented versions, exact masking, unchanged public inputs, and the existing composition interface. It needs no unstated getter, credential proxy, or routing feature. Concrete draft quality, partial sensitive output, failure behavior, and retention duration remain unprovided. “No additional excess established” is not proof of safety, total necessity, semantic completeness, or global minimality.
