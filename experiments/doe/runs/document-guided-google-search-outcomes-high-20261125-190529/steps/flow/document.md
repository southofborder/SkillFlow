# Google Search flow

- **Skill scope and setup.** The Skill describes Google PSE searches for live information, documentation or research when built-in `web_search` is unavailable. Setup requires enabling Custom Search API, obtaining an API key and CX ID, and storing `GOOGLE_API_KEY` and `GOOGLE_CSE_ID` in a workspace `.env`. The example instead supplies both as process environment variables. The workflow section contains only an omission marker, so its missing obligations remain unresolved. (`skill/SKILL.md:2-3`, `skill/SKILL.md:8-22`, `skill/SKILL.md:24-28`)

- **Independent callable entry.** `google_search(query, api_key, cse_id, num_results=5)` accepts caller-provided inputs without reading the environment. It sends an HTTP GET to `https://www.googleapis.com/customsearch/v1`, pairing `q` with `query`, `key` with `api_key`, `cx` with `cse_id`, and `num` with `num_results`. In order, it acquires the HTTP response through `requests.get`, checks its status, then returns the value decoded by `response.json()`. That returned value comes from the API response, not merely the request parameters. Failures propagate to the caller. (`skill/scripts/search.py:6-16`)

- **CLI entry and conditions.** Execution under `__main__` first checks whether `sys.argv` contains a query argument. If absent, it prints usage and exits with status 1. Otherwise, `sys.argv[1]` becomes the query; when `len(sys.argv) > 2`, `sys.argv[2]` is converted to an integer result count, otherwise the count is 5. Conversion occurs outside the exception handler, so conversion failure prevents credential reads and the request. (`skill/scripts/search.py:18-24`, `skill/scripts/search.py:34-39`)

- **Credentials, call and delivery.** The CLI next reads both named environment variables. If either value is falsey, it prints the credential error and exits with status 1. Otherwise, it calls `google_search(query, api_key, cse_id, num_results)`. The returned decoded API value is received as `results`, serialized using `json.dumps(results, indent=2)`, and printed. Exceptions caught around this call and output sequence produce an error message from the actual exception and exit status 1. Request failure, response-status failure, decoding failure and output failure occur at different stages; output failure can follow a successful API return. (`skill/scripts/search.py:26-39`)

- **Dependencies, state and gaps.** The script imports `sys`, `json`, `requests` and `os`; the CLI consumes the callable’s returned value. It reads existing process environment state but shows no `.env` loader, environment mutation, file save or later file read. Thus the Skill’s `.env` setup has no demonstrated loading connection to this script. No supplied source connects search results to analysis, saved-result ownership, reading or summarization; those relationships remain explicit gaps.
