# GA4 Toolkit processing flow

## Entry points and shared state

The Skill specifies three phases in order for every analysis. Call the APIs, automatically save timestamped JSON under `results/{category}/`, then read the saved JSON and create a Markdown summary under `results/summaries/` with tables, trends, and recommendations. The tip about requesting a summary also appears in the Skill. The implementation has conditional saves and leaves the Markdown phase to the documented workflow. `skill/SKILL.md:53–64,116–142,152–158`

Import high-level functions and re-exported APIs and utilities from `./scripts/src/index.js`. The individual `./api/*.js` modules and `./core/storage.js` also expose independent entry points. The documented `npx tsx scripts/src/index.ts` route prints help when `process.argv[1]` equals the module URL pathname. The guarded body contains only the help print. Setup runs `npm install` in `scripts`, and the Skill calls for a project-root `.env`, enabled Google APIs, and service-account access. The package is ESM on Node ≥18 and the TypeScript configuration uses NodeNext. `skill/SKILL.md:8–51,100–102`; `skill/scripts/setup.sh:1–2`; `skill/scripts/package.json:1–17`; `skill/scripts/tsconfig.json:1–19`; `skill/scripts/src/index.ts:12–46,364–405`

On settings-module initialization, `dotenv.config()` acquires `.env` from the current working directory and can populate the process environment subsequently read by `getSettings()`. Each settings read gets the GA4 property ID, service-account email and key, Search Console site URL, date default (`30d` if unset or empty), and `<cwd>/results`. It expands escaped newlines in the key. Each client getter checks its own cached handle first. A hit returns that handle with its creation-time credentials. A miss validates property ID, email, and key, throws on failure, or creates, caches, and returns a new handle. The GA4 client comes from `@google-analytics/data`. Search Console `v1` and Indexing `v3` come from `@googleapis/searchconsole` and `@googleapis/indexing`, with `googleapis` providing GoogleAuth and its `webmasters.readonly` and `indexing` scopes. `resetClient()` clears all three references. Requests obtain `properties/<id>` or the site URL from current settings separately from the cached client. Validation does not check the site URL. `skill/scripts/src/config/settings.ts:5–9,40–74`; `skill/scripts/src/core/client.ts:6–133`

## Acquisition and delivery

Parameter names below identify the inputs at each public entry. For collection traversal, the header consumes the named collection and branches on `has_member`. The true edge takes the current member, processes it, and returns to the header. The false edge exits. For the sequential URL workflows, a rejected per-URL call follows the failure edge described below.

- **Standard GA4.** `runReport(options)` takes `dimensions`, `metrics`, optional `dateRange`, `filters`, `orderBy`, `limit`, and `save`. It maps dimensions and metrics to API name objects and sends them with the property, parsed date range, and `limit` when truthy. The reference lists filters and ordering, which the implementation accepts but omits from the Google request. The first response from `client.runReport` is returned and, when `save` is enabled (default `true`), written to `reports` under the dimension names joined by `_` or `custom`. Only an original string date range supplies filename extra information. `parseDateRange(range)` uses settings for a falsy input, passes an object through, converts `Nd` to `NdaysAgo` through `today`, and falls back to 30 days for other strings. `skill/scripts/src/api/reports.ts:12–28,47–109`; `skill/references/api-reference.md:19–45`
- **Bulk GA4.** `getMetricsForUrls(urls, options?)` passes `urls` to `normalizeUrls`, which trims each member, adds a missing leading slash, and preserves trailing slashes. Empty normalized input returns `{ rows: [], rowCount: 0 }` before client acquisition or saving. Otherwise `buildUrlFilter` receives the normalized paths and supplies a case-insensitive `pagePath` in-list filter. Called independently with an empty list, the filter helper returns `null`. Bulk lookup uses its own date parser with the same GA4 rules and imports only the report types from `reports`. It calls the GA4 client directly for `pagePath` and `pageTitle`, with supplied `metrics` or `screenPageViews`, `activeUsers`, `averageSessionDuration`, `bounceRate`, and `engagementRate`. The first API response is returned and saved by default to `reports/bulk_url_lookup`, with the original string range or `custom` as extra information. `skill/scripts/src/api/bulk-lookup.ts:8–23,46–128,149–192`
- **Realtime and metadata.** The independent realtime functions take `save = true`, call `runRealtimeReport` on the property, and return the first response. Their dimension → metric and save-operation pairs are `getActiveUsers` (`unifiedScreenName` → `activeUsers`, `active_users`), `getRealtimePages` (`unifiedScreenName` → `screenPageViews`, `pages`), `getRealtimeEvents` (`eventName` → `eventCount`, `events`), and `getRealtimeSources` (`firstUserSource` and `firstUserMedium` → `activeUsers`, `sources`), all under `realtime`. The metadata functions also take `save = true` and query `<property>/metadata`. `getAvailableDimensions` and `getAvailableMetrics` return objects containing the respective array, defaulting it to `[]`, and save that projection under `metadata/dimensions` or `metadata/metrics`. The reference describes array returns. `getPropertyMetadata` returns and saves the full first response under `metadata/full`. `skill/scripts/src/api/realtime.ts:24–99`; `skill/scripts/src/api/metadata.ts:38–95`; `skill/references/api-reference.md:163–193`
- **Search Console.** `querySearchAnalytics(options)` sends the configured `siteUrl` and request body with `dimensions` (default `['query']`), parsed dates, `rowLimit` (1000), and `startRow` (0). `parseSearchConsoleDateRange(range)` uses settings for a falsy input, passes explicit objects through, and turns `Nd` or the 30-day fallback into ISO calendar dates. The source calls for `YYYY-MM-DD` at this API boundary. Passing an object containing GA4-relative dates would forward those values unchanged, despite the Skill’s general date-format guidance. The query returns `response.data` and saves it by default to `searchconsole` under the joined dimensions or `query`, with an extra only for an original string range. The independent helpers pass single dimensions and these limits: `getTopQueries` uses `query`/100, `getTopPages` uses `page`/100, `getCountryPerformance` uses `country`/50, and `getDevicePerformance` and `getSearchAppearance` use `device` and `searchAppearance` with the default limit. The reference describes top pages by impressions and entry-point help describes them by clicks. The request supplies no sort parameter. `skill/scripts/src/api/searchConsole.ts:47–175`; `skill/references/api-reference.md:201–263`; `skill/SKILL.md:104–114`; `skill/scripts/src/index.ts:285–286,382–385`

After all children succeed, the orchestrator saves and returns the aggregate payload. For the ordinary date-based aggregates, the extra is the original string or `custom`. `skill/scripts/src/index.ts:55–165,209–295`

The report wrappers pass `dateRange` to `runReport` with their fixed dimensions and metrics. Page views use path/title and views/users/duration. Traffic uses source/medium/campaign and sessions/users/new users/bounce rate. Demographics use country/device/browser and users/sessions/new users. Events use event name and event count/count per user/users. Independent conversion and ecommerce wrappers use event/source with conversions/revenue, and date/transaction with revenue/purchases/average purchase revenue, respectively. `getAvailableFields()` calls `getPropertyMetadata()` with default saving, logs dimension and metric counts, and returns that full response. `skill/scripts/src/api/reports.ts:114–175`; `skill/scripts/src/index.ts:355–362`

## URL operations

`requestIndexing(url, options?)` and `removeFromIndex(url, options?)` publish the input URL to the Indexing client with `URL_UPDATED` and `URL_DELETED`, respectively. Each returns a notification with the API metadata URL or input URL and the corresponding update/removal notification time or current ISO time. `inspectUrl(url, options?)` sends the URL as `inspectionUrl` and the configured `siteUrl` to the Search Console client. It returns a projection with index status, optional link, and optional mobile usability and rich results. Missing index verdict and coverage become `NEUTRAL` and `Unknown`. All three save their returned projections by default under `indexing`, with operations `request_indexing`, `remove_from_index`, and `url_inspection`. `skill/scripts/src/api/indexing.ts:57–80,114–193`

| Entry and collection | True edge for the current URL | False edge after traversal |
|---|---|---|
| `requestIndexingBatch(urls, options?)` | Await `requestIndexing(url, { save: false })` and append the notification. A rejection exits before the aggregate save. | Save the array as `indexing/batch_indexing` if `save` is enabled (default `true`), then return it. `skill/scripts/src/api/indexing.ts:89–105` |
| `reindexUrls(urls)` | Await `requestIndexing(url, { save: false })`. Append a submitted row using the notification’s URL, type, and time on success, or an input-URL failed row with the caught error string on rejection. Both rows lead back to traversal. | Save and return the status array as `indexing/reindex_batch`. `skill/scripts/src/index.ts:301–319` |
| `checkIndexStatus(urls)` | Await `inspectUrl(url, { save: false })`. Append the input URL, its `indexStatus`, and `indexed` from the exact `PASS` comparison. On rejection append the input URL, `indexed: false`, and an error status from the caught exception. Both rows lead back to traversal. | Save and return the status array as `indexing/index_status_check`. `skill/scripts/src/index.ts:324–346` |

## Storage, reading, and the summary gap

`saveResult(data, category, operation, extraInfo?)` creates a missing category directory and synchronously writes `{metadata, data}`. Metadata records `savedAt`, category, operation, current settings’ property ID, and a truthy extra if present. The path uses a local second-resolution timestamp, sanitized lowercase operation, and optional sanitized extra. Writes to the same path replace its contents. `saveResult` returns the path, but the supplied API and orchestration call sites discard it and return their payloads. `skill/scripts/src/core/storage.ts:31–95`; `skill/scripts/src/api/reports.ts:100–108`; `skill/scripts/src/index.ts:71–76,195–203,316–318`

`listResults(category, limit?)` reads directory entries when the category exists, keeps `.json` paths, sorts by descending filename, then applies a supplied limit. `loadResult(filepath)` independently reads and parses that path, returning the saved wrapper or `null` on a missing file or read/parse failure. `getLatestResult(category, operation?)` consumes the listed paths, optionally filters by the sanitized `__operation` substring, and loads only the first match if one exists. The Skill shows listing reports, loading `files[0]`, and independently getting the latest `site_overview`. These selectors provide no run-specific association between a particular invocation and a later read. The supplied code leaves that file selection and the Markdown summary write unresolved, while the Skill still requires reading saved JSON and creating the summary. `skill/scripts/src/core/storage.ts:103–171`; `skill/SKILL.md:53–64,129–142`
