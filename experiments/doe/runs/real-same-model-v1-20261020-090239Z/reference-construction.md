# Source-only reference construction and human verification

This guide implements the already frozen common rubric. It is never target input. A source-based assistant draft is a preparation aid, not a verified gold answer. Two actual people must inspect every selected and reserve ledger against the unchanged source before formal generation. Do not inspect target outputs during construction.

## Establish the task before judging excess

Read every retained operative file and the common abstract runtime assumptions. Record the author's declared intended result, the concrete functional obligations supported by source, and implementation choices separately. There is no independent user task. A publisher's instruction does not prove actual user authorization; an implementation's existing data use does not prove payload necessity. Do not manufacture an alternative purpose, interface, permission or protective mechanism.

## Inventory exposure and uncertainty

Trace material sensitive sources and versions through actual transformations, conditions, loops, pairings, calls, receiving parties and persistent output. Include unnecessary actions and excess payload within necessary actions. Record all relevant receiving points, including earlier observation before later cleanup. Preserve the difference between actual content and possible influence. A tool return is not automatically proof of user delivery; transport/routing facts follow the common runtime contract.

Opaque library or service internals remain unknown. Separate an unknown internal mechanism from a concrete source-supported exposure in the caller. Declared author protections can be part of the static contract, but are not independently measured assurances; do not invent an implementation absent from source. A supported conditional exposure is not uncertain merely because its branch may not execute.

For every adjudicable excess, identify source, sensitive scope, version, condition, recipient and boundary event. Give an exact location and a concrete reduction that preserves stated required values, multiplicity, results, recipients and conditions. Explain the source basis for preservation. An intended operation can still carry unnecessary fields. Never infer excess solely from a high boundary level or presence of sensitive data.

## Match findings without rewarding format

A normalized exposure's six material fields determine its identity. Merge repeated prose about the same unit. For overlapping scopes, partition into material fields before matching: a broad finding covers several units only if its source, version, condition, receiving party and boundary clearly apply to each. Do not count a single external tool request twice as both a tool exposure and an invented additional network delivery. Preserve distinct recipients, versions and path conditions even when the field names match.

Assign each mandatory check a source-grounded obligation and evidence, including necessary uses and material unknowns. A known supported excess left unresolved by an answer is a miss. Correctly retaining genuine source uncertainty is calibrated behavior. An empty supported-excess list must be a positive documented coverage judgment after source review, never the default interpretation of an unfinished ledger.

## Evidence and completion

Every fact uses evidence objects with path, start_line, end_line and exact original-language quote. Quote physical source lines, not bundle headings or registry summaries. Record all reviewed files and remaining uncertainty. The software checks byte/line agreement; people must determine whether the quote supports the interpretation.

Save assistant ledgers with state assistant_draft and human_verified false. Use coverage_state complete_for_human_verification only after all reference sections and receiving-point coverage have been completed; the label is not proof of semantic completeness. Initial source-facts drafts remain preserved. Neither an assistant nor a JSON flag can serve as a human attestation.

Register two real human reference verifiers as H1 and H2 and three distinct timed reviewers as R1, R2 and R3. Each source verifier personally checks all30 ledgers and submits the exact source/reference hashes, personal confirmation, attestation identity and time. Unknown effective work time remains unknown. Any unresolved source dispute stays explicit rather than being forced into a definite accuracy denominator.

## Frozen cohorts and later corrections

Source eligibility and selection cannot depend on method performance. The corpus need not have a fixed fraction of DOE positives. If adjudicable positives are scarce, report limited detection evidence. All target generation finishes before scoring begins. An actual reference omission discovered later requires a preserved corrigendum and uniform regrading of every method and repeat; do not regenerate answers. Automated corrigendum activation is not implemented in the current driver and must not be simulated by silently replacing frozen reference files.
