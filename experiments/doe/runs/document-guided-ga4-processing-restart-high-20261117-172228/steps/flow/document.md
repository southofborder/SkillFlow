The toolkit exposes callable analysis, indexing, and storage functions. The Skill specifies a separate workflow: analyze, save timestamped JSON, then read the saved JSON and write a Markdown summary with tables, trends, and recommendations. The implementation shows the API calls, saves, and independent readers. It shows neither an automatic summary step nor a link that identifies which saved files belong to a particular analysis invocation. (`skill/SKILL.md:39–64, 116–142`; `src/index.ts:12–46, 55–405`; `src/core/storage.ts:58–171`)

References below use `src/` for `skill/scripts/src/`.

**Entry and shared state.** Call the high-level functions through `scripts/src/index.js`, the documented import for `src/index.ts`, or import the individual API modules. The index re-exports all six API modules and selected client, storage, and settings utilities. The direct `npx tsx scripts/src/index.ts` entry only prints help if `process.argv[1]` exactly equals the module URL pathname; it dispatches no analysis. The Skill documents installation, a project-root `.env`, enabled Google APIs, and service-account access. The setup script installs from its own directory. The package is ESM on Node ≥18; TypeScript uses NodeNext/ES2022. (`skill/SKILL.md:8–51, 100–102`; `skill/scripts/setup.sh:1–2`; `skill/scripts/package.json:1–17`; `skill/scripts/tsconfig.json:2–19`; `src/index.ts:12–46, 364–405`)

On module initialization, `settings.ts` calls `dotenv.config()` for the current working directory. That call can affect the environment read by later `getSettings()` calls; the supplied source does not establish the actual bindings or dotenv’s internal precedence. Settings read `GA4_PROPERTY_ID`, `GA4_CLIENT_EMAIL`, `GA4_PRIVATE_KEY` (expanding literal `\n`), `GA4_DEFAULT_DATE_RANGE` (fallback `30d`), and `SEARCH_CONSOLE_SITE_URL`; the storage root is `process.cwd()/results`. Each client getter first checks its own cache. A hit returns the existing handle with its creation-time credentials. A miss validates property ID, email, and key, throws if any is missing, or creates and stores a distinct handle. Site URL is read separately and is not validated here. `resetClient()` clears all three cached bindings. Reports, realtime, metadata, and bulk use `BetaAnalyticsDataClient` from `@google-analytics/data` and the current `properties/<id>`. Search analytics and URL inspection use `@googleapis/searchconsole` `v1` and the current site URL; URL notifications use `@googleapis/indexing` `v3`. Each of those two client creation paths constructs `GoogleAuth` from `googleapis`, with both `webmasters.readonly` and `indexing` scopes. The lockfile resolves those four packages to `4.12.1`, `6.0.1`, `6.0.1`, and `170.1.0`, respectively. (`src/config/settings.ts:5–9, 40–74`; `src/core/client.ts:6–133`; `skill/scripts/package-lock.json:439–473, 1401–1413`)

**Analysis flow.** In the signatures below, each named argument comes from the caller’s `entry.<function>.<parameter>` key. Arrows are sequential awaits. The named child responses become the aggregate’s fields; each aggregate is saved before being returned. Children save by default unless the call explicitly disables saving. An uncaught failure stops the remaining calls and aggregate save; earlier writes can remain. Range-bearing wrappers forward the original `dateRange` to each child. Their aggregate filename extra is the original string, or `custom` for an object or omission. (`src/index.ts:55–295`)

**Independent API producers.**

- `runReport(options)` sends the property, one parsed range, and dimension and metric names; a truthy `limit` is included. `filters` and `orderBy` are accepted but never sent. It takes the first SDK response, optionally saves it under `reports/<dimensions joined by "_", or custom>` with an extra only from the original string range, and returns the response. Its date parser, also exported separately, uses settings for a falsy input, passes an object through, maps `Nd` to `NdaysAgo` through `today`, and falls back to 30 days for other strings. The presets pass the caller’s range unchanged: page views use `pagePath,pageTitle` / `screenPageViews,activeUsers,averageSessionDuration`; traffic uses `sessionSource,sessionMedium,sessionCampaignName` / `sessions,activeUsers,newUsers,bounceRate`; demographics use `country,deviceCategory,browser` / `activeUsers,sessions,newUsers`; events use `eventName` / `eventCount,eventCountPerUser,activeUsers`; conversions use `eventName,sessionSource` / `conversions,totalRevenue`; ecommerce uses `date,transactionId` / `totalRevenue,ecommercePurchases,averagePurchaseRevenue`. (`src/api/reports.ts:20–28, 47–175`)
- Bulk lookup has its own path and date parser; it only imports report types. `normalizeUrls(urls)` trims each input, adds a missing leading slash, and preserves trailing slashes. `buildUrlFilter(urls)` returns `null` for an empty list or a case-insensitive `pagePath` in-list filter using its supplied list. `getMetricsForUrls(urls, options?)` normalizes first; an empty normalized list returns `{rows: [], rowCount: 0}` without a request or save. Otherwise it sends the normalized paths in the filter, the property, one parsed range, `pagePath,pageTitle`, and supplied metrics or `screenPageViews,activeUsers,averageSessionDuration,bounceRate,engagementRate`. It optionally saves the first SDK response to `reports/bulk_url_lookup` with the original string range or `custom`, then returns it. (`src/api/bulk-lookup.ts:8–23, 46–128, 149–192`)
- `querySearchAnalytics(options)` sends the configured site URL and body dates, dimensions, `rowLimit`, and `startRow`; defaults are `query`, `1000`, and `0` for the latter three options. Its exported parser takes settings for falsy input, passes objects through, and converts `Nd` or the 30-day fallback into calendar date strings. The presets select `query/100`, `page/100`, `device/1000`, `country/50`, and independently `searchAppearance/1000`. The saved and returned value is `response.data`; operation is joined dimensions or `query`, with an extra only from the original string range. The reference describes top pages by impressions, while index help and the SEO wrapper log describe clicks; the request specifies neither sort. The Skill’s general date-range guidance does not supply relative-date conversion for Search Console objects or date parameters for capabilities whose signatures lack them. (`src/api/searchConsole.ts:51–175`; `skill/references/api-reference.md:215–233`; `src/index.ts:285–286, 379–385`; `skill/SKILL.md:104–114`)
- Realtime calls accept `save=true` by default and send the property with `unifiedScreenName/activeUsers`, `eventName/eventCount`, `unifiedScreenName/screenPageViews`, or independently `firstUserSource,firstUserMedium/activeUsers`. Each saves and returns the first SDK response (`realtime/active_users`, `events`, `pages`, or `sources`). Metadata calls also default to saving and each requests `<property>/metadata`: dimensions and metrics return and save their respective one-field objects with empty-array fallbacks; full metadata saves and returns the SDK response. The reference describes arrays for the first two metadata calls; the implementation returns objects, and its `metadata` category is absent from the Skill’s directory listing. (`src/api/realtime.ts:24–99`; `src/api/metadata.ts:38–95`; `skill/references/api-reference.md:165–193`; `skill/SKILL.md:118–127`)

**Indexing branches and order.** `requestIndexing(url, options?)` and `removeFromIndex(url, options?)` publish the supplied URL with `URL_UPDATED` and `URL_DELETED`, respectively. Their mapped results use the response URL or input URL, and the corresponding `latestUpdate` or `latestRemove` time or a new ISO time. They save by default as `request_indexing` or `remove_from_index`. `inspectUrl(url, options?)` sends the supplied URL as `inspectionUrl` with `siteUrl` to Search Console; it maps the response to index status (fallback verdict `NEUTRAL`, coverage `Unknown`) and includes mobile usability and rich results only when those sections exist. Its default save is `indexing/url_inspection`. These saves receive the mapped results. (`src/api/indexing.ts:57–80, 114–193`)

Each of the three batch entries has a header testing `has_member` on its input `urls`: true binds the current URL; a completed iteration goes back to the header; false exits to the batch save. Empty input therefore reaches the save with `[]` when saving is enabled. The iteration outcomes differ:

- `requestIndexingBatch(urls, options?)` awaits `requestIndexing(url, {save:false})` and appends its notification. A rejection exits the whole call before the optional `indexing/batch_indexing` save. (`src/api/indexing.ts:89–105`)
- `reindexUrls(urls)` calls that same single-URL function with saving disabled. Success appends `submitted` plus the notification, whose URL can replace the input URL. The catch appends the input URL, `failed`, and the actual exception converted to a string. Both predecessors continue to the next member; the exit saves and returns the array as `indexing/reindex_batch`. (`src/index.ts:301–318`)
- `checkIndexStatus(urls)` calls `inspectUrl(url, {save:false})`. Success appends the input URL, `indexed` from the exact `PASS` test, and only `result.indexStatus`. The catch appends the input URL, `indexed:false`, and an error status from the actual exception. Both predecessors continue to the next member; the exit saves and returns the array as `indexing/index_status_check`. A caught failure can occur before an API request or on its rejection; it does not establish a successful response. (`src/index.ts:324–345`; `src/api/indexing.ts:146–186`; `src/core/client.ts:87–122`)

**Persistence and the missing association.** `saveResult(data, category, operation, extraInfo?)` creates the category directory if absent and writes the supplied response, mapped result, or aggregate as `{metadata, data}`. Metadata carries the ISO save time, category, operation, the property ID read at save time, and a truthy extra if present. The filename uses a local timestamp to the second, sanitized operation, and optional sanitized extra. The write replaces the path if reused; there is no collision guard. `saveResult` returns a path, but the analysis and API callers discard it. Optional `save:false` paths skip the write, so the Skill’s general autosave wording does not describe every runtime path. (`src/core/storage.ts:31–95`; `src/api/reports.ts:77–108`; `src/index.ts:171–203`; `skill/SKILL.md:55–64`)

`listResults(category, limit?)` returns `[]` for an absent category; otherwise it collects `.json` paths, sorts by descending name, and slices if `limit` is supplied. `loadResult(filepath)` acquires file content from the supplied path and returns the parsed wrapper, or `null` for a missing file or read/parse failure. `getLatestResult(category, operation?)` lists paths, optionally filters by a sanitized filename substring, then loads only the first match or returns `null` if none exists. The Skill demonstrates listing `reports` with limit `10` and loading the first listed path; separately it demonstrates latest lookup with `reports` and `site_overview`. Those are valid reader inputs, but neither lookup proves ownership by any specific invocation. The required read-then-summary workflow remains documented; selection of that invocation’s files and the Markdown write to `results/summaries/` are not implemented in the supplied source. (`src/core/storage.ts:103–171`; `src/index.ts:20–23, 55–76`; `skill/SKILL.md:57–64, 129–142`)
