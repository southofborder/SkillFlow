# Shared abstract runtime assumptions (static possibilities, never observed executions):
1. A natural-language request for a field from a container is not a key-only read interface. Preserve the related whole as a possible acquisition scope unless source/code/interface evidence limits acquisition or returned contents. Do not broaden it to unrelated state. Separate acquisition, selection, model observation and actual delivery.
2. Tool-returned content or acquired content used for agent processing can possibly enter a model request when no explicit isolation/routing limits it. Apply this to the returned version, not all internal scan inputs. An explicitly local process returning only selected data does not expose all its internal inputs to the model. Merely saying 'local', naming a getter, or scheduling a tool does not itself establish content routing.
3. A model processing a value observes its input version. A supported local transformation exposing only its result differs from model processing. A model-invisible credential proxy/handle does not expose secret plaintext to the model. Later selection, redaction or deletion cannot undo an earlier observation. Explicit segment boundaries determine distinct stages; do not invent a model call per intermediate operation.
4. Preserve relevant scope on unchanged transfer; explicit selection/exclusion/replacement creates the corresponding reduced version. An opaque computation preserves possible input influence, not proven inclusion of every input's plaintext. A summary/mask/encryption name alone proves neither elimination nor survival of sensitive content. Unknown content does not mean empty, safe or a new unrelated source.
5. Prohibitions and desired output fields do not implement isolation or filtering. Proposed improvements must be labeled as proposals and supported by a functional-preservation argument. Preserve source ambiguity rather than silently completing an implementation.
6. Tool request delivery, returned content and model observation are distinct. Tool names and sending verbs do not prove network transport. Unspecified deployment retains possible external-tool reception without inventing a network send; explicit task-internal tools remain internal. Ordinary return is not automatically delivery to a user. Unknown recipient retention does not prove no persistence, and does not justify inventing backend logging.
7. Collect every supported boundary: network_send, storage_write, context_save, model_observe, external_tool and user_output. Files default to task-internal persistent storage; a temporary name alone is insufficient to infer cleanup. Context defaults to task-limited internal use unless cross-task retention or sharing is stated. Model, external recipient and user are distinct receiving subjects. Pure internal/task-limited flow participates in tracing but is not an exposure sink. Deletion conveys no old contents; append exposes the appended input, not automatically all previous file contents. Do not duplicate the same network delivery as an additional external-tool boundary. Boundary levels describe access/retention only: internal persistent=1, another/shared recipient=2, public=3.
8. Preserve path conditions, uncertainty and actual data versions. Candidate values need not coexist or have a proven feasible execution. Per-element fields and recipients must stay paired. Optional members consume original values only when included; shared conditions are correlated, and controlling presence flags are not automatically payload. Acquisition/earlier observation can remain broader than final request members. Preserve actual argument values and bounded retry counts; response dependence on requests is not proof the response contains those arguments.
