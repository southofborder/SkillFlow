The GA4 Toolkit exposes callable analysis, indexing, and storage functions. The Skill requires analysis → automatic timestamped JSON saving → reading the saved JSON → writing a Markdown summary with tables, trends, and recommendations in `results/summaries/`. The implementation shows saves and independent readers, but no summary writer or automatic handoff from an analysis return to a reader. Its explicit save exceptions remain visible alongside the Skill’s general obligation. (`skill/SKILL.md:39–64,116–142`; `skill/scripts/src/index.ts:12–46,55–362`)

**Entry and shared state.** The Skill shows imports from `./scripts/src/index.js` and direct execution with `npx tsx scripts/src/index.ts`. The barrel re-exports all six API modules and selected client, storage, and settings functions; the API reference also documents direct module imports. Direct execution only prints help if `process.argv[1]` equals the module URL’s pathname; it dispatches no analysis. Setup installs from `scripts/`; the package is ESM, requires Node ≥18, and uses NodeNext resolution. The lock resolves Analytics Data to 4.12.1, the dedicated Search Console and Indexing packages to 6.0.1 each, and `googleapis` to 170.1.0. (`skill/SKILL.md:8–51,100–102`; `skill/scripts/setup.sh:1–2`; `skill/scripts/package.json:1–17`; `skill/scripts/tsconfig.json:2–19`; `skill/scripts/package-lock.json:439–474,1401–1413`; `skill/scripts/src/index.ts:12–46,364–405`)

Importing settings calls `dotenv.config()` against the working directory; its return is discarded. Later `getSettings()` calls read the resulting environment and current working directory. They supply the property ID, email, newline-decoded private key, site URL, default range (`30d` if absent or empty), and `<cwd>/results`. Each client getter returns an existing handle with its creation-time credentials, or validates property ID, email and key before creating and caching a new handle. Validation does not require the site URL. Reports, bulk lookup, realtime and metadata use `BetaAnalyticsDataClient` from `@google-analytics/data` and a separately read `properties/<id>`. Search analytics and URL inspection use Search Console `v1` from `@googleapis/searchconsole` and a separately read site URL. URL notifications use Indexing `v3` from `@googleapis/indexing`. The latter two client constructors each obtain `googleapis` GoogleAuth with the configured credentials and both `webmasters.readonly` and `indexing` scopes. `resetClient()` clears all three cached handles. (`skill/scripts/src/config/settings.ts:5–9,40–74`; `skill/scripts/src/core/client.ts:6–133`)

**Analysis flow.** Public arguments come from caller context under the parameter names shown below; optional arguments can be omitted. Each arrow is an awaited call, and each `field ← call` pairs the returned value with its receiving field. The four standard GA4 composites and three Search Console composites pass the same caller `dateRange` to each child, leave child saving enabled, then save and return their aggregate. Their aggregate filename extra is the original string or `custom` for an object or omitted input. A rejected child prevents later calls and the aggregate save; prior saves can remain. (`skill/scripts/src/index.ts:55–295`)

- **Standard and bulk GA4.** `runReport(options)` sends the property, parsed range, dimensions, metrics, and a truthy `limit`; it accepts `filters` and `orderBy` without sending them. It returns the first API response and, if `save` is truthy (default `true`), saves that response under `reports`, with dimensions joined by underscores or `custom`, and the original range string if supplied. The standard helpers supply these dimension/metric pairs: `getPageViews`, `pagePath,pageTitle` / `screenPageViews,activeUsers,averageSessionDuration`; `getTrafficSources`, `sessionSource,sessionMedium,sessionCampaignName` / `sessions,activeUsers,newUsers,bounceRate`; `getUserDemographics`, `country,deviceCategory,browser` / `activeUsers,sessions,newUsers`; `getEventCounts`, `eventName` / `eventCount,eventCountPerUser,activeUsers`; `getConversions`, `eventName,sessionSource` / `conversions,totalRevenue`; `getEcommerceRevenue`, `date,transactionId` / `totalRevenue,ecommercePurchases,averagePurchaseRevenue`. The last two remain independently callable. Bulk’s `getMetricsForUrls(urls, options?)` independently calls GA4, not the standard wrapper. `normalizeUrls(urls)` trims each member and adds a missing leading slash, preserving trailing slashes. Empty input returns `{rows: [], rowCount: 0}` before client acquisition or saving. Otherwise `buildUrlFilter(normalizedUrls)` supplies a case-insensitive `pagePath` in-list filter (`null` if called with an empty list). Bulk requests `pagePath,pageTitle` and the caller’s metrics or `screenPageViews,activeUsers,averageSessionDuration,bounceRate,engagementRate`; it returns the first API response and conditionally saves it as `reports/bulk_url_lookup`, with the original range string or `custom`. Standard and bulk each parse ranges locally: falsy input takes the setting, objects pass through, `Nd` becomes `NdaysAgo` through `today`, and unmatched strings fall back to 30 days. Bulk imports only report types. (`skill/scripts/src/api/reports.ts:17–175`; `skill/scripts/src/api/bulk-lookup.ts:8–11,44–192`; `skill/scripts/src/index.ts:25–46`)

- **Search Console.** `querySearchAnalytics(options)` sends the site URL and parsed dates, dimensions, row limit and offset; defaults are `query`, 1,000 and 0. It returns `response.data` and, with `save` enabled by default, saves that payload to `searchconsole` under the joined dimensions or `query`, with the original range string if supplied. The helpers send `query/100`, `page/100`, `device/1000`, `country/50`, or `searchAppearance/1000`, respectively. The index selects `getTopPages` from `searchConsole.js` under its local alias. The reference describes top pages by impressions; the index describes clicks; the request supplies no sort. Search Console converts `Nd` and the 30-day fallback to calendar dates and passes objects unchanged. The Skill lists GA4 relative objects broadly, but the Search Console source says it requires `YYYY-MM-DD` and does not convert relative objects. (`skill/SKILL.md:104–114`; `skill/references/api-reference.md:201–263`; `skill/scripts/src/api/searchConsole.ts:47–175`; `skill/scripts/src/index.ts:39–45,281–289,378–385`)

- **Realtime and metadata.** Each realtime function takes `save = true`, returns the first API response and optionally saves it under `realtime`: `getActiveUsers` requests `unifiedScreenName/activeUsers` (`active_users`), `getRealtimePages` requests `unifiedScreenName/screenPageViews` (`pages`), `getRealtimeEvents` requests `eventName/eventCount` (`events`), and the independent `getRealtimeSources` requests `firstUserSource,firstUserMedium/activeUsers` (`sources`). Each metadata call requests `<property>/metadata`, also with `save = true`. `getAvailableDimensions` and `getAvailableMetrics` return and optionally save objects containing the selected array, defaulting to `[]`; the reference describes arrays. `getPropertyMetadata` returns and optionally saves the full response as `metadata/full`. `getAvailableFields()` calls it with default saving, logs the two counts and returns that same full response. (`skill/scripts/src/api/realtime.ts:24–99`; `skill/scripts/src/api/metadata.ts:38–95`; `skill/references/api-reference.md:165–193`; `skill/scripts/src/index.ts:355–362`)

**URL operations and traversal.** `requestIndexing(url, options?)` and `removeFromIndex(url, options?)` publish the input URL with `URL_UPDATED` and `URL_DELETED`, respectively. Each returns a notification using the response URL and corresponding update/removal time, falling back to the input URL and current ISO time; default saving writes that projection under `indexing/request_indexing` or `indexing/remove_from_index`. `inspectUrl(url, options?)` sends `inspectionUrl` and `siteUrl` to Search Console, then returns and by default saves the projected inspection under `indexing/url_inspection`. Missing index verdict and coverage become `NEUTRAL` and `Unknown`; mobile and rich-result sections are included only when their source sections exist. (`skill/scripts/src/api/indexing.ts:57–193`)

For each batch, the header tests `has_member(urls)`: true selects the current URL, awaits its call, and returns to the header after appending; false exits to the aggregate save and return. `requestIndexingBatch(urls, options?)` calls `requestIndexing(url, {save: false})`, appends successful notifications, and aborts on rejection; the finished array saves as `indexing/batch_indexing` if enabled. `reindexUrls(urls)` calls the same single-URL function with saving off, but merges success (`submitted`, with notification fields and its returned URL) and caught exception (`failed`, input URL and stringified error) before continuing. `checkIndexStatus(urls)` calls `inspectUrl(url, {save: false})`; success keeps the input URL and only the `indexStatus` projection, with `indexed` true exactly for `PASS`. Its caught-exception row has `indexed: false` and the stringified error in `status`. These two wrappers save their finished arrays as `indexing/reindex_batch` and `indexing/index_status_check`, even for empty input. A caught exception does not establish whether a remote request had already taken effect. For the mapping and filtering passes above and below, the same collection dispatch selects each member before transforming or testing it; exhaustion advances to the next stage. (`skill/scripts/src/api/indexing.ts:89–105`; `skill/scripts/src/index.ts:301–345`; `skill/scripts/src/api/bulk-lookup.ts:64–75,175–181`; `skill/scripts/src/api/reports.ts:92–98`; `skill/scripts/src/core/storage.ts:131–139,159–164`)

**Storage and the remaining gap.** `saveResult(data, category, operation, extraInfo?)` creates the category directory if missing and synchronously writes or replaces JSON under `<cwd>/results/<category>/`, with a local second-resolution timestamp and sanitized operation and optional extra in the filename. The file contains `{metadata, data}` with an ISO save time, category, operation, configured property ID and truthy extra. The public saver returns the path; analysis callers discard it and return their own payloads. `listResults(category, limit?)` returns matching `.json` paths in descending filename order, optionally sliced, or `[]` for a missing directory. `loadResult(filepath)` separately acquires and parses file content, returning the saved wrapper or `null` for an absent file or read/parse failure. `getLatestResult(category, operation?)` lists candidates, optionally filters by a sanitized path substring, and loads only the first remaining path, or returns `null` if none. The Skill illustrates `listResults('reports', 10)` → `loadResult(files[0])`, and separately `getLatestResult('reports', 'site_overview')`. Neither example identifies a file from a particular invocation. The reader-to-summary step remains a documented obligation with no supplied implementation, and the file selection for any particular analysis run remains unresolved. (`skill/scripts/src/core/storage.ts:31–171`; `skill/scripts/src/index.ts:20–23,71–76`; `skill/SKILL.md:53–64,129–142`)
