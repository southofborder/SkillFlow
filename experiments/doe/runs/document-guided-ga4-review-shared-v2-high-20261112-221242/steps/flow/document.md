# GA4 toolkit flow

References beginning with `api/`, `config/`, or `core/`, and references to `index.ts`, are relative to `skill/scripts/src/`. Each public signature below takes its named inputs from the invocation context. For example, `runReport(options)` reads `context.options`, and `siteOverview(dateRange?)` reads `context.dateRange`. Internal calls receive the arguments shown in the flow.

## Entry points and shared state

- The Skill documents importing from `./scripts/src/index.js` or running `npx tsx scripts/src/index.ts`. The barrel exports all six API modules and the named client, settings, and storage utilities. Direct execution prints help only when `process.argv[1]` equals the module URL’s pathname. Setup runs `npm install` from `scripts`. The package is ESM and declares Node ≥18. The Skill requires the Analytics Data, Search Console, and Indexing APIs to be enabled and a service account with GA4 property and Search Console access. (`skill/SKILL.md:8–51`, `skill/scripts/setup.sh:1–2`, `skill/scripts/package.json:1–17`, `index.ts:12–46,364–405`)
- Module initialization calls `dotenv.config()` with zero arguments to load `.env` from the working directory. `getSettings()` then reads current environment values for property ID, email, private key, default range, and site URL. It converts literal `\n` sequences in the key, defaults the range to `30d`, defaults missing IDs and credentials to empty strings, and derives `resultsDir` from the current working directory. `validateSettings()` returns `{valid, errors}` based on property ID, email, and private key. `getPropertyId()` prefixes the current ID with `properties/`. `getSiteUrl()` returns the current site URL, which can be empty. (`config/settings.ts:5–9,40–74`, `core/client.ts:50–53,130–133`)
- Each client getter returns its cached handle if present. On a cache miss it validates settings, throws on invalid settings, or constructs and caches a handle using credentials read during creation. GA4 uses `BetaAnalyticsDataClient` from `@google-analytics/data`. Search Console `v1` and Indexing `v3` use `@googleapis/searchconsole` and `@googleapis/indexing` respectively, each with a newly constructed `googleapis` `GoogleAuth` carrying the `webmasters.readonly` and `indexing` scopes. A cached handle keeps its creation-time provenance while property and site lookups read current settings. `resetClient()` clears all three cache bindings. (`core/client.ts:6–43,58–79,87–123`)

## API calls and returned values

Each saver below runs after acquisition and before return. `save` defaults to `true` where exposed. The operation names are arguments to storage, whose path return is discarded by these API callers.

|---|---|
| `parseDateRange(range)` and `runReport(options)` from `./api/reports.js` | The parser uses the configured default for falsy `range`, forwards an object as supplied, turns `Nd` into `NdaysAgo` through `today`, and falls back to `30daysAgo` through `today` for other strings. `runReport` sends the current property, one parsed range, named `dimensions` and `metrics`, and `limit` when truthy. The request omits the exposed `filters` and `orderBy`. It returns the first SDK response and, if saving, writes that response under `reports`, with dimensions joined by `_` or `custom` as operation and the original string range as optional extra info. (`api/reports.ts:12–28,47–109`, `skill/references/api-reference.md:31–45`) |
| `normalizeUrls(urls)`, `buildUrlFilter(urls)`, and `getMetricsForUrls(urls, options?)` from `./api/bulk-lookup.js` | Normalization trims paths and adds a leading slash where missing. The lookup normalizes first and returns `{rows: [], rowCount: 0}` for an empty list before client acquisition or saving. ## Orchestration in `index.ts`

Arrows indicate sequential awaits. Each result goes into the named aggregate field. Ordinary child calls save by default, then the wrapper saves and returns its aggregate. A child rejection stops the sequence before the aggregate save, so earlier child saves can already exist. Date-based aggregates use the original string argument as extra info, or `custom` for object or omitted ranges.

### URL loops

Each entry below initializes an empty result list. Its loop header consumes the invocation’s `urls` with `branch(predicate=has_member)`. The true edge obtains the current `url`. Each append goes back to the header. The false edge exits to the stated save and return, including for empty input.

- `requestIndexingBatch(urls, options?)` calls `requestIndexing(url, {save: false})` and appends each returned notification. An exception exits the call before the batch save. The exhausted loop saves as `indexing/batch_indexing` if `options.save` is true or defaulted, then returns the notification array. Earlier publishes can already have occurred. (`api/indexing.ts:57–105`)
- `reindexUrls(urls)` calls `requestIndexing(url, {save: false})` directly. The success predecessor appends `submitted` plus the notification, whose URL takes precedence over the input URL. The catch predecessor appends the input URL, `failed`, and `String(error)` from the caught exception. Both rejoin at the header. On exhaustion it saves as `indexing/reindex_batch` and returns the status array. (`index.ts:301–319`)
- `checkIndexStatus(urls)` calls `inspectUrl(url, {save: false})`. The success predecessor appends the input URL, `indexed` computed by equality with `PASS`, and the returned `indexStatus`. The catch predecessor appends the input URL, `indexed=false`, and a status containing `String(error)` from the caught exception. Both rejoin at the header. On exhaustion it saves as `indexing/index_status_check` and returns the status array. In both high-level loops a caught failure can arise during client acquisition before a request or during the API call. The final save is outside the per-item catch. (`index.ts:324–346`, `api/indexing.ts:57–67,146–157`, `core/client.ts:87–120`)

## Saving, reading, and summarizing

`saveResult(data, category, operation, extraInfo?)` creates the category directory if absent and writes UTF-8 JSON under `<cwd>/results/<category>/`. The filename uses a local, second-resolution timestamp, a sanitized operation, and a sanitized extra segment when `extraInfo` is truthy. Reusing the same path replaces its contents. The stored value is `{metadata, data}` with an ISO save time, category, original operation, current unprefixed property ID, and truthy extra info. The function returns the path. The API and orchestration callers return their payloads, while storage readers acquire the saved wrapper independently. (`core/storage.ts:12–95`, `index.ts:22,71–76,195–203`)

`listResults(category, limit?)` returns an empty list for a missing category, otherwise sorts `.json` paths in descending filename order and slices when a limit is supplied. `loadResult(filepath)` reads and parses the selected path, returning `null` for a missing file or read or parse failure. `getLatestResult(category, operation?)` lists the category, optionally filters paths by the sanitized operation substring, and loads only the first match or returns `null` when none exists. The Skill examples pass the first path from `listResults('reports', 10)` into `loadResult` and separately call `getLatestResult('reports', 'site_overview')`. (`core/storage.ts:103–171`, `skill/SKILL.md:129–142`)

The Skill’s workflow calls for analysis, timestamped JSON auto-save, then reading the saved JSON and creating a Markdown summary in `results/summaries/` with tables, trends, and recommendations. The implementation also exposes save opt-outs, an empty bulk-lookup return before saving, and a `metadata` save category beyond the documented directory tree. **The file association remains unresolved.** The analysis code shows which payload it hands to storage, but discards the returned path. The supplied sources show no invocation-to-file binding for the reader and no implementation that passes a selected read into a Markdown summary writer. A matching filename or operation label establishes a candidate path only. (`skill/SKILL.md:53–64,116–142`, `api/bulk-lookup.ts:153–188`, `api/metadata.ts:38–94`, `core/storage.ts:155–171`, `index.ts:71–76,180–203`)
