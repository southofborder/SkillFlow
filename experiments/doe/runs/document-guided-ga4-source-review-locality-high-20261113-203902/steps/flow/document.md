# GA4 toolkit source flow

## Entry points and shared state

The Skill specifies installation in `scripts`, a project-root `.env`, enabled Analytics Data, Search Console and Indexing APIs, and service-account access to the GA4 property and Search Console. `setup.sh` changes to its own directory and runs `npm install`. The package is ESM for Node ≥18, with NodeNext TypeScript configuration. The documented entry points are imports from `scripts/src/index.js`, direct imports from the API modules, and `npx tsx scripts/src/index.ts`. The direct-run branch prints help when `process.argv[1]` equals the module URL pathname. It dispatches no analysis. `index.ts` re-exports all six API modules and the named client, storage and settings utilities. (`skill/SKILL.md:8–51,100–102`; `skill/scripts/setup.sh:1–2`; `skill/scripts/package.json:1–17`; `skill/scripts/tsconfig.json:2–19`; `skill/scripts/src/index.ts:12–46,364–405`)

Settings initialization calls `dotenv.config()` for the working directory. Later `getSettings()` calls read the resulting environment and current working directory, expand escaped newlines in the key, default the range to `30d`, and derive `<cwd>/results`. The supplied source leaves dotenv’s internal binding updates unspecified. On a client cache hit, the getter returns the existing handle with its creation-time credentials. On a miss, validation checks property ID, email and key for all three clients. A failed check throws before the API request. Successful construction caches a new handle. `resetClient()` clears all three handles. `getPropertyId()` and `getSiteUrl()` read current settings separately, so request targets can reflect newer settings than a cached handle. An empty site URL passes local validation. (`skill/scripts/src/config/settings.ts:5–9,40–74`; `skill/scripts/src/core/client.ts:12–62,87–133`)

The selected constructors are `BetaAnalyticsDataClient` from `@google-analytics/data`, `searchconsole` v1 from `@googleapis/searchconsole`, and `indexing` v3 from `@googleapis/indexing`. The latter two each construct `GoogleAuth` from `googleapis` on their cache-miss path, using the service-account credentials and both `webmasters.readonly` and `indexing` scopes. The lockfile resolves those four packages to `4.12.1`, `6.0.1`, `6.0.1` and `170.1.0`, respectively. (`skill/scripts/src/core/client.ts:6–10,23–42,67–78,87–122`; `skill/scripts/package-lock.json:439–474,1401–1412`)

## API calls and returned values

Public arguments below come from the correspondingly named context keys, such as `context.dateRange`, `context.urls`, `context.range1` and `context.options.metrics`. Positional `save` uses `context.save`. Calls with empty parentheses acquire no caller argument. Each API call acquires its response from the named service. Where enabled, the producer saves the indicated response or derived result before returning it.

| Entry and source | Request, save and return |
|---|---|
| Reports `parseDateRange(range)`, `runReport(options)` and report helpers (`skill/scripts/src/api/reports.ts:47–175`) | The parser reads the configured default for a falsy range, passes an object through, translates `Nd` to `NdaysAgo`–`today`, and falls back to 30 days for unmatched strings. `runReport` sends `properties/<id>`, the parsed range and mapped `options.dimensions` and `options.metrics` to GA4, with `options.limit` only when truthy. `options.filters` and `options.orderBy` are accepted but omitted from the request. It takes the first response and returns it as `ReportResponse`. With `options.save` defaulting to `true`, it saves that response under `reports`, using joined dimensions or `custom` and the original range only if it was a string. |
| Bulk lookup `normalizeUrls(urls)`, `buildUrlFilter(urls)`, `getMetricsForUrls(urls, options?)` (`skill/scripts/src/api/bulk-lookup.ts:46–128,149–192`) | Normalization trims each path and prepends `/` when missing, preserving trailing slashes. The filter builder returns `null` for an empty input and otherwise builds a case-insensitive `pagePath` list filter from its supplied values. Lookup returns empty rows and count zero for an empty normalized list, before client acquisition or saving. Otherwise it uses its own range parser with the same GA4 rules and sends the filter, `pagePath` and `pageTitle`, and `options.metrics` or `screenPageViews`, `activeUsers`, `averageSessionDuration`, `bounceRate`, `engagementRate`. It returns the first GA4 response and, by default, saves it as `reports/bulk_url_lookup` with the original string range or `custom`. |
| Realtime calls `(save?)` (`skill/scripts/src/api/realtime.ts:24–99`) | All call GA4 `runRealtimeReport` for `properties/<id>` and return its first response. `getActiveUsers` pairs `unifiedScreenName` with `activeUsers`, `getRealtimePages` pairs it with `screenPageViews`, `getRealtimeEvents` pairs `eventName` with `eventCount`, and `getRealtimeSources` pairs `firstUserSource` and `firstUserMedium` with `activeUsers`. Default saves go to `realtime` as `active_users`, `pages`, `events` and `sources`, respectively. |
| Metadata calls `(save?)` (`skill/scripts/src/api/metadata.ts:38–95`) | Each independently requests `properties/<id>/metadata` from GA4. `getAvailableDimensions` and `getAvailableMetrics` return objects with the selected array, defaulting to `[]`. `getPropertyMetadata` returns the first full response. Default saves under `metadata` use `dimensions`, `metrics` and `full`, respectively, with the corresponding returned value. |
| Search Console `parseSearchConsoleDateRange(range)`, `querySearchAnalytics(options)` and helpers (`skill/scripts/src/api/searchConsole.ts:51–175`) | The parser uses the configured default for a falsy range and passes objects through. For strings it subtracts `N` days, or 30 for an unmatched string, and emits ISO date portions. The query sends `siteUrl` and the parsed dates, dimensions, row limit and offset to Search Console. Defaults are `['query']`, `1000`, `0` and `save=true`. It returns `response.data` and optionally saves it under `searchconsole`, using joined dimensions or `query` and the original range only if it was a string. The date-range helpers request `query`/100, `page`/100, `device`/1000, `country`/50 and `searchAppearance`/1000 for `getTopQueries`, `getTopPages`, `getDevicePerformance`, `getCountryPerformance` and `getSearchAppearance`, respectively. |

| `getUserDemographics` | `country`, `deviceCategory`, `browser` → `activeUsers`, `sessions`, `newUsers` |

## High-level analysis and indexing

The following calls await their producers in the order shown and place each returned value in the named field. Date-taking wrappers pass their original `dateRange` to every producer. They save the assembled object under the listed category and operation before returning it, using the original string range or `custom` as extra information. The child calls retain their default saves. An uncaught failure interrupts the sequence before the combined save, even if earlier children already saved. (`skill/scripts/src/index.ts:25–46,55–165,209–295`)

| Entry | Ordered producers and receiving fields | Combined save |
|---|---|---|
| `siteOverview(dateRange?)` | `getPageViews` → `pageViews`, `getTrafficSources` → `trafficSources`, `getUserDemographics` → `demographics`, `getEventCounts` → `events` | `reports/site_overview` |
| `trafficAnalysis(dateRange?)` | `getTrafficSources` → `sources`, `runReport` with `sessionSource/sessionMedium` and `sessions, engagedSessions, averageSessionDuration, bounceRate` → `sessions`, `runReport` with `newVsReturning` and `activeUsers, sessions, conversions` → `newVsReturning` | `reports/traffic_analysis` |
| `contentPerformance(dateRange?)` | `getPageViews` → `pages`, `runReport` with `landingPage` and `sessions, activeUsers, bounceRate, averageSessionDuration` → `landingPages`, `runReport` with `pagePath` and `exits, screenPageViews` → `exitPages` | `reports/content_performance` |
| `userBehavior(dateRange?)` | `getUserDemographics` → `demographics`, `getEventCounts` → `events`, `runReport` with `date` and `activeUsers, engagedSessions, engagementRate, averageSessionDuration` → `engagement` | `reports/user_behavior` |
| `liveSnapshot()` | `getActiveUsers()` → `activeUsers`, `getRealtimePages()` → `currentPages`, `getRealtimeEvents()` → `currentEvents` | `realtime/snapshot`, no extra |
| `searchConsoleOverview(dateRange?)` | `getTopQueries` → `topQueries`, Search Console `getTopPages` → `topPages`, `getDevicePerformance` → `devicePerformance`, `getCountryPerformance` → `countryPerformance` | `searchconsole/overview` |
| `keywordAnalysis(dateRange?)` | `getTopQueries` → `queries`, device-only `getDevicePerformance` → `deviceBreakdown` | `searchconsole/keyword_analysis` |
| `seoPagePerformance(dateRange?)` | Search Console `getTopPages` → `topPages`, country-only `getCountryPerformance` → `countryBreakdown` | `searchconsole/seo_page_performance` |

`compareDateRanges(range1, range2, dimensions?, metrics?)` calls `runReport` first with `range1`, then with `range2`, using the same dimensions and metrics and `save:false` for both. Defaults are `date` and `activeUsers, sessions, screenPageViews`. Each original range is paired with its own response under `period1` or `period2`. The comparison is saved as `reports/date_comparison` and returned. `getAvailableFields()` calls `getPropertyMetadata()` with its default save, logs the array counts and returns that same full response. (`skill/scripts/src/index.ts:171–203,355–361`)

`requestIndexing(url, options?)` and `removeFromIndex(url, options?)` publish the supplied URL to Indexing v3 with `URL_UPDATED` and `URL_DELETED`, respectively. Each returns the corresponding notification type, the response URL or input URL, and `latestUpdate` or `latestRemove` notification time, falling back to the current ISO time. `inspectUrl(url, options?)` instead sends `inspectionUrl` and configured `siteUrl` to Search Console v1. It returns a mapped inspection with defaults `NEUTRAL` and `Unknown` for missing verdict and coverage, and includes mobile and rich-results sections when present. The three default saves use `indexing/request_indexing`, `indexing/remove_from_index` and `indexing/url_inspection`, with the mapped results. (`skill/scripts/src/api/indexing.ts:57–79,114–193`)

For each of the three URL loops, the header consumes `context.urls` with `branch(predicate=has_member)`. The true body obtains the current URL, awaits the call below, and returns to the header after appending an entry. The false edge exits to the batch save and return, including for an empty list. (`skill/scripts/src/api/indexing.ts:89–105`; `skill/scripts/src/index.ts:301–345`)

| Entry | Body and predecessor outcomes | Exit |
|---|---|---|
| `requestIndexingBatch(urls, options?)` | `requestIndexing(current URL, {save:false})` appends the notification. A rejection exits the function before the batch save. Earlier requests may already have been submitted. | Save `indexing/batch_indexing` if `options.save` is true or omitted, then return notifications. |
| `reindexUrls(urls)` | The same call appends `submitted` with the notification fields, whose URL takes precedence in the entry. The catch appends `failed` with the input URL and stringified exception. Both append paths return to the header. | Save `indexing/reindex_batch`, then return status entries. |
| `checkIndexStatus(urls)` | `inspectUrl(current URL, {save:false})` appends the input URL, `indexed` from the `PASS` comparison and `indexStatus` as `status`. The catch appends the input URL, `indexed=false` and an error status from the exception. Both append paths return to the header. | Save `indexing/index_status_check`, then return status entries. |

## Saved results and summary obligation

`saveResult(data, category, operation, extraInfo?)` creates the category directory if needed and synchronously writes `{metadata, data}`. The filename uses local time to the second, a sanitized operation and a sanitized suffix when `extraInfo` is truthy. Metadata contains ISO `savedAt`, the original category and operation, the current raw property ID, and truthy extra information. Identical resolved paths can be overwritten. The public save returns the path. The analysis producers discard that path and return their response or assembled result. (`skill/scripts/src/core/storage.ts:31–95`; `skill/scripts/src/api/reports.ts:100–108`; `skill/scripts/src/index.ts:59–76,316–318`)

`listResults(category, limit?)` returns `[]` for a missing directory. Otherwise it selects `.json` entries, sorts paths by descending filename and slices when a limit is supplied. `loadResult(filepath)` separately acquires and parses the file contents, returning the saved wrapper or `null` for a missing file or read/parse failure. `getLatestResult(category, operation?)` lists the category, optionally filters paths by the `__<sanitized operation>` substring, and loads only the first match, or returns `null` if none exists. The Skill passes the first path from `listResults('reports', 10)` to `loadResult` and separately shows `getLatestResult('reports', 'site_overview')`. Neither example establishes that its selected file came from the shown `siteOverview('30d')` invocation. (`skill/scripts/src/core/storage.ts:103–171`; `skill/SKILL.md:39–45,129–142`)

The Skill specifies analysis, automatic JSON saving, then reading saved JSON and creating Markdown in `results/summaries/` with tables, trends and recommendations. Its tips also tell users to request summaries. The supplied runtime has conditional saves and the bulk empty-input bypass, and it supplies no Markdown writer, summary caller or invocation-to-file binding for the summary step. The Skill’s workflow obligation remains explicit alongside those implementation gaps. The reference describes metadata arrays where the implementation returns objects, and describes top pages by impressions where the CLI help and SEO wrapper say clicks. The shared page query supplies a page dimension and limit but no sort parameter, so the ranking conflict remains unresolved in the supplied source. (`skill/SKILL.md:53–64,118–142,152–155`; `skill/references/api-reference.md:165–193,225–233`; `skill/scripts/src/api/bulk-lookup.ts:153–188`; `skill/scripts/src/api/metadata.ts:38–77`; `skill/scripts/src/api/searchConsole.ts:102–111,138–143`; `skill/scripts/src/index.ts:281–289,378–385`)
