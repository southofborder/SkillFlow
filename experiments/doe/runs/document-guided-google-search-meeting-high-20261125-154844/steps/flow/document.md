# Google Search flow

- **Skill scope and setup:** The Skill describes Google PSE search for live information, documentation or research when built-in `web_search` is unavailable. It requires API setup and credentials stored in a workspace `.env`; its example instead supplies environment variables inline. The workflow section contains only a placeholder, so further workflow obligations are unavailable. (`skill/SKILL.md:3-22`, `skill/SKILL.md:24-28`)

- **Independent function entry:** `google_search(query, api_key, cse_id, num_results=5)` can be called independently of the CLI. Its selected imports are `sys`, `json`, `requests` and `os`. The function sends an HTTP GET to `https://www.googleapis.com/customsearch/v1`, pairing `query → q`, `api_key → key`, `cse_id → cx` and `num_results → num`. The response comes from that API; the function checks HTTP status, then returns the response’s parsed JSON. Request, status-check or JSON-decoding failures propagate to its caller. (`skill/scripts/search.py:1-16`)

- **CLI entry and conditions:** The main guard enables command-line execution. With no query argument, it prints usage and exits with status 1. Otherwise, it takes `sys.argv[1]` as the query and converts `sys.argv[2]` to an integer when present, defaulting to 5. Conversion occurs before the exception handler, so conversion failures escape that handler. It then reads `GOOGLE_API_KEY` and `GOOGLE_CSE_ID` from the process environment. If either is falsy, it prints the credential error and exits with status 1 before making a request. (`skill/scripts/search.py:18-32`)

- **Call, returned versions and recipients:** With credentials present, the CLI calls `google_search(query, api_key, cse_id, num_results)` using those actual values. The returned parsed JSON becomes CLI-local `results`; `json.dumps(results, indent=2)` produces a distinct serialized string for `print` to standard output. Exceptions raised within this protected call, serialization or printing path supply the caught `e`; the handler prints its error text and exits with status 1. A successful API result and a caught exception have separate sources. (`skill/scripts/search.py:34-39`)

- **State and unresolved links:** The script reads environment state but contains no `.env` loader, environment mutation, persistent shared result state, file save, saved-result read, analysis or summarization. Thus the Skill’s `.env` setup has no shown loading implementation, and no saved file can be associated with this invocation. The Skill’s example invokes `skills/google-search/scripts/search.py`, while the CLI usage message names `google_search.py`; both spellings remain as supplied. (`skill/SKILL.md:15-19`, `skill/SKILL.md:27`; `skill/scripts/search.py:1-39`)
