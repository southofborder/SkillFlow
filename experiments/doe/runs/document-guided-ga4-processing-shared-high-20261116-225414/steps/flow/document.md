# GA4 Analytics Toolkit flow

## Entry points and shared state

Import high-level functions from `skill/scripts/src/index.js`. The entry module also re-exports the six API modules and the settings, client, and storage utilities. The API reference supports direct imports from `./api/{reports,realtime,metadata,searchConsole,indexing,bulk-lookup}.js` and `./core/storage.js`. The documented `npx tsx scripts/src/index.ts` route prints help only if `process.argv[1]` equals the module URL pathname. The direct-run block invokes no analysis. Setup installs dependencies in `scripts` and calls for a service account with GA4 and Search Console access and all three Google APIs enabled. `skill/SKILL.md:8–51,100–102`, `skill/references/api-reference.md:19,117,163,199,269,319,358`, `skill/scripts/setup.sh:1–2`, `skill/scripts/src/index.ts:12–46,364–405`

On module initialization, `dotenv.config()` loads `.env` from the current working directory. Later settings calls read the resulting process environment, expand escaped private-key newlines, default the date range to `30d`, and derive the results directory from the current working directory. Validation checks property ID, email, and key. Each client getter returns its existing handle on a cache hit, retaining that handle’s creation-time credentials. A miss validates and either throws or creates and caches a new handle. GA4 uses `@google-analytics/data`. Search Console v1 and Indexing v3 use `@googleapis/searchconsole` and `@googleapis/indexing`, each with auth constructed through `googleapis` using the `webmasters.readonly` and `indexing` scopes. `resetClient()` clears all three handles. `getPropertyId()` and `getSiteUrl()` read current settings independently of the caches. Validation omits the site URL. `skill/scripts/src/config/settings.ts:5–9,40–73`, `skill/scripts/src/core/client.ts:6–133`

## Analysis and API boundaries

Parameter names below are the public invocation’s input keys. A missing or empty date-range string uses the configured default. GA4 reports and bulk lookup use separate parsers with the same behavior. They pass a range object through, turn `Nd` into `NdaysAgo` through `today`, and fall back to 30 days for other strings. Search Console also passes range objects through, but converts shorthand and the fallback to calendar dates serialized as `YYYY-MM-DD`. The Skill’s broad date-format description and Search Console’s stated date requirement leave acceptance of GA4-relative objects by Search Console unresolved. `skill/SKILL.md:104–114`, `skill/scripts/src/api/reports.ts:47–72`, `skill/scripts/src/api/bulk-lookup.ts:103–128`, `skill/scripts/src/api/searchConsole.ts:47–84`

| Public API | Request, returned version, and save |
|---|---|

The reference lists `filters` and `orderBy`, but the request omits both. Returns the first SDK response. With `save` enabled (default), saves that response under `reports`, with the joined dimensions or `custom` as operation and the original range string as optional extra. `skill/references/api-reference.md:31–45`, `skill/scripts/src/api/reports.ts:77–109` |

## Ordered orchestration

Each row gives the order of awaited producers and the aggregate recipient. Date-taking calls forward the original `dateRange` to each child. Where an aggregate uses a date extra, it uses the original string or `custom`. Child saves use their defaults unless stated. The aggregate is saved before it is returned. An uncaught request or write failure stops the flow at that point, so earlier successful requests or writes can already have taken effect. `skill/scripts/src/index.ts:55–296`

|---|---|
| `siteOverview(dateRange?)` | Page views → traffic sources → demographics → events → `reports/site_overview`. `skill/scripts/src/index.ts:55–77` |
| `trafficAnalysis(dateRange?)` | Traffic sources → `sessionSource,sessionMedium` with `sessions,engagedSessions,averageSessionDuration,bounceRate` → `newVsReturning` with `activeUsers,sessions,conversions` → `reports/traffic_analysis`. `skill/scripts/src/index.ts:82–108` |

| `userBehavior(dateRange?)` | Demographics → events → `date` with `activeUsers,engagedSessions,engagementRate,averageSessionDuration` → `reports/user_behavior`. `skill/scripts/src/index.ts:144–166` |

| `getAvailableFields()` | Calls `getPropertyMetadata()` with default saving, logs the dimension and metric counts, and returns that full response. `skill/scripts/src/index.ts:355–362` |

For each URL loop below, the header dispatches on `has_member(urls)`. The true edge obtains the current URL in input order and enters the body. A completed body returns to the header. The false edge exits to the aggregate save, including for empty input. `skill/scripts/src/api/indexing.ts:89–105`, `skill/scripts/src/index.ts:301–346`

- `requestIndexingBatch(urls, options?)` awaits `requestIndexing` for each member with `save: false`. A thrown failure exits before the final save and return. On completion it returns the notification array and, if `options.save` is enabled (default), saves it as `indexing/batch_indexing`. `skill/scripts/src/api/indexing.ts:89–105`
- `reindexUrls(urls)` uses the same per-member call. Success appends a `submitted` row whose URL comes from the returned notification. A caught exception appends the input URL, `failed`, and the stringified exception. Both paths continue, then the function saves and returns `indexing/reindex_batch` data. `skill/scripts/src/index.ts:301–319`
- `checkIndexStatus(urls)` calls `inspectUrl` per member with `save: false`. Success appends the input URL, an `indexed` value true only for `PASS`, and the returned `indexStatus` projection. A caught exception appends the input URL, `indexed: false`, and a status containing the stringified exception. Both paths continue, then the function saves and returns `indexing/index_status_check` data. `skill/scripts/src/index.ts:324–346`

## Saved results, reads, and summary obligation

`saveResult(data, category, operation, extraInfo?)` creates the category directory if missing and synchronously writes `{metadata, data}`. The filename uses local time to the second, a sanitized operation, and a sanitized extra suffix only when `extraInfo` is truthy. Metadata includes ISO save time, original category and operation, the property ID read at save time, and any truthy extra. The write replaces the file if the path already exists. `saveResult` returns the path, which the analysis callers discard. `skill/scripts/src/core/storage.ts:31–95`

`listResults(category, limit?)` returns an empty array for a missing category, otherwise sorts `.json` paths by descending filename and slices if a limit is supplied. `loadResult(filepath)` acquires and parses that file, returning the saved wrapper or `null` for a missing file or read/parse failure. `getLatestResult(category, operation?)` lists paths, filters them by a sanitized filename substring when an operation is supplied, then loads the first match or returns `null` if there is none. The Skill independently shows listing up to ten `reports` paths and loading `files[0]`, and looking up the latest `reports` result matching `site_overview`. The first example supplies no empty-list guard. `skill/scripts/src/core/storage.ts:103–171`, `skill/SKILL.md:129–142`

The Skill requires analysis, automatic JSON saving, then reading the saved JSON and creating a Markdown summary in `results/summaries/` with tables, trends, and recommendations. The implementation has conditional saves, an empty-input return without a save, and a `metadata` category absent from the Skill’s directory sketch. Those differences coexist with the Skill’s stated workflow. The supplied source shows no summary writer or handoff from a specific analysis invocation to a file read for summarization. Even a matching operation name in `getLatestResult` leaves that invocation-to-file association unresolved. `skill/SKILL.md:53–64,116–142`, `skill/scripts/src/api/bulk-lookup.ts:153–189`, `skill/scripts/src/api/metadata.ts:38–95`, `skill/scripts/src/core/storage.ts:155–171`, `skill/scripts/src/index.ts:20–23,55–77,171–204,355–405`
