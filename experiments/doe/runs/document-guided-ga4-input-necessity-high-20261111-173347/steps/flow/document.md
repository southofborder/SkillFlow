# GA4 Analytics Toolkit flow

## Entry points and shared state

The Skill specifies installing dependencies in `scripts`, configuring the project-root `.env`, enabling the Analytics Data, Search Console and Indexing APIs, and granting the service account GA4 and Search Console access. `setup.sh` changes to its own directory and runs `npm install`. The package is ESM on Node ≥18, with ES2022 and NodeNext compilation from `src` to `dist`. The documented import is `./scripts/src/index.js`. The index exports the orchestrators, all six API modules and selected client, storage and settings utilities. The API modules and `core/storage.js` also have documented direct imports. The documented `npx tsx scripts/src/index.ts` invocation prints help only if `process.argv[1]` equals the module URL pathname. That branch has no analysis dispatcher. (`skill/SKILL.md:8–51,100–102,129–142`, `skill/references/api-reference.md:19,117,163,199,269,319,358`, `skill/scripts/setup.sh:1–2`, `skill/scripts/package.json:1–17`, `skill/scripts/tsconfig.json:1–20`, `skill/scripts/src/index.ts:12–46,364–405`)

Importing settings calls `dotenv.config()` with no arguments, initializing environment bindings from the working-directory `.env`. `getSettings()` reads current `GA4_PROPERTY_ID`, `GA4_CLIENT_EMAIL`, `GA4_PRIVATE_KEY`, `GA4_DEFAULT_DATE_RANGE` and `SEARCH_CONSOLE_SITE_URL`, expands literal `\n` in the key, defaults the range to `30d`, and derives `<cwd>/results`. `validateSettings()` returns `{valid, errors}` based on property ID, email and key presence. Each client getter first tests its own cached handle. A hit returns the existing handle with its creation-time credentials. A miss validates and either throws before the request or creates and caches a new handle. `resetClient()` clears all three slots. `getPropertyId()` and `getSiteUrl()` read current settings separately, so a reused handle can receive a current property or site. (`skill/scripts/src/config/settings.ts:5–9,40–74`, `skill/scripts/src/core/client.ts:12–62,67–133`)

`getClient()` constructs `BetaAnalyticsDataClient` from `@google-analytics/data`. `getSearchConsoleClient()` selects `searchconsole` from `@googleapis/searchconsole` at `v1`, and `getIndexingClient()` selects `indexing` from `@googleapis/indexing` at `v3`. Each of those two creation paths constructs `google.auth.GoogleAuth` from `googleapis` with the configured email and key and both `webmasters.readonly` and `indexing` scopes. The lockfile resolves the four SDK packages to `4.12.1`, `6.0.1`, `6.0.1` and `170.1.0`, respectively. (`skill/scripts/src/core/client.ts:6–10,23–42,67–122`, `skill/scripts/package-lock.json:439–474,1401–1413`)

## Request and response boundaries

Public arguments come from the caller under the parameter names shown below. Internal calls use the values at their call sites. The GA4 report parser and bulk lookup’s private parser take `range`, use the configured default for falsy input, pass objects through, convert `Nd` to `NdaysAgo` through `today`, and fall back to 30 days for other strings. The Search Console parser shares the default and object pass-through, but converts shorthand or fallback to calendar dates using date subtraction and ISO date extraction. Search Console requires calendar dates according to its source comment. Relative-date objects still pass through unchanged. (`skill/scripts/src/api/reports.ts:47–72`, `skill/scripts/src/api/bulk-lookup.ts:103–128`, `skill/scripts/src/api/searchConsole.ts:47–84`, `skill/SKILL.md:104–114`)

- **Reports.** `runReport(options)` sends the current `properties/<id>`, parsed range, named `dimensions` and `metrics`, and a truthy `limit` to GA4. The interface and reference expose `filters` and `orderBy`, while the request omits both. It takes the first SDK response, saves that response by default under `reports` with the joined dimensions or `custom` as operation and the original string `dateRange` as optional extra, then returns the response. Date-only wrappers supply these dimension → metric sets:

  | Wrapper | Dimensions → metrics |
  |---|---|
  | `getPageViews` | `pagePath,pageTitle` → `screenPageViews,activeUsers,averageSessionDuration` |
  | `getTrafficSources` | `sessionSource,sessionMedium,sessionCampaignName` → `sessions,activeUsers,newUsers,bounceRate` |
  | `getUserDemographics` | `country,deviceCategory,browser` → `activeUsers,sessions,newUsers` |
  | `getEventCounts` | `eventName` → `eventCount,eventCountPerUser,activeUsers` |
  | `getConversions` | `eventName,sessionSource` → `conversions,totalRevenue` |
  | `getEcommerceRevenue` | `date,transactionId` → `totalRevenue,ecommercePurchases,averagePurchaseRevenue` |

  (`skill/scripts/src/api/reports.ts:20–28,77–175`, `skill/references/api-reference.md:31–45`)
- **Bulk lookup.** `normalizeUrls(urls)` trims each path and adds a leading slash when absent, preserving order and trailing slashes. Independently, `buildUrlFilter(urls)` returns `null` for an empty list or a case-insensitive `pagePath` inclusion filter for the supplied paths. `getMetricsForUrls(urls, options?)` normalizes first. An empty normalized list returns empty rows and zero count before client acquisition or saving. Otherwise it calls GA4 `runReport` directly with the property, parsed `options.dateRange`, `pagePath,pageTitle`, the normalized-path filter and `options.metrics` or `screenPageViews,activeUsers,averageSessionDuration,bounceRate,engagementRate`. It takes the first SDK response, conditionally saves it under `reports/bulk_url_lookup` with the original range string or `custom`, and returns it. The import from `reports.js` supplies types only. (`skill/scripts/src/api/bulk-lookup.ts:8–23,43–128,149–192`)
- **Realtime and metadata.** Each realtime function takes `save = true`, calls GA4 `runRealtimeReport` for the current property, and optionally saves and returns the first SDK response. `getActiveUsers` uses `unifiedScreenName`/`activeUsers` and saves `realtime/active_users`. `getRealtimePages` uses `unifiedScreenName`/`screenPageViews` and saves `realtime/pages`. `getRealtimeEvents` uses `eventName`/`eventCount` and saves `realtime/events`. `getRealtimeSources` uses `firstUserSource,firstUserMedium`/`activeUsers` and saves `realtime/sources`. Each metadata function takes `save = true` and requests `${property}/metadata`. `getAvailableDimensions` and `getAvailableMetrics` each return and optionally save an object containing the selected array, with an empty-array fallback, under `metadata/dimensions` or `metadata/metrics`. `getPropertyMetadata` returns and optionally saves the first SDK response under `metadata/full`. The reference describes arrays for the two projections. (`skill/scripts/src/api/realtime.ts:24–99`, `skill/scripts/src/api/metadata.ts:38–95`, `skill/references/api-reference.md:165–193`)
- **Search Console.** `querySearchAnalytics(options)` sends current `siteUrl` and a body with parsed dates, `dimensions` defaulting to `['query']`, `rowLimit` defaulting to `1000`, and `startRow` defaulting to `0`. It optionally saves `response.data` under `searchconsole`, with joined dimensions or `query` as operation and the original string range as optional extra, then returns that same data. Date-only wrappers select `query`/100 for `getTopQueries`, `page`/100 for `getTopPages`, `device`/default for `getDevicePerformance`, `country`/50 for `getCountryPerformance`, and `searchAppearance`/default for `getSearchAppearance`. The request specifies no sort. The reference describes top pages by impressions, while the Skill’s SEO description and index help use clicks. (`skill/scripts/src/api/searchConsole.ts:89–175`, `skill/references/api-reference.md:225–233`, `skill/SKILL.md:81–85`, `skill/scripts/src/index.ts:281–289,378–385`)
- **Indexing and inspection.** `requestIndexing(url, options?)` and `removeFromIndex(url, options?)` publish the supplied URL to Indexing with `URL_UPDATED` or `URL_DELETED`. Each constructs a notification result from the response URL or input URL, the requested type, and the respective update/removal notify time or current ISO time. They optionally save and return that constructed result under `indexing/request_indexing` or `indexing/remove_from_index`. `inspectUrl(url, options?)` sends `inspectionUrl` and current `siteUrl` to Search Console URL Inspection. It constructs an inspection result with index verdict and coverage fallbacks of `NEUTRAL` and `Unknown`, optional index details and link, and mobile usability and rich results only when their source sections exist. It optionally saves and returns that result under `indexing/url_inspection`. All three default `options.save` to true. (`skill/scripts/src/api/indexing.ts:57–79,114–193`)

The arrows give await order. Each named field receives the indicated producer’s return. The ordinary date-based orchestrators forward the same caller `dateRange` to each child, retain child default saves, then save and return their aggregate. The aggregate filename extra is the original string or `custom`. A rejection before the aggregate save can leave earlier child saves in place. (`skill/scripts/src/index.ts:55–165,235–295`)

Both child calls use `save: false`. It pairs each original range with its own response in `period1` and `period2`, then saves and returns the comparison under `reports/date_comparison`. `liveSnapshot()` calls `getActiveUsers()`, `getRealtimePages()`, then `getRealtimeEvents()` with default saves, and saves and returns `activeUsers`, `currentPages` and `currentEvents` under `realtime/snapshot`. `getAvailableFields()` calls `getPropertyMetadata()` with its default save, logs array counts and returns that metadata. For each URL loop below, the header tests `has_member` on the caller’s `urls`. The true branch selects the current URL, the body updates its local results array, and the backedge returns to the header. The false branch reaches the aggregate save and return, including for empty input. A client initialization failure can occur before dispatch, and an SDK rejection can occur after dispatch. Any exception that reaches a catch supplies its own error value. (`skill/scripts/src/api/indexing.ts:57–104,146–157`, `skill/scripts/src/index.ts:301–345`, `skill/scripts/src/core/client.ts:87–122`)

## Saved results, readers and summary gap

`saveResult(data, category, operation, extraInfo?)` creates the category directory if missing and synchronously writes `{metadata, data}` by replacement at a path under `<cwd>/results/<category>`. The filename uses a local second-resolution timestamp and sanitized operation and optional extra. Metadata records ISO `savedAt`, the original category and operation, the current property ID and any truthy extra. The function returns the path. API functions and orchestrators discard that path and return their data. A write failure can therefore interrupt a return after acquisition, and matching filenames can target the same path. (`skill/scripts/src/core/storage.ts:31–95`, `skill/scripts/src/api/reports.ts:100–108`, `skill/scripts/src/index.ts:59–76`)

`listResults(category, limit?)` returns `.json` paths in descending filename order, optionally sliced. `loadResult(filepath)` acquires and parses that file, returning the wrapper or `null` on absence or read/parse failure. `getLatestResult(category, operation?)` calls `listResults(category)`, optionally filters by a sanitized `__operation` substring in the path, and loads only the first match or returns `null`. The Skill illustrates `listResults('reports', 10)` feeding `files[0]` to `loadResult`, and separately `getLatestResult('reports', 'site_overview')`. Neither selection establishes which invocation produced the selected file. (`skill/scripts/src/core/storage.ts:103–171`, `skill/SKILL.md:129–142`)

The Skill prescribes analysis, automatic JSON saving, then reading saved JSON and creating Markdown in `results/summaries/` with tables, trends and recommendations. The implementation exposes the save exceptions above and writes metadata to a category omitted from the Skill’s directory sketch. The supplied sources establish the write producers and the independent readers. The association from a particular analysis invocation to the files consumed by its summary remains unresolved, and the supplied code provides no summary reader or Markdown writer that closes that gap. (`skill/SKILL.md:53–64,116–142`, `skill/scripts/src/api/metadata.ts:38–95`, `skill/scripts/src/core/storage.ts:58–171`, `skill/scripts/src/index.ts:12–23,55–405`)
