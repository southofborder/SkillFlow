5. OPERATION COMPATIBILITY
One timeline is CFG order -> events -> atomic_ops. Raw events are processing segments or single-level for_each with processing bodies. No profiles, roles, parallel effects or effect_index. No handwritten model_observe, guards or precedence. Respect order and definition/use; never replace old observation with a later cleaned value.
read: existing runtime_context/storage, context_read/fs_read.
receive: returned content from remote/net_receive or tool/null; ordered request influence and acquisition origin remain separate.
deliver: remote/net_send, user/user_output or tool/null. Request delivery is distinct from receive inputs.
write: runtime_context/context_write or storage/fs_write; replace/append consume input, delete consumes none and does not read old contents. Ordinary result binding is not context_write.
select_part/exclude_parts/update_fields/build/filter_items: explicit transforms with typed fields, retained unknown remainder and original member contents.
compute: inputs and per-input derived/possible dependencies have the same order and length. Zero-input opaque computation may use []. A null event permits only possible-compute or tool receive/deliver; it cannot hide reads, writes, field transformations or known networking. A non-null event includes its matching primary operation; parameter preparation cannot substitute for interaction.
for_each: one symbolic member shared by its body; keep same-element argument pairing. No nesting, state read/receive/write, mutable context operands, shadowing, cross-scope products or body-value export. Unsupported essential representation uses failure, not flattened fake pairing.

SHARED REPRESENTATION DECISIONS
CFG AND RETURN. CFG owns instructions, operands, result definitions, control, conditions, constraints and metadata. CFG evidence supports only its resolved graph fields. A result identifier names a value, not its members. Cite source lines for source-stated field existence or sensitivity; an explicit CFG literal, path or constraint supports only what it records, not unconditional runtime presence. Transfer operations and demands are annotation facts, even when they implement that IR. Ordinary return uses real CFG inputs, has no public output and may have empty events/output_bindings. Do not invent output 0 or user/network delivery. Caller-internal state is not separately modeled. Empty effects do not imply no action or identical IN/OUT.

COORDINATES. Direct CFG targets use exactly one complete form: {"instruction_id":"ir_demo","path":[]} for an instruction; {"block_id":"block_demo","path":[]} for a block; {"path":[]} for the graph; {"instruction_id":"ir_demo","side":"input","index":0} for an operand. path is required even when empty; bare identity is invalid. Realization bindings may use general graph/block/constraint targets. Executable action demands require an actual IR or atomic operation, not graph/block correspondence; value demands require actual operands or operation values, not names/containers. ValueRef input(index) always reads the enclosing IR entry operand; local(name) is lexical to that IR/scope. Operation demand input(index) instead selects the operation's consumed slot. Resolve slot -> ValueRef -> actual value before judging. Non-action self on an operation with an output targets that output, not its attached expression. compute/deliver/receive slots follow inputs; select_part/exclude_parts/filter_items and non-delete write use slot 0; update_fields uses base then updates. build visits parts in order: value, or when then value. Controls are not payload and false conditions do not renumber slots. read/delete have no slots. Control expressions use source-block dispatch inputs, never previous-IR locals.

In partial order only alternatives retaining an available candidate may reference a later local; no cycles.
