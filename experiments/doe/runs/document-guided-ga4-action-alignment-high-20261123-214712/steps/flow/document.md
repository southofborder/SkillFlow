The supplied code exposes independent GA4, realtime, metadata, Search Console, indexing, bulk lookup, and storage capabilities. The Skill requires analysis → saved JSON → reading those files → a Markdown summary with tables, trends, and recommendations in `results/summaries/`. **Independent acquisition boundaries.**

- `runReport(options)` consumes required `dimensions` and `metrics`, optional `dateRange`, `filters`, `orderBy`, `limit`, and `save=true`. It gets the client/property, parses the range, then sends property, one parsed date range, mapped dimensions/metrics, and a limit only when `limit` is truthy to Google’s `client.runReport`. Although destructured, `filters` and `orderBy` never enter the request. The acquired first response is conditionally saved under `reports`, with dimensions joined as operation (or `"custom"`), and only an original string range as extra information; that response is returned. (`src/api/reports.ts:20-28`, `77-108`)
- `parseDateRange(range)` uses the settings default for falsy input, returns an explicit object unchanged, translates matching `Nd` shorthand into `NdaysAgo`–`today`, and falls back to 30 days for other strings. Bulk lookup has its own private parser with the same branches. (`src/api/reports.ts:47-71`; `src/api/bulk-lookup.ts:103-127`)

Bulk lookup independently exposes `normalizeUrls(urls)`, which trims and adds a missing leading slash while preserving trailing slashes, and `buildUrlFilter(urls)`, which returns `null` for an empty collection or a case-insensitive `pagePath` inclusion filter using those supplied members. `getMetricsForUrls(urls, options={})` normalizes first. **Indexing loops and returned alternatives.** `requestIndexing(url, options={})` publishes the supplied URL with `URL_UPDATED`; `removeFromIndex` publishes it with `URL_DELETED`. Each creates a notification result from response metadata, falling back to the input URL and a current timestamp, conditionally saves it with default `save=true`, and returns that transformed result. Inspection instead uses the Search Console client with `{inspectionUrl:url, siteUrl:currentSiteUrl}`; it transforms the inspection response into index status plus optional mobile/rich-result sections, defaulting missing verdict/coverage to `NEUTRAL`/`Unknown`, then conditionally saves/returns that version. (`src/api/indexing.ts:57-79`, `114-136`, `146-192`)

Each following loop’s header tests `has_member(urls)` over the remaining traversal; the true branch obtains the current URL and executes its body, then returns to the header; the false branch exits:

- `requestIndexingBatch(urls, options={})` awaits `requestIndexing(currentUrl,{save:false})` and appends its returned notification. After traversal it conditionally saves the array as `indexing/batch_indexing` and returns it. An uncaught member failure prevents subsequent requests and the final save/return. (`src/api/indexing.ts:89-104`)
- `reindexUrls(urls)` makes the same sequential child call but catches each member failure. Success appends `{url:inputUrl,status:'submitted',...notification}`, so the returned notification’s URL can replace the input URL; failure appends the input URL, failed status, and the caught exception string. Both predecessors continue traversal. On exit it unconditionally saves `indexing/reindex_batch` and returns the mixed array. (`src/index.ts:301-318`)
- `checkIndexStatus(urls)` sequentially calls `inspectUrl(currentUrl,{save:false})`. Success appends input URL, `indexed` determined by verdict `=== 'PASS'`, and only `result.indexStatus`; failure appends input URL, `indexed:false`, and the caught exception string inside status. Both predecessors continue. It saves `indexing/index_status_check` and returns this reduced array, omitting inspection link/mobile/rich-result content. (`src/index.ts:324-345`)

Empty collections reach these loops’ final saves; only the low-level batch’s `save` option can suppress its save. Other acquisition/orchestration paths have no catches: earlier completed requests and saves can remain when a later call fails. Saving itself can also throw after acquisition. (`src/api/indexing.ts:89-104`; `src/index.ts:55-361`; `src/core/storage.ts:64-94`)

**Persistence, reading, and unresolved association.** `saveResult(data,category,operation,extraInfo?)` receives the actual response or transformed/combined result identified above. It creates a missing category directory, derives a second-resolution local-time filename with sanitized operation/extra text, and writes/replaces JSON containing a separate metadata wrapper and that data. Metadata records ISO save time, category, original operation, current property ID, and truthy extra information. Its public return is the path—not reread file content. Same-path writes can replace earlier content; no collision disambiguation is present. (`src/core/storage.ts:12-26`, `31-94`)

`loadResult(filepath)` independently acquires the named file’s content and parses it; missing files or caught read/parse failures return `null`. `listResults(category,limit?)` reads that category’s directory, keeps JSON paths, sorts descending lexically, and slices only when the limit is defined. `getLatestResult(category,operation?)` consumes that list, optionally filters by sanitized operation **substring in the path**, returns `null` if none remain, otherwise loads the first path. It does not establish exact operation identity or analysis ownership. (`src/core/storage.ts:103-170`)
