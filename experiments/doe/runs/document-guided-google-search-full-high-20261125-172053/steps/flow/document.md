# Google Search flow

- **Skill scope and setup.** The Skill describes Google Custom Search for live information, documentation, or research when built-in `web_search` is unavailable. Setup requires enabling the API, obtaining an API key and CX ID, and storing `GOOGLE_API_KEY` and `GOOGLE_CSE_ID` in a workspace `.env` file (`skill/SKILL.md:1-19`). Its example instead supplies those variables directly to a Python invocation with query `"OpenClaw documentation"` and no result-count argument (`skill/SKILL.md:24-28`). The script reads process environment variables; it contains no `.env` loader (`skill/scripts/search.py:1-4,26-28`). These are separate documented and implemented behaviors.

- **Independent callable entry.** `google_search(query, api_key, cse_id, num_results=5)` accepts caller-supplied values independently of CLI checks. It sends an HTTP GET to `https://www.googleapis.com/customsearch/v1`, pairing `query → q`, `api_key → key`, `cse_id → cx`, and `num_results → num` (`skill/scripts/search.py:6-14`). The returned HTTP response is consumed first by `raise_for_status()`, then by `response.json()`; the decoded API content becomes the function’s return value. Request, status-check, or decoding failures can propagate to its caller; the function has no local exception handler (`skill/scripts/search.py:14-16`).

- **CLI entry and order.** The main block runs only when `__name__ == "__main__"`. Fewer than two command-line arguments produces usage text and exit status 1. Otherwise, `sys.argv[1]` supplies the query; an existing `sys.argv[2]` is converted with `int`, or the count defaults to 5 (`skill/scripts/search.py:18-24`). Conversion occurs before the `try`, so conversion errors bypass the CLI handler. Next, the script reads both credential variables; if either is falsy, it prints the credential error and exits 1 before making a request (`skill/scripts/search.py:26-34`).

- **CLI call, versions, and recipients.** With credentials present, the CLI passes its query, environment-derived API key and CX ID, and selected count to `google_search`. The decoded return value is bound to `results`, serialized by `json.dumps(results, indent=2)`, and printed to standard output (`skill/scripts/search.py:34-36`). The HTTP response, decoded result, and serialized text are distinct values. An `Exception` raised within this `try` instead supplies `e` to the printed error message, followed by exit status 1. Depending on the failure point, a request may already have occurred or results may already have been decoded (`skill/scripts/search.py:34-39`).

- **Dependencies, state, and gaps.** Imports select `sys` for arguments/exits, `os` for environment reads, `requests` for acquisition, and `json` for output serialization (`skill/scripts/search.py:1-4,14,19-39`). No credential mutation, saved-result write, later file read, analysis, or summarization is shown. Consequently, no saved-file ownership or producer–consumer relationship for those activities is established. The Skill’s workflow contains only a placeholder, so it supplies no additional supported steps (`skill/SKILL.md:21-22`).
