**Indexing and explicit URL loops.** `requestIndexing(url, options={})` publishes the actual URL with `URL_UPDATED`; `removeFromIndex` independently publishes it with `URL_DELETED`. Each constructs a notification result from acquired metadata, falling back to the input URL and current ISO time when corresponding fields are falsy. Default saving writes that constructed version to indexing/request_indexing or indexing/remove_from_index, then returns it. (`skill/scripts/src/api/indexing.ts:57-80,114-137`)

`inspectUrl(url, options={})` sends the actual URL as inspectionUrl together with current siteUrl to the Search Console client. It constructs a result containing index status, optional inspection link, mobile usability and rich results. Missing status defaults to NEUTRAL/Unknown; optional sections exist only when their acquired sections exist, with their own verdict/list defaults. It optionally saves indexing/url_inspection and returns that constructed version. (`skill/scripts/src/api/indexing.ts:146-193`)

Each of the following loops starts with a fresh empty results array. Its header dispatch consumes the actual urls collection using `branch(predicate=has_member)`: true obtains the current URL, executes the body and returns to the header; false exits to the final save/return. The header merges entry and body backedges.

- `requestIndexingBatch(urls, options={})` calls requestIndexing with the current URL and save false, appends the returned notification, and continues. A failure propagates and prevents the final batch save/return. On loop exit, save defaults true and controls indexing/batch_indexing. (`skill/scripts/src/api/indexing.ts:89-105`)
- `reindexUrls(urls)` makes the same save-false request inside a per-member try/catch. Success appends submitted status plus the returned notification; the returned URL overrides the initially supplied URL because it is spread later. An actual caught exception instead produces a failed member with the input URL and its stringified error. Both predecessors merge before the backedge. Exit unconditionally saves indexing/reindex_batch and returns the array. (`skill/scripts/src/index.ts:301-319`)
- `checkIndexStatus(urls)` calls inspectUrl with the current URL and save false. Success appends the input URL, whether the returned verdict equals PASS, and the returned indexStatus only. A caught exception appends the input URL, indexed false and an error status. Both predecessors merge before the backedge; exit saves indexing/index_status_check and returns the array. (`skill/scripts/src/index.ts:324-346`)

**Persistence, reading and remaining gaps.** `saveResult(data, category, operation, extraInfo?)` receives the actual response, projection or assembled result described above. It reads current settings, creates the category directory only if absent, constructs a second-resolution local timestamp filename with sanitized operation/extra information, serializes `{metadata, data}`, writes/replaces that location, and returns its full path. Metadata records current propertyId even for Search Console/indexing data. API/orchestration callers discard this path; saving does not return file content. Repeated matching filenames can replace earlier writes. (`skill/scripts/src/core/storage.ts:31-95`)

`listResults(category, limit?)` independently reads the current category directory: absent means an empty array; otherwise it selects JSON paths, sorts by descending filename and applies slicing only when limit is defined. `loadResult(filepath)` separately reads/parses the supplied path, returning a SavedResult wrapper or null for absence/read/parse failure, without validating the wrapper. `getLatestResult(category, operation?)` consumes listResults output, optionally filters paths by a sanitized-operation substring, then loads only the first path or returns null for no matches. It neither checks exact metadata operation nor retries an older file after load failure. (`skill/scripts/src/core/storage.ts:103-171`)
