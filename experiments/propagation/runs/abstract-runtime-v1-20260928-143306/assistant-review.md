# 统一抽象运行时契约：工程验收与三例复测

本轮已将所有 Skill 共用的抽象运行时契约接入准备、Prompt、证据检查、运行身份、DOE 投影、加载与重放。三例联合标注均已按计划启动一次；001 完成标注和传播，010、013 在 DNS 解析阶段失败，未获得模型响应。本报告属于助手复核，不是用户人工确认或动态执行验证。

## 1. 固定下来的流程

```text
Skill + 既有 CFG
    → skillflow-abstract-runtime-v1
    → 一次联合标注：明确数据关系和契约下的可能观察
    → 确定性传播
```

唯一规则定义为 `src/skill_ir/runtime_contract.py`，EM01–EM09 全文以英文提供，中文主规范为 `docs/SkillFlow-统一抽象运行时契约.md`。本次契约 SHA-256：`d11080a8cf7879c3a0d01d6bf9b403f8fb0ed4ef4d16d5ed49b88bd2333712c0`。本次冻结全文可在 [001 标注材料](cases/001/annotation/inputs/material.json) 的 `execution_model` 中检查。

来源整体、工具内部读取、返回范围、模型观察和实际参数分别解释。契约适用的默认是静态可能关系；不把可能的 getter 当明确接口，不把本地扫描整个文件等同于模型观察整个文件，也不凭 Data 整体存在就补造观察。明确局部返回、结果限定和凭据隔离约束默认。传播器没有新增“每次 read 自动观察”的规则。

DOE 输入升级到 `skillflow-doe-input-v3`，只新增一次顶层 `execution_model={version,sha256}`；传播运行升级到 `skill-ir-propagation-v5`。标注 v6、Data v3、紧凑记录 v5、语义核对 v4 保持。没有重新提取图、启动反馈、修改原 IR 或迁移历史材料。

## 3. 001 方法表现

**已经保留的关系：** 整个 `events.json` 先读取，再作为同一版本进入 `model_observe`。模型通过 EM03 写明这是可能观察、不是已观测事实。筛选后的版本没有替换此前的整体观察；后续通知分别绑定 recipient 和 summary 的派生值，没有直接把整体作为通知参数，也没有凭禁传声明补出清洗动作。

**仍然存在的问题：**

1. 筛选结果、recipient 和 summary 仍是 opaque 的 `compute/derived`，没有可执行的逐记录字段选取与接收者配对关系。它们保留输入影响，但不足以证明“仅为该条记录的 summary 原值”，也不能反过来解释成原始文件所有明文都被发送。这是后续精度问题，不能由 DOE 靠名称猜测补齐。
2. `net_send` / `remote` 主要依据 notify.send 和 recipient 文字；网络机制本身没有明确依据。可以保留源文明示的通知发送，但不能把传输实现当已经确定，也不能据此断言它实际没有网络。
3. 筛选、计数被依据“没有提及 LLM”或 opcode 推定为本地运行时处理，理由过强。此处没有动态事实；但原整体已经记录可能观察，也不能机械要求再添加一次无依据的重复观察。

`complete`、空 unresolved、空 diagnostics 都不能覆盖上述助手发现。001 表明模型在本次输出中正确引用了默认整体观察；不能据此宣称三例改善、提示词有效率提高或标注全面正确。尤其 013 的新契约表现因网络失败仍无本轮数据。
