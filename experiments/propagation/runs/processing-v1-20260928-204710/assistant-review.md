## 改了什么

1. 联合标注 Prompt 用一个明确决策顺序选择处理模式：检查明确执行与回传机制；明示模型处理用 model；证据足以支持本地执行及可见边界才用 local；否则 default。原有 evidences 承担依据，不加机制字段或关键词判定器。
2. 将每个输出的原值关系和计算关系分开：原样转交直接绑定、已有字段用 select_part、保留成员的筛选用 filter_items；真正计算或内部不透明关系才使用 compute。增加通用配对例子和完整 JSON 格式示例，英文指令、中文解释。
3. 客户端增加可选 JSON Output，默认关闭。标注入口和各调度派生专用配置；提取／核对客户端不被动开启。实际 HTTP 参数、请求体摘要、配置、原始响应及编译材料参与恢复和重放核验。
4. 完整但无效响应不修剪、不修复、不质量补跑；传输未完成、截断、JSON 语法与结构／引文问题分别记录。服务拒绝参数不降级重发。注入客户端如实标记 HTTP 参数不可观测。
5. 标注运行升级 v8、传播运行 v7，相关调度身份同步。业务标注 v7、Data v4、记录 v6、DOE v4、运行时契约 v2及编译器保持不变。

本轮没有修改 CFG、生产提取 Prompt、源文核对、反馈闭环、Data、传播算法或观察编译规则。没有新增独立语义审查调用或自动语义修复。

## 实际请求与工程验证

- 共 **3 次逻辑调用、3 次 HTTP 尝试**，没有传输重试或质量补跑。请求模型为 deepseek-v4-flash，服务返回名称为 deepseek-flash，均原样记录。
- 三份实际请求均带 `response_format={"type":"json_object"}` 和 SSE 参数；精确请求体重建摘要匹配。三例均 finish_reason=stop、SSE DONE=true，没有接受截断输出。
- 三例标注离线解析／编译与保存结果一致，传播重放均 matched、differences=[]，不另存第二份最终 Data。
- 离线回归最终覆盖 **2,175 个不同测试**。初次 4 个失败分别是已接受记录删除的旧预期、以及未启用可选参数影响旧基线快照；针对性修正后相关 48／51 项通过。详细计数在验证说明中保留，没有隐去初次失败。
- 10,092 个受保护文件摘要均未改变；冻结源包、历史运行、30 例交付物及指定不修改的核心实现保持。
- 新产物凭据扫描未发现配置密钥。生成的 HTML 做了静态文件链接与锚点检查；没有把它声称为浏览器视觉验证。

## 仍保留的问题

- **001 的部分标注依据仍偏强。**虽然处理段已正确 default，执行主体理由仍有“未提 LLM，所以本地”的措辞；notify.send 被推成 remote/net_send，但材料没有明确网络实现。它没有影响本轮字段配对改善，但下一轮应审查依据是否足够。
- **001、010 的文件写入采用 replace，比原文“写入”更具体。**当前实际写入值正确，是否应默认覆盖旧文件需要单独明确，不能把本次强更新当成源文已证明的删除旧内容行为。
- **010 的可选参数条件尚未编译为条件化参数集合。**值与存在性输出已经分开，存在性标志未被当作参数发送；CFG 中仍保留“缺失则省略”。当前 may 记录不能读成所有参数每次都实际出现。
- **013 还有一个字段依据待核查点。**标注把“return its error”具体化成 `select_part(["error"])`，但源文没有明确字面字段路径，冻结图也只有输出标签。这可能是将错误对象过度具体化成字段；目前不能直接判定实际返回一定错误，也不能宣称该路径已被充分支持。结果按原样保留。
- **013 的禁传不因依赖关系而自动得到证明或反证。**archive 实际参数只有 source_id，状态追加不直接接收密钥；fast 响应仍可能受密钥影响。possible 依赖不是密钥明文包含，字段原值保留也不是实际执行验证。
- 路径条件和筛选谓词没有执行求值；default 观察是统一契约下的可能行为。完整结构、真实引文和重放一致，都不能自动证明模型语义判断正确。

建议下一轮聚焦语义审查只先覆盖三类容易产生实际影响的判断：处理方式与回传机制、明确原值关系是否被降精度、来源／观察版本与实际参数是否混淆。本轮未预先实现这个额外阶段，也未据复核意见自动改写结果。

审查时建议先读逐例复核，再打开传播页面查看相关 IR 和 Data；只在需要核实原始内容时进入 doe-input.json 或旁置审计材料。主业务文件仍不包含风险、必要性或 DOE 结论。
