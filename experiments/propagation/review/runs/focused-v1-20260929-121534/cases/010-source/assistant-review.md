# 010 工具获取来源丢失候选：助手复核

**确认受控缺陷被命中。**`f_ir007_missing_receive` 准确指出 ir_007 的 compute 只保存请求值的 possible 依赖，无法替代工具返回内容的获取来源。源文、CFG 返回值及 EM09 均支持该判断；编译观察从返回版本退成请求参数的影响也与候选一致。

建议实施时应将错误 compute **替换**为 receive，保留 tool 边界、无标签事件、原有实际请求输入和输出名。不能机械地追加一个同名 search_response，造成局部值重复定义；也不能为修复来源而补造网络标签。本轮没有执行修改。

本变体的 profile 仍声称“已通过 receive 表达获取”，而操作实际是 compute。审查利用了这项内部矛盾；这不影响本次命中，但不能由此推断在理由全部同步改写后也一定能够命中。

另一个发现 `f_ir012_missing_return_forwarding` 与 010 原标注同类：说明确实把关系承载位置说错，但当前 return 的合法空规格、CFG 中保留的原值输入和未单列的通用调用方边界，不能直接被判成已确认的数据交付遗漏。将它归为“部分成立、结论过强”，不计第二种新缺陷；原始 issue 保持不变。
