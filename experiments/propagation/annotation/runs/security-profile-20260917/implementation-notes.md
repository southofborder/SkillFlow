# 工程实现与验证边界

本文件记录 2026-09-17 本轮新增 Security Profile 模块的工程验收。真实调用的最终数量、执行失败和助手语义复核另见总报告，测试通过不等于标注正确。

## 已实现

- 独立 `skill_ir.security_profile` 模块及 `annotate_skill` 可注入服务；`prepare / run / replay` 不改变原有分析和反馈入口。
- 单次整图标注输入为完整可读 Skill、完整实际 CFG JSON、索引及六条固定执行规则。没有发送受控回述、旧候选、评审答案或传播集合。
- 每条 IR 的 profile 只有 `actor / roles / effects / evidences`。操作 ID 位于外层，未决记录另存，覆盖全部真实指令，包括控制与返回。
- 严格核验 JSON、重复键、固定词表、IR 覆盖、标签证据、实际定位及逐字引文。错误不会被自动补齐或用第二次调用修复。
- 源包原始字节与解码文本分开绑定，CFG、提示词、规则和源码身份可核验；模型发送文本与冻结文本一致。
- 复用共用快照、严格源文证据、SSE 传输、互斥锁、脱敏和持久化调用记录。已接受或不确定的请求不自动重发。
- 调用前、本地校验期间和接受响应后的中断决策持久保存。显式恢复可处理已保存响应，离线重放保留原停止状态。
- 固定 30 例调度最多三个独立案例并行；一例失败不阻断其他例；中断停止提交新例。

## 本轮真实运行发现的工程限制

002 的响应保存遇到 Windows `transport.json` 原子替换拒绝访问。此前有监控读取仍在写入的记录，读写竞争是可能原因，尚未独立证明唯一成因。本例保留为执行错误，没有重新调用。随后只在 `result.json` 出现后读取该例调用记录，避免主动读取活跃流文件。

调用记录的外层错误文字沿用了既有 SSE 适配器的 `network failure` 包装；002 的具体错误是本地文件替换失败，不能将其归因为远端模型语义失败。流中断与 DNS 失败同样按执行问题保存，不能算作模型漏标。

本轮没有中途修改已冻结传输或提示词。后续若要强化 Windows 下监控与原子写盘并发的兼容性，应建立新版本和新运行身份，并另做故障注入测试；不能改写这次结果或冒充首次调用成功。

本轮不执行数据传播，不推断实际容器内容，不计算敏感数据集合，不给风险、必要性或 DOE 结论。
