IR 解释与逐项核对契约：skill-ir-semantic-contract-v2
以下规则解释现有记录及核对边界，不增加当前 Skill 的业务要求。
[IR-RESOURCE] external_resource 标识文件、工具、API 或服务，不等于远端或网络资源；本地文件也可用该类型。资源定位符不当然是业务参数。根据实际类型、位置与用途核对，不能只据类型名推断网络发送或额外参数。
[IR-CONTROL] dispatch 与 return 是固定控制终结操作。dispatch 结束当前块，出边连接后继，inputs 记录选择分支使用的值；return 结束当前路径，inputs 记录返回值，也可无返回值。二者不产生结果输出。不能仅因源文没有写出这些 IR 术语判新增或未决；仍要核对实际输入、出边、条件和返回值身份。return 本身不表示向用户展示或发送内容。
[IR-IDENTITY] result 按实际 identifier 关联唯一结果定义；semantic_name、块名和相似文字不能替换结果身份。首次尝试、重试和回退得到的结果不能互换。操作数列表位置和操作次序照实核对，不自动视为可交换集合。
[IR-PATH] 边记录连接和条件文字；它们不证明所有路径实际可执行、条件恒真或循环必然终止。结构校验不保证所有路径上所有输入同时可用。不能仅因结果只在部分路径产生判语义错误；合流块可引用分支定义，循环可引用回边定义。不能据此虚构隐含 phi、运行时选值或可选参数机制。
[IR-DECLARATION] 图、块、操作级 constraints 是各作用域的声明，不等于已经记录对应操作或保证运行成功。约束与操作的冲突可以报告。块标题、名字和声明不能补造遗漏步骤；会改变数据内容、去向或执行条件的原文明示步骤必须分别可定位。
[IR-OPAQUE] 普通 opcode 是开放操作名，按明确文字和接口核对，不能凭名字猜测未记录的内部步骤。脚本沿用黑盒建模，核对显式接口、输入输出和已记录的外部副作用；metadata 或嵌入源码完整保留，不等于内部行为已被显式建模或执行成功。
[DEP-MERGE] 合流依赖可保守保留：已有多个 result 候选来源，且源文与记录的控制关系支持这些候选时，允许记录为候选依赖集合。必须列出至少两个已有操作数/定义事实编号，说明支持依据与丢失的按路径区分。这不声称各值同时作为实参使用、不声称图已实现精确选值，也不声称每个候选都会传递。不能仅因缺少更精确的选值区分就判遗漏、错转或未决。
[DEP-SOURCE] 来源依赖可保守保留：图中已有多个候选来源，源文和当前记录支持这组可能依赖，但无法进一步细分来源关系时，允许保留有依据的候选集合。逐项引用已有操作数/定义事实，写明失去的来源区分；不新增来源，不将候选说成全部实际读取、同时实参或必定传递。
[DEP-LIMIT] 保守规则只适用于数据来源和依赖精度。不能用于放宽动作、执行路径、业务实参、返回身份、次数、禁止事项或作用域；不能掩盖正确来源缺失、明确错误的返回结果、明确多传参数或禁传违反。不能只用容器、约束、metadata、类型字段或语义标签作为候选来源证据，也不能凭原文补造图中不存在的事实。选择完整操作数或标识事实；同一结果的定义和使用不是两个独立候选来源。保守接受必须由本次核对明确说明；程序不得把 unknown 自动改成 represented。
[REVIEW-MODALITY] 区分要求、许可、禁止、示例、背景和各自作用域。为实施条件检查存在性，不自动等于格式/合法性校验或规范化。“未要求某动作”不能自动改成“禁止某动作”。合法的表示辅助信息不自动成为新增业务步骤。源文歧义或冲突不得凭模型偏好消解，安全性判断也不能替代忠实性核对。
[REVIEW-UNIT] 按语义关系组织核对项，允许合并相关行为、条件和结果，不要求固定粒度或归属单一检查类别。组合要求中只要有一部分存在差异，必须说明具体差异，不能将整项标为 represented 掩盖局部错误；需要分别表达不同结论时合理拆分。动作存在不能代替对象、绑定、条件、次数、顺序和作用域成立。说明原文要求、受控记录、差异和证据，并检查结论与本项证据及其他发现是否一致。不用整体相似或编号覆盖代替判断。
