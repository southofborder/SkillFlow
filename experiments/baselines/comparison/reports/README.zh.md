# 对齐结果与汇总

本批汇总纳入直接强模型、Semia 和 SkillPrivus。每个结果记录都能追溯到 `case_id`、方法及变体、运行 ID、源包哈希和原始产物。汇总 ID 可使用 `audit-01` 这样的序号。

| 比较项 | 对齐字段 |
| --- | --- |
| 数据操作与边界 | 源文件和行号、数据范围、操作、目的地或接收者、适用条件 |
| 相对任务的额外暴露 | 任务依据、数据范围、边界、必要行为、可缩减范围及其保留条件 |
| 可用性及成本 | 运行终态、失败环节、实际输入覆盖、模型调用次数、已知 token、用量未知的请求数、端到端耗时 |

运行终态记录 `completed`、`partial`、`failed` 或 `not_run`，原生状态另存。事实和能力缺口可记录 `unresolved`、`unsupported` 或 `not_applicable`。零项结果只来自已经执行并返回空结果的环节。Semia 检测未运行、SkillPrivus 筛除或判断不完整、强模型证据定位被拒各自保留原含义。

缺独立标签时，精确率、召回率和 F1 记为 `not_evaluated`。三种方法均以同一源包哈希配对，用量及失败状态采用各运行的实际回执。

[汇总入口](summarize.py) 接收三组运行 ID 和一个新报告 ID。三组都有完整的 100 例终态记录后，入口核对共同清单和逐例源包哈希，生成 `results.jsonl`、`summary.json` 和 `summary.md`。`--wait` 在运行期间等待终态。涉及告警、额外暴露或情境完整性裁决的结论可沿逐例引用检查原始记录。
