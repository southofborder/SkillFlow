# F01 首次语义反馈：助手复核

本文件记录助手结合冻结源文、实际新图及核对记录给出的复核意见，**不是用户人工确认，也不是语义等价证明**。模型提取和核对输入均未读取本文件、其他复核笔记或外置预期。

本轮实现、首次五例实测和真实记录的离线重放均已完成。四个受控缺陷均在有效初轮核对中被识别，其中三个完成一次修复并获得核对器通过；另一个因提取流不完整而未完成修复。原图的核对也发生流中断。两处执行失败保留原记录，未自动重发。

实际为 **12 次逻辑调用：4 次提取、8 次核对；12 次 HTTP 尝试，0 次 HTTP 重试**。请求模型为 `deepseek-v4-flash`，接口实际返回名均为 `deepseek-flash`。四次语义修复尝试中三次得到有效新图，一次传输失败；没有结构修复调用。不是 80 次预算全额执行，也没有补跑选优。

## 已观察到的方法边界

1. **网络执行失败与语义失败分开。** c01 在 HTTP 200 后流中断，未完整结束，因此不能判断核对模型是否通过；c04 已识别错转，但修复响应未完整结束，没有可接受的新图。两例均按固定策略保留失败且没有自动重发。不能将部分响应当作有效核对或候选。
2. **同一缺陷不重复计数。** c02 的额外输入与内部冲突是同一密钥注入的两个角度。其初轮另有一处自由说明文字块 ID 写错，正式受控事实编号、程序映射和修复建议的位置正确；该瑕疵保留在复核笔记中。
3. **未决消失不等于程序修复了未决。** c03 初轮将 `dispatch` 的含义标为未决；当前 IR 赋予它固定控制角色，而核对输入未充分说明这一例外。新图仍保留合法 `dispatch`，下一轮却未再提出该项 unknown。应记录核对判断的波动，不能把它算作一次语义修复成功。
4. **重新编号后重新检查。** c02 与 c03 的操作位置、部分语义标签和约束归属发生变化。复核依据新图重新追踪请求/环境来源、操作数身份、控制边和返回绑定，没有用旧指针机械宣布缺陷消失。
5. **保留合理表达空间。** 源文未规定状态记录格式；`success`/`failure` 是可接受的表示。资源定位符不当作业务参数。声明存在、边存在或开放操作存在，都不证明实际文件写入、工具执行或运行无泄漏。
6. **建议不能越过冻结边界。** c04 提议修改的定义链接是派生证据，只能随实际操作数重新生成；c05 提议“补充源文依据”不适用于当前冻结实验。程序始终只接收完整候选，不修改源文或回述来迎合建议。
7. **概述不是完整使用位置证据。** c05 最终说明将密钥用途概述为 fast/retry，未列出实际存在性检查；新图本身保留该检查。说明性瑕疵留在逐例笔记，不误记为图中密钥泄露，也不能用概述替代后续数据传播。

## 交付与使用

优先阅读本文件；[自动对照报告](report.md) 展示模型原始分层记录与外置预期匹配候选，表中 `assistant_review_pending` 是自动匹配阶段本身不作人工结论的标记，已完成的助手判断以本文件及逐例笔记为准。

通过的新图分别位于 [c02](cases/c02/passed-cfg.json)、[c03](cases/c03/passed-cfg.json)、[c05](cases/c05/passed-cfg.json)。c01/c04 只有最后结构有效图，不提供通过图。每例 `report.md`、`rounds/` 和 `calls/` 保留全部实际差异、候选、约束、受控文本、证书、反馈、响应和失败证据。

本轮没有发现三个已完成修复图的关键语义退化或明确假通过；这是 F01 有限案例的助手复核结论。它不证明模型核对稳定、任意 Skill 的语义正确性或运行中的无泄漏。后续值得优先澄清固定控制操作与开放业务操作的表示边界，避免把本轮 `dispatch` 的判断波动当作已解决问题。
