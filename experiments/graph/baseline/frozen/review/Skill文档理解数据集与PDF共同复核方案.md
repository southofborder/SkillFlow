# Skill 文档理解数据集与 PDF 共同复核方案

## 1. 本轮目标与交付边界

先确定“文档中的什么内容应该被提取、怎样表达”，再建立 **24 份控制样例＋6 份真实 Skill** 的首批数据集，生成可阅读的 PDF，由我们共同确认原文和判定依据。

**这一阶段不修改生产 Prompt、IR 模型或提取流程，也不发起新的线上调用。** 先冻结样例与判断标准，避免看过模型结果后反过来修改答案。已有三个示例继续作为独立的回归样例，不计入这 30 份。

当前代码已经要求分析自然语言，但表格等内容只是原样传入，缺少更细的语义判定约定。实验重点因此放在两件事上：

- 同一行为换成段落、列表、表格或跨文档表达后，关键含义是否保留。
- 相似文字改成能力说明、调用要求、运行指令或引用示例后，提取是否随用途改变。

本轮只覆盖当前加载器可读取的文本。图片中的表格、扫描 PDF、不可解码文件等记录为输入能力边界，不把未读取的内容计为 Prompt 漏提。

## 2. 先明确语义表达约定

将以下规则写入标注规范和 PDF，作为共同复核的依据：

| 内容承担的作用 | 预期表达 |
| --- | --- |
| 实际读取、处理、调用、发送和返回 | 提取操作、输入输出及相应控制流 |
| 决定是否执行、执行哪个操作的条件 | 保留分支条件和所用数据；条件文字不能代替结果引用 |
| 参数格式、调用前提和参数省略要求 | 关联到所属调用，保留约束；不能据此凭空增加转换或校验操作 |
| 工具选择优先级、禁止事项 | 保留规则及作用范围；不能等同于一次无条件调用 |
| 单纯能力介绍、参数解释 | 不单独制造一次执行；实际调用引用这些说明时，保留相关要求 |
| 示例、引用、历史说明、反面教材 | 根据上下文判断是否参与当前流程，不能只因出现命令句就加入执行路径 |
| 被流程明确要求采用的示例或参考步骤 | 提取被引用的实际行为，不能因其位于“示例”章节就全部排除 |

约束采用用户确认的**“原文＋作用范围”**方式，不设计复杂规则语言：

- 区分整份 Skill、某个基本块、某条操作三个作用范围。
- 拟议输出约定为在相应层级使用 `constraints: list[str]`，由所在层级表达归属；不为每种约束增加专用分类字段。
- PDF 中展示这一字段约定，但本阶段不修改生产模型。
- 不能确定作用范围时，标为“待共同确认”，不能擅自提升为全局规则。
- 真正的数据读取、处理与传递仍必须体现在操作数和控制流中，不能仅藏在约束文字里。
- 简洁、语气、回答长度等保持低优先级，不作为本轮主要通过标准，也不因此增加流程步骤。

文档中确实要求执行的可疑行为应被描述并保留，不能因为可疑而被悄悄删除；分析器本身不执行这些要求。本轮不增加攻击分类、effect 或审计结论。

## 3. 数据集组成与标注

### 24 份控制样例

选择四个语义场景，每个场景制作六个版本：

| 场景 | 主要覆盖问题 |
| --- | --- |
| 条件通知与数据发送 | 否定条件、发送对象、发送哪些数据、何时不发送 |
| 查询调用与参数使用 | 参数格式、缺失值、省略参数、能力说明与实际调用的区别 |
| 工具选择与失败回退 | 优先选择、前置条件、失败重试、回退路径与停止条件 |
| 多文档处理与交付 | 引用关系、代码黑盒、独立行为、局部与全局约束 |

每组的六个版本固定为：

1. 编号步骤。
2. 连贯自然语言段落。
3. 表格表达。
4. 跨文件的混合表达，包含引用、列表、代码或配置片段。
5. 一个最小差异版本：只改变一句话的用途，例如将运行指令改为明确不执行的示例。
6. 另一个最小差异版本：只改变条件、允许范围或传递的数据，检查模型是否识别实质差异。

前四个版本保留相同的核心语义；后两个版本明确标注“哪些事实应该随改动变化”。两组使用中文、两组使用英文，同一组的等价版本保持语言一致，避免把语言变化与版式变化混在一起。

覆盖矩阵另行检查：表头和行内容的关联、参数表与步骤表的区别、嵌套列表、引用块、代码块、YAML/JSON 片段、跨文件引用、禁止事项与例外条件。它们分布在上述样例中，不做所有维度的全组合。

### 6 份真实 Skill

使用 [openai/skills](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431) 的固定提交快照，选取：

- `pdf`
- `playwright`
- `gh-fix-ci`
- `netlify-deploy`
- `linear`
- `transcribe`

保留包内原始文件、许可证和来源记录，不改写成迎合当前 Prompt 的文本；记录提交、文件清单及摘要。只分析其内容，不执行脚本、调用工具或进行部署。包外链接不自动下载为隐含输入，未提供的内容明确标注。

### 标注与开发／验证划分

每份样例具有独立的标注文件，包含：

- 覆盖目标、所属场景组和表达形式。
- 必须保留的行为、条件、数据来源与去向。
- 必须保留的约束及其作用范围。
- 不应凭空增加的行为。
- 可接受的不同表达，以及尚有争议的判断。
- 对应原文位置；表格证据包含必要表头，跨文件证据包含引用上下文。

**标注放在 Skill 包之外，绝不进入提取 Prompt。** 不要求固定 `opcode`、结果编号或唯一 CFG。

按整组划分：通知、工具回退、多文档三个控制组及前四份真实 Skill作为开发集，共 **22 份**；查询参数组及 `linear`、`transcribe` 作为保留验证集，共 **8 份**。保留集不用于编写 Prompt 示例，结果也不用于当前轮反复调参。

## 4. PDF 复核材料与后续实验流程

第一阶段交付：

- 数据集清单、原始样例、覆盖矩阵和外置事实标注。
- **复核主册 PDF**：说明判定规则，按组展示控制样例及差异；真实 Skill 展示足以判断的原文片段、作用范围和事实检查表。
- **原文附册 PDF**：提供真实包中可读取文本的完整内容，保留文件边界、代码和表格，便于追查主册未展示的上下文。

PDF 使用可检索的中文文字、目录、页码和清晰的样例编号；宽表和长代码合理换页，不通过缩小字号强塞。生成后逐页渲染检查，确认没有缺字、裁切、重叠或不可读表格。每条事实初始标为“待共同复核”，不预填语义通过结论。

我们确认样例和规则后，才进入下一阶段：

1. 冻结数据集、标注和当前 Prompt 快照。
2. 单独处理已确认的约束表达契约，记录它与原契约的差异；不把增加字段本身当作 Prompt 优化收益。
3. 在同一契约下运行基线和后续 Prompt 版本，每份样例重复 **3 次**；全量每版为 **90 次提取**，结构修复和 HTTP 重试继续分开记录。
4. 生成结果复核 PDF，增加实际 CFG、操作与数据引用、约束落点、三次运行差异，以及我的逐项初审意见，由我们共同确认。
5. 根据开发集的明确问题修改 Prompt，再检查保留集。没有证据支持的补充规则不加入提示词。

本轮验收以“30 份样例齐全、标注与输入隔离、覆盖矩阵可追溯、共同复核材料可读”为准。后续进入语义回溯阶段前，需要在这批验证范围内处理完已确认的关键行为遗漏、无依据新增操作、条件丢失和数据来源／去向错误；不以块数更少或单次结构通过作为语义正确的证据。
