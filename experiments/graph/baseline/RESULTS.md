## 初审意见与后续处理顺序

以下是基于本批次真实输出的外置初审，尚未成为用户共同确认结论；结构有效不作为语义通过标准。每条事实分别判断三轮，并绑定对应 `record.json` 与 `analysis.json` 的 SHA256。人工理由引用实际指令、块、边或约束落点，附加发现与原有事实分别保留。

1. **先确认数据与条件的实质偏差。** 通知跨文件样例 N04 凭空增加固定 payload.json 的运行时读取；部分通知 CFG 将逐记录条件压成集合处理。真实 CI 手动路径中可见缺省 PR、兼容字段重试、run/job 标识与日志写出绑定不完整。部署示例存在配置/故障恢复遗漏。已有意图文字不足以替代可验证的实际操作数和控制关系。保留集 R06 还观察到外层密钥门阻断源码允许的无密钥 dry-run；此处只记录固定基线偏差，不据此编写开发 Prompt 示例或反复调参。
2. **纠正无依据的范围和口径选择。** 多文档组 8 项把未知范围的原顺序备注强行指定到全局或转换块。通知“处理条数”的来源未决定口径，不能看见诊断承认歧义就将自行选择的计数视为完全保留。部署来源同时要求新站生产和先预览，模型应保留冲突，不替来源擅自选择一项。
3. **单独确认允许的表达粒度。** 多文档转换保留逐个意图、完整黑盒源码及 I/O，却以集合输入/列表输出表示，逐文档和每次 stdout 绑定尚不明确。这里标 partial，不要求特定 loop opcode，也不宣称全部意图丢失。固定 bundle.zip 文件副作用可衔接后续交付，无需强制添加合成结果值。
4. **关注不同路径上结果是否可用。** 有些合流操作消费互斥分支的全部结果，或在正常路径消费仅回退路径产生的值。表面引用 ID 存在不等于当前路径上一定有值；这些已在附加发现中记录，不强制特定 phi/selector opcode。

F 组全部 15 份有效结果保留十条冻结事实；N05/D05/F05 等把当前指令改为历史示例的差异，以及 N06/F06/D06 的数据去向变化，在对应有效结果中有明确识别证据。这些正向结果与失败、部分保留项一起呈现，不据单次成功作整体推广。

根据原方案，先共同确认本轮模型结果和上述表达边界，再仅依据开发集的明确问题形成下一版 Prompt。保留集用于本轮固定基线观察，不被写成 Prompt 示例或反复调参。五条失败如需补测，应另建有来源关联的补充批次，保留原始失败；不会删除或覆盖本批次记录。
