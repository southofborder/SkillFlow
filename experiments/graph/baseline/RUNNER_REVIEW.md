# 基线执行器独立复核

2026-09-10，由独立子代理只读检查 `src/skill_ir/experiments/resumable.py`、基线 `tools/run_baseline.py` 及其使用的客户端、配置和指标实现。未更改已锁定的生产源码或冻结身份，未读取保留集实际输出，未发起模型调用。

当前实际配置的调度和隔离路径可以继续使用。新增 `tests/experiments/test_semantics_resumable_audit.py` 的三个离线检查均通过，所有网络请求由内存响应替代：

- 使用真实 30 个冻结输入的配置，先运行开发集得到 66 个完成试验，再运行保留集累计 90 个；随后全量恢复没有新增请求。每个 `(case, variant, repetition)` 唯一。
- 故意让每次生成先经历一次 HTTP 500，再返回无效 JSON。3 个试验、每个最多 3 轮修复，最终恰为 12 次生成、9 次结构修复、24 次 HTTP 尝试、12 次 HTTP 重试；失败终态恢复没有重发。
- 实际 `baseline.json` 指向单独检查的 `dataset.json`，解析得到的 30 条源路径逐项等于冻结清单中的独立输入目录。

“90 次”表示 30 × 3 个独立提取试验，并非 HTTP 请求的硬上限。结构修复在各试验内单独计数；当前最多每试验 4 次生成。每次生成的 HTTP 重试再由有效配置中的 `max_retries` 限制。报告分别保留这些数字，结构成功不等于语义成功。

执行器为整个运行目录持有操作系统独占锁，同一目录不能由两个执行器并行推进。`record.json` 是试验提交点；已提交终态只核对产物摘要，不再自动调用模型。未提交试验中，已完成且 Prompt 一致的生成可从 trace 重放；有未完成调用的 trace 会归入 `uncertain`，不会自动补发。未使用表格事实或外置标注构造提取 Prompt。

后续可加固、但当前实际配置没有触发的问题：入口的 `baseline_definition()` 检查 `BASE/dataset.json`，而实际解析仍采用 `baseline.json` 的 `dataset` 字段。若将该字段误指另一份具有相同 30 个 ID 的清单，当前入口尚未逐项检查实际解析源路径。建议在下一次独立执行器修订中直接比对 `resolved.cases` 与冻结路径；本轮用针对实际配置的测试明确确认没有这种重定向。保持运行中的源码身份不变。

当前执行器没有按基础设施故障率自动停止的机制。调度采用 FIRST_COMPLETED；任一在途试验终结后会立即补位。主线程收到 KeyboardInterrupt 时会停止提交新试验，并等待已在途工作线程按已有 HTTP 重试预算结束后落盘；工作线程中的 HTTP 重试不会因此取消。没有可由外部写入的停止标记文件。普通管道中的 Ctrl-C 字符不应被当成保证有效的操作系统中断信号；突然终止进程则会留下远端结果未知的在途调用，恢复时按 `uncertain` 保留，不能当作从未调用过。

以上是本轮执行器行为与测试边界的记录，不是对样例实际提取结果的语义结论。
