# F01 闭环示范：工程验收与首次方法诊断

**工程原型已完成；首次实测没有通过完整语义闭环的方法验收。** 这两点需要同时保留。程序成功暴露并保存了证据错误，没有修补提示词、重发失败角色或挑选更好的响应。所有事后逐项复核意见由本助手完成，**尚不是用户复核结论，也不是独立人类评测**。

## 先看实际结果

请求模型为官方 DeepSeek `deepseek-v4-flash`，推理档 `max`；18 次实际响应均报告模型名 `deepseek-flash`。固定安排 21 个角色，实际发送 **18 次逻辑调用、18 次 HTTP 请求**。其中 **10 个角色得到通过契约校验的结果，8 个角色因无效图引用成为执行错误**；另外 3 个依赖失败回译的角色被阻断，未发送请求。没有自动修复、择优、补跑或 HTTP 重试。

| 输入 | 源文 → 图 | 结构化回述及其核对 | 自然语言回译及其核对 |
|---|---|---|---|
| c01 原图 | 执行错误：操作级约束被引用为块级约束 | 有效核对；7 条 `represented` | 回译与核对均有效；6 条 `represented`，但事后复核发现失败追加动作未明确表达的疑点 |
| c02 archive 增加密钥输入 | 同类证据地址错误；不能计正式命中 | 有效核对；32 条保留、1 条图内冲突 | 回译与核对有效；14 条保留、1 条图内冲突、1 条图证据未决 |
| c03 删除失败出口状态追加 | 同类证据地址错误；不能计正式命中 | 有效核对；18 条保留、1 条图内冲突；没有补回删除的操作 | 回译引用无效；后续图→回译核对阻断 |
| c04 重试成功却返回首次结果 | 同类证据地址错误；不能计正式命中 | 有效核对；18 条保留、1 条图内冲突；保留实际的首次结果绑定 | 回译引用无效；后续图→回译核对阻断 |
| c05 增加两秒等待 | 同类证据地址错误；不能计正式命中 | 有效核对；32 条保留；保留等待、数值、秒单位和次序 | 回译引用无效；后续图→回译核对阻断 |

每份结构化回述都有 **32 个文本单元**，覆盖入口、上下文、全局约束、14 个块与15条边；块内列出全部实际指令、操作数、定义引用、三级约束和 metadata。c03 的指令数为 27，c05 为 29，其余为 28。这里“核对有效”表示结果结构、覆盖和引用有效，**不等于核对器判断已被证明正确**。

一次源文提取生成 10 条候选要求，供五份输入共用。本助手逐项检查认为，它们覆盖了已冻结的四组要求：`req_2–4` 对应来源、门控与重试；`req_3、5–8` 对应回退、参数、返回绑定与停止；`req_9` 对应全流程禁传；`req_10` 对应每个终态返回前追加。`req_1` 是源 description 的总体说明，没有引入额外行为。

## 最关键的发现

### 1. 当前核对器能写出合理判断，却还不能稳定给出合格证据地址

8 份失败响应都是把操作级约束错放到块级，例如输出 `/blocks/block_011/constraints/1`，而实际位置在 `/blocks/block_011/instructions/0/constraints/1`。前者对应空数组中的不存在元素。校验器逐条解析 RFC6901 指针，没有用相近位置替换错误引用。

因此，五份源文→图响应均未成为正式有效核对结果，四个受控缺陷也**都不能在本轮计为合格证据支持的命中**。这不是“反例全漏检”：它们目前属于**无法正式评测的执行错误**，不能把四项记成四个漏报，更不能依据原始文字计算命中率。

失败响应仍然提供有价值的内容诊断：

| 反例 | 失败响应中的原始判断 | 本轮可作的解释 |
|---|---|---|
| c02 | `source_graph/finding_6、9、11` 指出 archive 输入包含 `result_002`，违反唯一参数及禁传要求 | 内容识别到了目标问题，整份证据记录不合格 |
| c03 | `source_graph/finding_10` 指出失败块只有 return；`narrative/unit_5` 区分了残留标题、声明与实际操作缺口 | 没有被标题“Append”直接补造步骤，但仍不能接受其完整结果 |
| c04 | `source_graph/finding_7` 指出应返回重试 `result_008`，实际返回首次 `result_004`；`narrative/unit_8` 也忠实保留了实际绑定 | 目标错绑被识别，不能人工修正引用后追认为本轮成功 |
| c05 | `source_graph/finding_11` 指出原文没有两秒等待依据，且等待发生在失败类型分支之前；`narrative/unit_5` 保留了操作、2 和秒单位 | 新增行为与位置被识别，完整结果依然无效 |

所有无效引用及展开后的原始文本见 [diagnostics/index.json](diagnostics/index.json) 和 `diagnostics/raw/`。这些文件只便于阅读，**没有修复、重新打分或送入下游模型**。

### 2. “图有错误”和“回述不忠实”仍会被核对器的标签混在一起

c02 两种回述、c03/c04 结构化回述中的 `internal_conflict`，理由实际都在说：回述准确保留了图中的声明—操作冲突或错误返回绑定。它们没有指出回述修改了图。c02 自然语言核对的 `finding_16 unknown` 则在讨论图里是否有诊断操作的证据，理由同时承认回译忠实表达了这个边界。

本报告保留这些原始标签，另将其归为**图内冲突的忠实呈现／图的执行证据未决**，不把它们自动算作 G→T 的回述错误。单凭“非 represented 数量”比较两种回述会得出错误结论。详细事后归层见 [method_review.json](method_review.json)。

### 3. 引用和指令 ID 覆盖，并不能替代关键动作含义覆盖

c01 的自然语言回译 `unit_5` 说 `ir_027` 以 `status.txt` 和 `failure` 为输入，却没有说出该指令的 opcode，也没有用中文明确表达“追加失败状态”。图中 `/blocks/block_014/instructions/0/opcode` 则明确记录 `append_final_status_to_status_file`。

相同的输入可以用于追加、覆盖或其他操作；ID 和指针仅提供定位，不能替代动作本身。`unit_6` 的全局“应追加”声明也不能补足实际指令的回述。原核对器在 `finding_5` 中仍判 `represented`。本助手将此记录为**疑似关键动作回述遗漏及核对器漏报，待用户按既定保真粒度复核**，没有改写原标签，也不据此报告统计漏报率。

### 4. 等价表达与未决边界的判断还不稳定

既定示范允许用 `success`／`failure` 表示最终状态，不要求把完整响应对象写入文件。但失败的源文→图响应中，c01 `finding_11`、c05 `finding_12` 把这两个字面量判为无依据新增；c02、c04 则将同一事项列为未决。这些属于**失败响应中的潜在误报／过度未决倾向**，不能进入有效误报率。

c04 的失败回译还把 `condition_text=null` 写成“边无条件”。当前契约只允许解释为没有记录条件文字，这是一处额外的过度解释。F01 图没有嵌入源码，但部分失败核对把普通源文依据标成 `embedded_content`，也暴露了依据类别的混淆。

两种回述都不能证明隐藏诊断输出不存在、文件写入一定成功或开放操作实现正确。自然语言结果仍偏逐块说明；本轮也没有独立评价它的可读性优势。

## 工程验收

- 示范规范、冻结来源 manifest、外置 oracle、两个人工规格示例、四个反例构造器和独立 `backtrace` 模块已交付。五图均通过现有结构完整性校验，原图未重写。
- `prepare`、`run`、`replay` 可用；客户端显式注入，模型角色上下文独立，source／graph／retelling／oracle 输入边界有测试约束。外置预期只进入最终评测，不进入 Skill 输入或模型提示词。
- 专项离线测试 **103 项通过**；最终全包回归 **852 passed in 65.36s**。全包数量包含专项测试，不能相加。
- 对本次实测执行了真正的离线 CLI 重放，并拦截 HTTP 与客户端工厂；两者调用数均为 **0**。原始与重放的全部角色结果及评测结果相同，原始调用文件字节未变化。重放退出码为 1 是如实保留 `completed_with_errors`，不是再次联网或重放失败。
- 核对了 **446 个受保护的旧文件**，内容均未改变；原有 `dataset/skills` 仍有 30 个 ZIP，`result` 仍有原来的 91 个文件。生产 Prompt、IR 字段、提取 pipeline、公共入口、旧冻结语料和已有评审产物均未修改。
- 原始提示词、响应、实际模型名、用量、响应摘要和完整 SSE 记录已保存；当前凭据未出现在本轮任何产物中。官方返回的总用量为 **546,820 tokens**（提示词 151,425；生成 395,395），此处只转录提供方计数，不估算费用。
- 没有执行 Skill 内的代码或工具；没有生成 PDF，也没有重做原有 ZIP/PNG。

机器核对记录见 [verification.json](verification.json)，全部模型原始判定与定位见 [report.md](report.md) / [report.json](report.json)，离线重放见 [replay/report.json](replay/report.json)。

## 本轮结论与下一轮边界

本轮已经形成**可运行、可拒绝无效证据、可回放、可审查的闭环实验原型**；尚未形成可信的完整语义闭环保证。最先需要处理的是证据寻址和问题归属：让核对器引用现有位置清单中的证据，明确区分图内冲突与图→文本不一致，并将关键动作、参数身份、触发条件和限制的覆盖分开核验。这是本轮诊断，不是在原批次上偷偷追加提示词优化实验。

新增 Lean 证明仍留到下一轮。拟定输入域是通过结构校验且可无损表示为 JSON 的 CFG；开放 opcode、条件、约束和 metadata 先作为未解释值保留。拟证明入口、块内次序、类型化操作数、定义引用、带文字条件的边、三级约束和嵌入内容等显式事实在受控打印／解析中保持，并明确合法 ID 重命名和存储重排的对应关系。当前结构化输出尚不是已经证明的受控 AST 打印器；自由自然语言回译的正确性更未获得证明。
