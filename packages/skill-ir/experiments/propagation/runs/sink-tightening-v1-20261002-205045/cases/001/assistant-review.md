# 001／N01：本轮助手复核

这是助手对保存材料的只读复核，不是用户人工确认，也不是实际 Agent 执行验证。复核依据为本例完整 Skill、冻结 CFG、模型原始联合标注、编译材料与 `doe-input.json`；没有修改图、标注或业务结果，没有调用额外模型。

本轮标注与传播均为 `complete`，10／10 条 IR 形成记录，动态诊断为空。相较上一轮，主要问题已经改善：`notify.send` 保留为部署未说明的工具接收边界，不再无依据声明网络通信。以下核查未发现需要修复的实质关系问题；这不等于证明模型标注或所有真实执行方式正确。

## 边界分类的实际改善

| 源文动作 | 上轮 sink-boundaries-v1 | 本轮 sink-tightening-v1 | 复核意见 |

原始标注 `location_evidences.loc_notify_send` 明确引用 EM12：部署未说明的工具保留外部接收可能性，但不虚构 `net_send`。同一位置为 `access_scope=recipient、retention=null`；null 仅表示该接收边界保存期限未建模，不宣称服务端不保存。

本轮 6 个 sink 模板位置为：4 个 `model_observe`／2、1 个 `external_tool`／2、1 个 `storage_write`／1。等级只表示边界性质，不是敏感度、必要性或 DOE 结论。

## 模式与观察

原始获取、筛选、逐元素字段准备、计数及写入段均采用 `default`，没有将“可以由本地程序实现”误当成源文已经规定的本地隔离。4 个观察位置由程序编译生成；原始响应并未重复手写最终观察列表。

部分 operator 理由仍使用“本地 agent 运行时”措辞，但没有据此采用 `local`、清除整体观察或降低接收边界。这属于说明措辞，当前没有改变范围、版本、参数或边界，因此不列作实质修复项。

禁止发送 access_token 的声明没有被改造成虚构的清洗步骤。工具交付仅为两份显式字段原值；此前可能发生的整体模型观察继续保留。这里不能据此直接宣布禁止约束已在真实运行中得到保证，也不能将契约下的可能观察写成已经发生的数据暴露。
