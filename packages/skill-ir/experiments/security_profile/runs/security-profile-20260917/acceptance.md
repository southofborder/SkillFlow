# Security Profile 首轮实施与验收报告

独立标注模块、严格校验、记录、恢复、离线重放及固定 30 图调度已实现。本轮按计划尝试了 30 次逻辑标注调用，**获得 9 例可接受的标注记录，另外 21 例没有可接受的整图标注**。工程测试通过不代表模型标注正确；本轮也没有完成 30 份均可用的标注集。

入口：[逐例助手复核](assistant-review.md) · [批次状态与标签分布](report.md) · [机器可读结果](experiment-result.json) · [工程核验结果](engineering-checks.json) · [实现及回归细节](implementation-notes.md) · [离线重放报告](replay/report.md)。

## 工程结果

- `skill_ir.security_profile` 提供可注入客户端的 `annotate_skill` 与独立 `prepare / run / replay` 入口。每图一次整图标注；没有受控回述、要求提取或逐节点补问。
- profile 严格只有 `actor / roles / effects / evidences`；操作 ID 在外层，未决项另存。固定词表、覆盖、证据位置与引文错误明确拒收。
- 30 个输入全部通过离线准备和来源核验：29 个第 1 轮，F03 第 3 轮；617 条真实 IR、76 份完整可读文件。六份 PNG 明确记为二进制边界，未执行脚本或工具。
- 111 项新增模块聚焦回归通过；全量相关回归 **1095 项通过**。既有 Lean 工程 18 个构建任务及 16 个主定理公理审计通过；本轮没有新建标注语义正确性的证明。
- 显式禁用网络连接与在线客户端后，全 30 例离线重放恢复相同标注、未决、失败状态和计数；原始调用记录字节未改变。
- 开工前记录的 **2142 个受保护文件全部保持原摘要**，覆盖生产提取 Prompt、pipeline、IR、冻结源包、标注、旧实验及既有 ZIP/PNG/评审产物。新产物中未发现实际 API 凭据。

共用能力提炼限于源包快照、源文索引、严格 JSON/引文检查；沿用既有 SSE、脱敏、互斥锁与持久化调用记录。没有改动生产提取语义或结构规则。

9 例合法记录共 **170 条 profile、7 项模型未决**。这 7 项不包含助手后来发现的证据不足；助手意见外置保存，没有偷偷改入模型的 `unresolved`。

计划和实际均为 **30 次逻辑调用**；底层共 **62 次传输尝试**，其中 32 次是原配置允许、发生在响应接受之前的传输重试。没有新一轮语义调用、提示词修复、选优补跑或已接受响应重发。

请求模型为 `deepseek-v4-flash`。获得模型元数据的响应实际返回 `deepseek-flash`，逐例调用记录同时保留请求配置与实际名称。没有收到响应的 DNS 失败案例不虚构返回模型或用量。

### 执行失败及拒收原因

- **13 例 DNS 失败**：007–019；配置内传输尝试结束后仍未获得模型响应。
- **5 例流不完整**：004、005、006、021、027；保留接收记录，没有在 HTTP 200 后自动重新请求。
- **1 例本地记录写入失败**：002 的 `transport.json` 在 Windows 原子替换时被拒绝访问。监控并发读取活跃记录可能参与了该问题，尚未证明唯一成因。其后停止读取仍在写入的流文件。此项是记录设施问题，不是远端语义判断错误。
- **2 例完整响应引文定位错误**：028 引文与 `src_062` 不匹配；029 与 `src_047` 不匹配。响应原文仍保存，校验器没有修引文、换位置或接受部分 profile。详细错配与未接受候选的诊断见各例助手复核。

## 方法观察与后续边界

逐例助手复核与模型原始结果分开保存，不冒充用户确认，不计算标注正确率。对执行失败案例完成的是输入和失败记录核查，不能声称已经评价了不存在的安全标注。

已可明确观察到以下问题：

1. **执行者归属的证据不足会影响模型观察效果。** 相近文件读取/字段提取动作被分别确定归为运行时、工具或 LLM，导致 `model_observe` 有无变化，而源图未明确给出这种执行机制差异。固定执行模型仍需要更清楚的动作映射，或者模型应保留未决。
2. **多角色未始终落实。** 003 的 `ir_001`，以及 020 的 `ir_001 / ir_003 / ir_005`，已经记录内容进入模型上下文，却未同时标记当前定义下的 `sink` 可见边界角色。引文存在不能检查出这种分类不一致。
3. **不能从动作名字推出边界。** 通知动作的 `net_send`、只由 `delivery_path` 推断本地 `fs_write`，以及将“LLM 可参与调度”改成确定 `actor=llm`，均有证据不足的实例。
4. **合法未决有价值。** 025 的四种安装、026 的通用交互/CLI 命令、030 的 SDK 安装条件未完全指定，模型把相关效果记录为未决，保留已知标签；这比臆造确定网络或文件效果更符合本轮契约。
5. **模型观察的内容边界需要保留。** 030 的脚本默认打印 `Wrote <路径>`，正文输出需要 `--stdout`。当前理由却把工具返回直接描述成模型看到转录正文；`model_observe` 标签可以描述输出路径可见，但不足以推出文件正文已进入上下文。此项保留为证据不足，未执行传播来补出数据集合。

复核也保留了有据的标注：脚本文字支持的文件读写与变换、多主体及多角色、明确网络调用的双向效果、只讨论 stdout 返回路径的模型观察，以及没有把禁止声明自动当成过滤/遮蔽操作。具体正面与负面证据均见逐例报告，不能由少量案例推断泛化表现。

本轮交付是动作安全语义标注工程及首次真实运行记录。**没有展开容器内容，没有执行二次传播，没有计算敏感数据集合、风险、必要性或 DOE。** 在下一阶段把标签当成确定输入前，应先处理现有证据不足与执行模型映射边界；网络失败案例若需重新实验，应使用新的运行身份，保留本轮失败记录。
