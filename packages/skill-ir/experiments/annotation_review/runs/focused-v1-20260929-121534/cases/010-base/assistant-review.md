# 010 原标注：助手复核

审查器提出 `f_ir012_return_forwarding_claim_unsupported`，原始状态为 issue。助手判断是**部分成立，但把它定为实质交付遗漏，结论过强**。模型结论保留原样，本意见单独保存。

成立的部分：profile 的说明声称“其未变更的值转发关系在 transfer_specs 中按输入操作数保留”，而该 return 的 events 和 output_bindings 均为空。理由确实说错了信息的承载位置。

不能直接成立的部分：当前 return 没有公开 outputs，输出绑定必须恰好覆盖真实 outputs；普通调用方也不是当前安全效果和 deliver 已定义的边界。无标签事件不能用于任意交付。补一个虚构输出、user_output 或网络效果，会引入源文没有支持的语义。

返回值身份仍在 CFG 中：ir_012 的实际输入为 result_009 / response_items，并有原值返回约束；上游 select_part 保留 response.items，DOE 文件包含完整 CFG 和入口状态。因此不能说返回关系已从全部材料中消失。当前只是不单独把通用调用方返回表示成一个传播交付事件。

若后续修正说明，可写成“返回值及其原值关系由 CFG 的 return 输入和约束保留”。本轮不做该修改，也不接受直接补事件／绑定的建议。此发现不计为已经确认的实质数据关系缺陷。

其他核对：工具 receive 保留新获取来源；请求值与参数存在标志分开；编译观察使用返回响应；total/items 保留字段关系。可选参数的条件精度是当前 may 表示边界，不能据候选值同时列出就断言它们每次都被发送。

方法限制：审查器可能没有充分掌握“哪些事实由 CFG 承载、哪些需要传递规格展开”。这是后续应补充的协议解释；本轮没有修改 Prompt 或补跑。
