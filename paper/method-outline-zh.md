# SkillFlow 方法章节提纲(§2–§7)

> 每节只说两件事:卡在哪、怎么破。

## 2 问题定义与威胁模型

只拦"数据流出去",简历润色、医疗咨询这种靠喂模型吃饭的 skill 全得死;只拦"任务不必需",一堆无害计数全成误报。真正该拦的夹在中间。

所以把问题拆两轴——**暴露**(越过什么边界、发给谁、留不留)和**必要性**(任务到底要不要这次外发),判据是二者合取 $E(f)\wedge(\mathrm{nec}(f)<\theta)$。不假设 skill 恶意、不假设提示注入,只管它"忠实干活却发多了"。两个对角例子各打死一种单轴做法。结尾埋雷:多条合规流汇一处会凑出新暴露,单条看不见(留给 §7)。

## 3 系统总览

判据要落地,得先说清必要性这个虚概念怎么算。

三阶段、纯静态、不跑 skill——不执行才审得了整个市场,这是全篇一切取舍的根。必要性靠一个反问撑起来:**这条流删了,任务还成不成**(→ $N_3$);就算这次外发确实要,也不等于该带这条数据、发这个接收方,于是再裂出 $N_1$(数据真进了这次动作没)、$N_2$(发给这种接收方对不对路),三者取最小。全篇守一条:**够用就好,状态最小**——算判定要的结构一处不漏,不影响裁决的差异一份不留。

## 4 技能流图 SFG

图该留什么、扔什么才是关键。四节共守一句:**"扔"这个方向必须准**,多留最多多审一次,错扔就是悄悄漏掉一处暴露。

**4.1 块分类提取.** 逐行扫关键词在自然语言 skill 上翻四种车:代码块被整段跳过、否定句被读反成外发、脚本调用炸到几百个节点、CHANGELOG 之类也被当动作源。病根都是一个——扫之前没分类型。改成先分类再派活(文件类型→块类型→各走各的策略);代码块和随包脚本共用一个 shell 命令分类器,同一条 `curl` 到哪都判一样;顺带修了元数据被拼进动作文本造假 sink 的坑,某 skill 从 800 个节点回到 580。

**4.2 语义门.** 规则给不出最终语义,而且规则判错的两个方向代价不对等——错扔是永久漏掉。所以规则宽进保召回、精度交给 LLM 收口,规则只在"扔"这方向卡严。表格最容易犯规,不去把规则做聪明(表格花样无穷),而是"长得像定义、动作列却带动作味"的行交给 LLM 定;角色只由节点自己定,边上的话只读数据、不参与定角色。

**4.3 连边.** 既别漏真数据依赖,又别把纯先后当数据流。召回(类型相容就连)和精度(把只表先后的边降级)两股劲对着来。否定句走一条分层链:粗筛留疑,LLM 分免责/约束,约束再分卫语型和次序型。关键一处返工:约束两端点的匹配挪到所有节点合并之后再做,分三级(词干匹配→LLM 兜底→占位)。

**4.4 节点单跨界.** 一个节点又发又存,越界点就对不上 sink。强制每节点最多跨一次界,超了就确定性拆开,让越界点和 sink 严格一对一;拆在连边之后做,子节点直接接管父边、不用重连。

## 5 标签流传播、环与判定单元

**5.1 传播.** 敏感标签从源头撒下,沿真正传数据的边跑,越一次界就在汇点落一个可裁决的观测。收敛不靠人为设上限,靠状态去重——状态空间有限,迭代必然停。这是后面敢拆掉所有"规模墙"的底气。

**5.2 到节点即合并.** 两条流何时算"一样"该并起来?这决定收敛、粒度和下游要不要重算。定死一条:**去重键的粗细正好等于下游裁决的粗细**——并了不影响裁决才准并,裁决一样却不并纯属浪费。据此状态取一个八元组。

**5.3 反馈环.** 自优化 skill 的核心恰恰是环(写回自身、下轮再读、每绕一圈再发一次),别人图省事一剪了之,连这层暴露一起丢了。我们不剪:回边只标不删,再判、再受控展开。真假环判不准(纯读写闭环也是真自优化),改问一个能答的——**这条回边作为反馈通路合不合理**(规则宽进、LLM 收口)。合理的环带进去只绕一圈;带什么出来看环里干了啥,细化取类别、聚合啥都不带,而且方向只能认语义类别、不能认派生标记(认错会凭空灌进上千条流)。"人在环里"是出环就清零的临时状态、不是一路带下去的血缘,所以只线性放大、不指数爆炸。

**5.4 产物.** 产出的不是一堆路径,是"标签×汇点"的观测集,每条流只背判定要用的那点东西,内存跟真实变换数走、不跟路径长度走。最重的 skill 会撞上三种成本(背路径、键太细、汇点平方级合并),都按同一准则摊平;纯线性的慢就让它慢,绝不动那把跟裁决对齐的去重键。观测集里如实记下"多条流汇到一处"这件事,交给 §7。

## 6 不必要暴露判定 UNEX

**6.1 两条正交轴.** 暴露和必要性极易混。最典型的错:把"喂 LLM 通常是任务要的"(必要性的结论)记成"喂 LLM 不算外泄"(暴露轴),于是对一整类真外泄睁眼瞎。改法:两轴分开算再合取,喂模型服务商照样满额算暴露,跟第三方网络、落盘、webhook 一个档,谁都不降格。必要性由 $N_1,N_2,N_3$ 取最小(取最小,任一轴的"不必要"就压不住),最终 $E(f)\wedge(\mathrm{nec}(f)<0.7)$。

**6.2 必要性结构化.** 这是最难一环。词袋数关键词,量的是文风不是结构,啰嗦的 skill 白刷分。探针一测:$N_1$ 一家独大(74% 的流整体值就等于它),而词袋给它垫了个假地板。所以三个分量全从"数词"改成"看结构":$N_1$ 看数据真被变换、是否落在声明的输入里,$N_2$ 用一张"接收方×数据类目"相容表(敏感类目在任何外发口都不许放行),$N_3$ 看声明里提没提这次外发。验收:517 条被单向清掉、0 条新判过度,没有一条 high/critical 被规则层擅自清除。

**6.3 工程原则.** 判错时最想走的捷径是给门加特例,但那把判别逻辑塞进分支、随语料膨胀、还把两轴又搅一起。原则:要修就修打分和阈值,让对错自然分开。探针为证——两簇分数落在 0.75–0.80 和 ≤0.65、中间干净一条缝,0.7 正好卡缝里,没有边界个案要救。

**6.4 证据包与送审减量.** LLM 判得准不准全看喂什么。平铺的证据条逼它自己把因果链重拼,费 token 又易错。改成以流为中心的三层结构(标签→越界边界→从源到汇的节点串),每个节点挂几个从图里直接读出的事实。再做两道减量:同一个判定单元只送置信度最高的代表(省约 75%,因为单元本就是裁决粒度,复用等价)、把溯源截到源头、纯先后边降级标注。两道都只省 token、不动判定单元集合。

## 7 从单流到联盟:跨路径聚合暴露

有一类暴露单条流上永远看不见:多条各自必要、各自合规的敏感流汇到同一个外发口,合起来的危害超过任一条(超可加)。这正是逐条判定天生的盲区。

**7.1 抬升判定单元.** 不用新传播,直接复用 §5.4 记下的"哪几条流汇到同一汇点",把判定单元从单条流抬成同汇点的流集合,只对集合的类目做纯结构判定。超可加由类目组合定死,所以这层纯静态、免 LLM,比单流复核还轻,却抓得住单流抓不到的东西。

**7.2 一次被数据推翻的转向.** 原型本来照搬 Sweeney 的人口学准标识符(生日+性别+邮编再识别 87% 美国人),可全语料一扫零命中。这不是 bug,是问题域本身——skill 经手的是凭证、数据库句柄、文件、密钥这类运营技术秘密,不是人口普查数据。于是判据从"人口学 QI"放宽成四类危害原型,Sweeney 退成理论动机,**能力聚合型**接棒当主角。

**7.3 主导威胁与竞品盲区.** 全语料扫出约 2152 处越界联盟,压倒性是能力聚合型(`{数据库,文件}` 这类)。这类联盟每条成员单看都必要、合一处就不必要(任务几乎从不需要三种能力挤到同一个外发口)。竞品的判据只在单个成员上取"存在"($\exists f:\mathrm{OverExp}(f)$),而每条成员消融都改输出、都被判必要,于是集合永远标不出来,可集合层的风险偏偏为真。盲区是**判据落在成员、风险却住在集合**,层级错位,照公式逐字可证。SkillFlow 把判定单元抬到集合层就补上了,而且纯结构、免执行,没牺牲可规模化。
