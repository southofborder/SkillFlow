## 2 问题定义与威胁模型

一个审计器该拦什么?如果盯的是"敏感数据有没有流出去",那简历润色、医疗咨询这类 skill 根本无法存在,它们声称的功能就是把用户数据喂给模型。如果盯的是"这次外发是不是任务必需的",那一切冗余的遥测、无害的计数都会触发误报。真正要拦的东西卡在这两个极端之间,它既是真实的跨边界暴露,又在任务上不必要。

我们不假设 skill 全局恶意,也不假设存在提示注入。我们刻画的是一类更隐蔽、更普遍的架构性风险,skill 在忠实执行其声称任务的同时,把敏感数据越过信任边界外发,而这一外发超出了任务本身的真实需要。攻击面是数据可达性与必要性的结构,而非某次具体执行的输入。因此有用的问题不是"数据有没有流出去",而是"这次流出该不该发生"。

要把"该不该发生"变成可计算的判定,先要看清它其实在问两件互不蕴含的事。一件是暴露(exposure),这次外发有多严重,数据越过的是什么信任边界、接收方多陌生、是否被留存。另一件是必要性(necessity),完成 skill 声称的任务到底需不需要这次外发。两轴正交,高敏未必不必要,不必要未必高敏。于是判据只能写成两轴的合取,

$$\text{OverExp}(f) \equiv E(f) \land (\text{nec}(f) < \theta)$$

其中 $E(f)$ 刻画流 $f$ 的暴露程度(边界 + 敏感度 + 接收方),$\text{nec}(f)$ 刻画其必要性,$\theta$ 为必要性阈值。只看一轴的审计器必在另一轴的极端上系统性失败。

两个分处对角的例子可印证这一点。例 A(高敏 × 高必),一个"简历润色"skill 把用户的完整简历发给模型服务商改写措辞。暴露轴满额,高敏个人信息越过信任边界;但必要性轴也满额,skill 声称的功能就是让模型加工这份简历,抽掉这条流它无法完成任务。合取判据下,这不是过度暴露。只看敏感度的审计器会在此假阳,而这一类"把用户数据喂给模型"的外发恰是真实生态里最普遍的一类。例 B(低敏 × 低必),另一个 skill 在完成主任务后,向分析端点发一条不含任何用户数据的"被调用一次"计数。必要性轴为低,抽掉它任务照常完成;但暴露轴也为低,它不承载任何敏感类目,构不成真外泄。合取判据下,这同样不是过度暴露。只看必要性的审计器会在此假阳。

两例各自击穿一种单轴方法,例 A 说明高敏不蕴含过度,例 B 说明不必要不蕴含过度;唯一触发标记的是"高敏 ∧ 不必要"这一象限。而这一象限里最隐蔽、也最考验方法的一种情形,是多条各自看似必要的敏感流汇聚到同一汇点、在集合意义上构成新的暴露,逐条合规,汇聚才泄露。这类跨路径聚合暴露是逐单元判定方法的结构盲区,§7 会展开如何检测它。

## 3 系统总览

SkillFlow 针对 §2 立下的判据,过度暴露是暴露与必要性的合取,设计了一条纯静态、免执行的三阶段流水线。输入是一个 agent skill 的分发包,输出是该 skill 内每条跨信任边界流的过度暴露判定。

第一阶段从 skill marketplace 拉取分发包。一个包由三部分组成,元数据(声称的功能、参数 schema)、自然语言指令文件(`SKILL.md` 等)、以及随包脚本与资源。第二阶段从这个包静态构建一张技能流图(Skill Flow Graph, SFG),节点是可被识别的动作步骤,边是数据依赖或控制依赖,图上叠加安全档案,每个节点的角色、每条边承载的数据、以及每处越过信任边界的观测点。第三阶段在每个信任边界的汇点(sink)上,沿暴露与必要性两轴判定其上的数据流是否构成"真外泄 ∧ 不必要"的过度暴露。

整条流水线不运行 skill、不起沙箱、不重放执行。这与已有工作形成根本对照,一类工作在运行时执行 agent 以采集污点轨迹,一类工作对每个候选动作、每个任务各跑两遍做消融对比,还有一类依赖动态沙箱观测。运行时方法的采样成本与 marketplace 的规模成反比,要么只能抽样审计,要么只能覆盖能被成功触发的执行路径。免执行是我们能够在全量、边界完备的意义上审计整个生态的根因,也是全文一切设计取舍的出发点。

先前我们将过度暴露定为两轴的合取,其中暴露轴相对直接(边界 + 敏感度 + 接收方),难在必要性轴。"任务需不需要这次外发"是个含混直觉,直接当标量既无法计算、也无从辩护。但只要顺着这句往下追问,它会自己裂成几个能分别求证的问题,每一个又恰好落在一条成熟的数据治理原则上,必要性于是不再是硬凑的标量,而是这几问的合取,任一问答否,这次外发就不必要。

最直接的追问是个反事实,把这条流从 skill 里删掉,它声称的任务还完不完得成?若照删无损、任务照旧,这次外发对任务本身就是多余的。这正是目的限制原则(GDPR Art 5(1)(b))在数据流上的落点,也接续移动安全里"声称行为 vs 实际行为"一线的做法(WHYPER, Pandita 等, 2013; CHABADA, Gorla 等, 2014),将应用声明与实际数据流比对以发现越权。静态审计无从真删了重跑,但 skill 的元数据与指令文档就是它对自身任务的声明,反事实于是有了可算的替身,声明要做的事里,提到要外发这条数据吗?落在声明之外的外发,任务上便存疑。这是任务必要性 $N_3$。

但"整条流多余"只是不必要的一种情形。哪怕这次外发确属任务所需,也不等于它就该带上这条数据、发往这个接收方,于是反事实再裂一层,追问的不再是"要不要这次外发",而是"这次外发是否非得外发这条数据"。这一层又分两问。

一问数据是否真进了这次动作。数据最小化与最小权限落到数据流上(GDPR Art 5(1)(c); Saltzer & Schroeder, 1975),就是一次外发唯有在其数据确为完成动作所需时才谈得上必要。一条只是途经某节点、被顺带扫出去的数据,与一条真被动作消费、变换后才外发的数据,必要性天差地别。这是动作输入必要性 $N_1$。

另一问是发给这种接收方在语义上相容吗。Nissenbaum 情境完整性(contextual integrity, 2004; 2010)讲的是,信息流正当与否取决于它相对情境规范是否恰当,而情境由发送方、接收方、数据主体、信息类型与传输原则共同刻画。同一份数据回给用户本人、留在 skill 内部、还是发往外部模型服务商,正当性判然不同。这是接收方语义必要性 $N_2$。

三问各答必要性的一个侧面,且互不蕴含,一条流可以真被动作消费($N_1$ 成立)、却把敏感数据发给语义不相容的接收方($N_2$ 不成立)。故三者是合取而非加权和,任一条低,必要性即低,$\text{nec}(f) = \min\{N_1(f), N_2(f), N_3(f)\}$。形式定义留待 §6;此处只需确立,必要性判定要回答的,恰是这三个从"任务需不需要外发这条数据"一路裂解出来、又能各自在数据流结构上求证的问题。

判据既已定为暴露与必要性(后者是三条原则的合取)的合取,后续三个阶段,构建 SFG(§4)、在图上传播标签(§5)、在汇点上判定(§6),就都不是独立的工程选择,而共同服从同一条准则,在保证能算出这一判定所需的全部证据的前提下,让图及其上传播的状态规模尽可能小。这就使得图首先必须保留足以正确求证上述三分量(连同暴露轴的边界证据)的每一处结构;漏掉一处,某条流的必要性就会被误判,而在本任务里一次必要性误判直接等于漏报或误报一次暴露。但同时,在满足充分性的前提下,凡不改变任何信任边界上暴露/必要性裁决的结构差异,都不该在图上多占一份状态。这条"充分且最小"准则是理解后三节每一处设计取舍的总纲,§4 决定图保留什么、舍弃什么,§5 决定传播时哪些流该合并、哪些必须分开,§6 决定把哪些结构事实作为硬证据喂给判定;它们各自的取舍标尺,最终都归到"是否改变某个信任边界上的暴露/必要性裁决"这一句上。

## 4 技能流图 SFG(The Skill Flow Graph)

SFG 是一张有向图,节点是 skill 内可被识别的动作步骤,边是数据依赖或控制依赖,图上叠加安全档案。真正要紧的问题不是怎样把 skill 画成图,而是这张图该保留什么、又该舍弃什么。§3 的构图准则给了答案,图不必忠实复现 skill 的全部文本,只须为必要性三分量连同暴露轴的边界证据,各自供上所需的结构事实。这就是"证据充分,状态最小"在提取层的形态,凡三分量要据以求证的结构,一处都不能漏,漏一处就是漏报或误报一次暴露。

本章展开四节,块分类提取(§4.1)把动作、schema 与数据类目从原始分发包里可靠取出,语义门(§4.2)为每个候选定性其可执行性、操作类别与接收方角色,连边(§4.3)把真正的数据依赖连通,节点单跨界性(§4.4)把每处越界归一到无歧义的汇点边界上。四节反复出现的一条子准则是规则在"丢弃"方向必须高精度,这是充分性下界的直接推论,误留一个候选至多多送一次审,误丢一个候选却是静默的召回损失。

### 4.1 块分类提取

最初的提取器对 `SKILL.md` 逐行跑关键词匹配来推断操作类型。在对生态中最热门的一批 skill 做人工复核时,这种一刀切的扫描暴露出四类系统性缺陷,它们表面无关,根因却相同。代码块被整体丢弃,提取器遇到 Markdown 围栏就跳过全部代码行,于是一个天气 skill 里真实的网络外发命令(`curl "wttr.in/..."`、`curl "api.open-meteo.com/..."`)被当成文本注释,产生零个 sink,真正的数据暴露面完全没进图。否定语义被误判,纯正向关键词匹配不处理否定,某 skill 免责声明区("What this skill does NOT do:")下的"Does not send any personal data"被反转成一次外发动作,凭空造出一个第三方外泄。脚本调用爆炸,对每个函数调用节点都建图,一个带 JS/TS 钩子脚本的自改进 skill 因此炸到数百个节点,连 `Array.isArray`、`.push` 这类语言内建都成了工具调用节点,淹没了真正安全相关的调用。非指令文档被误提取,CHANGELOG、license 等文档被当作动作源,且每份文档各造一个 `llm.inference` 节点,而这类节点本应全 skill 共用一个。

四类缺陷共享同一个根因,分析前没有对文本做类型分类。修复因此是把架构从逐行扫描改为先分类、再派发,每个文件先判文件类型(脚本、指令文档、非指令文档),指令文档内再判内容块类型(代码块、表格、列点、散文、免责声明),不同块类型派发不同的提取策略。

在这套架构下,四类缺陷各有确定性的解法。代码块不再被跳过,围栏检测捕获语言标记,shell 类围栏对每行命令建 `doc_step` 节点。关键设计是引入一个确定性 shell 命令分类器,由文档代码块路径与随包脚本的 shell 路径共用,两条路径若各写一套分类逻辑必然漂移,共用一套则保证同一条 `curl` 无论出现在文档还是脚本里都得到一致的角色判定。分类器按命令白名单(外发/执行/读/写)加 URL、主机、重定向、文件路径的正则,把命令行切成带操作类型与目标的片段,噪声行(`echo`、赋值等)返回空。否定语义单独成一条识别链(§4.3 详述其升级为约束边)。脚本调用改为按角色分类(sink/source/sanitizer/noise),丢弃语言内建,但未知的用户自定义函数一律保留,不猜测其为噪声,因为函数名本身即语义(如 `redactEmailAndSendWebhook`)。非指令文档则用正则挡在动作提取之外。这套改造把命令型 skill 的真实 sink 找了回来,同时把脚本型 skill 收缩到与安全相关的调用上。

一个更隐蔽的提取污染问题在拆分不变量(§4.4)落地后浮现,节点画像器在扫描"动作文本"时,误把节点自身的元数据,名字、语义门判定的 JSON、动作证据的 JSON,一并拼进被扫描文本。无成员步骤的路由类节点(如条件节点)于是按固定字符窗口切进 JSON 内部,产出 JSON 片段步骤,进而污染子节点的指令文本;同时门判定 JSON 里残留的 `model`、`send`、`post` 等词被裸关键词过匹配,把纯路由/纯读取节点误标成 sink,凭空分裂出大量假的 sink 子节点。这类"越界暴露"完全是提取假象。解法是分离动作文本源,动作步骤扫描只取指令文本、证据文本、源码行与描述,排除元数据 JSON 与文档 slug 名;同时收紧外发正则,传输类 token(`webhook`、`https`、`upload`、`email.send`)可裸配,而 `send`、`post`、`publish`、`share` 这类多义词必须带外发宾语才算,删去裸 `external`/`api`。修复后,一个自改进 skill 的节点数从被污染时的约 800 回落到干净基线的约 580,假 sink 被清除,只剩真实的 `curl` 外发和 llm 交互。

### 4.2 LLM 语义门

规则提取只负责产出候选动作节点;每个候选的最终语义,它是否真的可执行、属于哪个操作类别、是何种操作类型,交由一个 LLM 语义门判定,结果写入节点的 `semantic_gate` 字段。规则层刻意宽进、优先召回,把精度留给语义门收口。语义门同时承接规则无法解析的困难句式,缺主语的被动片段、指代前文名词的省略句、须结合上下文才能定性的复杂措辞,这些句子的语法结构规则无从拆解,由 LLM 补全隐含主语、再判定它是在描述还是在指令。语义门用真实 gpt-5.5,并做内容寻址缓存,同一候选重跑命中缓存、零重复开销。

这套分工的成本论证不能简单写成"规则高精度、LLM 只兜边角"。规则门的判定是二相性的,一条线要么被判为纯上下文(直接沉淀成定义节点、不进 LLM),要么被放行为候选(进 LLM 送审)。两个方向的错误代价并不对称。误留(本是定义却被放行)会到达 LLM 被判回定义,代价只是多一次送审;误丢(本可执行却被判成上下文)则在放行前就被短路,永远到不了 LLM,是一次静默的召回损失。因此真正的设计约束不是"规则整体要精确",而是规则在"丢弃"方向必须高精度,凡不能高置信度判为纯上下文的线,都应放行给语义门,而非就地丢弃。

表格是这条约束最容易被违反、也是我们据此加固的一处。规范形态的表格——两列术语表(`状态|含义`)、`SKILL.md` 里 Situation→Action 的路由表——规则确实能分别高精度地判为定义(丢弃)与动作(保留)。但"定义表"的识别退化为一组脆弱信号:表头命中固定词表,或"两列且首格短"。一旦某行的动作列其实携带可执行语义,却因动词不在句首、或用被动语态、或用了词表外的同义动词而绕过那个句首关键词的逃生阀,这一行就会被静默判成定义丢掉,一条真实 sink 就此蒸发。加固的方向不是把表格规则做得更聪明(表格形态无界,规则追不完),而是让它服从上面的非对称约束:"看着像定义、动作列却带动作信号"的行交语义门裁定,不由规则终判。这条保守化路径以开关门控、默认关闭——关闭时保留可复现、无 LLM 依赖的纯规则基线,打开时启用 LLM 兜底;两种模式之差,正好度量"规则丢弃有多激进"对召回的影响。

语义门的判定被严格限定在"节点自身该扮演什么角色"上。我们曾踩过一个反例:边上的散文理由(`semantic_reason`)被误用来反推节点的角色,导致一个 `user.query` 节点被边上的措辞污染成 sink。教训是角色必须由节点自身的角色集合(node roles)决定,边文本只读其数据流,不参与节点定性。

### 4.3 连边

节点连成图靠两股方向相反的力协同。一股是召回,类型分析器穷举节点两两之间的候选边,凡输出类型与输入类型相容就连上,宁滥勿缺,先保证真实数据依赖不被漏掉。另一股是精度,一个路由层读取边上的条件与卫语语义,把只表达执行先后、不传播数据的边降级为纯顺序边,把真正携带数据的边与仅约束次序的边区分开。下游判定只在活跃传播边上流动标签,顺序边不参与标签泛洪。

否定句的处理是这两股力协同的一个典型闭环,也是我们从"误报"走到"提纯语义"的完整链路。前述的否定误判修复,最初只是把所有否定句判为免责声明并丢弃;但人工复核发现这样又矫枉过正,一批否定句其实是安全约束而非免责,例如"Never install without vetting"(未审查前绝不安装)约束了 `vet` 必须先于 `install`,把它当免责丢掉等于吞掉了 skill 自带的安全语义。我们据此把否定句处理升级为一条分层链路。规则层先粗筛,命中否定但既非强免责(显式的"does NOT do:"列表)、又非"Limitations"标题下软否定的句子,被标为"待定否定",继续走动作提取进入语义门,而强免责与限制段下的软否定仍直接丢弃。进入语义门的待定否定,在同一批 LLM 调用里(不新增调用)多判两件事,该否定是免责还是约束,以及若为约束,其二元结构是什么(卫语型 guard,还是次序型 ordering,连同 before/after/被约束动作)。判定结果决定分派,免责的按上下文丢弃,卫语型约束落到节点的形式语义条件上、不建边,次序型约束则暂存待连。

链路上我们二次修正的关键在约束端点消解。约束的两个端点(如 `vet` 与 `install`)可能分别是文档节点、工具调用节点或脚本节点;最初端点匹配在文档提取内部进行,匹配池里只有文档一支节点,看不到工具/脚本端点就冗余合成假节点。修正是把端点消解移出到全局,在工具、脚本、文档、中介节点全部并入统一节点集之后才做匹配,并分三级消解,先用带轻量词干化的 token 重叠规则匹配(`vetting`→`vet`),规则不中再交 LLM 批量兜底(给出未解析短语与全局候选清单,逐短语返回节点或 null),LLM 也判 null 才合成占位节点。约束句自身(禁令的主语)被排除出匹配池。

这条链路产出的约束边被标记保护,不会在去环阶段(§5.3)被误删。整个升级零新增边属性,下游路由已能把这些 `state→state` 边识别为顺序型。

### 4.4 节点单跨界性

我们对图强制一条原则,每个节点最多跨越一次数据信任边界。一个节点若其动作序列里既有外发又有本地持久化,就把它确定性地拆成若干子节点,每个子节点恰好在一处边界结束。这条不变量带来一个关键性质,即边界观测点与 sink 节点严格 1:1,每处越界都对应唯一一个 sink 节点,使下游证据包可以把汇点边界作为一个顶层的、无歧义的结构块来组织。

这里有一个关键的工程收益,拆分安排在边连接完成之后进行。因为子节点直接继承父节点已连好的边,而不必对拆出的新节点重跑两两类型相容配对。拆分入边接到首子节点、出边接到末子节点,子节点之间用数据依赖边串联并标记为顺序拆分,下游据此仍把它们当作真实数据流而非纯顺序边。拆分是确定性的,动作序列本就以数据形式存在,拆分只是按"每段以一次跨界结尾"切段。一处需要小心的边界情形是合成的内建节点(如包装了某个工具名的 LLM 中介节点),它们的描述里会命名被包装的工具,若参与拆分会因描述里的词被误算出多次跨界,因此这类原子内建节点被显式排除在拆分与跨界校验之外。

## 5 标签流传播、环与判定单元

SFG 给出一张带安全档案的静态图;要在信任边界上判定暴露,还需知道哪些敏感数据、经哪条路径、汇到哪个越界汇点。这一信息由图上的一趟标签流传播得到,敏感标签自源头被播种,沿承载数据的边扩散,每越过一次信任边界即在该汇点沉淀一个可裁决的观测。本节先给出传播机制及其收敛性(§5.1),据此说明为何以"到节点即合并"为传播支点(§5.2);随后处理使朴素传播失效的一类结构,反馈环如何从被剪掉的噪声变成被表示的语义(§5.3);最后说明这一中间层究竟产出什么、如何以判定单元对齐下游,以及它在真实规模上为何仍然可行(§5.4)。

### 5.1 传播机制

传播的对象是数据标签,每个标签刻画一类敏感数据(类目、子类、敏感度、派生模式)。标签在具 `data_introduction` 角色的源节点上被播种,这些节点是数据进入 skill 的入口(用户输入、读取的文件、外部读取),其安全档案标注了引入的标签集合。播种即为每个源标签建立一条初始标签流,置入工作表待扩散。

扩散是一趟标准的工作表定点迭代,反复取出一条流,沿其所在节点的活跃传播边推进到后继节点,按该节点的操作语义对标签施加变换(脱敏、提取、聚合等),生成后继流放回工作表,直至工作表排空。传播因此是前向、数据驱动的,只跟随真实数据依赖,不理会纯表达执行先后的顺序边。

这趟迭代的收敛不依赖任何人为规模上限,而由状态去重保证,一条流每到达一节点,先被归约为一个传播状态,若图上已存在等价状态即被并入、不再扩散。记传播状态空间为 $\mathcal{S}$,它是各分量有限取值的笛卡尔积之子集,故 $|\mathcal{S}|<\infty$;工作表迭代对每个去重后的状态至多扩散一次,因此至多经 $|\mathcal{S}|$ 次去重即排空、抵达最小不动点。收敛由 $|\mathcal{S}|$ 有界这一结构事实保证,而非由人为截断保证。这是后文去除一切规模墙的前提,本地传播既必定收敛,就没有理由用墙钟或流数上限去截断一趟正确的分析。

### 5.2 到节点即合并

传播最关键的设计决策是,一条流到达某节点时,如何判断它与已有的流"相同"、从而应当合并? 这个判据同时决定三件事,传播能否收敛、图输出的粒度、下游是否需重建信息。

我们的准则是去重键的粒度必须恰好等于下游判定单元的粒度。记一条流为 $f$、UNEX 在其汇点上给出的裁决为 $V(f)$;传播时用去重键 $\kappa$ 决定合并,$\kappa(f_1)=\kappa(f_2)$ 的两条流被并为一。UNEX 的裁决单元是 $(\text{标签},\ \text{汇点},\ \text{所施变换},\ \text{来源类别})$,两条会得到相同裁决的流对下游无区别、应合并为一,两条会得到不同裁决的流则必须分开。整条准则可写成去重键与裁决在等价关系上的一致,
$$\kappa(f_1)=\kappa(f_2)\quad\Longleftrightarrow\quad V(f_1)=V(f_2).$$
其中 $\Rightarrow$ 方向是正确性(键相等则裁决必相等,合并才安全),$\Leftarrow$ 方向是无过度分区(裁决相等则键必相等,否则纯属多造状态)。据此传播状态取为一个八分量元组
$$s(f)=(\,n,\ \ell,\ \alpha,\ \sigma,\ \mu,\ \pi,\ o,\ R\,),$$
依次为所在节点 $n$、标签身份 $\ell$、可得性 $\alpha$、存储键 $\sigma$、流模式 $\mu$、执行阶段 $\pi$、来源类别 $o$,以及外发前所施的去标识化操作集合 $R$,而 $\kappa(f)=s(f)$。粒度分粗会把本应区别对待的裁决错误合并,分细则是纯过度分区,多造的流对裁决零贡献,只增传播规模。

这条准则也解释了为何"合并"是支点而非细节。朴素做法让每条到达的流各自独立扩散,状态数随路径数增长,在有环或高扇出的真实 skill 上退化为路径枚举。以判定单元为键的合并把这种增长收束回状态空间本身,凡不影响裁决的路径差异(经过哪些中转、以何序透传)都被折叠,只有影响裁决的差异才产生新状态。传播的收敛性正源于此。

### 5.3 反馈环,从被剪掉的噪声到被表示的语义

§5.1 的前向传播预设图为有向无环,真实 skill 却未必如此。一类自优化、反馈型 skill 的核心行为恰是环,它把一次运行的产物写回自身状态,下一轮再读出精炼。一个把"学到的经验"写进 `.learnings` 文件、下轮再读回的 skill,其 `write ⇄ read` 局部闭环承载的正是它对同一份数据的反复加工与沿途反复外发。既有 agent 数据流分析大多剪掉这类环,实现省事,却把这层语义连同它承载的暴露一并静默丢弃。环因此对我们既是挑战也是机会,能否表示它,直接决定了能否刻画那种每绕一轮就重新外发一次的周期性泄露,而这恰是剪环、逐单元的方法按构造看不见的一类。

我们于是不剪环,而是保留、判别并在传播中受控展开它。保留意味着制造环的回边不被删除、只被标记,图的其余分析照常在无环视图上进行,回边留待传播层专门处理。判别一个环时,原本诱人的做法是径直判定它是真是假,譬如认定唯有穿过 LLM 推理节点的环才承载真实的自我加工、其余可安全剪除;真实语料否证了这条捷径,一个纯 `write ⇄ read`、根本不碰 LLM 的局部文件闭环,恰恰是最典型的自优化语义,按上述判据反会被误删。真伪既不可靠可判、也不必强判,我们代之以一个可操作的替代问句,这条回边作为一条反馈通路是否合理。判定规则宽进、LLM 收口,明显合理的(涉及汇点、或本就是受保护的语义边)直接放行,可疑的少数交一次批量复核,任何解析失败或超时都保守地退回保留。实测绝大多数回边被判为承载合理反馈,反馈结构在真实 skill 中远非罕见的 corner case。

真正承载语义的是展开。判为合理的环被带进传播层绕行恰好一轮,数据在环体里被加工一次后带出,而非被反复迭代到不动点,后者在大型 skill 上根本不收敛,而"绕一轮"恰好是这类反馈 skill 每次运行的真实语义。绕行让每处越界观测按其与环体的关系分成两类,供 §7 区别判定,周期型(periodic)的汇点落在环体之内,数据每绕一轮都被重新加工、重新外发,循环泄露的语义正落在这一型上;坍缩型(collapse)的流先穿过环体、再经普通边流向环外的汇点。至于什么该带出环参与后续判定,取决于环体对数据做了什么,若它把一个笼统标签细化成若干可具名的具体类(如从模糊用户数据析出 PII、位置、凭证),这些具体类各自成流带出,若它只是把数据聚合变粗、不产生新信息,则无物可带。而这条"细化还是聚合"的方向判断必须落在标签的语义类别上,不能图省事去看它的派生模式,二者初看可以互换,细化产物确带着"派生"的标记,但聚合产物同样被标为派生,单看模式便会把聚合误当细化、凭空注入成千条本不该存在的流,只有认类别不认模式,方向才无歧义。

这套展开之所以只带来流数的线性放大而非指数爆炸,关键在一处克制,"数据正在环内"只是一个随流携带、出环即清零的瞬时状态,而非沿血缘永久传递的印记。若把它当印记一路传下去,环之后每个可达节点都要分裂成"经过环"与"未经过环"两份、状态空间逐层翻倍;让它一出环就与环外普通流重新合并,整套机制的代价便收敛回一个线性常数因子。正因如此,环展开是默认行为而非需谨慎开启的实验旁路,即便反馈结构最密集的 skill 也能跑到自然收敛,慢而不失控。实测反馈结构在真实 skill 中远非罕见的 corner case,把环当作可安全忽略的边角情形,本身就是一个被数据否证的假设。<!-- eval:prevalence 数据最终以审计集为准 -->

### 5.4 传播的产物,与真实规模

传播到此产出的不是一堆路径,而是一个"标签 × 汇点"的观测集,每条敏感标签自源头出发,每越过一次信任边界就在该汇点沉淀一个判定单元,UNEX 随后消费的正是这些单元而非原始图。也正因如此,一条流不必背着它走过的整条路径,只需携带判定真正要用的东西,有序的变换摘要、来源、边界。这让每条流的内存占用降到与它真实经历的变换数同阶、而非与路径长度同阶,恰是 §3"证据充分,状态最小"准则在传播层的一次兑现,图产出的粒度就是判定消费的粒度,下游无需从路径重建任何东西。

把这套传播放到真实生态里,最重的那几个 skill 会依次撞上三种成本压力,拷贝整条路径拖垮内存、过细的去重键把收敛退化成路径枚举、以及一处随汇聚宽度平方增长的存储合并。三者都循同一条准则被逐一治平,凡不改变任何汇点裁决的状态差异都不该多占内存,凡真正超线性的开销都摊成增量,使传播即便在反馈最密、扇出最广的 skill 上也能跑到自然收敛。剩下的纯线性成本我们不加掩饰地让它慢下去,而不去动那把已校准到与裁决严格对齐的去重键、拿正确性换速度。<!-- 规模化的具体做法(去重键的两处修正、缩减维的反链化、存储合并的增量化)留待 §8 或附录展开 -->

## 6 不必要暴露判定 UNEX(UNnecessary EXposure)

传播层给出了一个"标签 × 汇点"的观测集,每条敏感标签在每个越界汇点沉淀一个判定单元,要在这些单元上判定哪些外发构成过度暴露,核心问题是把两件容易被混为一谈的事拆开看。一次外发被判为过度暴露,当且仅当它既真的越界外泄又对任务不必要,两条轴必须分开算、最后再合取,任一轴判错都会把结论带偏(§6.1)。而必要性一轴不能靠关键词词袋来算,那类做法度量的是措辞而非结构,一个写得啰嗦的 skill 会凭空刷出必要性,唯一稳健的做法是把三个分量逐一从"数词"落到"看结构"(§6.2)。判别力该从哪里来,是贯穿这一重写的工程原则,靠打分体系内生、而不是事后在门层打补丁(§6.3)。最后一环是把结构事实作为硬证据喂给 LLM,这要求证据包以流为中心、并在送审前做两道减量,让 LLM 只看该看的、且每个判定单元只判一次(§6.4)。

### 6.1 两条正交轴,外泄 ∧ 不必要

暴露(exposure)与必要性(necessity)度量的是两件互不蕴含的事。一次外发可以既严重又必要,也可以不怎么严重但完全没必要,把两者混为一谈会把判定带偏。一个典型的混淆是把"汇点是 model_provider"当成"不算真外泄"的理由,这实际上是把必要性的结论(喂 LLM 通常是任务所需)错记到暴露轴上了。正确的拆分是该模式暴露满额(边界风险 0.9、确实越界),但必要(生成摘要就是要调模型),所以最终非过度暴露,结论不变,但理由必须是"外泄重但必要",而不是"不算外泄"。把数据喂给模型服务商是当代 AI skill 最重要、也最易被误当"可信内部"的外泄面,它满额计入暴露,和第三方网络、持久化存储、webhook 同档。所有真外泄一视同仁,不因接收方是 LLM 服务商就降格,这是暴露轴上一条容易被违反的原则。

必要性回答"这么严重的外发,任务上到底需不需要"。§3 已把这句含混直觉顺着一个反事实裂成三个能各自求证的问题,任务必要性 $N_3$(删掉这条流,skill 声称的任务还成不成)、动作输入必要性 $N_1$(数据是否真进了这次动作)、接收方语义必要性 $N_2$(把这类数据发给这种接收方,语义上相容吗),三者取最小值合成必要性,任一分量低,整体即低,
$$\mathrm{nec}(f)=\min\{N_1(f),\ N_2(f),\ N_3(f)\}.$$
取最小而非加权和,是因为三者是必要性的合取条件而非可相互补偿的加分项,一条流哪怕在接收方与任务两轴上都说得通,只要它根本没进这次动作($N_1$ 低),就仍不必要。取最小让任一轴的"不必要"都无法被另两轴的高分淹没。记一次越界观测的暴露判定为 $E(f)$(真外泄为真),过度暴露的最终判据是两轴的合取,
$$\mathrm{OverExp}(f)\ \equiv\ E(f)\ \wedge\ \big(\mathrm{nec}(f)<\theta\big),\qquad \theta=0.7.$$
凡 $\mathrm{nec}(f)<\theta$ 的真外泄被标为潜在过度暴露,进入 LLM 复核。阈值 $\theta=0.7$ 并非揣测随意拍板,其落点由分数簇隙探针实证定位(§6.3)。

这条区分不只是概念上的整洁,它直接决定判定能否对准真问题。正如刚才所说，若把"喂 LLM 通常是任务所需"误读成"喂 LLM 不算外泄",判定就会对一整类真实的、严重的外泄面系统性失明。

### 6.2 必要性,从关键词词袋到结构化判据

必要性是整套判定里最难的一环。三分量的科学动机(数据最小化、情境完整性、目的限制)已在 §3 交代,本节处理的是如何把每一分量从 SFG 结构算出,以及朴素的词袋实现为何不够。关键词词袋的做法是把动作名、参数键、汇点描述等文本拼起来,数"必要性提示词"(如 `required`、`input`、动作动词)与"可选性提示词"的命中,加权得分。这类做法看似稳健,实则脆弱,它度量的是措辞而非结构,一个写得啰嗦的 skill 会凭空刷出必要性,一个用词朴素的 skill 则被系统性低估。

归因探针揭示了词袋的致命缺陷。关掉三分量里的两个、只留一个,看裁决翻转多少,结果是动作输入必要性($N_1$)一家独大,在某语料的 4431 条越界流里,3265 条(74%)的整体必要性恰好等于动作输入分量,也就是说另外两分量在绝大多数情况下根本没参与决定裁决。而词袋实现给这一主宰分量凑出了一个约 522 的假地板,大量本该判低必要性的流,只因描述文本里碰巧出现必要性提示词而被抬到阈值之上。主宰项被措辞污染,等于整个必要性轴被污染,调词表只能修个案、治不了根。

结构化判据的思路是把三个分量逐一从"数词"改为"看结构",记为 N1–N3。

**N1 动作输入必要性,数据是否真进了这次动作。** 判据换成三个结构事实,取代提示词计数。第一个是变换参与,即这条流在到达汇点前是否真被某个动作消费/变换过(而非只是路过被顺带外发),真参与的流给高分(约 0.9)。第二个是操作语义,即消费它的操作属于哪一类(读取、变换、纯转发……),按操作类别而非动词字面定分。第三个是 schema 归属,即这条流承载的字段是否落在动作声明的输入 schema 里,落在声明输入内的给近满分(约 0.95),因为"skill 自己声明要这个输入"是任务需要它的最硬证据。三者都是从 SFG 结构直接读出的事实,不再受描述文风影响。

**N2 接收方语义必要性,把这类数据发给这种接收方语义上相容吗。** 判据是一张接收方作用域 × 数据类目的相容矩阵,把接收方按作用域归类(本地/用户回显、同 skill 内部、模型服务商、任意第三方……),把数据按敏感类目归类(身份标识、健康、金融、凭证……),矩阵给出每个 (作用域, 类目) 组合的语义相容度。关键约束是敏感类目在任何外发作用域上都不得被误清,矩阵里所有"敏感数据 × 真外发"的格子必须落在阈值下,不能因为某种接收方"看起来正常"就放行。这一版实测敏感类目零误清。

**N3 任务必要性,skill 自己声明的任务里提到要这条数据吗。** 判据是声明覆盖度,把 skill 描述/元数据里声明的任务意图与这条流的字段、汇点比对,声明里明确要这次外发的给高分。同时补两条边界护栏,都作用在打分而非门。其一是汇点地板,一切真外泄汇点的必要性默认不允许高过 0.7 的判定阈,即真外泄默认进复核,除非结构判据主动抬升。其二是泛化边界汇点封顶,对那种"什么都往里塞"的笼统汇点(如一个通用 `send`),必要性封顶在很低的值(约 0.12),防止笼统性被误读成"任务需要"。

三分量重写后合成仍是取最小值。在同一语料上验收,相比词袋版,517 条流的裁决被清除(从判过度暴露变为非过度暴露)、0 条被新判为过度暴露,翻转全为单向,说明重写只在纠正词袋的假阳、没有引入任何新的假阴方向的漂移。没有任何一条 high/critical 严重度的真外泄被规则层终判清除,它们要么本就必要、要么被送进 LLM 复核,规则层无权终清。被清除的主要是 medium 档,235 条 medium 流最终塌缩成 6 种判定模式,逐一核对全部确为任务必要。整个重写没有污染任何 gate 或暴露分数,这引出下一节的工程原则。

### 6.3 工程原则:判别力靠打分内生,不靠门层护栏

重写必要性时,最诱人的捷径是给 gate 加特例,遇到判错的个案,就在门层写一条 `if 这种 skill/这种汇点 then 特殊处理`。这条路走不得,理由是可证的,门层特例把判别逻辑从"分数分布"里挪到"分支条件"里,后者不可度量、会随语料膨胀、且把两条正交轴又重新耦合起来。原则是,要修判别,就去优化打分函数和阈值,让正确与错误的样本在分数上自然分开,不要靠 gate 特化护栏硬掰个案。

分数簇隙探针证明了这条原则的有效性。把所有样本按最终裁决分成两簇,画它们的必要性分数分布,结果两簇之间存在一条干净的空隙,应判清除的一簇落在约 0.75–0.80,应判保留(过度暴露)的一簇落在约 0.65 及以下,两簇零重叠,阈值 0.7 正好落在空隙里。也就是说,判别力已经完全内生于打分,不需要任何一条 gate 特例去救边界个案,因为根本没有卡在阈值上的边界个案(逃逸数为零)。§6.2 终验里那 6+3 种判定模式逐一核对,gate 与护栏均未改动而全部判对,这就是"改打分不改门"能自洽收敛的直接证据。

### 6.4 以流为中心的证据包与送审减量

UNEX 的复核靠 LLM,而 LLM 判得准不准,取决于喂它什么。这里有两个设计动作,把证据包从"平铺证据条"改造成"以流为中心"的结构(让 LLM 看清这条流从源到汇的完整因果链),以及在送审前做两道减量(让 LLM 只看该看的、且每个判定单元只判一次)。跨路径聚合不在这一层解决,它读的是 §5.4 沉淀在 SFG 里的 `label_flow_ids`,由 §7 的静态扫描直接消费,不经 LLM。

**以流为中心的证据包。** 平铺的 `evidence[]` 索引让 LLM 做了不该它做的事,每条证据一行,LLM 要自己在脑子里把"哪些证据属于同一条流、这条流从哪个源、经哪些变换、到哪个汇点"重新拼起来,既费 token 又易错。正确的做法是把每个判定单元(单条 (观测, 标签流))的证据整个换成一个以该流为主体的三层结构,即 label(这条流承载的数据标签)→ sink_boundary(它越过的汇点边界)→ flow(这条流从源到汇的节点序列)。`flow` 按序列出该流途经的每个节点及其结构事实,让 LLM 一眼看清"这条流从哪来、被谁变换过、最终外发到哪"的完整因果链,而不必从散落的证据行里反推。原来的 `evidence[]` 索引整个删掉,下游改引 `node_name/label/sink_boundary`。

证据包里的每个 flow 节点挂了两类结构事实(不是散文,是从 SFG 直接读出的布尔/枚举),供 LLM 做接地判断,`schema_declares_input`(这条流的字段是否落在动作声明的输入 schema 里)、`origin_trust`(数据源的信任等级)。汇点上则挂 `high_sensitivity_egress` 档(§6.1)。prompt 锚点强调这些是真外泄的结构证据,并显式纠正"喂 LLM 就算内部"的措辞误区(呼应 §6.1 的正交性)。

**flow_state 瘦身,只喂该喂的。** 喂给判定层的 flow_state 只保留判定真正消费的字段,UNEX 实际只读其中 4 个,于是砍掉一批死字段(约 41% 字节),`provenance` 只保留标签真变换事件,并删掉 `node_flow_sets`。瘦身连带保证了 `reduction_applied` 沿投影层如实转发,它承载的 +0.2 必要性加成(缩减在外发前施加则更可能必要)才能落地生效,某 518 条 assessment 的 skill 由此正确带上 `reduced=true`。134+56 测试逐位回归、零功能损失。

**两道送审减量。** 第一道是送审去重,同一个判定单元 `(observation_id | label | transform_signature)` 可能被多条路径重复触达,只把置信度最高的代表送给 LLM,其余成员复用该判定,这一步省下约 75% 的送审量,且因为判定单元本就是 UNEX 的裁决粒度(§5.2),复用是等价的、不是近似。第二道是溯源裁剪与顺序边降级,P1 把每条流的溯源链截到 origin_node 为止、不穿越源引入点(LLM 不需要看源之前的历史),P2 把纯顺序控制流(只表达执行先后、不传数据)降级为 `may_flow` 并在证据包里标 `order_only`,避免 LLM 把"先后"误读成"数据依赖"。两道减量都只减 token、不改判定单元集合。

至此,UNEX 的两条正交轴(§6.1)、必要性的结构化重写(§6.2)、"改打分不改门"的收敛证据(§6.3)、以及以流为中心的证据包与送审减量(§6.4)构成完整的单流判定链路。而"同一汇点收敛哪几条 label 流"这一事实并不在证据包里、也不经 LLM,它由 §5.4 的传播层沉淀在每个越界观测的 `label_flow_ids` 上,正是下一节聚合判定的入口。

## 7 从单流到联盟:跨路径聚合暴露(Coalitional Exposure)

§6 的判定逐条流地问"这次外发该不该发生"。但存在一类暴露,任何单条流上都看不见,只在流的集合上才显形:多条各自看似必要、各自合规的敏感流汇聚到同一外发汇点,其集合的敏感度超过任一单条(超可加,superadditive)。这类跨路径聚合暴露是逐单元判定方法的结构盲区,也是 SkillFlow 相对既有工作的一处关键差异。它并非独立于 §6 的另一套判据,而是把 UNEX 的"不必要"从单流抬到集合:纵使每条流单独判来都任务必要,它们在同一汇点的共现通常并非任务所需——判据仍是"暴露 ∧ 不必要",只是两轴都在集合层重新度量。

### 7.1 判定单元的抬升:同汇点的流集合

聚合判定不需要新的传播,它复用 §5.4 已沉淀的底座:每个越界观测(observation)本就携带汇到该汇点的全部标签流 id(`label_flow_ids`)——传播层如实记录了"哪几条 label 流收敛到同一汇点边界"这一事实。聚合层做的只是把判定单元从单条流(observation × label_flow)抬升为同一汇点边界上收敛的标签流集合,再对这个集合的语义类目做一次纯结构判定。

超可加是这层的核心概念,也是它区别于"把单流分数相加"的地方。设一个汇点上收敛的标签集合为 $L$,聚合暴露关心的不是 $\sum_{\ell\in L}\mathrm{sev}(\ell)$,而是 $\mathrm{sev}(L) > \max_{\ell\in L}\mathrm{sev}(\ell)$——集合作为整体,是否解锁了任一成员单独不具备的危害。一条数据库记录流、一条文件内容流各自或许只算中等敏感,但二者在同一外发点共现,就构成"可批量拖库并落地取证"的组合能力,其危害不是两个中等之和,而是跃升到一个新档。正因危害在集合层是超可加的,它无法由任何逐成员的打分或消融复原(§7.3)。

这也决定了聚合判定为什么可以、且应当是纯静态、免 LLM 的。集合的类目构成是从本体标签字典直接读出的结构事实,超可加与否由类目组合的固定判据决定,既不需运行 skill、也不需模型裁决——它比 §6 的单流复核更轻,却抓的是单流复核构造上抓不到的东西,与全流水线免执行的立场一致。

### 7.2 从人口学准标识符到危害原型:一次被数据推翻的转向

聚合暴露的理论原型来自 Sweeney 的再识别工作:人口学准标识符(quasi-identifier)——出生日期、性别、邮编——三者单独都不能定位个人,合起来却能唯一再识别约 87% 的美国人口。这是超可加的经典范例,也是我们最初为聚合层设定的判据:扫描是否有多条人口学流汇到同一汇点、其标签集合命中 Sweeney 三元组。

但对全语料做这一扫描,结果是零命中。<!-- eval:设计期实测,最终以审计集为准 -->这不是实现缺陷,而是一个关于问题域的事实:agent skill 处理的根本不是人口学微数据。它们不是医院发布的病历表、不是人口普查公开集,而是自动化工具,经手的是凭证、数据库句柄、文件内容、API 密钥这类运营与技术秘密。人口学再识别的威胁模型整个错位了——继续押注 Sweeney 三元组,等于拿量人口普查的尺子去量攻击工具箱。

于是判据从"人口学 QI"泛化为一套危害原型(harm archetype)分类:凡多条高敏流汇到同一外发汇点,即按其类目家族归入四类之一。再识别型即人口学 QI(Sweeney 情形,本语料下为理论项);个人画像型是直接标识符叠加通信/记录/位置/健康/金融属性,拼出已知个人的富画像;能力聚合型是凭证、数据库、文件、安全/网络数据共现,拼出一套攻击工具箱;混合型则跨个人与运营两个家族。四类共性是超可加,差别在危害的性质——前两类指向个人隐私,后两类指向系统失陷。Sweeney 由此从"实证头牌"退为"理论动机",能力聚合型接棒成为本语料真正的主导威胁。

### 7.3 主导威胁与竞品的构造性盲区

按上述分类对全语料做结构扫描:在所有多流汇点中,相当一部分在同一外发点收敛了两个及以上不同的高/危类目,其中越界外发的联盟约 2152 处;主导的联盟签名是 `{数据库记录, 文件内容}`(约 901)、`{凭证, 数据库记录, 文件内容}`(约 339)、`{通信, 文件内容}`(约 265)。<!-- eval:设计期实测,最终以审计集为准 -->分布压倒性地落在能力聚合型一侧:真实生态里的聚合暴露,主要不是"谁被再识别",而是"一个外发点同时握有拖库、取文件、带凭证的组合能力"。这条实证结论本身,就是把卖点从人口学 QI 转向能力聚合的依据。

回到"不必要"这条轴:能力聚合型联盟之所以是暴露 ∧ 不必要,恰在于其成员可以逐条必要、集合却不必要。一个运维类 skill 也许确实需要读数据库、需要读配置文件、也需要用凭证认证——三条流各自都能通过 §6 的单流必要性。但任务几乎从不需要三者在同一个外发点同时出现:把它们汇到一处,是把三项本可分散、分别授权的能力,固化成一个单点即可全取的攻击面。必要性在集合层被违反,而非在任何单条流上——这正是 §6 的单流判据够不到、须由聚合层接手的缝隙。

而这条缝隙恰是逐单元判定方法构造上接不住的。AgentRaft 以单条传输 $D_{\text{trans}}$ 为裁决粒度,SkillScope 以单动作消融(移除一个动作、看输出是否改变)判必要性——两者的判据都作用在单个成员上:一个单元方法给每条成员流独立赋一个裁决,并当且仅当某成员被判过度暴露时才标记其所在集合,即
$$\mathrm{Flag}(C)\ \equiv\ \exists f\in C:\ \mathrm{OverExp}(f).$$
而能力聚合型联盟的每条成员流各自贡献一份互异的载荷,消融任一条都会改变输出、从而被判任务必要($\mathrm{nec}(f)\ge\theta$),于是 $\neg\,\mathrm{OverExp}(f)$ 对所有 $f\in C$ 成立,$\mathrm{Flag}(C)$ 恒假。但集合层的风险谓词 $\mathrm{Risk}(C)$ 是超可加的(§7.1),可在每个单成员裁决都为"非过度"时仍然为真:
$$\mathrm{Risk}(C)=\text{true}\quad\text{而}\quad \forall f\in C:\ \neg\,\mathrm{OverExp}(f).$$
盲区因此不是他们疏忽了某个案例,而是判据的作用域(单成员)与风险的存在层级(成员集合)错位——由 $\mathrm{Flag}$ 只在成员上取存在量词这一形式即可逐字证明。SkillFlow 把判定单元显式抬到集合层(§7.1),正是补上这一层级;而由于该判定纯结构、免执行(§7.1 末),补上它并不以牺牲"免执行、可规模化"这一全局立场为代价。
