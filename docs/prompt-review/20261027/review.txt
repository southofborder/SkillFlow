来源：src/skillflow/task/prompts.py :: TASK_WORKFLOW

[ENGLISH]
4. EXTRACTION RULES
Purpose and each requirement need exact {file,start_line,end_line,reason}, inclusive one-based physical spans. No copied quote or paragraph ID. Extract independently checkable obligations while keeping their relational context: required results, original-value identity, conditions, applicability, counts, ordering, quality, side effects and prohibitions. Several obligations can share a line; one obligation can span files. Avoid mechanical conjunction splitting and broad bundles hiding separately omitted duties.
Current whole-record use, capabilities, examples and implementation facts are not automatically requirements. A precise obligation inside an implementation step still counts. A required action does not exempt all payloads; genuine explicit whole-value requirements must not be narrowed for a desired result.
Read the complete source to identify obligations, but do not classify or register every source line. Evidence spans support individual purpose, requirement and issue claims; unreferenced context is allowed and does not prove an omission. Keep each supported prohibition even when the current implementation appears to obey it.
Record ambiguity/conflict in issues with original evidence, affected requirement_ids, resolution and reason. Faithfully retained open descriptions are allowed; do not invent success, encoding, mechanism or implementation. Never output bindings, demands, sensitivity or unsupported fields.

4. 提取规则
purpose 和每条 requirement 都需要精确的 {file,start_line,end_line,reason}，使用从 1 开始、包含两端的物理行范围。不复制引文，不使用段落 ID。提取可以分别检查的义务，同时保留它们之间的关系背景：规定结果、原值身份、条件、适用范围、次数、顺序、质量、副作用及禁止事项。同一行可以包含多项义务；同一项义务可以跨文件。避免按连词机械拆分，也避免用宽泛的一项掩盖可以分别遗漏的职责。

graph.filling · 完整 CFG 填写规则
来源：src/skillflow/document_guided/prompts.py :: _GRAPH_FILLING
使用阶段：完整 CFG 填写、图语义修复

[ENGLISH]
Fill one complete existing CFG candidate from the completed flow document and its source.
Use the document as a fallible working result, not an authority above the source.
Keep source-supported entry points, independent components, conditions, explicit
cross-file producer/consumer relationships and unresolved conflicts. Do not add
edges from proximity or names. The program numbers and validates explicit model
objects; it does not infer control or data connections.

Each instruction is one definite source action. Source-specified changes and
transfers with different versions stay distinct. Code bodies remain black boxes:
retain callable interface, actual acquisition, arguments, returned values and
explicit side effects; do not construct an internal call stack or script CFG.
Acquisition is a source block (context/external) with exactly one acquisition
instruction followed by dispatch/return. Context acquisition consumes declared
context_key entries. Resource identifiers are not the acquired values. Ordinary
computation uses data_source_kind=null. Every produced result identifier is unique
throughout the candidate; later consumers use that actual identifier, including
across branches and loops. Do not invent relay acquisitions or a second producer.
Preserve repeated calls and returns as different versions.

A block with outgoing edges ends in dispatch; a terminal block ends in return.
Both have no outputs. dispatch consumes the values used to choose its edges;
return consumes its actual result. Edge condition_text is not a data dependency.
Place source constraints at their real graph/block/instruction scope. A stated
restriction is not an implemented guard, deletion or extra operation. Faithfully
retained source ambiguity does not require choosing a winning interpretation.

For code, put the exact frozen source selection in the existing metadata field
as _source_span={file,start_line,end_line}; the program copies that exact original
text into metadata.script_content and removes this technical selection. Never
invent a range or duplicate the code in the response. Other metadata is preserved.
Check all explicit connections, operands, unique references and actual entry
before returning one complete JSON object. No fragment, patch or additional keys.
Use cannot_assess only when no usable whole candidate can represent a necessary
relationship; cite frozen source. Open details or preserved ambiguity alone are
not a failure. Explanations use English; source quotations retain their language.


[中文对照]
根据已完成的流程文档及其原文，填写一份完整的现有 CFG candidate。
将文档视为可能出错的工作成果，不赋予它高于原文的权威。
保留原文支持的入口、独立组成部分、条件、明确的
跨文件生产／消费关系及未解决冲突。不要根据
位置邻近或名称添加边。程序对模型明确提供的对象编号并校验；
它不会推断控制或数据连接。

每条 instruction 对应原文中的一个确定动作。原文明确规定且
具有不同版本的变更和传递必须保持区分。代码正文保持黑盒粒度：
保留可调用接口、实际获取、参数、返回值及
明确副作用；不要构造内部调用栈或脚本 CFG。
获取是一个来源块（context/external），恰好包含一条 acquisition
instruction，随后是 dispatch/return。context 获取消费已声明的
context_key 条目。资源标识符不是取得的数据值。普通
计算使用 data_source_kind=null。每个生产出的结果 identifier 在
整个 candidate 中唯一；后续消费者使用该真实 identifier，包括
跨分支和循环的消费。不要虚构中继获取或第二个生产者。
将重复调用及其返回保留为不同版本。

具有出边的块以 dispatch 结束；终态块以 return 结束。
二者都没有输出。dispatch 消费用于选择其边的值；
return 消费它真正返回的结果。边的 condition_text 不是数据依赖。
将源文限制放在其真实的图／块／instruction 作用域。
声明的限制不等于已经实现的守卫、删除或额外操作。忠实
保留的原文歧义不要求选出一个优先解释。

对于代码，在现有 metadata 字段中提供精确的冻结源文选取范围，
形式为 _source_span={file,start_line,end_line}；程序将该精确原文
复制到 metadata.script_content，并移除这一技术性选取信息。绝不
编造范围，也不要在响应中重复代码。其他 metadata 保持。
返回一个完整 JSON 对象前，检查全部明确连接、操作数、
唯一引用和真实入口。不要返回片段、补丁或额外键。
只有不存在可用的完整 candidate 来表示某项必要关系时，
才使用 cannot_assess；引用冻结原文。开放细节或保留的歧义本身
不是失败。解释使用英文；原文引文保持其语言。

conflicts. These are reading prompts, not output classification fields.

not automatically mean exact preservation.

runtime behavior may remain ambiguous while this representation is reviewable.

requirements, and insufficient information; do not mechanically label additions.

annotation-workflow · 联合标注：填写顺序
来源：src/skillflow/propagation/annotation/prompts.py :: WORKFLOW
使用阶段：完整联合标注、固定 Task 标注修复

[ENGLISH]
4. FILL BY DEPENDENCY
A. LOCATIONS. Identify sources/receivers and location kind,name,operand_refs,access_scope,retention. Use the runtime boundary rules; all location IDs require nonempty location_evidences. Reuse identities and supported aliases. Do not invent an operand for an implicit boundary or confuse an ancestor source with its selected operand value; an unanchored source location may use operand_refs=[] and connect via read/local/select_part. Storage/runtime_context require non-null retention. Do not emit sink_boundaries, sink_type, exposure_level or scores.
B. PROCESSING. Cover every actual IR (not block) in ir_semantics. Operator labels describe independently evidenced executors, not sources/recipients; scheduling alone does not prove model visibility. operator_evidences contains value matching each label; confirmed empty operator requires value=null and no nonempty list may use null. Each segment, scope, operation and output binding needs nonempty evidence. Each effect occurrence needs its own stage/range/order explanation; repeat distinct stages, not runtime loop counts or sorted effect vocabularies. Non-null event: nonempty event.evidences. Null event: event.evidences=[] or omitted, while operation.evidences remains nonempty. If every recursive event has effect=null (or there are no events), supply IR.empty_effect_evidences even when atomic operations exist; otherwise omit that IR field. It explains effect inapplicability, not inability to assess. Ordinary return/control/output aliasing can still matter.
PROCESSING DECISION ORDER
1. Identify the actual content and whether source/code/interface specifies execution AND content-return mechanisms.
2. Explicit model content processing uses mode=model and independently supported llm operator.
3. Only explicit local execution AND its content-visibility/return boundary support mode=local. State returns explicitly; [] requires supported no-content return. Could be implemented locally does not mean local isolation is specified: opcode, executor labels, a predicate and absence of an LLM mention are insufficient.
4. Otherwise mode=default applies the supplied EM rules. Separately supported stages remain separate. order=partial preserves supported alternatives, definition/use and compiler causality, not protection-first preference.
EXPLICIT VALUE RELATIONS
Choose each output relation independently: unchanged whole -> output_bindings; existing field/index -> select_part; unchanged selected members -> filter_items; deletion/replacement/composition -> exclude_parts/update_fields/build; classification/count/summary -> compute; opaque processing -> relevant possible dependencies. Do not weaken an explicit field-original relation into opaque compute or infer paths from names. A summary-named field may simply be copied. A classification and an original payload can need separate compute/select_part operations.
For acquisition retain the declared source and target value separately. Apply runtime defaults or explicit local mechanisms, select supported fields, and bind public outputs and actual arguments. An identified source may remain opaque without fabricated fields. A selected field operand does not identify its entire source container. Receiving tool content is acquisition, not query-only computation; networking is a separate claim. Internal read, returned data, model observation and actual parameters are distinct.
C. SENSITIVITY. Declare once at its defining IR or existing for_each scope using value,path,property,label,evidences. Bind actual lexical input/local versions, not resource/source identity. Cite only supplied Skill physical spans. A path may include one {kind:each}, a member information template, not index zero/new loop. Value sensitivity does not automatically classify presence/cardinality/shape/truth. Do not invent undisclosed fields or outside policies; absence of declarations is not proof of nonsensitivity. Influence is not plaintext containment or proof of sanitization.
D. DEMANDS AND EXPRESSIONS. Seed the required result, actual endpoint input, behavior or condition, not a broad upstream input just because it is consumed. Properties are value/presence/cardinality/shape/truth/action. expected/expected_path preserves a supported original-value relationship; it cannot justify a wrong target or whole scope. No prohibit demand. Requirements need not each have a positive goal: supported restrictions use realization.constraints; unsupported remaining restrictions use gaps. No duplicate seed just for coverage.
Only compute/filter_items carry expression={expression,evidences}, with physical source evidence; top-level expressions describe actual CFG controls. AST: ref/literal/field/present/count, eq/ne/lt/le/gt/ge, not/and/or. References are actually consumed in-scope values. present distinguishes absence from null and false. Count is collection cardinality, not inferred successful action count. Do not restate select/build/update semantics or infer a computation from its name.
E. REALIZATIONS. Cover every supplied requirement_id exactly once after inspecting its demands, constraints and remaining limits. bindings are general CFG correspondences, not executable declarations. expressed: supported demand(s) or constraint(s), no gaps; partial: supported demand(s) or constraint(s), explicit remaining gap(s); retained_only: no executable declaration, gap for unsupported restrictions; unmapped: no executable declaration or binding, gap explains missing grounding. Recompute status after changing declarations; a general binding cannot replace them. Pure restrictions need no positive seed. Check all positive and restriction parts of a compound requirement separately. Each gap needs nonempty physical-source evidence for an actual unrepresented requirement; open implementation details alone are not gaps. Status describes expression, not compliance; a compound requirement is not fully expressed merely because one action seed exists.


[中文对照]
4. 按依赖顺序填写
A. LOCATIONS。识别来源／接收方，以及位置的 kind、name、operand_refs、access_scope、retention。采用运行时边界规则；每个位置 ID 都须有非空 location_evidences。复用身份及有依据的别名。不要为隐式边界编造操作数，也不要将祖先来源与已经选取的操作数值混淆；无操作数锚点的来源位置可以使用 operand_refs=[]，并通过 read／local／select_part 建立关联。storage／runtime_context 的 retention 不得为 null。不得输出 sink_boundaries、sink_type、exposure_level 或分数。
B. PROCESSING。在 ir_semantics 中覆盖每条实际 IR（不是每个块）。operator 标签描述独立证据支持的执行者，不是来源／接收者；仅有调度并不能证明模型可见性。operator_evidences 中的 value 必须匹配每个标签；确认 operator 为空时使用 value=null，非空标签列表不得使用 null。每个处理段、作用域、操作及输出绑定都需要非空证据。每次效果出现都需要说明自己的阶段、范围和顺序；重复填写不同阶段，而不是运行时循环次数或排序后的效果词表。非 null 事件须有非空 event.evidences。null 事件的 event.evidences=[] 或省略，但 operation.evidences 仍须非空。如果所有递归包含的事件均为 effect=null（或没有事件），即使存在原子操作，也须填写 IR.empty_effect_evidences；否则省略该 IR 字段。它解释效果为何不适用，不表示无法评估。普通 return、控制及输出别名仍可能有作用。
处理方式的判断顺序
1. 识别实际内容，以及原文／代码／接口是否同时明确了执行机制与内容回传机制。
2. 明确由模型处理内容时，使用 mode=model 和独立证据支持的 llm operator。
3. 只有明确的本地执行，以及明确的内容可见／回传边界，才能支持 mode=local。明确说明返回内容；[] 需要有依据证明不返回内容。“可以本地实现”不表示已经规定本地隔离：opcode、执行者标签、谓词以及未提及 LLM 均不足以证明。
4. 否则使用 mode=default，应用提供的 EM 规则。分别有依据的阶段仍须分开。order=partial 保留受支持的候选安排、定义／使用关系与编译器因果关系，不表达“优先保护”的偏好。
明确的值关系
分别选择每个输出的关系：完整原值不变 → output_bindings；已有字段／下标 → select_part；保留原内容的成员选取 → filter_items；删除／替换／组合 → exclude_parts／update_fields／build；分类／计数／摘要 → compute；不透明处理 → 相关 possible 依赖。不要将明确的字段原值关系弱化为不透明 compute，也不要从名称推断路径。名为 summary 的字段可能只是原样复制。分类结果与原始载荷可能需要分别使用 compute／select_part。
获取时分别保留声明的来源和目标值。应用运行时默认规则或明确的本地机制，选择有依据的字段，并绑定公开输出及实际参数。已经识别的来源可以保持不透明，不必编造字段。被选取字段的操作数不等于整个来源容器。接收工具内容属于获取，不是仅查询的计算；网络通信是另一项需要证明的声称。内部读取、返回数据、模型观察与实际参数彼此不同。
C. SENSITIVITY。在其定义 IR 或已有 for_each 作用域中，使用 value、path、property、label、evidences 声明一次。绑定实际词法作用域中的 input／local 版本，不绑定资源／来源身份。只引用提供的 Skill 物理行范围。路径可包含一个 {kind:each}，表示成员信息模板，而不是下标零或新循环。值敏感性不会自动把 presence／cardinality／shape／truth 分类为敏感。不要编造未披露字段或外部策略；没有声明不证明不敏感。影响关系不等于明文包含，也不能证明已脱敏。
D. DEMANDS AND EXPRESSIONS。从规定结果、实际接收输入、行为或条件建立需求种子，不要仅因上游宽输入被消费，就为它建立需求。性质为 value／presence／cardinality／shape／truth／action。expected／expected_path 保留有依据的原值关系；不能证明错误目标或整体范围合理。没有 prohibit demand。并非每项要求都需要正向 goal：受支持的限制使用 realization.constraints；未支持的剩余限制使用 gaps。不要仅为了覆盖而重复建立种子。
只有 compute／filter_items 承载 expression={expression,evidences}，并使用物理行原文证据；顶层 expressions 描述实际 CFG 控制。AST 支持 ref／literal／field／present／count、eq／ne／lt／le／gt／ge、not／and／or。引用必须是作用域内实际消费的值。present 区分缺失、null 与 false。count 表示集合基数，不能推断为成功动作次数。不要重述 select／build／update 的语义，也不要从名称推断计算关系。
E. REALIZATIONS。检查 demands、constraints 和剩余限制后，对提供的每个 requirement_id 恰好填写一次。bindings 是一般 CFG 对应关系，不是可执行声明。expressed：存在受支持的 demand 或 constraint，且没有 gaps；partial：存在受支持的 demand 或 constraint，同时明确剩余 gaps；retained_only：没有可执行声明，gap 说明未支持的限制；unmapped：没有可执行声明或 binding，由 gap 解释缺失的依据。修改声明后须重新核对状态；一般 binding 不能替代声明。纯限制不需要正向种子。分别检查复合要求中的全部正向部分与限制部分。每个 gap 都需要非空物理行证据，支持一项实际尚未表达的要求；仅有开放的实现细节并不是 gap。状态描述表达情况，不是合规情况；仅有一个 action 种子不表示复合要求已经完整表达。

[ENGLISH]
5. OPERATION COMPATIBILITY
One timeline is CFG order -> events -> atomic_ops. Raw events are processing segments or single-level for_each with processing bodies. No profiles, roles, parallel effects or effect_index. No handwritten model_observe, guards or precedence. Respect order and definition/use; never replace old observation with a later cleaned value.
read: existing runtime_context/storage, context_read/fs_read.
receive: returned content from remote/net_receive or tool/null; ordered request influence and acquisition origin remain separate.
deliver: remote/net_send, user/user_output or tool/null. Request delivery is distinct from receive inputs.
write: runtime_context/context_write or storage/fs_write; replace/append consume input, delete consumes none and does not read old contents. Ordinary result binding is not context_write.
select_part/exclude_parts/update_fields/build/filter_items: explicit transforms with typed fields, retained unknown remainder and original member contents.
compute: inputs and per-input derived/possible dependencies have the same order and length. Zero-input opaque computation may use []. A null event permits only possible-compute or tool receive/deliver; it cannot hide reads, writes, field transformations or known networking. A non-null event includes its matching primary operation; parameter preparation cannot substitute for interaction.
for_each: one symbolic member shared by its body; keep same-element argument pairing. No nesting, state read/receive/write, mutable context operands, shadowing, cross-scope products or body-value export. Unsupported essential representation uses failure, not flattened fake pairing.
Evidence forms: {file,start_line,end_line,reason}, {target,reason}, {rule_id,reason}. Physical lines are inclusive, one-based; exact supplied filenames only. Task gaps, sensitivity and attached expressions require physical source evidence. Program extracts text: no quotes, paragraph IDs or generated hashes/indices. True references do not prove their explanation.


[中文对照]
5. 操作相容性
统一时序为 CFG 顺序 → events → atomic_ops。原始事件是 processing 段，或包含 processing body 的单层 for_each。没有 profiles、roles、并列效果或 effect_index。不要手写 model_observe、guards 或 precedence。遵守顺序与定义／使用关系；不能用后续清理后的值替换早先观察。
read：已有 runtime_context／storage，使用 context_read／fs_read。
receive：从 remote／net_receive 或 tool／null 获得返回内容；有序请求影响与获取来源仍须区分。
deliver：remote／net_send、user／user_output 或 tool／null。请求交付与 receive 输入不同。
write：runtime_context／context_write 或 storage／fs_write；replace／append 消费输入，delete 不消费输入，也不读取旧内容。普通结果绑定不是 context_write。
select_part／exclude_parts／update_fields／build／filter_items：使用有类型的字段明确表达变换，保留未知剩余与原成员内容。
compute：inputs 与每个输入的 derived／possible 依赖顺序及长度相同。零输入的不透明计算可以使用 []。null 事件只允许 possible-compute 或 tool receive／deliver；不能隐藏读取、写入、字段变换或已知网络通信。非 null 事件包含其对应的主要操作；参数准备不能替代交互。
for_each：body 共用一个符号成员，保留同元素的参数配对。不支持嵌套、状态 read／receive／write、可变上下文操作数、变量遮蔽、跨作用域笛卡尔组合或 body 值导出。必要关系无法表示时使用失败，不能将配对扁平化伪造出来。
证据形式：{file,start_line,end_line,reason}、{target,reason}、{rule_id,reason}。物理行范围包含两端，从 1 开始；仅使用提供的精确文件名。Task gaps、敏感性及附着表达式要求物理行原文证据。程序提取文本：不要填写引文副本、段落 ID、生成的摘要或索引。引用真实不证明其解释成立。

CFG AND RETURN. CFG owns instructions, operands, result definitions, control, conditions, constraints and metadata. CFG evidence supports only its resolved graph fields. A result identifier names a value, not its members. Cite source lines for source-stated field existence or sensitivity; an explicit CFG literal, path or constraint supports only what it records, not unconditional runtime presence. Transfer operations and demands are annotation facts, even when they implement that IR. Ordinary return uses real CFG inputs, has no public output and may have empty events/output_bindings. CFG 与 RETURN。CFG 拥有指令、操作数、结果定义、控制、条件、约束和 metadata。CFG 证据只支持实际解析出的图字段。结果标识符命名一个值，而不是其成员。源文声明的字段存在性或敏感性应引用原文行；明确 CFG 字面值、路径或约束只支持它实际记录的内容，不证明运行时无条件存在。传递操作与 demands 属于标注事实，即使它们实现了该 IR。普通 return 使用真实 CFG 输入，没有公开输出，并可具有空 events／output_bindings。不要编造 output 0 或 user／network 交付。调用者内部状态不另行建模。空 effects 不表示没有动作，也不表示 IN／OUT 相同。

shared-rule-02 · 共用规则 2：坐标
来源：src/skillflow/propagation/contracts/format_instructions.py :: _RULES[1]
使用阶段：完整联合标注、固定 Task 标注修复、全局语义初审、标注独立复审、共用规则、显示与格式

[ENGLISH]
COORDINATES. Direct CFG targets use exactly one complete form: {"instruction_id":"ir_demo","path":[]} for an instruction; {"block_id":"block_demo","path":[]} for a block; {"path":[]} for the graph; {"instruction_id":"ir_demo","side":"input","index":0} for an operand. path is required even when empty; bare identity is invalid. Realization bindings may use general graph/block/constraint targets. Executable action demands require an actual IR or atomic operation, not graph/block correspondence; value demands require actual operands or operation values, not names/containers. ValueRef input(index) always reads the enclosing IR entry operand; local(name) is lexical to that IR/scope. Operation demand input(index) instead selects the operation's consumed slot. Resolve slot -> ValueRef -> actual value before judging. Non-action self on an operation with an output targets that output, not its attached expression. compute/deliver/receive slots follow inputs; select_part/exclude_parts/filter_items and non-delete write use slot 0; update_fields uses base then updates. build visits parts in order: value, or when then value. Controls are not payload and false conditions do not renumber slots. read/delete have no slots. Control expressions use source-block dispatch inputs, never previous-IR locals.

[中文对照]
坐标。直接 CFG target 只能使用一种完整形式：指令为 {"instruction_id":"ir_demo","path":[]}；块为 {"block_id":"block_demo","path":[]}；图为 {"path":[]}；操作数为 {"instruction_id":"ir_demo","side":"input","index":0}。path 即使为空也必须填写；仅有身份无效。realization bindings 可使用一般图／块／约束目标。可执行 action demands 要求实际 IR 或原子操作，不能用图／块对应关系替代；value demands 要求实际操作数或操作值，不能使用名称／容器。ValueRef input(index) 始终读取所属 IR 的入口操作数；local(name) 的词法作用域限于该 IR／scope。操作 demand 的 input(index) 则选择该操作消费的槽位。判断前解析 slot → ValueRef → 实际值。有输出操作的非 action self 指向该输出，而非附着表达式。compute／deliver／receive 槽位按 inputs 顺序；select_part／exclude_parts／filter_items 和非 delete write 使用槽位 0；update_fields 先 base 后 updates。build 按 parts 顺序遍历：value，或先 when 后 value。控制不是载荷，false 条件不会重新编号槽位。read／delete 没有槽位。控制表达式使用源块 dispatch 输入，不能使用上一 IR 的 locals。

shared-rule-03 · 共用规则 3：路径与引用

[ENGLISH]
PATHS AND REFERENCES. Preserve ordered inputs and repeated uses. String keys and integer indexes differ. Alternatives are candidates, not composed contents. Resource identifiers locate boundaries, not automatically contents. Define locals once; body locals do not escape and scopes cannot shadow. In partial order only alternatives retaining an available candidate may reference a later local; no cycles. Output bindings cover exactly public outputs and alias existing values without hidden processing or writes.

[中文对照]
路径与引用。保留输入顺序及重复使用。字符串键与整数下标不同。alternatives 是候选，不是拼合后的内容。资源标识符定位边界，不自动代表内容。locals 只定义一次；body locals 不外泄，作用域不可遮蔽。在部分顺序中，只有仍保留可用候选的安排才能引用较后的 local；不能存在环。输出绑定恰好覆盖公开输出，只为已有值建立别名，不包含隐式处理或写入。

shared-rule-04 · 共用规则 4：需求性质
来源：src/skillflow/propagation/contracts/format_instructions.py :: _RULES[3]
使用阶段：完整联合标注、固定 Task 标注修复、全局语义初审、标注独立复审、共用规则、显示与格式

[ENGLISH]
DEMAND PROPERTIES. value preserves exact content or a specified field; presence preserves existence, not nullness or truth; cardinality preserves collection count, not successful action count; shape preserves relevant structure/member selection, not every member value; truth preserves an actual Boolean/condition result; action preserves required behavior, not all arguments. A filter_items output is a collection, not the predicate Boolean: neither self/truth nor output/truth encodes its predicate. Its expression supplies the member decision when supported demands traverse the filter; do not invent a separate predicate-value seed. Downstream field demands and count demands remain separate. Genuine whole-value requirements stay value; opaque output demands may conservatively retain whole inputs without asserting that source requires every input field.

[中文对照]
需求性质。value 保持精确内容或指定字段；presence 保持存在性，不是 null 与否或真值；cardinality 保持集合数量，不是成功动作次数；shape 保持相关结构／成员选择，不是每个成员的值；truth 保持实际布尔／条件结果；action 保持规定行为，不是全部参数。filter_items 输出是集合，不是谓词布尔值：self/truth 与 output/truth 都不能编码其谓词。受支持的需求穿过筛选时，由该操作 expression 提供成员判断；不要编造单独的谓词值种子。下游字段需求与计数需求仍分开。真实整值要求仍使用 value；不透明输出需求可以保守保留完整输入，但不能声称原文要求每个输入字段。

ENDPOINT DEMANDS. Required delivered content needs a demand at the actual deliver input slot, retaining field-original relation, conditions, version and same-element identity. A receiver-input shape demand preserves members/structure, not their values; action plus shape cannot substitute for required parameter content. expected/expected_path states the required original relation; it does not execute select_part, narrow actual payload, or encode a Boolean when. Its independent source demand does not inherit build.when: omit redundant expected for a conditional member whose original value is already retained by explicit select_part/build; build controls consumption. Keep actual field selection and conditional construction explicit even if expected names the desired field. An upstream select_part/build seed alone does not flow forward to every receiver. Migrate redundant endpoint-only content demands, removing their old placements; retain actual select/build/when, independently required upstream results and conservative dependencies. A shared requirement ID does not prove redundancy. A required save preserves both its action and specified actual write input; append means the new payload, not old storage. Inspect every applicable invocation, retry and terminal write separately. Shared requirement IDs or Data IDs do not copy demands across recipients/stages. Preserve supported abstract result-to-write relationships without inventing a serializer. Open encoding alone creates no gap; a separately required format/quality/order restriction that remains unrepresented needs an evidenced gap. A declared gap does not excuse the representable part.

[中文对照]
接收边界需求。规定交付的内容需要在实际 deliver 输入槽位建立 demand，保留字段原值关系、条件、版本和同元素身份。接收输入的 shape demand 保持成员／结构，不保持其值；action 加 shape 不能替代规定参数内容。expected／expected_path 说明规定原值关系；不执行 select_part、不缩小实际载荷，也不编码布尔 when。它产生的独立来源需求不继承 build.when：当条件成员的原值已经由明确 select_part／build 保留时，应省略冗余 expected；由 build 控制消费。即使 expected 命名目标字段，也须明确保留实际字段选取与条件构造。仅有上游 select_part／build 种子不会向前流到每个接收方。迁移仅服务接收端的冗余内容 demands，删除旧位置的副本；保留实际 select／build／when、独立要求的上游结果与保守依赖。共享 requirement ID 不能证明冗余。规定保存既保持动作，也保持指定实际写入输入；append 表示本次新载荷，不是旧存储内容。分别检查每次适用调用、重试和终态写入。共享 requirement ID 或 Data ID 不会跨接收方／阶段复制 demands。保留有依据的抽象结果到写入关系，不编造序列化器。仅有编码开放不产生 gap；另有规定但尚未表达的格式／质量／顺序限制，才需要有证据的 gap。声明 gap 不能免除可表达部分。

CONSTRAINT DECLARATIONS. review-workflow · 语义审查：四轴检查
来源：src/skillflow/propagation/review/prompts.py :: WORKFLOW
使用阶段：全局语义初审、标注独立复审

[ENGLISH]
4. FOUR INSPECTION AXES
Source inspection: reread all supplied skill/ files, including background, implementation, capabilities and examples. Report a concrete omission through a finding with exact source evidence and a real Task parent target; do not emit a per-line coverage table. A line may contain several obligations; one obligation may span files. Explicit source prohibitions must remain in Task even when implementation excludes the information or sensitivity labels exist; private/sensitive wording alone is not a prohibition. Report omissions as source-only domain=task objections; do not invent a prohibit demand or requirement ID. Check conflicts, outstanding Task issues and precedence. Accepted limitations remain limitations.
Requirement checks: cover each existing requirement exactly once. Compare purpose, outcomes, conditions, scope, counts, ordering, quality, identity, pairing, side effects and prohibitions to source. Then inspect realization, all applicable operations, demands, constraints and gaps. Check missing demands, not only declaration_index: required delivery content needs an actual receiver-input demand; a required save needs specified write payload as well as action. Upstream selection/build goals do not automatically reach a downstream boundary. Check every retry/invocation/terminal covered by the requirement; matching values do not confer coverage. An evidenced remaining format restriction does not excuse an already-supported abstract result-to-write relationship. Open encoding alone is not a gap; do not invent encoding or an unsupported format obligation. Missing requirements belong in source/task findings, not fabricated IDs. expressed/partial/retained_only/unmapped means expression, not satisfaction.
Declaration checks: copy the exact set of raw_pointer strings from declaration_index, once each, covering both kind=demand and kind=constraint. Do not invent or infer a pointer for a missing demand; report that omission through requirement_checks and an existing realization/operation parent. Resolve operation slot -> ValueRef -> actual IR/local version before judging; never substitute an IR input index for an operation parameter slot. Check demand property, path, expected original relation, version, condition, member scope and receiver, not merely whether expected points somewhere real. Apply the shared acquisition/demand distinction: a whole read or observation does not by itself justify a whole-value Task demand. Detect required field expanded to whole value; filtering expanded to every member's content; collection output truth pretending to be predicate; presence/count expanded to all content; model filtering information expanded to tool payload; action expanded to all inputs; broad upstream input replacing required result. Preserve actual whole-value obligations and conservative opaque/receive influence. Conservative whole request retention is not the required precise parameter relation.
For constraints, inspect the prohibited information relation, complete applicable receivers/events, same-version condition, occurrence unit/reset scope and event matching. A pure restriction needs no positive demand. Expression is not enforcement: reject a claimed implemented deletion, guard, call bound or order inferred only from a Task restriction. Supported constraints need not be marked satisfied; unknown checking capability and possible violation are not instructions to fabricate a mechanism. Mixed requirements must retain both positive and restriction parts; a single constraint does not cover an unrelated positive obligation.
IR checks: reviewed_ir_ids covers every actual IR exactly once. Inspect source scope, actual processing/mode, field/member relations, acquisition origins, versions, delivery, sensitivity and lexical scopes. This declares inspection, not comprehensive source-to-CFG equivalence or semantic proof.


[中文对照]
4. 四个检查轴
原文检查：重新阅读所有提供的 skill/ 文件，包括背景、实现、能力及样例。通过有精确原文证据和真实 Task 父目标的 finding 报告具体遗漏；不要输出逐行覆盖表。一行可能包含多项义务，一项义务也可能跨文件。源文明示的禁止事项必须保留在 Task 中，即使实现已经排除该信息或已有敏感性标签；仅有 private／sensitive 措辞并不是禁令。将遗漏报告为仅依赖源文的 domain=task 异议；不要编造 prohibit demand 或 requirement ID。检查冲突、尚未解决的 Task issues 及优先级。已经接受的能力限制仍是限制。
要求检查：每项既有 requirement 恰好覆盖一次。将目的、结果、条件、范围、次数、顺序、质量、身份、配对、副作用和禁止事项与原文比对。然后检查 realization、全部适用操作、demands、constraints 与 gaps。检查缺失的 demands，而不只是 declaration_index：规定的交付内容需要实际接收输入 demand；规定的保存不仅需要 action，也需要指定写入载荷。上游选取／build goals 不会自动到达下游边界。检查要求覆盖的每次重试／调用／终态；值相同不能证明覆盖。即使有证据支持剩余格式限制，也不能省略已经有依据的抽象结果到写入关系。编码开放本身不是 gap；不要编造编码或无依据的格式义务。遗漏要求应在 source／task findings 中报告，不得编造 ID。expressed／partial／retained_only／unmapped 表示表达情况，不是满足情况。
声明检查：从 declaration_index 原样复制全部 raw_pointer，每条恰好一次，同时覆盖 kind=demand 与 kind=constraint。不要为缺失 demand 编造或推断指针；通过 requirement_checks 和已有 realization／operation 父对象报告遗漏。判断前解析 operation slot → ValueRef → 实际 IR／local 版本；不能用 IR 输入下标替代操作参数槽位。检查 demand 的性质、路径、预期原值关系、版本、条件、成员作用域和接收方，而不只是 expected 是否指向真实位置。应用获取／需求区别：整体读取或观察本身不能证明整值 Task demand。识别这些扩大：规定字段扩大为整值；筛选扩大为每个成员的全部内容；集合输出 truth 冒充谓词；presence／count 扩大为全部内容；模型筛选信息扩大为工具载荷；action 扩大为全部输入；宽上游输入替代规定结果。保留真实整值义务，以及不透明／receive 的保守影响。保守保留完整请求不等于已经表达规定的精确参数关系。
对于 constraints，检查禁止的信息关系、完整适用接收方／事件、同版本条件、发生单位／重置范围和事件匹配。纯限制无需正向 demand。表达不等于实施：拒绝仅从 Task 限制推断已实施删除、guard、调用上限或顺序的声称。受支持的 constraints 不必标为满足；检查能力未知或可能违反，不意味着应该编造机制。混合要求必须保留正向部分和限制部分；一个 constraint 不能覆盖无关的正向义务。
IR 检查：reviewed_ir_ids 对每条实际 IR 恰好覆盖一次。检查来源范围、实际处理／mode、字段／成员关系、获取来源、版本、交付、敏感性与词法作用域。这是已检查的声明，不是完整源文—CFG 等价或语义证明。

5. REVIEW DECISIONS AND ROUTING
Use frozen runtime defaults. Simplicity, predicates, operator labels, tool names or no LLM mention do not prove local isolation. Respect explicitly limited local returns/getters/proxies. Distinguish internal reads, returned contents, model-visible versions and downstream parameters. Old observations survive later cleanup; contract observations are static possibilities, not measured exposure. Check modes against evidence, not merely compiler success.
Explicit fields require select_part; unchanged member selection requires filter_items. Do not infer paths from names or excuse opaque field extraction just because CFG names an output. Preserve same-element pairing and conditions. Influence is not plaintext inclusion; unknown content is not absence of sensitive information. Optional fields keep original value and separate Boolean presence control; false omits, not null; controls are not payload. Request delivery, acquired return source and model observation remain different facts.
Inspect location access_scope/retention against evidence and runtime defaults. Tool names, send verbs and recipient labels are not transport evidence. Unspecified deployment can use tool/recipient/null without invented networking; unknown network transport must not erase known acquisition/delivery. Deletion is not content saving; append concerns actual new payload. The compiler derives sink types/levels, not model-written scores.
Check sensitivity against supplied original context: omitted supported sensitive content, invented fields, wrong value/path/property/version/member scope, or unsupported categories are material. Value sensitivity does not automatically make presence/cardinality/shape/truth sensitive; each is a member template, not index zero. Cross-check Task, demands, constraints, processing and sensitivity. Prohibitions and sensitivity are independent; do not fabricate a ban from a sensitivity label or positive demand from a prohibition. Do not demand per-IR necessity, constraint satisfaction proofs, reduction verdicts or unsupported constraint semantics.
Report concrete differences affecting scope, identity, dependence, versions or boundaries, not wording alone. Ordinary return identity is in CFG inputs even with empty events/output_bindings; no fabricated public output or caller delivery. Do not reopen full CFG equivalence or change CFG to fit annotation. Faithful opacity, defaults, candidates, partial order and honest unsupported restrictions do not alone justify cannot_assess.
FINDINGS: use existing target_index IDs; missing claims point to existing parents. Each finding connects expected relation, actual claim, discrepancy, affected information and actionable suggestion. Program assigns finding IDs; do not emit them.
- domain=task: source interpretation/omission/broadening, lost condition/scope, atomicity or conflict resolution. Target a task claim/container and cite source spans only. task_objection contains only finite code, source_spans={file,start_line,end_line}, existing requirement_ids (empty for omissions). No free review text, CFG, goals, payloads or sinks enters this projection. An omitted requirement has no existing requirement row: its source evidence and source-only objection anchor the finding; do not invent an ID or check row. For each existing requirement named in an objection, mark its requirement check issue and link this finding.
- domain=annotation: incorrect realization/demand/constraint/processing/sensitivity against a faithful Task. No task_objection; suggest complete fixed-Task repair. Missing endpoint demands target realization/operation parents. For each redundant upstream content demand, cite its supplied demand target ID or exact declaration_index.raw_pointer and destination receiver slot/path; include named IDs in target_ids for repair resolution. Remove that original demand when relocating, not its operation. Resolve redundancy against the actual Task, not a generic conditional suggestion. Preserve select_part/build/when, supported control demands, independent upstream/return demands and conservative relations; do not preserve the named redundant demands or duplicate them. A Task wrongly requiring the whole object needs a task finding.
Checks use only section 3's keys: put explanations in reason, never new note fields. accepted requires finding_indexes: []; issue requires existing zero-based finding indexes and cannot hide its conclusion only in reason. Evidence supports source or graph facts; target_ids already locates the candidate claim. Source evidence alone may suffice. Source spans are inclusive and program-extracted: no quote/basis/paragraph/digest copies.

5. 审查判断与修复归属
采用冻结的运行时默认规则。简单性、谓词、operator 标签、工具名称或未提及 LLM 不能证明本地隔离。尊重明确限定的本地 returns／getters／proxies。区分内部读取、返回内容、模型可见版本与下游参数。后续清理不会撤销旧观察；契约观察是静态可能性，不是测得的暴露。根据证据检查 mode，而不只是检查编译成功。
明确字段需要 select_part；成员原内容不变的选取需要 filter_items。不要从名称推断路径，也不能因 CFG 给输出起了名字，就认可不透明字段提取。保留同元素配对与条件。影响不是明文包含；未知内容不等于没有敏感信息。可选字段保留原值，并将布尔存在性控制分开；false 表示省略，不是 null；控制不是载荷。请求交付、返回获取来源和模型观察仍是不同事实。
对照证据和运行时默认检查位置 access_scope／retention。工具名称、发送动词和接收者标签不是传输证据。部署未说明时可使用 tool／recipient／null，不编造网络通信；网络传输未知也不能抹掉已知获取／交付。删除不是保存内容；append 关注本次实际新载荷。sink 类型／等级由编译器推导，不由模型填写分数。
根据提供的原始语境检查敏感性：遗漏有依据的敏感内容、编造字段、错误的 value／path／property／version／成员作用域或无依据的类别，均是实质问题。值敏感性不会自动使 presence／cardinality／shape／truth 敏感；each 表示成员模板，不是下标零。交叉核对 Task、demands、constraints、处理和敏感性。禁止事项与敏感性彼此独立；不得由敏感性标签编造禁令，也不得由禁令生成正向 demand。不要要求逐 IR 必要性、constraint 满足证明、缩减裁决或未支持的 constraint 语义。
报告影响范围、身份、依赖、版本或边界的具体差异，而不只报告措辞。即使 events／output_bindings 为空，普通 return 身份仍在 CFG 输入中；不编造公开输出或向调用者的交付。不要重做完整 CFG 等价核对，也不要为了适配标注修改 CFG。忠实的不透明关系、默认规则、候选、部分顺序和如实表达的未支持限制，本身不足以构成 cannot_assess。
FINDINGS：使用已有 target_index ID；缺失声称定位到已有父对象。每条 finding 连接预期关系、实际声称、差异、受影响信息与可执行建议。finding ID 由程序生成，不要输出。
- domain=task：原文解释／遗漏／扩大、丢失条件／范围、原子化或冲突解决问题。定位 Task 声称／容器，只引用原文范围。task_objection 只包含有限 code、source_spans={file,start_line,end_line} 和既有 requirement_ids（遗漏时为空）。不得向这个投影输入审查自由文本、CFG、goals、载荷或 sinks。遗漏要求没有既有 requirement 行：以原文证据和仅源文异议定位 finding，不编造 ID 或检查行。异议中提到的每项既有 requirement 都须在其检查中标记 issue 并链接该 finding。
- domain=annotation：Task 忠实，但 realization／demand／constraint／处理／敏感性错误。没有 task_objection；建议完整的固定 Task 修复。缺失接收需求定位到 realization／operation 父对象。对每条冗余上游内容 demand，引用提供的 demand 目标 ID 或精确 declaration_index.raw_pointer，并指明目标接收槽位／路径；在 target_ids 中加入这些具体 ID，便于修复定位。迁移时删除原 demand，不删除其操作。根据实际 Task 判断冗余，不能只给泛泛的条件建议。保留 select_part／build／when、受支持的控制 demands、独立上游／return demands 和保守关系；不要保留点名的冗余 demands 或重复添加。如果 Task 错误地要求整个对象，应提出 task finding。
检查项只使用第 3 节规定的键：解释写入 reason，不新增 note 字段。accepted 必须有 finding_indexes: []；issue 必须引用已有的从零开始的 finding 下标，不能只在 reason 中暗含结论。证据支持源文或图事实；target_ids 已经定位候选声称。仅源文证据也可能足够。原文范围包含两端并由程序提取：不要复制 quote／basis／段落／摘要。

REFERENCE SPACES (complete forms, never interchangeable)
| Field | Supplied object | Purpose |
| findings[].target_ids | IDs from target_index | Locate the candidate claim or an existing parent for missing content. |
| declaration_checks[].raw_pointer | Exact strings from declaration_index | Check each existing demand or constraint; a missing declaration has no pointer to invent. |
| evidences[].target | An actual cfg object: e.g. {"instruction_id":"ir_example","side":"input","index":0} or {"instruction_id":"ir_example","path":["constraints",0]} | Support that graph operand or constraint, not a candidate demand list. Whole instruction/block references require path:[]. |
| evidences[].file/start_line/end_line, or rule_id | Frozen source, or supplied runtime rule | Support the stated requirement, mechanism or applicable default. Include reason. |
CHECK KEYS (exact; no additional fields): requirement_checks={requirement_id,status,reason,finding_indexes}; declaration_checks={raw_pointer,status,reason,finding_indexes}.
Processing segments, atomic_ops, their demands and realization constraints belong to raw_annotation. Do not place their paths under a CFG evidence target or claim that a CFG IR contains those annotation operations/demands. Its evidence reason must state only the resolved graph fact; target_ids locates candidate operations/demands. Field membership established by source belongs in file/line evidence, including in sensitivity findings. A bare result operand supports its symbol identity only: do not add a clause such as "which contains the source-named field". Omit CFG evidence when it adds no needed graph fact; source evidence alone may suffice. Real metadata with the same name remains a graph field; resolve the object, not a key-name blacklist.

来源：src/skillflow/common/prompt_format.py :: render_prompt_format legend

[ENGLISH]
Format notation: fields are required unless suffixed ?. Omission is distinct from null. ANY allows one or more branches; ONE exactly one; ALL and & require all constraints. extra:FORBIDDEN rejects unknown object keys; extra:JSON permits them. Arrays preserve order; ... describes each remaining item. Defaults apply only on omission. JSON means any JSON value. pattern is a regular-expression constraint. Named types below are definitions, not additional response fields. Application rules follow.

[中文对照]
格式记号：没有 ? 后缀的字段都是必填字段。省略与 null 不同。ANY 允许一个或多个分支，ONE 恰好一个，ALL 和 & 要求满足全部约束。extra:FORBIDDEN 拒绝未知对象键；extra:JSON 允许。数组保留顺序；... 描述剩余每个元素。默认值只在省略时应用。JSON 表示任意 JSON 值。pattern 是正则表达式约束。下方命名类型是定义，不是额外响应字段。后续还有应用规则。
