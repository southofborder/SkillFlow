# SkillFlow Data 数据结构与更新规则

状态：Data v4 数据契约。快照版本为 `skillflow-data-v4`；v1／v2／v3 历史快照不自动迁移。

本模块为后续静态数据最小化分析提供统一的数据载体。来源整体、组成部分和处理结果
均使用 `Data`，固定表达已知内容、数据身份以及调用方声明的生产关系。数据结构本身
不证明原 Skill 与 CFG 等价，不执行 Skill，不判断敏感信息是否必要或已经发生泄露。

Data 模块本身不实现传播记录、图遍历、固定点、观察事件或 DOE 判定，不调用 LLM。
操作关系由调用方依据已有材料明确提供；模块不从开放 opcode 或标签猜测业务语义。
原始 IR、Security Profile 与现有生产流程不依赖本模块，也不增加字段。

## 文件与依赖

```text
src/skill_ir/data/
  __init__.py       公共模型与注册表入口
  models.py         固定字段、内容形态和局部结构校验
  registry.py       身份、登记、细化、引用、快照导入导出
examples/
  data_model_demo.py
tests/data/
  test_models.py
  test_registry.py
  test_resolution.py
```

注册表依赖模型；Data 模块不依赖 LLM 客户端、Security Profile 或传播运行时。
独立传播模块读取 IR 与动作标注，再调用本模块。IR 不反向导入 Data。

## 固定数据契约

`Data` 外层只有四个字段，所有结构拒绝未知字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 注册表命名空间中的稳定数据身份，不直接等于 IR result ID |
| `content` | 当前内容的组织、已知部分或保留/排除范围 |
| `origin` | 获取位置、所属整体、已有操作、输入和输出依赖 |
| `annotations` | 描述、已有敏感性标签，以及留给后续 DOE 敏感性判断的依据 |

结构由 Pydantic 模型约束，不以任意开放字典代替正式契约。`LiteralContent` 中
被分析数据的 JSON 值可以包含业务字段；这不允许在 Data 结构上增加任意字段。

### 内容的六种形态

| `form` | 字段 | 解释 |
| --- | --- | --- |
| `opaque` | 无额外字段 | 内容尚未展开；不是空值、空对象或无依赖 |
| `known_parts` | `parts`、`parts_complete` | 已识别的可能组成部分；默认未列全 |
| `whole_except` | `base`、`excluded_parts` | 保留 base 整体，明确排除所列位置及其内部组成 |
| `field_updates` | `base`、`updates` | 用指定 Data 覆盖非交叠路径；保留 base 的其他未知内容 |
| `subset_view` | `base`、`predicate` | 原集合的候选子集视图；成员内容身份保留，文字谓词不由分析器执行 |
| `literal` | `value` | 明确的 JSON 值，包括 null、空对象和空列表 |

组成条目采用 `DataPart(path=[...], data="Data ID")`。`parts` 是固定结构条目的列表，
不内嵌另一份 Data。此前草图中的业务字段字典落为这个列表，是为了统一保留字段路径
和索引类型：`["0"]` 是字段名，`[0]` 是数组索引，二者不能混同；布尔值不能冒充索引。
字符串片段保持原始值，不根据点号、斜杠或名称相似性猜测路径层级。

v4 的路径增加 `{"kind":"element","scope":"稳定作用域身份"}`，表示未知长度集合中当前符号元素。
它不同于真实第零项、字符串 `"*"` 或字段名。`resolve_elements(collection, scope)` 在开放集合上
产生一个稳定的符号元素；在已经明确给定的有限字面列表上返回各候选成员。对子集视图，选择
穿过 `base`，同一元素的字段仍来自原集合；记录另外保留实际遍历的子集 ID。分析器不执行谓词，
不声称所有候选成员真的会被选中。固定下标不能穿过子集直接当作原集合同一下标。

新增 `subset_view(key, base, predicate, origin)` 登记视图；`resolve_element/resolve_elements` 复用成员；
`validate_element_membership` 独立核验 DOE 中的元素属于该集合或其基础集合。字面列表成员也有
明确 `part_of/path`，不会仅因值相同就合并来源身份。实际原子操作和记录见
[字段关系与观察编译](SkillFlow-字段关系与观察编译.md)。

```python
KnownPartsContent(
    parts=[DataPart(path=["amount"], data=amount_id)],
    parts_complete=False,
)
WholeExceptContent(base=document_id, excluded_parts=[["api_key"]])
FieldUpdatesContent(base=document_id, updates=[DataPart(path=["owner"], data=new_owner_id)])
```

`parts` 表示已识别的可能组成，不保证每次运行都存在，也不保证同时存在。
本版合并可能组成时不附路径条件。普通发现不能将 `parts_complete` 自动升级为真。
只有调用方明确声明组成已完整列举，才指定 `parts_complete=True`。该声明的判断责任
在规格／构造边界，例如明确 `build` 的构造范围；Data 不复制上游证据，也不再要求一个
非空证据字符串来“证明”完整。字段默认仍为 False，发现部分不自动关闭未知剩余。

明确构造 `{owner, total, debug}` 可以登记完整组成；从文档中发现两个字段不能据此
认定它只有两个字段。明确空对象通过 `literal(value={})` 表达，与 opaque 有别。

### 来源、输入与依赖

`Origin` 固定包含以下字段，按适用情形填写：

| 字段 | 含义 |
| --- | --- |
| `at`、`acquired_from` | 操作定位与外部获取来源 |
| `part_of`、`path` | 某部分所属的整体与选择位置，成对提供 |
| `inputs` | 操作实际使用的数据 ID，保留次序与重复出现 |
| `dependencies` | `Dependency(data, relation)` 列表 |

依赖的 `relation` 只取 `derived` 或 `possible`：前者记录已有明确运算依据下的
派生关系；后者记录尚未排除的依赖可能性。内容保留通过 content 的引用、组成和
排除表达，不由 inputs 或 dependencies 推断为明文包含。

例如，`sum(B.amount)` 的结果与金额有关，但不声称保存金额明细；不透明 `f(B)`
保留对 B 的可能依赖，也不声称包含 B 的全部明文。这类结果仍可由后续算法使用，
本模块不因 opaque 或 possible 发起人工核对或额外模型调用。

新结果 ID 不等于新外部来源。常量、求和、摘要和加密结果均不会自动设置获取来源。
外部响应可以同时具有获取来源和输入依赖，这两种信息不设为互斥身份。

`Annotations` 固定包含 `description`、`sensitivity`、`evidences`。敏感性标签采用调用方
已有的字符串标签，本轮不引入固定分类。`evidences` 为不重复的非空白字符串列表，默认
为空，**只留给后续 DOE 阶段的敏感性判断依据**，不用于描述来源、传播关系或计算过程。
传播不会自动填写它，也不会把原来的 `spec:` 定位或传播证据迁入该字段。

`Origin` 与 `Dependency` 不再保存证据字段。获取位置、输入和派生关系仍保留，它们是
分析所需的数据关系，不是额外证据链。没有敏感性标签不等于不敏感；Data 不保存风险、
必要性或 DOE 结论，也不检查依据文字的语义真伪。本轮没有实现终端敏感性判定算法。

## 身份、登记与更新

注册表公共入口为 `DataRegistry(namespace)`；主要接口如下：

| 接口 | 行为 |
| --- | --- |
| `register_source(key, acquired_from=..., ...)` | 按稳定获取身份登记来源 |
| `create_result(key, content=..., origin=..., ...)` | 登记有明确生产关系的结果 |
| `register_part(parent_id, path, ...)` | 登记并复用同一整体的同一部分 |
| `refine(data_id, parts=..., annotations=..., ...)` | 在同一身份上补充组成描述或敏感性标注 |
| `get(data_id)`、`get_part(data_id, path)` | 查询记录或可明确定位的部分 |
| `resolve_part(data_id, path)` | 确定性解析路径，必要时登记部分或经过排除／覆盖的子视图 |
| `revision` | 当前实例的描述变更计数；纯新增结果不推进该计数 |
| `validate()` | 检查当前注册表的结构与引用一致性 |
| `to_dict()`、`to_json()` | 导出完整快照 |
| `from_dict()`、`from_json()` | 校验并恢复同版本快照 |

三个登记／细化接口不再接受 `evidence_refs`；旧关键字明确报错，没有兼容别名：

```python
register_source(key, *, acquired_from, at=None, content=None, annotations=None)
register_part(parent_id, path, *, content=None, annotations=None)
refine(data_id, *, parts=None, parts_complete=None, annotations=None)
```

来源和结果 ID 由格式版本、命名空间、登记类别及调用方稳定身份键确定性生成，采用 SHA-256。
它们不依赖当前内容或已知部分数量。同名资源在不同获取位置不能自动合并；相同静态
结果位置重复登记复用身份。调用方应把所选分析身份放入命名空间，避免把不相关图的
同名操作误当成同一位置。该机制不是运行时对象身份分析，也不是循环传播算法。

部分身份由父 Data 与规范化路径稳定确定；相同位置重复发现不增生 ID。
通过部分的 `part_of/path` 归一到所属根与完整路径，因此先登记 `B.a.x`，或先登记
`B.a` 再登记其中的 `x`，使用同一部分身份。字段名与下标的类型参与身份计算。
IR 结果与 Data 的绑定留在外置传播记录中，不要求为每次原样传递新建 Data。

更新规则：

1. **细化保持身份。** 发现 B 原本就有字段，只补充 B 的描述，并按需登记子 Data。
   不将原始获取改写为后来处理，不自动缩小原整体，也不自动认定已列全。
2. **内容变化产生结果。** 删除、追加、替换、组合和运算登记另一个结果，输入保持不变。
   明确选择已经登记的部分可以复用该部分，原样传递直接复用已有 ID。
3. **合并可能组成不附条件。** 不建立分支专属 B；也不把多个可能部分解释为必然同时存在。
   本轮没有路径记录或分支可行性分析。
4. **重复更新幂等。** 相同部分和敏感性依据不重复积累；同身份的不兼容定义明确失败，不采用
   后写覆盖。已有输入次序和重复项不因集合去重而丢失。
   同身份重复登记要求完整 `origin` 一致：获取位置、来源、输入次序与重复以及依赖对象、
   关系与次序均不能改变。已有非空 `description` 不被不同文字替换，敏感性标签和其依据
   可以追加；本模块不判断两段不同描述是否语义等价。将当前组成明确设为完整须显式
   调用 `refine(..., parts_complete=True)`，不在 Data 内另设证明字段。
5. **完整组成不可任意扩展。** 完整组成与新的不兼容定义冲突时报告结构使用错误；不能
   用普通细化重写它、将其重新设为不完整，或借 opaque 抹除已知内容。相同路径不能换成
   不同 Data；以完整内容重复登记来源／结果时，也不能遗漏此前已知部分。
6. **查询对象与内部记录隔离。** 返回值为深拷贝。修改返回对象的嵌套列表或字典不会修改
   注册表；请求中的对象也不直接保存为可由调用方绕过接口修改的共享容器。
7. **覆盖不枚举剩余。** `field_updates` 先匹配更新路径，再查询原 base；后续识别的未覆盖
   部分仍保留。一次 updates 至少一项，不允许相同或父子交叠路径。确有先后覆盖时登记
   多个结果版本，不让列表顺序暗中决定覆盖含义。覆盖前的原 Data 保持原样。

`revision` 只在已有 Data 的内容、描述或敏感性标注实际变化时增长。新增结果不会单独触发；
新增部分通常同时细化已有父 Data，因此会增长。重复登记相同事实不增长，失败更新不增长。
该计数供求解器发现“ID 未变但描述已细化”，不写入快照、不参与身份；导入新实例从零开始。

组成关系与派生关系分别校验，不把所有 Data 引用强制为一个无环图。允许的依赖环并不
意味着支持了循环语义、无限对象展开或固定点收敛。

### 排除与后续细化

`whole_except` 保存 base 引用和排除路径，不物化当前剩余字段列表。例如
`B_without_key = whole_except(B, api_key)` 创建后，再识别 B 的 address，address
仍属于未被排除范围。B 的 api_key 即使后来展开出子部分，也不会重新进入输出。

`get_part` 只返回能安全对应到已有记录的部分。请求被排除部分、其内部组成，或者
请求一个内部已被局部排除的祖先部分时，不能返回未经筛选的原 Data 冒充输出。
后一种情形会报错，不在查询时悄悄构造新数据。本版查询也不猜测尚未登记的部分。
这属于结构查询边界，不是推断“其余数据不存在”。查询已登记部分失败，也不构成未来
传播必须停止的规则；未展开的整体及其可能依赖仍然保留。当前模块本身没有传播调度。

`resolve_part` 是明确的、可登记视图的接口，区别于上述只读 `get_part`：

- opaque 或未列全的 known_parts：登记稳定部分，不缩小整体；在排除／覆盖视图上发现的
  未受影响部分登记回原始 base。
- literal：按实际 JSON 类型解析路径，保留 null、空对象、空列表及数字类型；不执行开放函数。
- whole_except：被排除部分仍拒绝；选择被局部排除的祖先时，建立相对路径排除的子视图。
- field_updates：更新内容优先；选择被部分更新的祖先时，建立对应子覆盖视图，不能直接
  返回旧祖先。明确新增的更新值可以重新引入字段，但不能借此恢复原来已经排除的未知内容。
- 已知不存在的字段不补造成 opaque；同一输入和路径重复解析复用身份，来源 inputs 不变。

解析失败会回滚该次调用的全部中间登记、描述细化和 revision。视图是数据内容关系，
不会补造 CFG 指令，也不声称任何 Skill 操作已经成功执行。

## 快照与错误边界

JSON 快照保存 `skillflow-data-v4` 版本、命名空间、身份键以及全部 Data。导入恢复
原有身份、关系、字面值类型和输入次序；引用与身份不匹配的快照明确拒绝。
未知版本不自动迁移。严格 JSON 不接受重复键、非有限数字或非 JSON 对象冒充值。
缺失版本同样拒绝，不将其默认为当前版本。字段类型也不通过空 tuple、字典等值自动
转换为列表；完整组成的重复声明不能遗漏此前已经登记的部分。

v3 拒绝 Origin／Dependency 的旧 `evidence_refs` 和 Annotations 的旧同名字段，不能靠
删除未知字段静默迁移。格式版本参与 ID 计算，所以同一身份键在 v3 的 Data ID 与 v2
不同；需要在新运行中生成新版材料，不改写历史记录、旧引用或既有摘要来冒充原运行。

错误分为结构模型不合法、身份/定义冲突、缺失引用、非法组成关系、不可返回的部分以及
不兼容快照。它们均不能静默补齐或按最后一项覆盖。完整声明和结构检查不能代替语义
判断；注册表不验证调用方所说的删除、求和或完整构造是否真的出现在 Skill 中。

局部模型问题使用 Pydantic `ValidationError`；注册表提供 `DataRegistryError`，以及
其子类 `DataConflictError`、`DataReferenceError`，分别表达定义冲突与引用/查询失败。
这些异常均属于 `ValueError` 家族。更新失败不会留下部分提交的数据。
重叠路径会核对沿途的组成、封闭范围与排除关系，不能用外层的直接深路径绕过中间
数据的排除或完整组成。对尚未展开内容的缺少认识与明确禁止返回的部分分别处理。

## 可运行示例与集中验收

先安装包，再从仓库根目录运行：

```powershell
python -m pip install -e packages/skill-ir
python packages/skill-ir/examples/data_model_demo.py
python -m pytest packages/skill-ir/tests/data -q
```

示例提供 `build_demo() -> DataRegistry`，只构造分析记录并将快照 JSON 打印到标准
输出，不写文件、不保存真实凭据、不执行求和或外部调用。打印前先做导出恢复一致性检查。

示例构造 A.owner、B.amount 和 B.api_key；T 由 B.amount 派生；C 的完整组成是
`owner → A.owner`、`total → T`、`debug → B`。随后登记排除 C.debug、排除 B.api_key
的新结果，以及对 A.owner、B 保留可能依赖的不透明结果 U。最后细化 B.address，
验证删除密钥后的内容仍保留 address，而被排除的密钥不能通过查询取回。
示例还展示覆盖 C.debug.api_key、解析更新后的 debug 子视图，以及 literal 的确定性选取；
覆盖视图仍保留后来识别的 B.address，不将替换字段推断成完整的隐私保护保证。
v3 示例只在全部关系构造后显式追加一条人工敏感性示例，用 `annotations.evidences`
说明凭据标签；这不是传播自动推断，也不是已实现 DOE 判定的实测结果。

测试集中覆盖内容形态、空值区分、严格字段、类型明确的路径、输入次序、重复登记、
来源区分、细化不换身份、新结果不覆盖旧数据、排除关系与后续细化、快照恢复、错误引用、
调用方容器隔离及依赖边界。测试是设计和实现验收，不是在未来每次传播时新增语义复核。

独立的[传播算法与 IR 传递规格](SkillFlow-传播算法与IR传递规格.md)引用本规范，规定 IR
绑定、候选集合、效果事件、传播调度和更新规则。本版结构检查不宣称数据传播健全性、
原文与图等价或 DOE 判定正确。
