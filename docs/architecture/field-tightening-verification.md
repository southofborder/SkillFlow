## 已落实的边界

1. 联合输入只有 source、cfg、runtime_contract、user_request。物理行展示按需生成；不发送段落编号或整图地址表。
2. Task 保留目的、要求、原文依据及一般图中对应；demands 引用要求并说明真实起点与 preserve。操作参数槽和 IR 输入槽分别校验。
3. 全部证据采用源文范围、直接 CFG target 或运行规则 rule_id。敏感性与 Task 仍必须有源文依据；引文覆盖不等于语义证明。
4. 输入快照 v2 保存原始包一次。修复和审查沿明确的上游引用取得材料；接受响应、编译结果与位置映射分清来源。
5. 传播仅保存 Data、记录、实际 sink 及自身审计；DOE 仅保存自己的结论、推导和恢复信息。没有替代 doe-input 的新总包。
6. 旧切片、Task、需求和敏感性实验运行包装退出；算法与正式入口保留。旧运行不兼容解释，历史数据不改写。

末轮重复材料检查继续删除了修复上下文全文、审查 `resolved_findings` 展开副本，以及 DOE 声明索引中的原声明与证据副本。它们分别从已封存的原候选／初审、审查目标、所选标注重建。保存位置和恢复职责改变，实际调用记录及最终 DOE 业务字段没有因此被改写。

原始 Prompt 与响应照实保存。它们即使包含已冻结源文，也属于实际调用记录，不通过改写历史请求达到去重。程序生成的模型观察仍是契约下的静态可能关系。

## 规模对照

采用紧凑 JSON、ensure_ascii=False；完整 Prompt 使用实际文本。数据如下，单位均为 UTF-8 字节：

| 案例 | 原模型输入材料 | 新模型输入材料 | 原完整 Prompt | 新完整 Prompt |
|---|---:|---:|---:|---:|
| 001 | 35,007 | 20,051 | 96,132 | 91,937 |
| 010 | 40,111 | 21,878 | 101,236 | 93,764 |
| 013 | 60,781 | 28,662 | 121,906 | 100,548 |

输入材料分别减少约 43%、45%、53%；完整 Prompt 分别减少约 4%、7%、18%。Schema、绑定示例及输出规则仍有固定开销，不能把输入材料降幅当成整个请求的降幅。这些是字符／字节测量，没有声称精确 token 或实际费用下降比例。

传播阶段原总包与新三组件的紧凑字节数分别为 26,126 → 18,257、65,929 → 54,663、117,986 → 99,686。新组件不再包含上游已有内容；该比较不是整套审计目录体积或跨版本语义等价证明。关系对照使用明确标识的离线重建夹具，保留 6、12、16 个 sink，不冒充新版模型输出。
