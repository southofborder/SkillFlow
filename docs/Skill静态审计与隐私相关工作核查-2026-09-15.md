# Skill 静态审计与隐私相关工作核查

核查日期：2026-09-15。对象为 Agent Skills、SKILL.md 及其脚本、资源和跨 Skill 组合。检索覆盖静态审计、数据外传、隐私暴露、声明一致性、控制/数据流与形式化表示；同时检查 8—9 月新稿及旧稿的最新修订。引用以 arXiv 摘要页的版本历史和作者全文为准，接收状态只转述论文或 arXiv 页面注明的状态。

这是一轮有针对性的相关工作核查，不是可保证穷尽的系统综述；搜索索引可能滞后。本轮没有复现实验，也没有据此修改生产代码或既定实验记录。下文的“重合程度”和研究建议属于阅读判断；作者报告的指标不是我们独立验证的结果。

## 判断

**宽泛研究位置已经被占据。**“对 Skill 做静态安全审计”“自然语言转 IR/图”“回述后核对原文”“找凭据泄露”“发现未声明行为”“跨 Skill 数据链”均已有直接论文。应正面比较 Semia、MalSkills、SkillConsist、两篇不同的 SkillScope，以及凭据泄露研究，不能仅把它们放在泛背景中。

**尚不能据此判定我们的具体工作失去价值。**可能形成增量的是：明确分析器生成表示的错误来源，在实际受控文本上保证显式事实保持，并证明或实证说明细粒度条件、结果身份、作用域与传播解释如何改变真实数据暴露判断。但“用了 Lean”“有更细 IR”“只调用一次模型”本身不足以说明已形成足够的新贡献。

### 方法上最值得核实的差距

Semia 的传播对单个调用采用输入影响所有输出的近似，并将相邻调用输出与后继输入广泛连接。后续可以检验真实定义/使用身份和更精确的操作解释能否减少误报，但我们尚未完成这个对照。其回述核验不是我们实现的 Lean 文本往返命题。[Semia §4–6](https://arxiv.org/html/2605.00314v1)

SkillConsist 已有细粒度字段核对与四值判定，He 的 SKILLSCOPE 已有原文加图的核对，Wu 的 SkillScope 也评估了节点、边和跨层链接抽取质量。在所读版本中，尚未看到与我们“实际可读文本→解析→全事实恢复”对应的机器检查证明；这只说明一个具体保证的差异，不能推出这些论文不关心正确性。[SkillConsist](https://arxiv.org/html/2608.07639v1)、[He 的 SKILLSCOPE](https://arxiv.org/html/2605.12875v1)、[Wu 的 SkillScope](https://arxiv.org/html/2605.05868v3)

MalSkills 的程序控制依赖范围、SkillFortify 对已抽取操作的保证范围，提示我们必须把“原文解释”“图的记录保持”“抽象传播”“真实执行”分开评价，不以一层证明覆盖其他层。[MalSkills §4–5](https://arxiv.org/html/2603.27204v2)、[SkillFortify §8.2、§9.5](https://arxiv.org/html/2603.00195v2)

## 我们当前可以和不可以声称什么

我们当前已经实现并验证的是：规范 CFG 结构检查、完整事实域、Lean 受控文本往返、实际输入恢复比较、完整原文与受控文本的单任务核对，以及 F01 五案例的方法示范。传播的操作解释、未知行为边界、隐式流及数据暴露性质尚未因此获得证明。[当前规范](Skill-IR受控语义回述与源文核对规范.md)、[首次验收](../packages/skill-ir/experiments/semantic_backtrace/runs/controlled-v2-f01-20260914T142804Z/acceptance.md)

不宜再作为独立首创主张：

- 首次对 Skill 做静态审计、引入 IR/图、分析凭据或敏感数据泄露。
- 首次用回述或图表示核对源文、首次发现声明与实际行为不一致。
- 首次给 Skill 使用形式方法、污点分析、跨包数据链或细粒度修改定位。
- 首次关注正常功能中的意外暴露，或者把“没有恶意”与“没有隐私风险”分开。

值得验证的研究问题：

1. **哪些表示错误会改变安全结论？** 对遗漏条件、错误结果绑定、声明与操作混淆、返回/异常/回退路径缺失分别标注，检验受控核对能否降低这些错误；既报告漏报，也报告无依据补图。
2. **精细传播究竟增加了什么？** 在相同输入和威胁模型下，比较真实定义/使用、变换契约、作用域与路径条件带来的差异；不能预设图更细就更准确。
3. **证明如何接到实际产物？** 保留实际文本、图、证据和实现摘要绑定，并将抽取不确定性传入后续分析；不要把原文开放语义默认为已证明。

精细传播还需要明确观察者与执行假设：实际作为工具参数传递、进入共享模型上下文、写日志/文件、改变可观察分支，是不同的暴露方式。如果某个运行模型允许后续操作读取共享上下文，只因没有显式参数引用就删除传播边，可能减少告警却造成不健全。应比较在同一执行模型下哪些边有依据，而不是把既有保守近似直接称为实现错误。

建议下一项研究性工作先做小规模直接基线复现，而不是继续扩大功能清单：优先 Semia、MalSkills、He 的 SKILLSCOPE、SkillConsist；若主张任务必要性，再加 Wu 的 SkillScope；若主张跨 Skill，再加 ChainGuard。先找出它们在同一组真实/受控隐私案例上的具体失误及原因，再决定论文贡献。不要把不同数据集上的作者 F1 数字拼成排行榜。

这个核查支持的判断是：**研究对象和整体路线已经拥挤；可争取的位置应建立在可验证的分析精度、明确的语义边界和新增安全发现上。当前尚不能承诺已获得一个无人覆盖的顶会选题。**
