# SkillFlow 统一抽象运行时契约

当前流程是：**完整 Skill 与 CFG → 统一抽象运行时契约 → 一次联合标注处理方式及字段关系 → 程序编译观察 → 确定性传播**。所有 Skill 共用一份契约，不为每个 Skill 选择运行时，也不要求逐例动态验证。

唯一权威英文规则定义位于 [`runtime_contract.py`](../packages/skill-ir/src/skill_ir/runtime_contract.py)，当前版本为 `skillflow-abstract-runtime-v5`。`execution_model()` 返回隔离副本；`execution_model_binding(model)` 返回版本与规则全文的规范化 SHA-256。模型材料中的 `execution_model` 只注入一次规则，证据仍使用 `basis="execution_model"` 和 EM 编号。本规范解释其含义；实际英文规则决定模型输入。处理规格及编译细节统一见[字段关系与观察编译](SkillFlow-字段关系与观察编译.md)。

## 1. 规则与保证边界

规则区分显式事实与保守默认。默认描述契约下的静态可能行为，不是实际执行的测量，也不是“所有 Agent 必然如此”的断言。收窄范围、局部处理和隔离例外需要源文、代码或接口依据。

| 编号 | 规则 | 适用边界 |
|---|---|---|
| EM01 | 来源范围默认 | 从整体取得字段时保留整体与字段关系。目标名、执行主体或 getter 式名称不能证明局部接口；明确机制才能限定获取／返回范围。不编造其他字段、敏感性或无关资源。 |
| EM02 | 工具返回默认 | 未明确隔离时保留返回内容进入模型的可能性。适用对象是返回版本，而非工具内部所有扫描内容。本地扫描整体、仅回传一个字段时不能直接推导整体观察。 |
| EM03 | 模型可见边界 | 内容进入模型请求构成观察，不证明模型理解或记住内容。缺少隔离且内容用于 Agent 处理时应用可能观察默认；纯调度不能证明观察。 |
| EM04 | 数据版本与明确机制 | 模型处理原输入与本地处理后仅回传结果不同。凭据句柄不等于明文；后来删减不能撤销早先观察，transform 也不证明脱敏。 |
| EM05 | 声明不是保护动作 | 禁止传递或只需某字段，不自动实现筛选或隔离。契约只作用于有依据的现有动作，不能制造无关来源或业务操作。 |
| EM06 | 交互边界独立 | 工具名称和 LLM 参与不证明网络，普通 return 不证明面向用户。可能观察整体不扩大真实调用参数。真实冲突和次序不明仍保留。 |
| EM07 | 上下文写入 | 只有改变后续可读上下文内容／绑定才是 context_write。结果登记不自动构成写入；原样保存不自动 transform，删除不自动读取旧内容。 |
| EM08 | 符号传递边界 | 没有明确缩减则保留相关范围。possible 依赖不等于明文包含；来源内容未知不等于地址未知；登记 Data 不自动形成交付。 |
| EM09 | 获取与计算不同 | 检索返回保留获取边界、请求输入及可能依赖。网络明确使用 remote/net_receive；网络未定的工具获取使用 tool/无标签 receive。纯计算仍是 compute。 |
| EM10 | 处理模式的确定性编译 | 模型标注 model/local/default 模式，程序按实际引用插入观察。model 要求原 operator 包含 llm；local 要有机制依据及显式 returns；default 应用既有保守默认。编译不证明模式判断正确，也不机械补 operator/roles。 |
| EM11 | 元素作用域与筛选 | filter_items 保留可能被选中元素的身份，不执行自然语言谓词。for_each 用同一元素绑定关联各字段和参数，是分析作用域，不是新增 CFG 循环或运行次数。summary 字段不自动成为摘要生成。 |
| EM12 | 接收范围与留存默认 | 位置新增 access_scope/retention。工具部署未说明保留外部接收可能性但不补网络标签；上下文默认任务内临时；文件默认任务内持久，明确临时和清理机制才能降低留存；模型、远端和用户默认另一接收主体。 |
| EM13 | 交付与 sink 分类 | tool 请求交付与返回获取分别表达。程序编译观察后按边界属性生成六类 sink 和固定暴露等级；任务内部临时流动、删除和普通 return 不虚构内容交付，等级不表示敏感性或 DOE。 |
| EM14 | 可选请求成员 | 布尔控制决定原字段值是否成为对象成员；控制与载荷分开，同一控制共享决定，条件观察沿用相同条件。 |
| EM15 | 请求交付与获取 | 同一 IR／作用域／边界中的完全相同有序请求引用唯一配对，获取复用实际交付版本；不按名称或 FIFO 猜测。 |

## 2. 读取、处理与观察分别表达

| 已知事实／标注 | 程序处理 |
|---|---|
| 未说明局部机制，从容器取得字段供 Agent 处理 | default 模式保留相关整体获取；read 后观察取得版本，select_part 连接目标字段。不能声称原文明示了整体观察。 |
| 明确本地扫描整体，只回传一个字段 | local 模式内部读取不生成观察；明确返回字段才在段末被观察。 |
| 模型处理已经取得的数据 | model 模式在首次使用前观察段外输入；同段生成的中间结果不算新的外部输入或额外模型调用。 |
| 工具取得响应 | model/default 中 receive 后观察响应，不因取得响应就同时观察请求参数。 |
| 明确本地删减，只回传清理结果 | local 的 returns 引用新版本；不补原版本观察。 |
| 模型先看原数据，随后删减 | 先前观察保留原版本；中间计算结果不回写早先事件。 |
| 明确凭据代理不回传凭据 | local 的 returns 可为空或只含有依据的句柄，不能把句柄变成密钥明文。 |
| 仅参与调度 | 不因 operator 有 llm 就制造数据；观察仍须有处理模式与具体值引用。 |

同一处理段中相同外部符号引用去重；不同处理段及不同取得／返回版本分别保留。此去重是记录同一抽象处理边界，不推断模型实际调用次数。顺序使用 `order=fixed/partial`。partial 保留编译生成的必要先后约束并计算候选排列，不能借数组位置断言先保护后观察。模型输入观察先于处理、read/receive 先于对应观察、本地段全部操作先于回传观察；不同处理段可在原子操作之间交错。

## 3. 各阶段职责

CFG 提取与源文核对只保留原文行为和约束。逻辑来源不等于实际整体读取；局部接口不能丢失；运行时默认观察不补造成 CFG 操作。它们不新增 IR 字段，也不读取安全标注答案。

联合标注读取完整源文、CFG 与契约，输出原始处理规格，不自行输出 `model_observe`。它必须判断模式、局部机制、字段路径和数据关系；名称或 opcode 不能替代判断。指令正文英文，理由中文，引文保留原语言。默认、opaque、possible 和可求值的 partial 均正常完成。不能完成必要判断时返回独立 cannot_assess/failure，经校验记录 semantic_failure，不用空业务结果冒充通过。

编译器检查原始结构、编号和引文，按类型规则插入观察，建立原始位置到编译位置的映射，再检查编译结构。它不理解任意英文理由，也不能证明 local 依据充分、model 判断真实或源文已经被完整覆盖。将模型参与写入 operator、将动作标为 sink，仍须标注方独立给出依据；接收方是模型不会自动改变这两个字段。

模型标注位置访问范围与留存性质，程序再从具体交付和非删除写入生成 sink 清单及 exposure_level；清单不按 roles 筛选。边界默认、明确例外和六类等级见[Sink 边界主规范](SkillFlow-Sink边界与固定分级.md)，不在这里另建一套分类规则。任务内部上下文写入仍传播，但不自动成为暴露 sink；工具参数交付和工具返回后的观察分别绑定。

传播器执行编译后的规格，不追加 LLM 调用，不按 opcode 补关系。稳定后的记录是静态可能性，不是执行日志。`complete` 不代表行为必然发生、语义完整或不存在 DOE。

## 4. 版本与身份

DOE 文件顶层保存一次契约绑定：

```json
"execution_model": {
  "version": "skillflow-abstract-runtime-v5",
  "sha256": "实际冻结规则全文的规范化摘要"
}
```

完整规则在标注材料和传播审计目录中保存。完整运行加载同时核验原始响应、重新编译结果、映射与摘要；只验证编译结构不等于验证编译来源。普通业务读取允许按当前支持的契约加载，重新求解还需源码身份一致。旧记录不迁移、不重新计算摘要掩盖变化。

当前版本：联合标注 `security-profile-v10`、标注运行 `skill-ir-security-profile-v11`（格式 11），Data `skillflow-data-v4`，传播记录 `skillflow-propagation-record-v9`，DOE 输入 `skillflow-doe-input-v7`，传播运行 `skill-ir-propagation-v10`（格式 10）。表示契约为 v3，编译器为 v4，语义核对响应仍为 v5。v3 将泛化未决改为可求值部分顺序或明确任务失败；v4 补齐位置属性和交付边界，不把静态可能性升级为实测行为。

`abstract-runtime-v1-*` 三例试验及当时的 `run_runtime_pilot.py` 调度属于 v1 历史材料。当前调度已经更新，不能用新契约重解释旧模型响应；先前处理段试验使用 v2，实际结果以相应运行材料为准。历史一轮经明确批准只原位替换 `processing-v1-20260928-204710` 内三例派生产物，保留经核验的选定 CFG，并建立新运行身份；这不构成旧响应的迁移或重新解释。

集中验证包括：模式边界、获取与请求区分、本地返回版本、段内中间值去重、逐元素参数配对、引文与摘要篡改拒绝、零 API 重放。它验证程序规则；模型实测另行报告模式误判、字段关系错误和明确失败，不以编译成功替代语义正确性。

## 可选参数与请求关联

EM14 规定可选对象成员引用原字段值，布尔条件只决定加入或省略，不成为请求明文。成员条件为 false 时不消费该值；抽象布尔保留两种形状。同一条件的多个成员共用决定。先前整体观察仍保留。

EM15 规定同一 IR／作用域／边界的交付与获取使用完全一致的有序请求引用，程序唯一配对并复用实际交付的数据版本。不按名字或 FIFO 猜测；歧义明确失败。规则不承诺采用 JSON 作为网络序列化格式。

v5 收紧网络机制证据，并补齐上述条件消费、观察与请求复用；Data 保持 v4。完整规范见[Sink 标注收紧与可选参数](SkillFlow-Sink标注收紧与可选参数.md)。
