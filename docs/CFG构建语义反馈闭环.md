# CFG 构建的语义反馈闭环

本规范固定独立的 `skill_ir.feedback` 工作流。目标是依据完整原文和当前图中的明确差异，有界地重新提取 CFG，并保存可复核的每轮证据。成功状态称为**核对器通过**，不称为已证明语义等价。

当前版本为 **v5**：核对与反馈共用 [IR 解释契约与逐项核对规范](Skill-IR解释契约与逐项语义核对规范.md)，七类检查点仅作阅读提示，核对项可组合关联要求；保守依赖说明仅在适用时填写，不将未说明者自动称为精确。保留有界核对执行重试。v1/v2/v3/v4 的历史响应、图和报告保留原样；源码、契约、提示词和重试策略变化后使用新目录，不在暂停目录上续跑或重新解释旧结果。

## 1. 单一主流程及模块边界

```text
同一冻结 Skill 内容
  → 完整提取候选 → 编译、重新赋号、结构校验
  → Lean 生成受控文本 → 实际文本解析、恢复、逐字段比较
  → 完整原文与受控文本独立核对
  → 程序判断停止条件
      ├─ 核对器通过 / 语义失败 / 执行失败 / 次数耗尽：停止
      └─ 仍有明确差异：追加本轮定向反馈，重新完整提取
```

输入已有有效 `analysis.json` 时直接以其实际 `cfg` 开始第 0 轮核对；不重新解释其旧候选。通用服务不识别 F01、不读取反例标签或外置人工答案。

公共提取 Prompt、IR 字段、结构规则及现有 `analyze_skill` 默认行为保持原样。反馈编排只在单个案例的新请求后追加纠错材料。程序不编辑 CFG 以迎合建议，也不从编译后的 ID 猜测原候选 ID。

## 2. 两个模型职责与输入隔离

| 角色 | 实际输入 | 输出 |
|---|---|---|
| 提取 | 固定完整 Skill 与候选契约；修复轮另附上一轮实际 CFG、所有明确差异 | 完整候选 JSON，由既有编译器重新赋号和校验 |
| 核对 | 同一冻结完整源文、源文定位索引、当前图经保真检查的受控文本及受控事实编号 | 单个核对契约的完整 JSON |

每次核对均使用独立上下文，不接收上一轮判断、建议、原始 CFG、候选 JSON、反例身份或人工预期。它重新检查完整原文与当前受控文本，因此能够报告修复带来的新问题。

核对器与反馈读取同一版本化解释契约：`dispatch`/`return` 是固定控制操作；`external_resource` 不等同远端；约束是声明。合流操作允许引用不同分支结果，未精确区分选值时可按固定规则保守接受，不强迫补造选择操作，也不推断同时传参。明确错绑、额外业务参数、遗漏动作及禁传冲突仍严格核对。生产 IR 与结构规则不变。

定向反馈由程序生成，不额外调用模型改写建议。反馈包含最近一轮 `omitted`、`mistranslated`、`unsupported_addition`、`internal_conflict` 项及其引文、当前事实、程序映射位置和建议。保守依赖保留项不进入修复清单。合法 `cannot_assess` 响应保存为 `semantic_failure` 后停止，不组装修复请求。能够按契约保留的开放关系和保守候选正常核对；不能完成必要判断时不猜测修复。

建议是待核实依据，**原文优先**：不得为了消除核对器意见而加入原文没有的等待、参数、限制或承诺。只携带最近一轮图和核对结果，不累积历史对话。旧图 ID 仅解释上一轮问题；新候选无须沿用，下一轮使用新图重新生成证据索引。

## 3. 通过与停止的精确定义

只有同时满足以下条件才产生 `audit_passed`：

1. 当前 CFG 结构和引用校验通过。
2. 实际受控文本可独立解析并恢复出同一规范化图，逐字段检查及证书检查通过。
3. 核对响应的 JSON、编号、引文、适用的可选说明及完整源文／受控单元覆盖有效。
4. 存在至少一个 `kind="semantic"` 的业务核对项。
5. 所有业务项均为 `represented`，没有明确差异，响应为 `outcome="completed"`。

`represented` 仅表示该业务项按本轮契约被核对模型判为保留，不再强制标记精度；明确使用保守依赖规则时填写 `conservative`。保守项可以通过，但结果和报告都须保存候选、规则和丢失的区分，后续不得把候选当成必定传递。`complete`、`requires_review=False`、结构通过、完整编号覆盖，或全背景项均不能替代以上条件；编号覆盖不证明模型找全所有要求。程序仅报告保留总数及其中明确记录保守依赖的数量。

| 情况 | 状态与行为 |
|---|---|
| 满足全部通过条件 | `audit_passed`；保存通过图与核对证据 |
| 有明确差异且仍可语义修复 | 组装定向反馈；重新完整提取 |
| 模型报告无法完成必要判断，或完整结果仅含背景项 | `semantic_failure`；保存原因与证据，不修复、不计通过 |
| 明确差异仍存在且已耗尽语义修复次数 | `revision_limit`；保留最终差异 |
| 结构修复耗尽 | `extraction_error` |
| 受控往返或证书检查失败 | `fidelity_error`；禁止调用核对模型 |
| 核对 JSON、引文、编号或覆盖无效 | `audit_error`；不静默修补响应 |
| 核对暂态传输失败 | 最多额外执行重试 2 次；仍失败则 `audit_error`，不消耗语义修复次数 |
| 用户中断 | `interrupted`；保存已开始的调用，不启动后续调用 |

结果同时记录最后有效图与核对器通过图。未通过时最后有效图仅供检查，不从历史轮次选择“最高分图”作为成功结果。

## 4. 修复、执行与传输次数独立计数

默认最多 3 次**语义修复**，不包含首次生成或已有图的第 0 轮核对。每次完整提取默认最多 3 次**结构修复**，即最多 4 次提取逻辑调用。每轮核对默认最多 2 次额外**执行重试**，即最多 3 次核对执行尝试；HTTP 传输尝试与重试单独记录。

| 默认入口 | 最多提取逻辑调用 | 最多核对逻辑调用 | 合计 |
|---|---:|---:|---:|
| 从原始 Skill 生成 | `(1 + 3) × (1 + 3) = 16` | `1 + 3 = 4` | 20 |
| 从已有有效图开始 | `3 × (1 + 3) = 12` | `1 + 3 = 4` | 16 |
| F01 五例均从已有图开始 | 60 | 20 | 80 |

上表统计逻辑调用单元。通用配置为语义上限 `S`（允许 0–3）、结构上限 `T` 时，从源文开始提取上限为 `(S+1)(T+1)`，从已有图开始为 `S(T+1)`，核对逻辑单元上限均为 `S+1`。执行重试上限 `R` 默认 2，核对执行尝试上限为 `(S+1)(R+1)`。默认从源包开始实际执行模型调用上限为 `16+12=28`，从已有图开始为 `12+12=24`；HTTP 尝试另计。停止规则优先于预算。

结果同时保存 `audit_logical_calls`、`audit_execution_calls`、`audit_execution_retries`、`total_logical_calls`、`total_execution_calls`；语义修复、结构修复和 HTTP 次数另外记录。一次核对传输失败后成功重试，并不算又修复了一次图，也不算获得了两份可供择优的有效判断。

执行重试只针对记录能够证实的暂态故障，例如 DNS/连接/读取超时、原 HTTP 重试耗尽的 429/5xx，以及 HTTP 已接受后明确失败的未完整响应流。默认退避为 5 秒、10 秒。每次使用完全相同的原文和已检查受控文本，独立保存失败、重试决定和新响应。首个完整响应收到后停止重试；后续解析得到坏 JSON、错误引文/覆盖、合法 `cannot_assess` 或明确语义差异都不会触发重试。

本地文件写入/权限错误、记录损坏、鉴权及其他不可重试 HTTP 错误、用户中断和仍为 running 的不确定请求不自动重发。本轮用户明确授权后，已接受但以可识别传输错误结束的核对请求允许创建新的有界尝试；底层历史 SSE 适配器的接受后不重试规则保持原样，外层通过独立记录完成新策略，不把旧失败覆盖成成功。

## 5. 源文冻结、运行记录与恢复

开始运行时一次读取并冻结源包。提取和核对使用同一份可读内容；原始文件字节 SHA-256 与解码后文本 SHA-256 分别保存。二进制和未解释内容列入边界，不把它们算作已完成全文语义理解。

每轮记录完整候选、CFG、结构诊断、受控文本与证书、核对结果、反馈 Prompt 和停止决策。每次实际模型调用保存 Prompt、响应、模型实际返回名、用量、摘要、HTTP 尝试以及 SSE 的已接收进度。凭据不写入记录。

互斥锁禁止并发写入同一运行目录。恢复首先使用已保存的完整响应；明确以暂态传输失败结束的核对按已绑定预算和重试决定继续，已开始但状态不确定或被用户中断的调用不自动重发。输入、配置、契约、重试策略或源码身份变化时明确拒绝继续。历史单次核对及 v1/v2/v3/v4 反馈记录不被解释为 v5 运行。重试策略和执行循环由 `skill_ir.audit_execution` 统一提供。

`replay` 不创建在线客户端，不读取凭据，不调用 API。它使用保存的源包及响应重走解析、编译、受控往返、核对和停止判断；不通过直接复制旧的最终状态伪装重放。

## 6. 通用命令与 Python 服务

在仓库根目录安装 `packages/skill-ir` 后：

```powershell
python -m skill_ir.feedback run --input path/to/skill --run-dir path/to/new-run
python -m skill_ir.feedback run --input path/to/skill.zip --initial-analysis path/to/analysis.json --run-dir path/to/seeded-run --max-semantic-revisions 3 --max-structural-repairs 3 --max-audit-execution-retries 2 --env-file path/to/settings.env
python -m skill_ir.feedback replay --run-dir path/to/seeded-run
```

两个命令均可显式指定 `--renderer <Lean 打印器>`。`run` 使用已有 LLM 环境配置，日志只保存公开配置白名单。相同 `--run-dir` 用于恢复时要求身份一致，不自动迁移旧记录。通用命令退出码 0 表示核对器通过，1 表示其他停止状态。

当前默认 `LLM_TIMEOUT=600000`，即 10 分钟，显式环境配置仍可覆盖。现有 urllib/SSE 传输使用它作为连接及阻塞读取的等待时间，持续收到流数据时可以超过 10 分钟；它不是整次生成的总时限，也不保证系统 DNS 解析失败会因加长时间自动恢复。新全流程批次将 600000 明确写入自身配置，历史基线配置文件不修改。

```python
from skill_ir.feedback import refine_skill

result = refine_skill(
    "path/to/skill",
    run_dir="path/to/new-run",
    extraction_client=extraction_client,
    audit_client=audit_client,
    max_semantic_revisions=3,
    max_structural_repairs=3,
    max_audit_execution_retries=2,
)
```

两个客户端分别注入，均实现 `complete(prompt)`。在线 CLI 使用共用的 SSE 调用记录组件；测试可注入离线响应。既有单次提取入口继续独立可用。

## 7. F01 首次实验及事后判断

实验代码位于 `packages/skill-ir/experiments/semantic_feedback/`。五个初始图沿用已绑定 SHA-256 的 F01 原图与四个结构有效变体，种子文件只包含各例实际 CFG，不携带构造前的旧候选。请求官方 DeepSeek `deepseek-v4-flash`，返回模型名以记录为准。每例第 0 轮重新核对；单例失败不阻断其他例，中断后不启动后续案例。

```powershell
python packages/skill-ir/experiments/semantic_feedback/tools/run_f01.py run --run-dir packages/skill-ir/experiments/semantic_feedback/runs/<new-id>
python packages/skill-ir/experiments/semantic_feedback/tools/run_f01.py replay --run-dir packages/skill-ir/experiments/semantic_feedback/runs/<new-id>
```

初轮证据与外置预期的自动匹配仅产生复核候选。图重新赋号后，不能用旧指针直接宣称缺陷消失。助手须结合完整源文、新图的操作及数据绑定、新证据逐项判断是否修复、是否误改以及是否出现核对器假通过；该复核与用户人工确认分开标注。

中文报告分别呈现工程验收与方法表现：有界循环和记录通过测试，不意味着核对模型无漏报或误报；“迭代后终于通过”也不证明修复正确。首次五例只作方法诊断，不作泛化或统计显著性结论。

## 8. 聚焦验收范围

回归覆盖零修复通过、一次修复通过、连续三次仍有差异、明确差异后遇到语义失败、初轮语义失败停止，以及修复旧问题后引入新问题。全背景、非法引文、缺失覆盖、坏 JSON 和保真失败均不得产生假成功。

另检查修复/执行/HTTP 计数分离、模型输入隔离、源文每轮一致、反馈位置来自上一轮实际图、新图重新索引、明确暂态故障的有界重试、完整响应与用户中断不重发、离线重放零 API、原始图及历史产物未变化。既有提取、受控回述、Lean 证明及语料隔离回归继续执行。
