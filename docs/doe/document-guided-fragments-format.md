# Document-guided semantic fragments

The v9 entry makes seven semantic requests. Processing, task correspondence and
sensitivity submit separate JSON records. Python composes and compiles the
annotation; there is no annotation-completion model request. The schemas rendered
by `fragment_adapter(kind)` are the authoritative field formats.

## Ownership and references

| Fragment | Top-level fields | Forbidden cross-owner content |
|---|---|---|
| processing | `ir_semantics`, `locations`, `expressions`, `processing_gaps` | Task realizations, demands, sensitivity |
| task-correspondence | `realizations`, `demands`, `operation_demands` | Operations, locations, sensitivity |
| sensitivity | `declarations` | Task, demands, operations |

CFG and all three fragments receive the complete frozen source in both initial
generation and semantic reconstruction; upstream citations do not select their
visible source ranges. Exact duplicate embedded code remains omitted from CFG
views. The submitted-input character limit remains explicit; nothing is silently
truncated.

Processing receives source and CFG, not Task. Correspondence receives the sealed
Task and accepted processing. Sensitivity receives accepted processing without
Task or correspondence. All references name existing CFG instructions and exact
lexical processing values. A source citation is evidence to inspect, not a proof
that a declaration is semantically correct.

`OperationDemands.operation_path` addresses one processing operation, for example
`["segments",0,"ops",0]`, or a loop-body operation such as
`["segments",0,"body",0,"ops",0]`. It never selects a neighboring operation by
name, input equality or execution order. Existing demand targets retain their
input/output/self meaning. Constraints on a call retain their explicit
request/response phase; omitted phase means request.

## Values, calls and collections

CFG literals and processing literals use different, intentional interfaces:

```json
{"type":"literal","literal_value":0}
```

```json
{"kind":"literal","value":0}
```

Do not supply `semantic_name`. Processing references an actual IR input with
`{"kind":"input","index":0}`, or a declared local value with
`{"kind":"local","name":"reply"}`. Literal strings that resemble file paths
are data; they do not request source-file reads.

An explicit call is:

```json
{"op":"call","location":"api","inputs":[{"kind":"input","index":0}],"output":"reply"}
```

The location must already be declared by processing. Python generates the
request/response pairing. A remote or tool response is acquired content, not a
calculation exhausted by its query parameters.

Public entry arguments require actual context acquisition. Internal calls keep
their real arguments, returned values and boundary effects at the call site;
metadata parameter names or disconnected function bodies are not data bindings.
Real zero-argument calls and source-supported zero-input expressions are valid.

Ordinary saving with unspecified update semantics may omit `write.mode`; the
program emits explicit `replace`. Explicit `append` and `delete` retain their
meaning. This is the runtime's declared default, not a claim that the source
explicitly says overwrite. Unknown serialization does not erase the actual
saved value or stop a representable boundary. The raw backend format still
requires an explicit mode.

An explicit traversal tests `branch(predicate="has_member")` at its header and
obtains `member` only in the true body; member produces the element, not a second
Boolean. Multiway decisions use binary dispatches with real condition operands.
The current guided CFG rejects a dispatch with more than two distinct successors
before processing. Validated connected caller, traversal and binary examples
are generated by `interface_examples.alignment_examples()` and included in the
applicable phase formats.

Splitting an invalid multiway dispatch requires new blocks and changed edges.
That diagnosed structural correction uses the existing full-CFG response within
the same single-correction budget; other locatable errors still replace only
their supplied existing record slots.

Review findings that require changed CFG blocks, edges, inputs, public outputs
or producer positions belong to `cfg`. Changes expressible inside the fixed CFG
belong to the owning annotation fragment. The existing repair closure applies;
there is no extra `repair_owner` field or program interpretation of suggestion
text.

For a source-defined list of URL strings and one actual request per occurrence,
the processing structure can be:

```json
{
  "kind":"for_each",
  "collection":{"kind":"input","index":0},
  "item":"url",
  "body":[{
    "mode":"local",
    "returns":[],
    "ops":[{"op":"call","location":"api","inputs":[{"kind":"local","name":"url"}],"output":"reply"}]
  }],
  "yield":{"kind":"local","name":"reply"},
  "output":"responses"
}
```

The enclosing IR needs applicable source evidence; segment array order defaults to fixed. A real CFG
result can bind to that collection with
`{"output_index":0,"value":{"kind":"local","name":"responses"}}`.
`yield` is not a model observation. An actual return to the model requires an
explicit local `returns` route for the final collection, supported by source.

Keep duplicate occurrences, real order and separate response versions. Empty
collections produce an empty collection; symbolic membership is not a known
length-one array. This compact body keeps its lexical scope. Explicit CFG loops, including
nested loops, use the merge/member/branch relations described below; no generic
exception executor or exact per-member cache execution is introduced. Normal completion and per-item caught errors remain distinct.

## Evidence, order and unsupported relationships

Use exact `{file,start_line,end_line}` citations to frozen source. Interpretive
reasons are English; original text and quotations retain their language. Omitted
operation evidence inherits the closest applicable parent. Sensitivity and
expression evidence inherit existing source citations only; CFG/rule citations
are not converted into source support. Override inherited references when the
sensitive source or mechanism differs.

Segment arrays declare fixed order by default, including multiple segments and
`for_each`. Use explicit `partial` for a supported non-fixed ordering. Local
processing requires an explicit `returns`, including `[]`; yield is different
from returning content to the model. The program does not infer execution order
from source prose.

Demand paths preserve field prefixes and repeated member selectors, for example
`["pages",{"kind":"each"},"rows",{"kind":"each"},"key"]`. Each selector follows
its actual member scope. Do not remove prefixes, move selectors, invent selection
operations, or replace cardinality with whole-content necessity.

A source-backed processing gap names `instruction_id`, `reason`, `evidences` and
optional `outputs`, `locations`, `control`, `unmodeled`. `unmodeled:false` limits
otherwise complete may facts. `unmodeled:true` explicitly omits the IR's
executable semantics and prevents publishing its block OUT. Missing actual
writes cannot be disguised as a precision-only limitation.

Program-origin validation gaps are generated from actual failed validation.
Models cannot submit them. Neither kind creates a fake compute, empty event,
unknown source, identity transfer or proof of safety. Unresolved boundary
declarations remain separate from resolved sink records.

## Explicit loops and no-operation candidates

Only processing submits typed loop relations. `merge` supplies incoming
`{predecessor,value}` pairs and an output; each predecessor must be a real CFG
predecessor. It selects that incoming edge, not a simultaneous computation over
all values. `member` selects an input collection occurrence into a local output.
The program supplies member identity and nesting. `branch` supplies an input,
a supported `predicate` and `true_target`/`false_target` CFG blocks; `truthy`
requires concrete Boolean values, not host-language truth coercion. `has_member`
is traversal availability, not an exact runtime counter. Unknown predicates keep
possible paths. `append` supplies its input collection, contributed value,
`mode:item|items` and output. Preserve real collection contributions instead of
using opaque compute as append.

A `cases` candidate may use `segments:[]` and yield an already available value.
It does not invent processing or model observation. Throw candidates cannot yield
normal output; each returning candidate yields when its summary declares output.
The program retains the case control identity without a fabricated data action.

The authoritative cross-field rules are `fragment_contract_rules(kind)` and
`cfg_contract_rules()`. `phase_examples(kind)` contains compact, executable test
examples and remains separate from the analyzed Skill's source.

## Correction and review

One structural correction is allowed per stage. For identifiable bad records the
program supplies record IDs and accepts only their complete replacements:

```json
{"replacements":[{"record_id":"/ir_semantics/ir_fetch","value":{"evidences":[{"file":"skill/SKILL.md","start_line":1,"end_line":1}],"segments":[{"mode":"local","returns":[],"ops":[{"op":"call","location":"api","inputs":[{"kind":"input","index":0}],"output":"reply"}]}],"output_bindings":[{"output_index":0,"value":{"kind":"local","name":"reply"}}]}}]}
```

This example assumes the existing IR has that one call result. The replacement
must preserve source-supported semantics and cover actual outputs.
Unlisted records are retained. Arbitrary insert/delete/move patches are not
supported. Unparseable top-level answers require a whole fragment instead.
Raw replies and merged candidates are independently preserved and verified.

The source reviewer reports concrete `cfg`, `task` or `annotation` findings.
Annotation targets have program-owned processing/correspondence/sensitivity
owners. Empty sensitivity containers locate missing declarations; they do not
mean nonsensitive or accepted. When assembly is unavailable, actual retained
fragments and stage-failure targets remain reviewable without a fake annotation.
Source-backed semantic findings may use the single shared repair round;
format failure alone does not authorize another quality sample.
