# Processing 修订超时：证据、通用修复与验收边界

本轮已于 2026-11-17 闭环：788/788 最终 scoped 回归通过；唯一新 GA4 的完整初始输入减少 12.53%，但首答重复共享表被拒绝，初始 processing 纠错在三次内部采样重试后触及 2700 秒总时限。没有接受的 processing 或 DOE；不能宣称修订超时已解决。唯一回放匹配且无新调用。提示未明确声明 codec 的 vN 命名规则是新发现的缺口。完整结果和后续方案见 [中文评估](../../output/verification/online-ga4-processing-timeout-20261116/assessment.zh.md) 与 [修改方案](../../output/verification/online-ga4-processing-timeout-20261116/followup-plan.zh.md)。以下保留实施设计及其验收边界，后续方案尚未实施。

本轮来自 2026-11-16 的明确请求。先只读检查已经关闭的 GA4，再修复和离线验证；验收后只启动一轮新的 GA4，并由同一 controller 执行它唯一一次零调用回放。历史运行不重启、不重放、不改写，不执行被分析 Skill。

## 已查明的原因与未知部分

上次修订 processing 的终止条件是 **2700 秒原生进程总时限**，不是输入长度拒绝，也不能笼统称为连接超时。请求启动后第 1469.450 秒记录 WebSocket 在完成前关闭，第 1719.260 秒记录连接被重置，第 1734.643 秒记录采样请求超时；三条 CLI 内部重连记录不能计成三个新的原生调用。最后一条重连到进程终止仍有约 965 秒，日志没有解释这段时间的分配。

原始 prompt 为 810,707 个 Unicode 字符，含固定封套共 810,919，低于 1,048,576 的输入上限。相较初始 processing，增加 270,953 字符，其中 239,300 字符来自修订上下文，占增量 88.32%。旧 processing 本身占 228,473 字符；完整源文区仍为 180,842 字符，内容逐字相同。当前 CFG 从 679 IR 增至 770 IR，模型需要完整重建处理描述。

初始两次完成的 processing 请求分别耗时 1564.117 秒、1679.002 秒，公开输出用量为 62,249、66,789 token。总耗时包含提交、服务端处理、网络和本地开销，不能当成纯生成时长。这些公开事件没有 token delta；失败修订没有完整答复和最终用量，因此首 token 时间、纯生成时间、丢弃输出和失败请求用量均未知。网络中断与更大的生成任务同时存在，现有证据不能确定哪个因素主导。

精确时间线、计数程序和原始材料摘要见 [英文审计](../../output/verification/processing-timeout-20261116/timeout-evidence.en.md) 与 [机器证据](../../output/verification/processing-timeout-20261116/timeout-evidence.json)。

## 本轮代码方案

1. **完整输入的可逆表示。** processing 的 flow、当前 CFG、runtime contract、旧 fragment 和全部修订意见进入一个有摘要的结构化输入。重复 JSON 值和记录列可共享；程序展开后逐字比较逻辑 JSON。源文仍独立完整呈现，Task、对应关系和敏感性判断不进入 processing。既有纠错在更短时联合表示原输入、完整候选或指定记录和全部诊断。不是删字段、截源文或减少契约。
2. **完整输出的可逆表示。** 模型可以为重复证据、绑定和契约使用自包含共享值表。每个当前 IR 仍须出现在展开结果中；不存在默认复用旧 IR、跨产物指针、模板参数或省略记录继承。展开后执行原有 schema、覆盖、引用、证据、工具契约和语义校验。诊断、局部纠错、隔离和编译映射使用展开后的真实位置；原始回答仍原样记录。
3. **表示错误严格拒绝。** 悬空引用、循环引用、错误封套、重复键、未使用的错误定义及非法数值均不能通过。共享展开在分配结果前检查字符、节点和深度边界；超出边界是具体的表示错误，不以截断或虚构 unmodeled 代替。相同值在每次出现处独立复制，不合并操作、条件、成员或证据身份。
4. **公开事件的被动观察。** 在既有进程轮询和退出时记录日志字节数、公开事件类型、最终消息长度与摘要、主机观察时间区间。原始 stdout/stderr 不变，不读取私有会话或隐藏推理。此记录不声称测得首 token 或服务端生成耗时，也不影响回答验收和用量关联。
5. **修订失败的范围控制。** 当修订阶段发生已经确认结束、记录完整的请求失败，而原先已有一致的 Task/CFG/annotation 和绑定审查时，保留整套原始材料及全部审查问题。未完成修订不得替换其中某一部分；没有一致的新 annotation 时不发无意义的修订复审。原结果按真实证据继续给出局限和局部结论，修订始终标为未确认。初始生成失败、未知进程状态、材料完整性错误和用户中断仍保持原有失败／中断边界。
6. **并行失败回放。** 扩大回归发现：尚无选中 annotation 时，某条请求失败可能与另一个 worker 的完成交错，直接重新调度会得到不同的观察终态。新运行对此类已确认的早期请求失败记录有摘要绑定的阶段终止材料。回放验证全部实际准备的阶段、调用和失败传输记录，重编译图并核对源文、Task、CFG、片段、审查和修订依据，再独立复现主要失败原因；不启动缺失阶段，不生成可用 annotation。材料缺失、篡改或保存失败都不能宣称回放通过。成功运行仍走原有完整回放。另统一了 Task 原始中断与保存后中断的分类，Task v5 的语义职责和接口不变。

这几项适用于后续 Skill，不识别 GA4 名称，也不按固定字段制作特例。旧同名 IR 不代表相同语义，跨 CFG 自动复用不在本轮实现内。

## 预算、身份和验证

七次正常语义请求、两个 worker、每阶段一次结构纠错、一次共享语义修订、2700 秒原生时限及两次额外瞬态重试预算保持原值。超时不因此成为可外层重试的条件，不新增逐 IR 请求，不更换模型或推理强度。

新产物使用 guided run v14、document step v11、document fragments v6；processing 输入表示为 `skillflow-processing-input-display-v1`，可选输出表示为 `skillflow-processing-json-v1`，被动观察为 `skillflow-public-observation-v1`。展开后的 annotation、编译、source review、Task v5、demand 和 DOE 语义身份不变；旧产物保持原身份，不迁移结论。

并行失败材料使用 `skillflow-fatal-semantic-frontier-v1`，只适用于本轮新协议生成的符合条件的失败；没有为历史运行补写材料。启动门禁要求验收摘要覆盖全部运输层和生命周期脚本；回放必须同时结果相同且新增原生启动数为零才能标记 matched。原生进程退出未确认时，controller 不得写成 generation_closed。

离线验证覆盖精确展开与别名隔离、全部当前 IR 覆盖、普通和共享回答编译等价、坏引用／循环／资源边界、纠错和隔离坐标、完整源文和依赖隔离、失败修订整套保留、未知失败终止，以及注入答复的七请求分析与零调用回放。遥测使用假进程，验证其失败不改变原调用结果或重试策略。所有初始失败及对应修正记录保留，验收按最新测试身份汇总，不冒充一次全库全绿执行。

旧材料的纯显示比较证明字符规模可以降低，但不是线上 token 或耗时节省的实测。新实验将分别报告模型是否采用共享输出、真实请求／回答规模、重连和观察区间、可见用量及未知部分、最终选中的版本、传播与 DOE 覆盖。是否解决本次超时只能由新实验回答；后续修改方案以该次真实结果为依据。
