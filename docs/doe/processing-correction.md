# Processing format diagnostics and dependency-scoped CFG correction

This change makes the existing correction request more useful without changing acceptance rules or adding semantic requests. Processing prompts now state the complete existing shared-output grammar. A supplemental reader reports independently established format errors in a rejected raw answer. CFG correction can replace a sufficient set of existing dependency records when a global missing-endpoint diagnostic is demonstrably a consequence of rejected blocks. Every merged response still receives the original complete validation.

The implementation and interim offline evidence belong to [processing-correction-20261117](../../output/verification/processing-correction-20261117/). This document describes code present on 2026-11-17. Individual receipts below are interim evidence, not a final acceptance seal or a claim that an online timeout has been solved. See the [Chinese explanation](processing-correction.zh.md) and the [closed-run findings that motivated this work](../../output/verification/online-ga4-processing-timeout-20261116/assessment.en.md).

The closed run exposed two distinct correction problems. A processing answer contained two `shared_values` members and invalid mnemonic definition names, but strict JSON parsing stopped at the duplicate member. Separately, invalid local reads caused two CFG blocks to be rejected; edges referring to those blocks then produced a global constructor error. Treating that entire error as unexplained forced a complete CFG replacement. Selecting only the two erroneous heads would also be insufficient: the valid repair needed retained-value instructions in their bodies. Neither observation authorizes choosing between duplicate tables, weakening validation, or inventing a semantic fix.

The processing output language remains `skillflow-processing-json-v1`. Plain complete fragment JSON remains valid. Its optional envelope has exactly `format`, `payload` and one `shared_values` table. Definition names match `v(?:0|[1-9][0-9]*)`; `v0` and `v12` are valid, while mnemonic names and `v01` are not. Each JSON member occurs once. An exact `{"$ref":"v0"}` substitutes one complete declared JSON value. Forward and nested references are permitted; missing references, cycles and invalid unused definitions are rejected. Literal marker keys use `{"$literal_object":[["key",value],...]}` with distinct string keys. These forms do not introduce templates, partial merges, previous-run references or omitted-record inheritance.

The same grammar function is used for initial and revision processing, and is explicitly supplied on both complete and existing-record correction paths, including custom base prompts. Its example demonstrates forward/nested references and literal escaping; explanatory example fields are not a fragment schema. Complete initial/revision responses retain every current IR and required contract. A local correction replaces only the explicitly allowed existing slots it changes; unchanged slots are reused, each supplied replacement value is complete, and the final merged coverage is checked. The existing expansion limits remain 16,777,216 serialized characters, 500,000 nodes and 128 levels, with reference indirection bounded as well. Every expanded occurrence is an independent copy and passes the unchanged schema, reference, evidence, coverage and semantic checks.

`processing_wire_diagnostics.py` runs only after the authoritative processing parser or codec rejects a raw string. The original rejection stays first and unchanged. The supplemental reader keeps ordered object-member occurrences and positions, so it can report duplicate members together with independent name or marker-shape violations. It never selects a definition table, merges alternatives, resolves references, expands payloads, returns a candidate or performs semantic validation. A unique supported `format` declaration is required before applying wire-specific rules; an ambiguous format is not interpreted. Literal-object keys remain data, and only their encoded values are checked. A complete scan with no supplemental findings proves nothing about acceptance: missing references and cycles remain the codec's responsibility.

The diagnostic scan is bounded to 2,097,152 raw characters, 100,000 nodes and 96 nesting levels. A complete scan records counts by rule, at most three examples per group, and an explicit undisplayed count; all examples together use at most 12,000 serialized characters. Raw SHA-256 and zero-based, end-exclusive Unicode code-point spans bind the evidence to the exact string. Occurrence paths use member indexes and same-key occurrence numbers, not expanded IR coordinates. Non-string inputs receive no invented raw identity. Malformed syntax, scan limits and handled scanner resource failures produce explicit incomplete diagnostic coverage. The original complete raw answer remains in the recorded correction context; limiting supplemental examples never truncates source, contracts or the candidate. Supplemental diagnostics are root-only, so ambiguous wire data cannot become a local replacement or a salvaged fragment.

The CFG compiler retains all original diagnostic codes, paths, messages, ordering and validation outcomes. It records typed endpoint ownership only after the existing constructor has failed. That explanation requires exactly a root constructor value error matching the complete structured missing-endpoint issue set. Every explained endpoint must refer to a block actually rejected in that compilation. The evidence records original diagnostic indexes and values, block indexes/references/canonical IDs, original edge indexes, endpoint roles and the compiled candidate digest. A field-validation error, absent entry or unrelated structural defect cannot acquire this explanation. The diagnostic-only graph projection is never returned or used for acceptance.

The adapter separately binds diagnostics to the exact raw CFG wire digest. This matters because source copying and normalization change the compiler input: the compiled digest is provenance, not a claim that it equals the raw wire. `select_cfg_correction(candidate, diagnostics)` verifies the raw binding, rejecting-diagnostic ownership and every explained endpoint occurrence before deriving existing-record permissions. The result binds the complete diagnostics digest as well as the candidate digest.

For a local read-before-definition or completely explained rejected-block cascade, the editable region includes the affected control-flow strongly connected components, their actual result producers, and immediate and explicitly declared carry predecessors. This includes loop bodies where a missing retained value must be produced. Declared carry predecessors must agree with actual incoming relationships. Cross-boundary readers/producers and incident control edges are recorded as unchanged reference context. Unrelated downstream consumers and all transitive upstream ancestors are not automatically made editable. Selection follows authored identities and graph relationships, not names in prose, byte size, a fixed block radius or GA4-specific rules.

The correction prompt includes the complete current candidate once, the complete source supplied by the stage, all diagnostics, allowed record IDs and scope evidence. The model may supply complete replacements for a subset of permitted existing block slots, including additional instructions and fresh result identifiers inside them. Dependency correction cannot add or delete block records, change `block_ref` identities, alter edges or change entry. Before merging, the strategy rederives the permissions from the original candidate and diagnostics; stale candidate/context/permissions fail. Unlisted records are reused unchanged. The whole merged CFG then passes the unchanged validator. A head-only edit that references an unproduced retained value still fails.

Unexplained global defects, incomplete or stale causal evidence, ambiguous/malformed identities, binary dispatch requiring new topology, missing producers and inconsistent carry relationships use the existing whole-response correction. A genuinely absent authored endpoint is never reclassified as a rejected-block cascade. Ordinary precisely located schema, entry or edge record corrections retain their existing behavior when they can safely replace existing records; mixed dependency repair requiring topology changes falls back to a complete response. The program does not automatically repair source semantics, and the later source review still owns semantic faithfulness.
