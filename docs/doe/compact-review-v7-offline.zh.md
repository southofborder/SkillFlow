# 通用精简审查与生成自查：v7 实施及离线验收

日期：2026-10-29。正常七次语义请求、两个 worker、Task／任务对应／敏感性隔离及确定性后端保持。本轮只调整模型材料和流程故障处理，不按单个 Skill 的结构或大小设置特例。

## 实现

- 新运行使用 `skillflow-document-guided-run-v7`，保存 compact-v1 审查、自查与请求失败诊断继续策略；既有 step、annotation 和源包格式保持。
- 模型审查视图仅移除 `target_index` 和 annotation 内 `_fragment_origins`。完整定位表、归属表及全部原始材料继续在本地保存。未知目标只返回错误位置和最近有效父目标，不回送完整目录、不自动猜测。
- Task 复用既有自查，flow、CFG、processing、任务对应、sensitivity 和审查补充简短提交前自查。模型直接修正结果，不增加调用、不输出通过表或隐藏推理；只检查本阶段实际提供的材料。
- CLI 客户端在启动前检查含包装文本的 1,048,576 字符接口上限。完整输入保留，超限不发起过程、不裁剪、不重试、不增加用量；已保存完整答案优先复用。这不是模型 token 容量判断。
- 只有明确的 ModelRequestFailure／InputTooLarge 可以成为审查 request_failure。合法已编译候选继续传播与 DOE，结果保持 partial、diagnostic_only 和审查 incomplete；没有合法候选不生成假 DOE。
- 已保存异常保留原始类型和持久化失败标记；完整性、配置、未知进程状态、保存错误和用户中断不被降级。失败复审保留原问题为未确认，仍只有一轮共享修复。终态不残留假的 running。
- 旧 prompt 缺省关闭新自查；旧审查视图缺省保持旧渲染。旧合成示例重建显式选择旧视图，原文件不迁移。新运行使用新策略。
