# CFG／processing 对齐：v9 设计与验收口径

本轮直接处理 GA4 和 001／010／013 上一轮传播提前停止的表示与接口问题。正常七调用、两个 worker、程序组装和 Task／任务对应／敏感性隔离保持。已经完成的材料与定位索引复用继续使用。

## 接口改动

- **完整源文交付。**CFG 和三个语义片段的首次生成及语义重建都读取完整冻结源文，flow 或 processing 的引用范围不再控制下游能看到的代码。完全相同的嵌入代码和机械目录仍可省略；实际提交文本继续经过字符长度检查，没有切片或静默删减。
- **统一可执行形状。**公共参数从 context 获取；内部调用在实际调用点保留输入、返回和边界作用。循环采用 has_member 判断后取得 member，后者只产生当前成员。多路条件拆为二路条件；超过两个后继的 guided dispatch 提前诊断。零参调用、常量和真实 undefined 的不透明表达式仍可表示，undefined 不改成 null。
- **公开保存默认。**未说明更新方式的普通写入默认 replace；明确 append、delete 等语义优先。模型可以省略 mode，程序展开为明确模式。后端仍使用原有写入操作，不猜序列化格式，也不把该默认声称为源文明示。
- **按根因修复。**改变块、边、输入、公共输出或生产位置需要 cfg 问题域；固定 CFG 内可改的事实归 processing。已有的一轮依赖闭包负责重建，未新增归属字段或自动解读建议的机制。
- **拓扑纠正能实际完成。**检测到超过两个后继的 dispatch 时，拆分需要增加块和修改边，因此原有的一次结构纠正提交完整 CFG；其他可定位记录仍只替换指定槽。没有增加纠正预算或 patch 格式。
- **已知空集合保持为空。**实际失败回归发现：过滤／逐项映射后的已知空集合在 guard 中被当作未知。现在仅沿有限内容关系识别确定空的源集合，不执行过滤条件，不把未知来源且成员记录为空解释成空集合，也不整份重校验 DataRegistry。
- **路径未激活与缺失记录分开。**经传播材料验证为 not_reached 的目标保留需求声明，并输出非阻断 inactive_goal，避免寻找该路径上不存在的 producer。未建模、阻断与未解析绑定仍保留阻断诊断；某项 Task 没有任何可用需求时仍报告 unbound_requirement，不把路径未激活算作需求已满足。

CFG、processing、运行时契约与审查共用边界说明；几组可编译、传播的连接例子展示实际参数／返回、guard/member 和二路条件。例子增大了说明长度，离线记录单独报告字符数，不预设 token 节省。

当前运行身份为 `skillflow-document-guided-run-v9`，步骤／组装身份为 v8，运行时契约为 v11。源包格式保持不变；历史运行不会改版或续跑。

## 回归与限制

四个案例的源码及历史错误只作为独立离线夹具的来源。修正候选经编译、传播、保存及 DOE 检查；它们是人工编写的测试候选，不是模型已能够自行生成正确表示的证据。额外敏感字段的 DOE 阳性与必要敏感使用的反例单列，不进入线上目标输入。

源码中的计数歧义、无法独立表达的精确顺序要求、过滤谓词的可行性、精确缓存命中次数等仍按现有能力记录。完整对象需求与字段需求按实际接收方分别判断；动作必要不代表全部敏感载荷必要。
