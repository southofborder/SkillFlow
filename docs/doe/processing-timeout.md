# Processing timeout: general representation and observability changes

Closed online outcome (2026-11-17): the final affected-scope regression passed 788/788, but the sole fresh GA4 failed during initial processing correction. Complete same-material input was 12.53% shorter. The first shared answer duplicated its definition table; the prompt also omitted the codec's exact identifier grammar. Its correction encountered three internal sampling retries and hit the 2700-second total deadline. No accepted processing or DOE resulted. The sole replay matched with zero new starts. See the [English assessment](../../output/verification/online-ga4-processing-timeout-20261116/assessment.en.md) and [proposal](../../output/verification/online-ga4-processing-timeout-20261116/processing-result-followup-proposal.en.md). The design below records the implemented scope; proposed follow-ups are not implemented.

The previous GA4 revision-processing request hit the unchanged 2700-second native deadline. Public logs establish three sampling reconnects. They do not establish connection setup time, model-only generation time, or discarded output. The failed delivery was 810,919 Unicode characters including its envelope, below the adapter cap; it had no completed answer or final usage. The complete source did not grow. Most prompt growth came from including the entire prior processing fragment in a full 770-IR revision.

See the [raw-evidence audit](../../output/verification/processing-timeout-20261116/timeout-evidence.en.md), [architecture audit](../../output/verification/processing-timeout-20261116/architecture-design-audit.en.md), and [Chinese design and acceptance boundaries](processing-timeout.zh.md).

The implementation addresses repeated serialization on both sides of processing requests. Program-authored input shares exact structured values and record columns, with an exact expansion check and an independent unchanged complete-source suffix. The optional model-authored output envelope shares exact JSON values within that one answer. It neither imports old records nor infers missing current IR. Expansion precedes every existing schema, coverage, evidence, contract and operation check. Raw responses remain immutable; corrections, salvage and compilation use logical coordinates. Missing or cyclic references, malformed unused definitions and bounded-expansion errors remain explicit structural failures.

Passive public-log observations run at the existing native polling boundaries and exit. They add no process, thread, model call or retry. They record host observation intervals, byte positions, event types and completed-final sizes/hashes, without copying message bodies into telemetry. Optional monitoring failures cannot alter native response acceptance. Token timing remains unknown: the public CLI interface used here does not expose a proven text-delta stream. Official guidance distinguishes first nonempty text-delta timing from end-to-end latency; a completed CLI message is not a first-token event. [OpenAI latency guidance](https://developers.openai.com/api/docs/guides/latency-optimization).

A confirmed-ended shared-repair delivery failure can preserve the entire original selected Task/CFG/annotation bundle together with its original bound source review and objections. No partial revised material replaces one member. If no consistent revised annotation exists, the revision re-review is skipped and repair remains unconfirmed. Initial missing material, unknown process state, recording/integrity failure and user interruption do not gain a usable semantic result. Task v5 retains its interface; typed Task failures are recovered only from intact hash-bound failed-call and transport receipts.

Expanded offline regression also exposed a fatal-phase scheduling race when no annotation had been selected. A new `skillflow-fatal-semantic-frontier-v1` receipt binds the actual prepared stages, call files and observed terminal state for confirmed early request failures. Replay verifies every actual sibling, current guided dependencies and source-review bindings, and independently reproduces the primary failure before the unchanged final decision comparison. It does not reschedule absent stages, create a semantic value or continue to the backend. Missing, changed or incompletely saved evidence cannot pass. Successful-run replay is unchanged; historical runs receive no new receipt. Task's saved interruption classification now matches its original interruption classification without changing Task v5's interface or semantic responsibilities.

Seven normal requests, two workers, one structural correction per stage, one shared repair round, the 2700-second deadline and the existing two additional transient native attempts remain unchanged. The source-review codec, contract strictness, Task ownership and downstream demand/DOE semantics remain unchanged. New guided run v14, step v11 and fragment v6 distinguish future products; old artifacts are not migrated.

Offline tests must establish exact logical equivalence, complete source and current-IR coverage, correction and salvage behavior, representation limits, failure provenance, selected-bundle binding and fresh injected seven-request integration with zero-call replay. The new online run follows only after acceptance. Retrospective character reductions are not realized token savings or latency measurements; the final assessment must report what the fresh model actually emitted, all available usage and unknown work, selected coverage, and result-dependent follow-up recommendations.
