# 接口衔接修复与新一轮线上验证

本轮依据 2026-11-04 backend-r3 四例线上失败修复四个具体衔接点。保持正常七调用、两个 worker、Task／任务对应／sensitivity 隔离与现有单次结构纠正、单轮语义修复预算。旧运行、原始答案和失败回执不修改。

## 修改范围

- **可选 cases body：**模型省略 `segments` 与显式给出 `[]` 使用同一个空 body 语义。程序在展开与片段拆分中一致读取默认值；不扩大异常捕获，不把程序 KeyError 交给模型纠正。
- **写入输出：**普通保存／追加表达文件位置、实际输入及副作用，不要求生成整份写后文件的公共输出。源码确实返回路径、句柄或之后读取内容时，仍保留真实生产关系，不自动删除有用值。013 的四个无消费者写入结果作为独立离线反例，修正的是表示，不新增文件读操作。
- **表达式引用：**任务对应看到由已接受 processing 提取的简短规范化表达式目标，用现有引用类型直接引用；不给整个机械定位目录，不按自然语言猜条件或自动改写错误引用。初次生成与语义重建采用相同契约。
- **审查归属：**约束、禁止接收方和需求缺口定位到任务对应的 realization；敏感性仅负责来源、范围、属性和证据。改变公共输出、生产位置或边的发现归 CFG。程序继续按真实目标来源确定修复闭包，不根据解释文字重新猜测领域。

这些变更不改变确定性传播算法，不引入通用缓存、调用栈、异常执行器、额外模型阶段或新必填字段。格式规范、可用引用与短例子放在现有 prompt 内。模型能否自行选择正确表示，仍由新运行检验；离线注入正确候选不能被当作线上准确性证据。

## 离线验证口径

新夹具位于 `tests/fixtures/online_interface_r4/`，保留原始来源及哈希。分别检查可选空 body 的展开／编译、013 四条终态 append 与 return 的传播／保存／DOE、010／013 条件引用及 001 审查修复归属。必要的负例保持失败：错误表达式位置不会被程序偷偷改写，无关 sensitivity 不因禁止交付缺口而重建。

具体修正的语义界限如下：

- GA4 夹具证明合法省略可以展开、编译及组装，不声称旧整份 processing 答案在修复后已经语义完整，也不重放旧运行。
- 013 独立修正候选可处理全部 27 条 IR，保留四条实际 append 及四条 return。未相关的任务缺口仍为 partial，不能因此宣称没有 DOE。
- 010 条件引用可解析后，现有控制抽象仍可能给出 `potential_violation`；引用合法与约束满足分开报告。013 只修引用的副本仍保留旧写入缺口，条件结论保持未建立。
- 001 审查定位修正后只重建任务对应及复审。程序不从解释文字推断真实 owner；模型仍需将发现定位到应该改变的对象。

模型填写规模没有增加。010 和 013 的表达式视图分别为 2 条／453 字符和 1 条／187 字符；连同新增任务对应指引及标题，新增提示分别约为 1,263 和 997 字符。这是两个固定夹具的实际文本长度，不是任意 Skill 的长度保证，也不是 token 计费估算。

正常路径仍需恰好七次注入响应；重建按现有依赖闭包进行。测试中产生的回放只针对新建离线夹具，不续跑或重放旧线上目录。离线报告、XML 回执、接受后的实现哈希保存在 `output/verification/online-interface-r4-20261104/`。

## 新运行约束

离线通过后仅准备一批新的 GA4 → 001 → 010 → 013，沿用 `gpt-6.1-sol / high / openai` 和逐字相同的冻结源包，GA4 仍为全部 16 文件。Root 的单一队列拥有全部启动，各控制器拥有一次零模型调用重放。期间冻结实现、提示词、传输和预算；普通失败保留并继续队列，不追加择优采样。

最终区分生成 IR 覆盖、源码边界覆盖、支持／矛盾／未决关系及 DOE 有用性。完整公开调用与 tokens 包含纠正、修复和传输尝试；缺失用量保持未知。后端计算、保存、DOE、主分析、重放分别计时，嵌套区间不相加。旧 v9 进程和 heartbeat 保持暂停。
