# Aggregate CFG diagnostics and recovery without an accepted CFG

The change closes the complete path from a rejected required CFG through source review and the existing single shared repair round. A rejected candidate remains evidence; it never supplies a valid graph or authorizes backend execution.

Schema-valid CFG candidates now receive both preflight and compiler diagnostics before the single structural correction. Shape and source barriers remain strict. They prevent compiler speculation and causal/global scope inference, while exact existing-record correction remains available when identities and locations are safe. The causal selector binds the original candidate, every relevant rejected endpoint and dispatch diagnostic, and the exact global diagnostic. It independently verifies the cause inventory; insufficient proof falls back to whole-candidate correction. Every merged candidate receives full validation.

Failed-stage review targets use one exact policy: Task belongs to task, flow/graph to cfg, and the three annotation owners retain their existing domains. The supplied inventory binds source and actual failed request material. Request failures, skipped stages and an already accepted object do not create a failed-stage substitute. Correction cannot delete or reclassify an allegation to evade an unrepresentable target; valid independent findings remain usable.

Missing-CFG repair requires an accepted source-only Task and flow, a source-bound terminal structural CFG rejection, and a completed or locally retained source review. The deterministic rejection of the required graph can justify this existing round even without another semantic finding. Network failures and capability declarations do not authorize resampling. A fresh complete graph must pass the same validators; its dependent fragments must be rebuilt and form a consistent selected annotation. No additional normal stage or repair round is introduced.

Rejected evidence is retained in `audit/failed-stages`, including each attempt's validation and actual request, response, transport and chain bindings. The separate shared-repair decision records admission, barriers and evidence digests. Fatal frontier v2 binds these materials even if a sibling request fails before a revision-graph owner exists. Zero-call replay reconstructs observed failures and admission from verified saved calls and review inputs; it does not recategorize unobserved aborted siblings as review findings.

The new identities are guided run v16, step v13, fragments v8, source-review fragment v6 and fatal frontier v2. Task v5 isolation, seven normal semantic requests, two workers, one correction per chain and one shared repair round remain unchanged. Complete source and contracts are retained. Old artifacts keep their original identities.
