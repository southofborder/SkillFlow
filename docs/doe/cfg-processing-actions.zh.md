# CFG 动作与 processing 的字段级对齐

CFG 负责说明哪些动作会一起发生，processing 负责说明这些动作读取、生成和传送哪些值。同一路径上的「记录日志、查询、取响应字段」可以共用一条 IR。若某个选择会改变后续可达的保存、返回或异常路径，应在图中表达相应控制流。

## 从草图组装采集块

模型沿用原来的块、操作和出口格式。一个只含分支、跳转或返回的块，如果只消费已有结果或字面量，程序将它组装为普通控制块。若一个块先明确采集输入，随后在同一条路径处理采集结果，程序可以将第一次采集和后续操作拆成两个块，保留原有生产者、消费者和源码位置。程序插入的无条件跳转没有数据操作数。组装收据中的 `block_layout` 记录哪些原块经过归类或拆分。

如果同一次接收混用了原始上下文键和已计算的值，或者拆块会改变一条限制的作用范围，程序会将整个受影响块作为一个可修改位置。模型可以用原有的 `Block[]` 一次回答该块的相关问题。校验会同时报告未解决的编译错误和被拒绝的更新。若草图尚未成为有效 CFG，源文审查也可以引用草图里的具体动作或出口。程序只在这些位置授权修改，保留同一阶段的其他事实。

用上轮 GA4 的 117 块原始答复做离线验收时，程序直接归类了 25 个块，拆分了 18 个块。其余 6 个块通过一次注入纠错后，Lean 校验通过的 372 条 IR 全部交到了 processing 的正常入口。[完整验收与跨机复现](../../output/verification/online-ga4-cfg-assembly-20261123/offline-handoff.zh.md)

## 源码动作如何对应到运算

每条新指令保存局部动作标识、动作含义和源码行。只有一个源码动作时，程序可将该指令的处理位置归给它。有多个动作时，processing 要给出各自动作的实际位置，包括 case、成员循环、返回和输出绑定。校验检查位置是否存在、是否被重复使用、是否覆盖完整，以及可同时执行的动作次序。

已知调用、接收、读取、写入和交付各有语义角色。举例来说，声明了 `call` 的源码动作必须绑定到真实调用，才能建立接口输入义务与请求／响应关系。只绑定到占位、返回值或另一成员的操作会触发纠错。若 CFG 把已知外部调用写成普通计算，源文审查可分别定位 CFG 的角色和 processing 里的占位。对于纠错后仍缺失的绑定表，程序只在源码位置、角色和执行顺序共同给出唯一匹配时恢复它；歧义会保留在相应 IR 的审查材料中。

例如 Search Console 总览先调用日志，再查询远端，从响应中取 `data`，在默认配置下保存结果，并把它写入总览的 `topQueries` 字段。日志实现缺失时，可以保留这个动作的源文位置和有限影响范围。查询的请求、接收方、响应、字段投影和两次保存各有自己的操作记录。离线回归固定了完整的 16 文件输入，用人工提供的查询参数走这条路径，逐个比较查询返回、保存和报告字段上的数据版本。

## 入口参数与调用实参

一次采集对应源码中一次调用接收或一次资源读取。比如分别调用 `getPageViews(dateRange)` 和 `getTrafficSources(dateRange)` 时，两个形参属于不同的调用入口；如果 `siteOverview` 把自己的同一实参传给这两个函数，两个请求就应能追到同一个调用方版本。一个调用可以接收多个参数，一次读取的对象可以继续按字段投影。

CFG 用现有源码位置、动作、输入输出和分支表达这些关系。程序可从可识别的具名签名核实直接参数，并结合实际选择路径及消费者定位跨调用的合并。需要语义判断时，纠错同时给出相关采集块、选择分支和参数消费位置。对已有 CFG 的 processing 修订，`read_only.current_joins` 列出相关合并点的新前驱、输入版本及生产位置；仅有图上的可达关系仍不足以决定源文选中了哪个值。

processing 保留有依据的接收和输出绑定。可选参数的缺失与显式提供的空值有不同来源。缺失路径执行源码规定的默认逻辑，只有提供参数的路径能产生对应输入的读取证据。模块加载时的初始化按其实际发生条件单独处理；局部未知的值或效果可以随同已知操作记录为占位符。

完整 16 文件 GA4 回归使用上轮原始接收、选择分支和 processing 答复的摘录。三个调用入口从纠错后的同一份材料开始传播，分别核对发出的请求、SDK 返回的第 0 项、保存的版本和总览成员。可运行 `python -m pytest -q tests/document_guided/test_ga4_entry_occurrence_trace.py`。[夹具与覆盖范围](../../tests/fixtures/ga4_entry_occurrences/README.md)

## 局部未知如何参与判断

| 场景 | 程序如何处理 |
|---|---|
| 未知的返回值 | 在实际操作及其输入版本上生成符号值。结果可被投影、装入对象、作为条件或传给已知操作。 |
| 未知的行为 | 保留 `effect` 占位、可能涉及的输入和源码依据。已知的远端调用仍需填写真正的请求与响应接口。 |
| 可能改写状态 | 在声明的位置做弱更新，同时保留旧版本和可能产生的新版本。已确定的替换可消除旧版本的后续影响。未知地址的别名范围受资源类型约束。 |
| 任务只需已知字段 | 从任务选中的输出按字段倒推。没有经过占位的字段沿用原有精确关系。 |
| 任务需要占位输出 | 标出该输出、占位操作、源码依据及可能影响它的输入。上游经过选字段时，未决只回到相应字段。敏感性沿可能依赖传播时保留“可能影响”的性质。 |
| 整条 IR 缺少模型 | 源文审查为每个位置给出单独决定。能够拆解时提出局部修订，保留整条缺口时须给出具体缺失关系、阻断原因及出处。 |

报告的 `processed` 表示该指令的实际处理没有用到占位；`processed_with_placeholder` 表示该指令执行过占位，已知操作也有实际记录；`blocked` 等状态表示相应位置缺少可执行记录。某个 `processed` 指令仍可能接收上游符号值，字段的必要性以需求推导证据为准。

例如同一计算实际读取 `a.a`、`b.b` 和 `c.c`，其已审查契约只将前两项与所需结果关联。若同一条 IR 内还有未知日志，且任务或约束没有依赖日志中的 `c.c`，第三项仍可列为可删除。若任务改为要求一个可能取决于 `c.c` 的回调结果，该字段有局部未决依据。

入口敏感性缺口沿修订保留原始位置。如果一个仍存在的 CFG 动作暂时缺少 processing，它的入口缺口继续有效。已有缺口的消解需能回指当前入口或提供原位置确已删除的依据。历史材料用其记录的生产者身份只读验证。

## 本机离线验收

在同一份冻结代码上分四组运行完整的 `tests/`，6,291 项通过，4 项跳过，0 项失败。两项跳过涉及 Windows 创建符号链接的权限，两项依赖本机未安装的可选历史实验材料。Lean 使用本机从仓库源码构建的校验器。各组命令范围、时间和 JUnit 文件摘要见 [离线验收记录](../../output/verification/online-ga4-action-alignment-20261123/offline-acceptance.json)。

同源 GA4 回归核对了查询响应、`data` 投影、默认保存、`topQueries` 成员及总览保存的数据版本。另一项回归通过七个注入的正常阶段和零调用重放，检查了已选 CFG 与 processing 的动作绑定。73 项原有入口缺口的修订回归分别检查原位置保留和单项消解。
