# 后端传播精简：离线验收与 GA4 限时结果

本轮四项后端修改已完成，离线回归通过。**实测新版传播在 17 分 32.55 秒返回，处理 326/347 条生成 IR（93.95%）；仍有 2 条未建模、19 条阻断，完整 DOE 未在 30 分钟内产出。**因此不能把这次结果称为完整 GA4 跑通或完整有用的 DOE。

旧版超时在传播，新版实测 r2 超时在 DOE 阶段；一次栈采样定位到初始化中的整份记录重复复制。后续已经补掉 DOE 中每查一个操作数就复制整份记录的问题，形成最终 r3；该补修有回归和局部微测，**没有追加完整 GA4 计算**。旧进程、队列及自动化保持暂停。

## 1. 实现完成了什么

| 修改 | 现在的行为 |
|---|---|
| 去掉热路径重复校验 | 外部材料接受必要检查后复用；相同类型、内容、来源的重复登记直接返回，不增长 revision、不通知消费者；内部计算不重复整表验证。仍判断实际缺输入、来源冲突、集合操作数和成员不兼容。 |
| 实际依赖驱动工作队列 | 工作项是基本块内的关联分区。记录实际读取的 Data／字段，包括递归读取和缺失字段；数据变化唤醒消费者，边变化更新相应后继。删除全局 revision 变化就重跑全部已访问块的规则。 |
| 活跃位置裁剪 | 操作证据形成后，只保留后续计算或证据需要的位置。强覆盖可以结束旧值用途，可能写入和别名仍保留旧值。不会根据 Task 的必要性判断删掉可能暴露的数据。 |
| 关系行合流与兼容连接 | `(A,a)`、`(B,b)` 作为完整关系保留，不拆成独立集合产生交叉配对。投影后完全相同的行才去重；输入候选先检查绑定兼容，再组合。 |

循环内已有的 family、mapped／accumulated collection 继续使用。入口／回边、merge 前驱、内外成员和正常／错误候选的区别由程序保留。边撤销旧关系时，包括 SCC 内部边撤销，程序从仍存在的外部输入重建该 SCC 的当前出边；纯增长不触发这一重建。历史 Data 和可能交付不会因工作状态裁剪而消失。

这实际采用了程序分析的依赖驱动不动点、活跃变量／位置分析和关系分区思想。没有增加通用调用栈、异常执行器、持久缓存或另一套逐指令调度系统。方法出处及精确限制见[设计](backend-sparse-design.zh.md)和[英文计算契约](../propagation/backend-computation-contract.md)。

传播记录 v16 的 entry／exit 是计算和证据所需位置的投影，运行身份为 v21。位置省略不表示清空、不可达或安全；旧 v15／v20 材料保留原语义只读支持。本轮没有改模型字段、提示词或正常七调用流程。

## 2. 完整 GA4：真实结果与成本

两版使用同一固定输入、同一台机器串行执行，每版限时 1,800 秒，包含传播、DOE 和保存。输入是旧 v9 已选 CFG 与 compiled annotation 的独立副本，177 块、347 条 IR；没有恢复旧控制器或调用其 replay。

| 指标 | 冻结旧版 | 实测新版 r2 |
|---|---:|---:|
| 总墙钟时间 | 1,800.11 秒，超时 | 1,800.07 秒，超时 |
| 子进程 CPU | 1,791.45 秒 | 1,789.64 秒 |
| 采样峰值 private memory | 527.29 MiB | 304.66 MiB |
| 传播 | 未返回；最后记录的活动区间已达 1,796.07 秒 | **1,052.55 秒返回**，状态 incomplete |
| 最终生成 IR 覆盖 | 无最终结果 | **326 处理 / 2 未建模 / 19 阻断** |
| DOE | 未进入 | 未返回；最后活动区间已达 740.06 秒 |
| 完整结果保存 | 未完成 | 未完成 |
| 传播热路径整表 registry 校验 | **12,546 次**，累计遍历 8,836,479 条记录 | **0 次** |

旧版虽然观察到进入过 320 条不同 IR，但它没有返回最终传播结果，不能把这个数当作已处理覆盖率。完整产物在 DOE 返回后保存，因此新版保留的是传播已返回的覆盖、统计、诊断回执，没有完整传播记录文件或 DOE 结果文件。

两版达到的阶段不同，**不报告完整流程加速比，也不把峰值内存数字称为同完成范围的内存降幅**。两次完整限时计算合计约 60 分 0.18 秒墙钟、59 分 41.09 秒子进程 CPU。小基准和测试成本另有回执。

新版还有明显的关系计算工作量：2,842 次分区求值、79,334 次 IR 求值、383,127 个兼容候选；最大活跃关系行 7,650，单分区最多 107 行。`block_115` 最多 1,486 行，`block_125` 最多 1,485 行，`block_116/118/119/122` 各最多 716 行。剩余规模主要集中于 reindex 循环中仍有区别的活跃关系。不能因为投影已经实现，就宣称所有有效关系都已压缩到理想规模；旧版未完成，也没有同完成点的关系行缩减率。

证据：[完整限时对比汇总](../../output/verification/backend-sparse-20261103/bounded-comparison-summary.json)、[旧版回执](../../output/verification/backend-sparse-20261103/performance/baseline/parent-result.json)、[新版回执](../../output/verification/backend-sparse-20261103/performance/current/parent-result.json)。

## 3. 传播剩余缺口在哪里

这次传播没有因为循环不收敛或普通接口异常而整体退出，但原 annotation 的两条未建模项仍然截断相应路径：

- **`ir_029`：选定分析函数的调用边界。**缺少真实函数实例与保存结果的关联，后续 `ir_030–047` 的结果选择、读取已保存 JSON、生成并保存 Markdown 总结被阻断。这是关键主流程，所以 93.95% 不能解释为用户关心的完整流程已经成功。
- **`ir_301`：目录不存在时的 `mkdirSync`。**这条分支未建模，后续 `ir_302` 阻断；目录已存在的另一路径应分开看。

旧输入还保留 36 条 processing gaps，50 个 Task realizations 中 47 个带有 gap。`ir_238` 的正常 notification-helper 候选也保留调用者／状态关系的精度限制。本轮没有偷偷修改这些模型答案。

另外两条 `ir_312` 的 `missing_part` 诊断与内部 completion 的 `value` 选择有关。模型此前分别构造正常 `{normal:true,value:...}` 和两个错误 `{normal:false,error:...}` 候选；从结构看，错误候选没有 `value`。这不是“原始保存 JSON 缺少业务字段”的证据，也不能在缺少完整记录的情况下断言两个 Data ID 的具体路径。它们是非致命诊断，与两条未建模截断分别记录。

本轮无法从 IR 统计替代对 13 个 API 点、25 个保存点、3 个源码循环的完整边界审计；不提供新的源文覆盖率、总体准确率或“没有 DOE”的结论。详见[原建模限制与源码定位](../../output/verification/backend-sparse-20261103/frozen-model-limitations.en.md)。

## 4. 完成的小基准与配对核对

每个版本、每个小夹具串行运行三次，以下是指定计时段的中位数：

| 夹具 | 旧值 | 新值 | 可以支持的结论 |
|---|---:|---:|---|
| 959 条普通 registry 记录上重复登记 1,486 次 | 45.151 秒 | 0.409 秒 | 该登记路径约 **110.47 倍**；整表验证 1,486 → 0 |
| 循环＋独立分支的传播 | 0.479 秒 | 0.101 秒 | 该夹具约 **4.72 倍**；独立 IR 重算 **3 → 1**，全部 IR 求值 55 → 32 |
| 嵌套成员与接收方配对的传播 | 0.752 秒 | 0.096 秒 | 该夹具约 **7.79 倍**；全部 IR 求值 66 → 21 |
| r2／r3 的 1,200 次操作数查询 | 0.266 秒 | 0.00189 秒 | records getter **1,200 → 0**；构造阶段读取一次 |

登记夹具只是按现场规模重建，不是暂停进程的内存复原。查询微测不计引擎初始化、完整 DOE 或保存。以上数字均不能外推成完整 GA4 加速倍数。

循环夹具的 Data 和操作事实保持一致。嵌套夹具的 23 条 Data 完全一致，接收方与载荷严格保持 `A→a0`、`A→a1`、`B→b0`、`B→b1`。一处原始操作事实哈希不同，经独立核对只有两个完整候选的列表排列顺序变化；事件顺序、输入输出槽位和配对没有变化。仅规范化完整候选行后哈希一致，另用两个 hash seed 复核该夹具的结果稳定。原始不同哈希仍保留，详见[差异核对](../../output/verification/backend-sparse-20261103/nested-operation-facts-audit/assessment.md)。

## 5. DOE 初始化的补修

限时计算中的一次非阻塞栈采样定位到：`DemandEngine._operand_data` 每次通过 `PropagationMaterials.records` 获取数据，都会深拷贝整份记录。它发生在 DOE 初始化，不能解释为传播仍在计算循环不动点。

现在 `_Index` 取得一次独立 CFG／Data／records，建立状态绑定和操作数引用索引；需求、敏感性与约束消费者复用当前实例的材料。Task review 也只取得一次局部 CFG。公开 getter 仍返回独立副本，内部索引、返回候选、结果 coverage 和不同分析实例之间仍隔离。

这是 r3 相对实测 r2 唯一的一组生产改动，共七个 DOE 文件；全部传播文件未变。三次查询微测结果与 r2 原方法的候选哈希一致，相关用例通过。**这说明定位到的复制路径已被消除，不代表已经实测证明整个 GA4 DOE 会在限时内完成。**两版各一次完整计算的额度已经用完，本轮没有追加第三次。
