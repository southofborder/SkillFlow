# 审查恢复、地址身份与执行错误局部隔离

反复出现 `partial` 不能统一归因于“运行时契约不够严谨”。最近一次 GA4
同时暴露了三种问题：审查纠错投递重复材料过多；未知内容被误当作未知地址；
一个局部集合类型错误中断了独立的后续工作。它们分别需要修正纠错协议、
地址语义及执行器的失败传播范围。源文确有缺失或语义暂不受支持时，保留局部
未决仍然是正确行为，不能通过放宽校验消除 `partial`。

审查纠错改为由程序确定可以替换的记录和可以补填的义务槽。缺失槽来自当前
完整契约清单，关联冲突覆盖受影响的 finding 和 check 两侧；模型不能增加
未知槽、变更其他记录或把插入等同于通过。完整合并结果仍经过原有严格校验。
没有变化的前次答复保留在不可变文件中，投递保留全部源文、契约和运行时规范。
无法确定局部范围时仍采用完整答复纠错。该机制没有 GA4 专用分支。

若已有的一次纠错投递以可确认结束的类型化错误失败，可从完整首次答复中
严格隔离并保留独立有效记录。凭证绑定原始答复、现有正规化、校验、投递错误、
当前材料和隔离结果。缺失、无效、冲突范围继续阻断，报告保留原始失败并标记
partial。进程状态未知、记录损坏、身份不一致均不能走这条恢复路径。有效
finding 仍可进入已有的一轮共享修复，按真实依赖闭包重建。

地址声明新增 `address_kind`，默认 `identified`。确实无法确定地址关系时才
使用 `unidentified`，并提供具体原因及源文位置，理由是否成立由源文审查判断。
参数值、异常内容、返回值未知，并不意味着它们存放在同一地址。名称只是身份
标签；真正未知的地址仍保留同类地址的保守别名和弱写入。不可变 Data 身份与
严格对象／集合检查没有放宽。

已知的操作数或集合域错误记录准确的 IR、操作、输入 Data 和成功前缀观察。
失败 IR 的注册表修改回滚，声明输出及可能写入位置标记为不可用，再沿值、状态、
成员及控制依赖传播阻断。独立工作继续执行；确定覆盖写入可以解除后续状态依赖，
控制依赖只有在证明有限汇合后才解除。未知程序错误和完整性错误仍是致命错误。
中断后尚未执行的节点不能当作已证明不可达，更不能据此判定输入可删。

规范需要覆盖的是系统实际支持的有限操作集合。本轮运行时契约 v12 增加与
类型 schema 核对的清单：14 种原子操作、flat call、3 种结构以及 14 种结构化
表达式，明确域、身份与别名、效果、失败及证据要求。这是补齐受支持词汇的
规范，不是枚举任意 Skill 的所有外部语义。无法表达的源文行为必须给出有定位的
缺口；工具接口的必要输入仍须有接口依据，不能从当前实参反向自证。

受影响身份升级：guided v17、step v14、annotation v11、flat annotation v6、
fragments v9、source review v7、编译映射 v15、profile v24、propagation v22、
demand v11、sensitivity review v9、DOE v11。Task 接口及源文隔离职责保持不变。
旧产物保留原身份和原结论。

从 processing 重跑使用新的材料继承入口。它把所选 source、Task、flow、CFG
及其已接受答复链完整复制到新目录，核验实际依赖关系，保留旧生产者身份，绑定
新凭证。新一轮重新生成 processing、任务对应、敏感性和源文审查；若共享修复
需要，仍按正常依赖重建后续材料。保持七阶段职责：继承前三阶段，新发四次正常
请求；两个 worker、每阶段一次纠错、一轮共享修复和传输预算均不变。继承成本
与新增调用成本分别报告。

离线原始结果保存在 `output/verification/runtime-locality-20261117/`，最终通过
数量和实现身份以该目录的验收凭证为准。新一轮控制器位于
`output/verification/online-ga4-runtime-locality-20261117/`，只有离线验收后才可
准备和启动。线上结论须依据实际审查覆盖、传播、源文边界、输入评估、DOE 和
成本作出；本设计说明不预先声称线上完成。
