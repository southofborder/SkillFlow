# 源文审查的严格局部隔离

本轮修复分为两部分：让缺失字段的结构诊断准确指出应修改的现有记录；在既有结构修正预算耗尽后，保留已通过核验且不受冲突影响的独立审查结论。输入类型、字段路径、源文引用、契约覆盖和材料身份的验证要求均不放宽。

## 原问题与边界

旧 Schema 没有展示 `kind` 与 `actual` 的对应关系，也没有给 missing-field 路径声明 `minItems=1`。首答把缺字段写成缺整个参数，运行时先报类型关系错误；唯一纠错把定位改为 `input_range` 的空路径后，才碰到第二条隐藏约束。新实现让这两项规则直接进入可见 Schema。源文只为 `limit` 建立了明确 SDK 字段路径；filters／orderBy 的逻辑用途不能自动充当 SDK 字段编码。定位不成立时必须保留具体限制，不能猜名字以通过校验。

上一轮 GA4 的末次源文审查包含 271 条契约检查记录，但三个 `missing_field` 记录使用了空的实际字段路径。三条记录指向同一个实际操作，而整体响应验证拒绝了整份审查。这里的 271 是候选答复中的记录数量，不是 271 条已核验通过的结论。

本轮不会把空路径解释成缺失字段，也不会把错误记录自动改成 `missing_argument`。缺少字段和缺少整个参数具有不同语义：前者必须定位实际存在的输入槽及其中被要求的字段路径；后者只能用于整个参数确实未提供的情况。诊断保留原记录位置，让模型补充或纠正关系，并继续经过原有严格验证。

普通局部语法错误仍替换现有记录。源文输入错误或跨记录冲突可能要求改用其他合法审查表，例如把未确立的字段编码表示为具体契约缺口，因此它们使用既有的一次完整答复修正，而不是只能改原槽位的替换格式。完整修正必须保留源文支持的原有问题，不得猜字段、伪称整个参数缺失或删掉问题来通过验证。错误的修正外壳（例如要求完整答复却返回 replacements）会被拒绝，原候选仍保留用于局部隔离；外壳合法但内部仍有问题的新候选则成为最终核验对象。

局部隔离不保证能挽救任何固定数量的契约。源文确有跨区域错误、目标无法定位，或者宽范围 CFG／annotation finding 与多条契约冲突时，相关范围仍会阻断。

## 逐记录验证与完整覆盖

源文审查保留四类完整表：普通 findings、输入契约检查、获取投影检查、源文输入错误。程序逐条验证结构、真实目标、原文依据及关系约束，再检查完整 inventory 的覆盖、重复和冲突。候选答复、候选哈希、每条验证结果、全部 inventory 和阻断关系一并保存到不可变审查材料。

只有已通过自身验证、覆盖所需范围且没有相关冲突的记录可以供后端使用。漏行、重复、坏引用、非法枚举和定位失败均保留明确状态，不能把被过滤的行当成“不需要审查”，也不能将缺少结论解释成接受。

普通 finding 使用原有目标前缀重叠规则。比如指向整个 CFG 的有效问题可能与大量 accepted 契约冲突；局部隔离不会悄悄缩小该目标或替模型消除矛盾。有效的源文输入错误仍是语义错误，继续报告其实际输入、预期关系和输出／动作影响；验证失败的候选记录只形成验证阻碍，不能冒充已发现的语义错误。

## 验证阻碍如何定位

`validation_barriers` 保存失败记录位置、验证代码、具体原因、所需修正以及受影响操作引用。能够从候选目标解析到真实操作时，按 `instruction_id` 与原始操作路径的精确组合定位。需要请求／响应配对的关系保持每个实际出现位置，不合并成一个虚构操作。

当前阻碍粒度为整个操作。一个非法的字段定位并未证明更窄的字段关系，因此不能仅保护候选字段而放行同一操作的其余输入。只有目标或整段材料本身无法可靠定位时，才使用明确的 `all_operations` 阻碍，并保留为何无法局部化的验证依据。它不是由“计算黑盒”或“值未知”推导出的泛化未决。

缺失契约检查和缺失投影检查仍按完整 inventory 记录阻断；未接受的范围不能使用同一操作的其他 accepted 行填补。投影能力还必须匹配实际请求与响应，不能从另一调用借用。

## 后端统一消费

需求计算只使用已绑定当前材料的审查凭据。`partial` 允许访问自身覆盖完整且未被阻断的契约范围；顶层状态为 complete 本身也不再足以证明某条契约可用。

对受阻碍操作的必要动作或输出，后端保留到达该位置的任务需求身份，并保守回传所有实际输入槽的整值需求。这个门控也适用于选字段等确定性操作：确定性转移不能替无效审查记录补出尚未核验的语义关系。程序不创建缺失输入，不改写正向读取、不缩小原始观察，也不把验证阻碍新增为任务种子。

全部输入评估从实际 CFG 和操作记录枚举。受阻碍操作即使没有任何任务需求，其输入也必须有整值 unresolved 范围和精确验证诊断，不能凭零需求给出删除结论。IR 输入及获取结果通过实际词法引用和生产者／消费者关系查找相关阻碍；不会因全局 Data 值相同就污染另一消费位置。独立输入仍可按其真实需求及限制判断可删除。未到达位置继续单列覆盖状态。

删除影响和限制保持使用同一份操作阻碍。受影响的修改不能再借助原来的确定性规则或“结构约束”快速路径获得保持证明。阻碍没有被证明与某个字段无关之前，不声明该字段删除安全。获取结果的需求范围与接口能否裁剪仍分别处理。

保存后的需求结果也接受上述检查：适用阻碍必须存在可核对的诊断和整值 unresolved 范围，不允许移除这些记录后把输入改报为 deletable。生成与加载共用只读的实际输入引用索引，诊断包含失败记录位置、原因和所需补充。

## 修复、身份与预算

通过验证的 partial 审查 findings 可进入原有语义修复路由，由相应 processing、CFG 或 Task 责任方处理，并重建既有依赖闭包。非法记录本身不会成为凭空增加模型调用的理由，也不会被路由成已证实的 Skill 语义错误。修复后的审查必须重新绑定修复后的材料，修复前凭据不可继续授权新契约。

本轮仍是七次正常语义请求、两个 worker、原有每阶段结构修正预算和一轮共享语义修复预算。没有逐 IR 模型调用，没有为失败记录分拆额外审查请求，没有增加重试或传输预算。完整源文与完整契约继续送审，既有无损审查显示格式保持可还原。

修正提示把原始逻辑输入与完整候选／诊断放进同一可还原显示，共享精确重复值，并对修正上下文的对象数组使用现有列式记录格式。原始完整源文只保留一次且逐字不变，原有格式约束和指令保持。相同 finding 引起的冲突可合并显示，但显式列出每一个检查记录、义务及目标关系；全部原始诊断和映射仍保存在审计材料中。程序在使用压缩显示前核对展开结果与完整逻辑 JSON 精确相等，并选择完整展示中更短的一个。它不截断内容、不漏契约、不提高传输上限，也不保证任意未来输入都必然低于上限。

源文审查、输入契约凭据、需求结果和 guided run 使用新协议身份区分本轮行为；旧产物保留原身份和结论，不迁移、不重写。审查加载会从精确候选及当前 source、CFG、annotation、mapping 和 inventory 重新核验隔离账本；重新计算表面哈希不能令伪造覆盖、删掉阻碍或陈旧材料通过。

## 离线验收范围

专门后端测试覆盖：精确操作配对；partial 的自身覆盖条件；契约和投影阻断；确定性操作零需求保护；同一 IR 的独立消费不受污染；FIFO／LIFO 一致；删除影响与结构限制保持；以及无法定位时的显式全操作阻碍。

公共链路用注入的离线审查答复依次经过 `isolate_source_review`、不可变凭据构建、`prepare_demand_review`、`prepare_sensitivity_review` 和正式 HTML／Markdown 报告。三个非法 missing-field 记录只阻断其指向的确定性操作；另一计算的无需求输入仍可删除，必要字段仍保留，实际读取和模型观察记录完全不变。报告保留验证原因、记录指针和输入修改位置。

对上一轮冻结 GA4 材料另做了纯离线验证与提示渲染测量，没有重跑其 controller、replay 或后端。首答的 317 条原始诊断合并显示为 16 条，末次候选的 311 条合并为 10 条；两者的 307 对冲突关系均完整保留于六组中。包含 212 字符传输外壳后的完整修正输入分别为 1,014,657 和 1,014,077 字符，距未变的 1,048,576 上限还剩 33,919 和 34,499 字符。完整源文、全部逻辑输入、候选、诊断、冲突配对及目标均通过精确还原检查。输入文件、实现和提示哈希见 `review-correction-size.json`；这些数字是冻结材料的衍生离线测量，不是新的线上实验结果。

更多覆盖包括记录修正、严格候选拒绝、完整 inventory、宽目标冲突、材料变更及伪造账本拒绝。离线测试只能证明这些实现和回归边界，不证明自然语言审查必然完整或某次真实 GA4 一定能得到删除结论。具体验收命令与结果保存在 `output/verification/source-review-locality-20261113/`；新线上实验由 root 在离线验收后按本轮单次授权另行准备，历史运行保持关闭。
