# 通用循环与输出契约精简

本轮依据 2026-10-29 批准的方案实施，只进行离线验证。正常七调用、两个 worker、独立 Task 和任务对应／敏感性隔离保持。v7 的真实运行、原答、失败和重放记录保持原样；新协议不用于续跑它。

## 1. 模型和程序的职责

保留显式循环 CFG。CFG 给出真实块、边、操作数和生产／消费关系；processing 给出可执行分析语义。程序从控制流识别循环和嵌套作用域，不向模型索取循环编号、迭代次数或求解过程。

处理原语补齐入边合流、当前成员和有类型的边选择。合流按真实前驱选择值；同一前驱上的值组成保持一致，不各自自由拼接。成员绑定源集合的 occurrence，重复值不意味着同一次获取。分支引用实际值与目标边，只有受支持的具体条件才能排除路径，不能执行自然语言 condition_text。

集合累计保留初始内容和后续贡献。已知空集合不产生循环体作用；未知成员不是一条实际成员。重试或分页的未知重复次数不伪装成一次调用。内外循环作用域由程序组合，不需要额外填写嵌套管理字段。

## 2. 有限传播和 DOE

普通不可变 Data 身份保留。循环内部使用有限的静态定义、候选、成员、位置和关系事实；达到不动点后封存摘要。不能仅把结果 ID 改成操作位置，却继续递归增长内容树或来源链。

循环输出的摘要明确区分实际内容与可能依赖，保留获取来源、成员与接收方对应、输入与返回身份。未知重复、递归内容未展开范围和无法证明的条件分别保留。摘要不能证明某次写入必然发生、精确缓存命中次数或每次 handle 都采用最新凭据。

确定单一位置的覆盖可以保持强更新；别名／汇总位置使用可能更新。边界观察单独累计，之后删除或覆盖不能撤销已经发生的可能交付。正常完成集合与失败前缀保持区别，未捕获失败不能得到伪造的最终保存。

需求路径复用已有 each 标记并允许逐层出现，敏感性和反向需求按照实际成员关系逐层传递；基数需求不转化成所有成员内容需求。缺少真实传播记录的边界保持“已声明、尚未解析”，不能显示成无载荷或无暴露。局部不支持只截止相应依赖后续，独立分支保留其结果。

共享值的创建来源与当前使用成员分开。程序的透明使用别名仍指向实际存储版本，不能
制造一次新获取或新 handle；同一来源候选的多个值保留共同选择。有限摘要无法保留的
多代关联只在不同携带值共同依赖已丢失历史选择时明确截止，不通过自由组合伪造完整元组。
单个摘要游标与固定参数或独立保留的当前接收方仍可一起分析；同一值的重复引用仍是同一个选择。

## 3. 接口减法和模型可见契约

合法候选没有新增操作时允许空 body，并直接 yield 已有值。yield 不等于模型观察，不能为了格式要求增加 local returns 或假 compute。段数组默认声明 fixed；无固定顺序时显式 partial。模型仍需依据源码选择，程序不替模型推断顺序。

按实际 kind 选择验证分支，普通 processing 无需新增必填 kind。普通证据和适用源文证据分别继承；敏感性和表达式不会以 CFG 引用替代源文。记录替换槽保持固定，但可修正记录内被诊断的目标引用，再执行全对象覆盖／作用域验证。

各阶段只获得自身的类型格式、短的跨字段规则及少量完整例子。类型生成字段说明；实际校验器附近的规则说明类型无法表达的顺序、证据、身份和作用域关系。覆盖清单检查 annotation_wire、fragments 和 cfg_wire 中具名定制诊断族的说明与例子关联；其余依靠实际 schema、代表性正反例和既有编译测试，不声称穷尽全后端所有语义组合。不建立第二套可执行格式语言。内部文件损坏或程序错误不作为模型格式纠正任务。

英文例子应通过实际片段验证、展开和编译，不用空对象代替复杂合法分支。每阶段最多一次结构纠正、全流程一轮语义修复不变。已有完整答案本地复用，CLI 交付方式不变。

## 4. 新协议与失败重放

新 guided run 使用 v8，step 与 annotation 使用 v7，运行时契约使用 v10。冻结历史协议和产物不迁移。DOE 未提交结果时，失败重放重新执行相同的确定性计算并比较原始错误；不将缺失成功 manifest 的包装错误当作原始失败，不发布新的 DOE 结果。

对应的新保存格式为 security-profile v21、Data v6、传播记录 v15、传播 run v20、
annotation run v21 和 DOE run v7。共享的源文抽象规则放在 common 层，图生成不会反向依赖
传播实现；原契约模块保留导入兼容，不复制另一份规则。

无 usage、关闭监控或统计失败不改变语义分析。模型调用数、结构纠正数、修复数和传输次数仍分别统计。格式规模测量只说明类型／说明的字符数和字段位置数量，不等于真实响应大小、tokens 或速度提升。

## 5. 验收边界

验收覆盖逐项、重试、分页、累积、嵌套、空／未知／重复成员、候选与接收方配对、覆盖与历史观察、嵌套 each、完整对象需求和多余字段；同时保持七调用、隔离、有限修复与零模型重放。采用冻结 GA4 源码支持的夹具及其他结构的合成材料。

循环计算完成不证明源码和标注语义等价，也不证明所有路径可行、敏感性穷尽或需求最小。实际速度和准确性需要后续获授权的新运行验证；本轮离线通过不能替代它们。

局部语义缺口与全局资源上限分别记录。现有 `max_variants` 默认 100,000，分别限制候选组合、关系事实、条件路由与入边状态候选；耗尽时返回 `resource_limit`，可能停止尚未处理的独立分支。这不同于只截止相关区域的未支持关联，有限表示也不保证任意规模 Skill 的耗时或内存都足够小。

显式 CFG 累计使用初始值和追加贡献的有限方程，保留成员及接收方配对；它不等于逐轮
执行后得到的具体数组。即使输入是已知列表，一般显式累计的最终精确长度、位置、
顺序及抽象前缀排除也未自动得到证明；源位置和响应对应仍保留。既有
结构化 for_each 的源位置、重复成员与映射集合关系继续保留，不能把一般累计摘要误报成
同样精确的完整有序数组。精确下标依赖超出摘要能证明的范围时，应说明未解析关系。
