# SkillFlow DOE 目标与设计原则

## 当前实现更新（2026-10-15）：独立任务基准与逐项转译审查

当前正式链为 **源文驱动的独立 Task 提取 → 固定 Task 的需求／处理／敏感联合标注 → 四轴完整语义审查 → 至多一轮受控修复与独立复审 → 确定性传播和全部 sink 的 DOE 对照**。这替换此前“Task 与处理语义同次生成”的责任分工；没有最终 DOE 模型调用，也不执行缩减后的 Skill。

[独立 Task v3](task-evidence.md) 只接收全部冻结可读源文和可选独立用户任务。程序要求全部非空物理行登记，封存 Task 来源与版本；Task 中没有图绑定。标注逐 requirement 输出 realization 与 gaps，并只声明 `value / presence / cardinality / shape / truth / action` 六类正向保持目标。禁止事项与未支持限制保留在 Task 和 realization，不再以限制 goal 获得含糊的 bound 状态。

[逐 seed 反向需求 v3](backward-demand.md) 保留每条推导的 `seed_goal_id`，由程序生成“真实原文 → Task → realization／缺口 → raw demand → compiled goal → 推导 → sink”对应。[完整分析链 v6](joint-pipeline.md) 强制审查原文、每项 Task、每个 demand 与全部 IR；正常三次语义调用，仅标注修复五次，Task 修订六次，结构纠正与传输重试另计。

修订 Task 只读取旧 Task、原始源文和有限问题类别／源范围／requirement ID，不能接收全链意见的自由文本、当前载荷或 DOE。Task 修订后完整重标注；两类修复共同限一轮。现阶段未表达限制的影响范围没有独立局部证明时按全局保守处理，计算成功不能抹掉审查失败或表达缺口。

[敏感范围对照 v3](sensitivity.md) 仍以明确声明和已支持关系为条件，不保证完整敏感性、不把 `possible` 当明文、不把保守保留当不可替代性。工程测试、模拟客户端和离线重放与真实模型语义效果实验分开报告。

Language update (2026-10-16): maintained prompts, synthetic examples, generated interpretations/reasons, diagnostics, and new reports use English, including new three-case experiments. Genuine source text and quotations retain their original language. Historical frozen artifacts remain unchanged; discussion with the user may remain in Chinese.

以下确认的总目标、接收边界及静态可能性原则继续有效；早期接口草图和最终模型分工属于历史设计，以本节链接的当前协议为准。冻结输入、传播事实和历史实验不回写。

确认日期：2026-10-06。本文固定后续 DOE 设计的目标和已经确认的原则，不是尚未实现的算法或结果格式。后续用户明确调整目标时，在此更新；历史实验和旧方案不自动成为现行要求。

设计补充：2026-10-10 已确认[任务基准与用途切片](SkillFlow-DOE任务基准与用途切片.md)，固定默认目的依据、功能保持要求及 sink 审查材料选择。该补充不改变本文的总目标，也不表示 DOE 判断或切片算法已经实现。

## 1. 核心目标

> **SkillFlow 面向 Agent Skills 开展任务相关的静态数据最小化分析，结合敏感数据来源、沿途处理、路径条件和接收方，以发现所有非必要敏感数据暴露为目标，并提供具体定位与最小化建议。**

覆盖范围包含不必要动作造成的敏感数据暴露，也包含必要动作中不必要的敏感载荷、字段、范围或表示精度。不能先筛选出必要动作，再把其余动作及暴露排除在 DOE 审计之外。“所有”是分析覆盖目标，不是对当前实现零漏报的保证。

其中，**动作必要，不代表这个动作携带的每份数据、每个敏感字段都必要**，是我们重点强调的独特贡献点之一。它要求把动作必要性与具体数据对接收方的必要性分别判断，而不是将研究范围限制在必要动作中。该贡献定位的实际优势仍需对照实验验证。

DOE 阶段要说明多暴露了什么、在什么条件下交给谁、为什么不属于该任务所需，以及可以在哪里减少暴露。数据被读取、进入模型、发送或保存，本身都不足以得出 DOE 结论；需要结合具体任务与接收边界判断。

本项目沿用 Data Over-Exposure（DOE）作为问题名称，不沿用旧 DOE 引擎的评分公式、数据格式或裁决方法。

## 2. 判断对象

围绕一个具体 sink，联合考察以下事实：

对所有已纳入的 sink 开展判断，不以动作是否必要作为审计准入条件。动作必要性与载荷必要性共同参与判断：必要动作不能获得全部载荷的豁免，不必要动作造成的敏感暴露也不能漏掉。

| 要素 | 要回答的问题 |
|---|---|
| 任务与动作 | 任务需要实现什么，这个动作承担什么用途？ |
| 数据及版本 | 实际绑定哪些可能数据？来自哪个整体、字段或处理结果？ |
| 沿途处理 | 是否明确选取、删除、替换、筛选或计算？观察发生在处理前还是处理后？ |
| 条件与范围 | 哪些分支、候选或条件影响本次交付？哪些只是保守可能性？ |
| 接收与保存边界 | 谁取得内容，以什么访问范围或留存性质取得？ |

不能只按操作名称、单个敏感标签、整条 IR 或整个 Skill 给出笼统裁决。同一数据交给不同接收方、不同版本交给同一接收方，都可能需要不同判断。候选集合不表示所有数据同时存在；逐元素接收者与正文配对不能丢失。

例如，任务要求把每条记录的 summary 发送给该记录的 recipient。发送动作可以必要；将额外的内部备注或凭据一同发送，则应独立检查其必要性。模型为处理任务观察某份内容是否必要，也要与最终工具参数是否必要分开判断。

## 3. 与现有架构的衔接

整体架构继续是 **构图 → 传播 → DOE**：

- **构图：**保留源文动作、来源、条件、限制、结果身份和控制关系，形成可分析的 CFG；通过受控回述、源文核对及反馈改进表示。
- **传播：**在统一抽象运行时契约下，标注数据关系和处理方式，编译可能观察，确定性计算来源范围、数据版本、交付和保存事实。
- **DOE：**在上述事实之上判断敏感性、任务相关必要性及非必要暴露，生成具体解释和修改建议。

传播保存 Data、记录和实际 sink，清单引用所选标注；公共只读加载器核验整条材料链。DOE 在 `src/skillflow/doe/` 实现，产物独立保存，不回写传播事实、CFG 或冻结输入。不保留旧总包或另一套评分引擎。

设计时可以把上游表示足够忠实作为输入前提，继续推进 DOE；这不把现有结构检查、事实保持证明或模型核对通过升级为“已经证明自然语言与 CFG 完全等价”。

程序落实标注的处理方式与契约默认，但不能证明标注推断正确。当前传播保留条件和保守候选，不执行自然语言条件求解，也不证明每种候选组合都有可行路径；DOE 必须保留这一解释边界，不能把候选路径写成已证实会发生的路径。

## 4. 数据范围与可能性的既定原则

1. **原样传递，不自动缩小。**没有明确选取、排除、覆盖或可见性隔离依据时，保留相关来源范围；这不叫自动扩大，也不能扩展到无关资源。
2. **描述细化不等于删减。**发现整体中的一个字段，不把整体替换成该字段；真正改变内容产生新的 Data，原样引用复用身份。
3. **读取、模型观察与实际参数分别判断。**整体可能被模型观察，不意味着后续工具接收整体；本地内部扫描整体但只返回字段，也不自动意味着模型观察整体。
4. **不透明处理继续保守传播。**没有排除某输入影响的依据时，保留 `possible` 依赖，不自动删除它，也不因此要求逐例人工补全。
5. **可能影响不等于明文包含。**`origin.inputs`、`derived` 或 `possible` 关系不能证明结果仍含有输入的全部明文；摘要、加密或遮蔽名称也不能证明敏感性已经消除。
6. **观察不能被后续清理撤销。**早先观察绑定当时的数据版本，不能被后来的清理结果替换。
7. **未知内容不是无敏感内容。**未展开 Data 不代表空值，未标注不代表不敏感；也不能凭空编造其他密钥、字段或敏感性。

统一运行时契约对所有 Skill 适用，不增加逐 Skill 运行时选择或强制动态验证。契约补充的观察是静态可能关系，不是测得的运行事实。可计算的候选、部分顺序和可能依赖应继续分析；真实材料缺失、引用错误或能力限制明确报告失败或诊断，不能用空结果冒充无暴露。

## 5. Sink 与等级边界

沿用现行六类 sink：`network_send`、`storage_write`、`context_save`、`model_observe`、`external_tool`、`user_output`。纳入条件和固定分级以 [Sink 主规范](../propagation/SkillFlow-Sink边界与固定分级.md)为准，不在 DOE 中另建一套相冲突的边界规则。

`exposure_level` 只表示接收范围和留存性质，不表示数据敏感度、必要性或最终风险。任务内部临时流动继续参与传播；持久保存、跨主体接收和公开发布分别保留。部署未说明的工具可以是契约下的外部接收可能性，不能因此直接标成网络发送。普通 return 不自动成为用户输出。

DOE 从实际形成记录的 sink 数据绑定出发，结合 `status`、`coverage` 和 `diagnostics` 检查材料是否足够。未完成传播没有产生某条 sink，不能解释成该处已经安全。

## 6. 预期交付与研究要求

后续判断应提供可核查的解释：**哪份敏感数据或影响、来自哪里、经过什么处理、在什么条件下交给哪个边界、该动作与接收方为任务需要什么，以及不必要的部分在哪里。**动作本身不必要时，可以建议取消相应交付或保存；动作必要但载荷过多时，保留必要动作并缩减载荷、字段、精度、可见范围或保存范围。不能将源文没有的保护机制补造成现有事实；允许提出新增明确局部处理或限定回传机制的建议，但须标明为建议并说明功能保持依据。

为控制输入规模，采用 **sink 中心的回溯与用途切片**：保留与该暴露有关的来源、处理、条件、接收方和任务依据，同时提供当前动作与少量相关生产／消费操作。仅有回溯不能解释模型观察或保存的用途，下游存在使用也不能自动证明必要。各阶段事实及上游身份共同承担审计职责，不应重复发送全图、全部 IN／OUT 与无关 Data；正式 DOE 读取经校验的传播材料，精确需求使用对应的原始／编译标注和映射。最小职责结构与保持要求已在[任务基准与用途切片规范](SkillFlow-DOE任务基准与用途切片.md)固定，当前已实现任务保持需求和敏感范围的确定性对照；压缩不能删除会改变判断的关系。

以 Semia 为首要对照，追求更细、准确且可操作的定位，同时减少使用和审查复杂度。优势需要同等分析假设与可比实验验证，不能仅凭架构差异、新术语或更多字段宣称领先。

本阶段不以恶意 Skill 检测、危险动作扫描或整体风险打分为主要目标；不宣称证明任意复杂处理的完全独立性、真实执行必然暴露、所有路径可执行，或已经找到了全局最小的数据使用方案。

## 7. 已固定的设计与后续工作

2026-10-10 已固定以下设计，详见[任务基准与用途切片规范](SkillFlow-DOE任务基准与用途切片.md)：

1. **目的依据：**有独立用户任务时以其为目的依据；没有时自动审计 Skill 声明用途，并限定结论身份，不将作者声明视为真实用户授权。
2. **功能保持：**保留明确结果、条件、次数、质量、必要副作用和禁止事项；不从当前载荷倒推必要范围，不以存在使用或找不到缩减方案证明全局必要。
3. **判断材料：**同一 sink 的载荷回溯与相关用途上下文共同提供依据；共享原文与索引，保持字段范围、版本、控制、配对和静态可能性，不重复发送全部状态。
4. **责任分工（2026-10-15 替换）：**独立提取并封存 Task，固定基准后标注 demands、处理及敏感性，四轴审查与一次受控修复保留语义缺口；程序计算前向事实、逐 seed 反向需求及全部 sink 对照，不增加最终 DOE 判断模型调用。

2026-10-10 已实现[离线切片与审查材料](SkillFlow-DOE离线切片与审查材料.md)，提供共享事实、每 sink 的回溯和用途关联及零 API 重放。后续需要完成判断输出类型、敏感性表达和必要性判断协议，以及方法验收。至少覆盖必要动作中的必要敏感使用、必要动作中的多余敏感暴露、不必要动作造成的敏感暴露，分别检验误报与漏报，并与增强 Semia 在可比假设下对照。离线准备不代表判断能力已经实现，也不恢复旧引擎或旧分数。
