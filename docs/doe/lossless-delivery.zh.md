# 语义阶段的无损交付与提交前体积检查

敏感性和 Task 对应的正常、结构纠错和修订请求统一使用结构化输入的共享值与列式表示。完整 processing、CFG、对应阶段的 Task 与表达式引用，以及修订范围和证据都先作为对象编码。编码器对解码后的逻辑值和摘要进行核对。相同子值通过共享定义表示，每个使用位置的操作、版本、成员、接收方和证据身份继续独立。

完整源文单独放在 RELATED SOURCE 区，输出格式及原有严格校验继续定义模型答复。范围修订携带被程序授权的完整槽位。结构纠错将原材料与全部纠错数据一起编码，校验和合并仍使用原始逻辑路径。不能识别的自定义提示沿用完整调用材料。

阶段审计覆盖独立 Task、flow、GraphFacts、三个语义片段、源文审查以及现有纠错和共享修订入口。Processing 和审查复用原有无损格式；源文定位的图修订范围也使用相同共享编码。独立 Task 仍只读取自己的源文及被允许的修订材料。

CLI 对每次实际提交的最终字符串执行本地预检。计数包括适配器前缀，单位为 Unicode 码点，同时记录 UTF-8 字节数、完整交付摘要与各提示分区。保存的 preflight.json 与具体请求和原文本绑定，适配器在启动进程前拒绝超限交付。正常请求、纠错和修订均经过这一入口。预检不发送模型请求。独立并行请求各自检查自己的最终交付。

离线回归包含源文、缺失字段与 null、共享值的独立使用、所有者隔离、有限槽位及完整纠错、完整与局部修订，以及最终交付的边界值、中文与非 BMP 字符。使用上一轮 162541 保存的实际 processing 与 CFG 渲染，敏感性正常交付为 495,187 字符，Task 对应为 540,921 字符；添加完整修订材料的样例分别为 495,675 和 541,392 字符。每份输入均核对完整 16 文件源文及逻辑对象的解码结果。结果和测试回执记录在 output/verification/lossless-delivery-20261119。

新运行使用 guided run v19、document step v16 和 CLI v4。模型输出协议、七个正常语义阶段、两个 worker、一次结构纠错、一次共享修订，以及传输重试和截止预算继续沿用现有设置。旧产物以其原身份读取。
