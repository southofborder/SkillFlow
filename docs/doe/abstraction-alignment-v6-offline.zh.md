# 抽象粒度对齐 v6：实现与离线验收

本轮目标是先提升复杂 Skill 的可分析覆盖。正常流程仍为七次语义请求，两个 worker；Task 独立，任务对应与敏感性互相隔离，annotation 由程序组装。实际速度、DOE 正确性和真实覆盖由随后唯一一次全新 GA4 High 运行检验，不能用本报告的离线通过替代。

## 实现范围

flow、CFG、processing、运行时与统一审查采用共同的调用边界粒度。纯局部计算保留真实输入和 possible 依赖；获取、条件返回、保存、初始化版本和接收方变化须保留真实边界。完整 processing 片段明确覆盖当前全部 IR，包括 dispatch 和 return；语义重建完整替换当前版本，指定记录替换只用于结构纠正。

processing 的非递归 `cases` 保留候选条件、实际操作与正常／抛出结果。候选和局部身份由程序生成。逐项 catch 返回的正常／错误值是同一 occurrence 的替代结果；未捕获失败保留先前交付，但不向正常 OUT 注入失败状态，不形成错误记录后继续的假行为。已知重复、空集合和未知集合分别保留；映射集合不枚举整批候选数组。

具名 task-local runtime_context 允许显式 `may` 替换摘要。旧 handle 与新 handle 及其创建凭据关系独立保留，循环中没有逐成员缓存求解。写读关联使用实际写入载荷与读取版本，不能把弱更新中沿用的旧值当成新写入，也不能将互斥候选或失败写入连接到正常后续。

需求路径允许字段／索引前缀与后缀之间一个 `each`。需求、反向传递、敏感范围与报告保持该前缀、成员身份和接收方；基数需求不变成全部成员内容。整体读取不自动成为整体必要，完整 raw 保存与摘要接收方分别判断，真实 complete-metadata 要求保留。

程序对可识别记录汇总类型、引用、证据及作用域错误。一次结构纠正保留其他记录；真正非法的对象不被程序改写成虚构语义。统一审查可查看实际候选和部分片段，机械坐标本身不被登记为新的语义问题。

## 有限能力边界

- 含 `cases` 的 IR 使用 `fixed` 顺序，至少有一个返回候选。始终抛出的路径使用真实 CFG 终止；不会发布虚假的正常输出。
- 不支持嵌套 cases／循环、多重 each、循环内任意共享存储写入或通用异常执行器。
- 不精确求解缓存命中／创建次数和跨成员状态顺序；相关 Task 限制保持未决。
- 候选条件来自源文，代表静态可能性，不证明某次执行发生。错误必须来自实际受保护调用的异常来源，不能从 URL 推算。
- 分析与保存文件的真实身份关系若源文缺失，仍保留局部缺口；不凭目录、名称或相邻顺序补造联系。

## 离线验收

验收记录位于 `output/verification/boundary-alignment-v6/`；最终机器可读结果为 `offline-acceptance.json`。该文件只有在集中测试与独立复核完成后才写入通过状态。

覆盖的工程行为包括：

1. 七调用、并行依赖、隔离、结构纠正、修复依赖闭包、无 usage 继续、已有答案复用和零模型调用重放。
2. GA4 原样源码及 SHA 来源记录支持的批次正常返回、逐项 catch、URL／状态配对，以及普通条件与初始化版本投影。
3. 请求前错误无网络交付，重复 occurrence 和同参／零参工具请求不混配；空集合无成员初始化。
4. 失败前缀和正常 OUT 分离；正常／错误成员候选不增加成员数；基数、字段需求与接收方隔离。
5. 原始／编译标注、Data、记录经过 JSON 保存与加载，再贯通需求、敏感性和最终 HTML／Markdown 报告。

集成复核额外发现并修复了候选被串行计数、成员位置被重复枚举、弱状态旧值的假写读连边，以及映射集合缺少报告渲染分支等问题。源文审查目标保留真实对象，跳过 case_path 等机械坐标。当前合成接口样张已按新版本重新生成；历史运行及 GA4 原答不迁移。

## 验收结果（2026-10-29）

受影响接口的整体验收为 **473 passed，234.26 秒**；最后一处写读关联修正后重新执行的针对性回归为 **100 passed，60.86 秒**。两组有重叠，不相加为独立测试数量。后一组包含新 GA4 粒度夹具、case 全链保存／恢复／报告、需求与 material 回归及当前示例重建。独立集成复核另有 **11 passed，14.41 秒**，确认保留两个失败前缀写入，同时没有错误正常读取关联或隐式需求。

更宽的历史实验测试集合未全部执行完，其日志保留，不将其记为通过。开发过程中发现并修复了示例过期、修复提示分隔符及旧隔离断言问题，均由新的定向检查验证。以上全部使用 fake client 或纯确定性处理，真实模型调用为零。机器验收记录位于 `output/verification/boundary-alignment-v6/offline-acceptance.json`，日志在同目录。

## 新运行约束

只启动一次新的 GA4 分析：`gpt-6.1-sol / high / openai`、两个 worker、七调用正常流程、每阶段一次结构纠正和全流程一轮语义修复。源包仍为同一份 16 文件、155170 UTF-8 字节，源文摘要 `3b6eef9f43262d96949e30fe0c39797fe680c578ac5e90bf367da15592445bbd`。全部 Task、CFG 和标注重新生成。

启动前封存实现、英文提示词与格式、运行配置和源文。启动后不边改边续跑，不新增探针或监控模型请求，不安装或执行 Skill。使用现有 45 分钟单请求上限、无完整答案的暂态传输最多两次额外尝试、已有答案本地复用政策。最后只进行一次零模型调用重放，并报告完整 DOE 的实际覆盖、未决范围和所有可得成本。
