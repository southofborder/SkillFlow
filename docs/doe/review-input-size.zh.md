# 源文审查输入超限：通用修复与验收

本次修复进入所有后续 Skill 共用的源文审查代码，默认采用 `shared-v2`
展示策略；没有 GA4 名称、文件路径、领域或 IR 数量特判。保持七次正常语义请求、
两个 worker、Task v5 隔离和原有修复、纠错、传输预算。

## 此次为什么超限

2026-11-12 已关闭的 GA4 替代运行实际请求为 **1,079,505 个 Unicode 字符**，
比适配器上限 1,048,576 多 30,929。它在本地启动模型前被拒绝，
不是连接超时，也不是 Windows 命令行长度问题；适配器通过 stdin 传递内容。

其中逻辑 JSON 占 874,402 字符，完整带行号源文占 180,825；说明、响应格式及
封装合计 24,278。JSON 内主要为 annotation 403,839、契约审查清单 244,455、
CFG 154,115、Task 39,090、运行契约 22,020、processing 缺口 10,579。
字段名、范围描述和证据在多个位置重复，新增完整契约清单进一步放大了体积。

本地 `review/inputs.json` 约 1,087 万字符，但其中索引和审计元数据原本就没有
全部发给模型。这次也没有同时重复发送完整 fragments：该请求的 fragments 和
observations 为空。因此不能把问题归因于“把本地大文件原样全发了”，更不能靠
截断源文或删除契约清单解决。

## 写入代码的通用机制

新增 `review_display.py`，对逻辑 JSON 生成可直接阅读的无损展示：

1. 完全相同的 JSON 值只保存一份，在各个原位置引用它。字段、条件、版本、
   成员、接收方、源文位置、顺序和类型有任何差异，就不会被当作同一值。
2. 契约清单和范围清单的记录使用“列名＋行值”，减少反复出现的字段名。
   不同记录形状使用不同列集合，保留缺字段与显式 null 的区别。
3. 程序比较普通展示、共享值、列式记录及二者组合；再比较完整格式说明的开销。
   只有最终请求更短才使用新展示，否则保持原 JSON。小材料、少重复材料不会变大。
4. 完整源文在独立区段原样发送。所有契约条目和范围都保留，引用不合并审查结论
   或操作身份。发现与修复仍定位原始对象，不能指向展示用的共享表。

格式有显式身份、英文解释和确定性解码器，保留与标记同名的原始字面值；
缺引用、循环引用或坏表格会被拒绝。模型不需要额外工具或额外请求来读取材料。
新运行身份升级为 guided run v12；旧 `compact-v1` 和旧产物保持原身份与原渲染。

## 验证结果与边界

只读使用失败请求做渲染回归，新完整请求为 **903,775 字符**，减少 175,730
（16.28%），距上限还有 144,801。逐值展开后与原逻辑 JSON 的序列化完全一致：
16 份完整源文件、344 条审查项、1,195 个范围的内容、身份和顺序均保留；
12 份跟踪的历史产物哈希不变。该过程没有调用模型、执行 Skill 或重放历史分析。

最终受影响模块集成回归 **511 项通过，零跳过、零失败**，用时 408.07 秒；
不是一次全仓库测试。见[本轮验收记录](../../output/verification/review-input-size-20261112/offline-acceptance.json)。
离线验收覆盖任意名称与多种规模、低重复和近似但不相同的数据、特殊字面值、
完整与部分材料、原始修复坐标、契约覆盖检查、传输临界值、七次注入答复、
两个 worker 与隔离边界及零调用重放。此前小范围收据均保留，不重复累加通过数。

如果完整信息本身已超过容量且无法再无损缩小，仍明确报超限；该机制不保证
任意大的材料都能装进一次请求，也不删除源文或契约。无损验证证明信息保留，
不能证明模型一定正确理解。离线验收后，已按本次授权完成一轮新的 GA4 及唯一
零调用重放，使用同一完整源包。两次实际审查请求为 861,152 和 867,125 字符，
材料完整且未超限；但三条源输入发现的字段定位仍未通过校验，最终为 partial，
没有正式接纳的契约检查，也没有建立可删除输入。见[本轮中文报告](../../output/verification/online-ga4-review-shared-v2-20261112/assessment.zh.md)。
实际 12 次启动＝7 次正常＋5 次结构纠错，语义修复与外层重试均为零；
本轮启动和重放授权已经用完。
