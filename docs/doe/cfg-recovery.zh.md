# CFG 诊断汇总与失败阶段恢复

本轮修复覆盖一条完整路径：CFG 在唯一格式纠错后仍无有效结果时，源文审查能准确指向失败阶段，并在原有一次共享修订内重建必要的 CFG。只有新图通过全部结构检查，依赖片段重新生成并形成一致 annotation 后，才进入后端分析。

## 为什么上一轮能继续，这一轮却提前停止

先前运行第一次就暴露循环自读和全局端点错误，触发整图重写；最新运行先遇到分支输入缺失，前置检查立刻抛出异常，编译器尚未报告两个已经存在的循环错误。唯一纠错因此只修了分支，随后才发现循环错误。旧选择器遇到这种单一局部路径也会选择局部替换，不能把失败简单归因于新选择器。

审查和修订随后又碰到两个已有缺口：提示允许失败阶段目标，但目标清单没有 graph；没有已接受 CFG 时，共享修订入口也不成立。局部隔离实际上保留了五条 Task 发现，并非整份审查失效。这一轮的流程结果确实倒退了。之前的验收没有把跨校验层错误共存、失败 CFG 的审查和无 CFG 修订连起来验证，是实现整合与验收覆盖不足。

历史记录仅做只读字节与哈希比较，没有重跑旧候选。两次生成的 flow 和 CFG 不同，因此不能声称已经做了受控回归对照。详细证据见 `output/verification/cfg-recovery-20261117/regression-causality.json`。

## 三项通用改动

1. **一次汇总可确定的 CFG 诊断。** 形状合法的原始候选即使有分支前置错误，仍进入编译诊断，合并两层错误和原始定位。形状、源文引用等阻碍仍严格拒绝。阻碍编译诊断不等于禁止局部替换：身份和定位明确时，仍可替换已有记录，合并后完整校验；存在这些阻碍时不能推断全局或因果依赖范围。诊断用途的部分编译对象从不成为有效 CFG。因果范围证书绑定原始候选、全部相关端点、分支错误和精确根级诊断；证明不足就回退整图纠错。
2. **统一失败阶段的审查目标。** Task 对应 task，flow/graph 对应 cfg，processing/task-correspondence/sensitivity 保持既有 annotation 归属。目标必须精确出现在清单里，绑定完整源文和已执行请求的失败材料。不能把任意 `stage:` 字符串当成合法定位；不能删除或改投其他领域来掩盖无法表示的发现。局部错误继续隔离，不使其他有效发现失效。
3. **缺少有效 CFG 时使用现有共享修订。** 已接受的源文 Task 和 flow、当前 CFG 的可核验结构拒绝、完成或保留有效部分的源文审查，共同构成入口。即使审查未另提语义发现，已确定的必要 CFG 结构失败也能使用这一次修订。请求失败或模型能力声明不构成重采样理由。失败候选只作为拒绝证据；新图必须从完整源文和 flow 重建，并重建其依赖片段。没有第二次共享修订。

## 证据与回放

`audit/failed-stages/<stage>.json` 保存原始响应、最终合并候选、每次诊断及其请求/响应/传输/链/源文身份，标记 `accepted: false`。`audit/shared-repair-decision.json` 保存明确的入口、阻碍及材料摘要身份，不重复复制整份失败材料。

新 fatal frontier v2 记录实际发生的并发终止状态，绑定失败材料及修订决定。离线回放重新验证请求材料、重建失败证据和入口决定，核对审查实际使用的失败输入。未被调度器观察为失败的已终止兄弟请求不能反过来变成审查输入。即使修订图尚未准备就发生请求失败，修订入口也必须可以核验。

新协议为 guided run v16、step v13、fragments v8、source review fragment v6、fatal frontier v2。Task v5 职责不变。历史产物保留原身份，不迁移。

## 验收范围与限制

离线验收包含跨层诊断、真实依赖范围纠错、严格目标与局部隔离、无 CFG 成功恢复到真实后端、再次失败保持未选中、共享修订中的并发请求失败，以及零调用回放和材料篡改拒绝。注入响应只证明机制能按这些条件工作，不证明真实模型一定生成合格的 GA4。

保持七次正常语义请求、两个 worker、每阶段一次结构纠错、一次共享修订和现有请求预算；不截断源文或契约。缺少已接受 Task 或 flow 时，本轮不扩展为另一个重采样入口；本轮也没有执行被分析 Skill。新 GA4 必须在离线验收通过后单独准备，冻结实现后只运行一次及其唯一零调用回放。准确回执与最终线上结果写入对应 verification 目录。
