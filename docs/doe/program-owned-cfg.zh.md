# 程序组装 CFG 与局部修订

最近一次 GA4 的 CFG 修订请求有 432,728 个字符。已封存的记录显示 TLS 握手 EOF、WebSocket 重试、回退 HTTP，随后两次响应体解码失败，最后到达本地 2,700 秒截止时间。该请求没有完整答复，因此实际输出规模、使用量和生成用时未知；没有输入超限证据。参见 `output/verification/online-ga4-runtime-locality-20261117/assessment.zh.md`。本轮没有启动新线上实验。

CFG 正常请求返回 `GraphFacts`：入口、实际动作、值的生产者与消费者、分支和返回，以及对应的原文位置。程序从这些事实生成终结指令和边，分配编号，并从冻结源文复制代码。显示名称可以从引用派生；实际条件、生产者、接收方和返回值缺失时必须记录缺口。显式空列表表达“没有”，省略字段不会得到同一含义。只有整个图经严格校验后才能发布。

程序根据当前事实和审查位置签发可修改槽位。可定位的结构错误在现有纠错内一次提交；没有可信槽位时不再发请求。源文审查发现的问题也只会启动绑定到原图和审查的槽位修订。局部拓扑修订冻结外部控制、数据和返回端口，并保留原有动作及其外部效果；开放的操作名本身不足以证明新增动作是纯计算。对已接受的图，如果几个补丁不兼容，程序尽可能独立验证并保留能够共同通过的修改。拒绝、缺项或无权限修改有各自的位置。无法形成一致新结果时，继续使用旧 CFG、注解和与其匹配的审查。旧审查不重新绑定给修订结果。

Processing 依据真实 IR、引用和覆盖关系同时报告能够确定的错误。模型只需填写必要的记录或字段，程序保留其余记录后重新严格验证。源文修订使用稳定 IR 编号和实际生产者到消费者的依赖范围；共享位置或表达式缺乏可验证映射时，修订留待处理。敏感性按相同值和位置的实际依赖维护；无待填写槽位时由程序保留。Task 对应在 CFG 和 processing 的依赖完全一致时，可按封存的需求编号修订，包括该需求完整的全局约束；实际目标空间变化而无法证明局部覆盖时，现有共享轮可重新建立 Task 对应。独立 Task 及其接口不变。

执行失败仍可能发生，例如源操作实际得到的形状违反了后续操作契约。对于无法建立执行事实的必需动作，需求端根据已校验的字段、条件和位置向上保护它确实依赖的输入。这个结论不创建执行成功、数据流出或副作用记录。成功与失败候选并存时，成功记录不抹去失败路径。对本 IR 的直接字段选择控制，传播根据成对记录缩小被读取的不可变结果版本；不会按同值、名字或易变上下文地址推断另一个位置的版本。

保持七个正常语义阶段、两个 worker，结构纠错、共享修订和运输预算不增加。新引导运行和步骤使用 v18、v15；传播和需求使用 v23、v12，DOE run 使用 v12。原有实验和证据原样保留。

离线体积对照：合成的 80 块、160 IR 图，完整相同的双文件源文和一个可定位的操作输入。原整图修订交付为 **77,091 字符**，槽位修订为 **9,129 字符**（少 88.2%），两份源文件均完整出现。另一个合成 processing 缺项例中，纠错输入由 16,132 降为 14,292 字符；完整与局部答复示例分别是 19,484 和 291 字符。这里测量的是实际渲染文本，不能推算 GA4 的 token、耗时或网络可靠性。

离线验收：DOE 全目录 1,500 通过、1 跳过；最终版相关 DOE 定向复验 91 通过、同一项跳过。引导测试首次扫描 1,264 通过，报告的 18 个失败全部在最终版定向复测通过，包含一个改成检查局部修订边界的替代用例。新协议的注入测试覆盖正常七阶段、JSON 文本纠错、失败后恢复、局部图变更发布和零调用回放。详见 `output/verification/program-owned-cfg-20261118/offline-acceptance.json`。这些是分组验收，没有重跑整个仓库。

后续建议：先用离线捕获格式继续覆盖调用边界、可选输出以及真实作用域错误，保持“已知事实、明确缺口、严格校验”三者独立。收到新线上授权时，只需一轮保留旧 CFG 的对照：记录每个请求的提交字符数、可见用量和连接事件，分开判断局部协议的收益与传输问题是否复现。即使 CFG 的组装和验证完全由程序控制，源文未说明的语义也仍须作为具体缺口报告。
