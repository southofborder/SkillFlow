# 修订、入口敏感字段与 DOE 报告

## 换机后的 CFG 核验

仓库和 Python 安装包都包含固定版本的 Lean 工程。装好工具链后，运行
`python -m skillflow.lean_renderer` 会从安装包或检出的源码构建，并用实际 CFG 检查生成和解析。
构建收据记录工具链、源码、可执行文件和自测图的摘要。[首次安装与本机构建](../../formal/README.md)

从 processing 继承 CFG 时，程序先核对原运行记录中的证书字节摘要，再使用本机 Lean
生成并解析同一张图，逐项比较文本、图、证据单元、引用和检查结果。原证书保留旧生产者
的身份，新运行的 `graph/initial/local-verification.json` 同时引用原证书和本机验证结果。
重放会重新比对这份收据。收据缺失、内容被改动或实际复核失败都会产生明确错误。

## 语义修订和分析

processing 局部修订沿用正常阶段的条件必填规则。请求对每个可编辑 IR 给出旧操作的位置、输入数、附件名和写入指针，另附完整的只读 location 与 expression 表。新建操作同样要通过编译器的契约义务枚举。程序可以按授权指针合并附件，新旧内容合并后仍须通过整份候选的校验。

若一次纠错用尽后只保留了部分 processing，修订规划器从终端答复、合并候选和校验回执核对摘要，取得被隔离的记录。该记录构成修订证据。即使源文审查没有 finding，具体校验错误仍可打开共享修订。错误记录必须修正或说明有依据的语义缺口。新的 Task、CFG、annotation 与源文审查按身份成套选用。

敏感性阶段分类 Skill 调用参数、实际环境或文件读取，以及工具响应的字段。模型提交入口、字段路径、信息属性、敏感标签和源文位置。证据说明来源字段本身敏感时，使用 `source_field`。证据只支持特定读取用途时，使用 `access` 并列出清单中的读取位置。程序处理后续复制、构造和可能影响，保留实际读取位置、版本、成员和接收方。能否删除取决于任务反向需求和约束保持结果。

若两次读取解析到同一 Data 版本，而标记只适用于第一次读取，程序从第一次读取的消费槽位出发，沿记录中的数据关系追到接收方。在两次读取分别形成对象成员时，成员路径继续区分两条来源。如果记录不足以说明重复实参中哪一项形成输出，局部诊断会列出该操作和缺失的关系。

有关联的分支在有源文证据时声明判别输入、字段和有限谓词。共享同一不可变值的判断保留相容选择，独立版本上的选择分别传播。未获证据支持的排除不能用于证明字段可删。反向需求还要保护触发输出和实际必需动作的条件。

当前 demand v13 为这类需求保存 `selector_ref`，可以追溯到被测字段、支持的谓词及源文证据。只测字段缺失时保留其存在性。只测对象种类时保留判定结果，删除对象中与判定无关的子字段仍可单独评估。若工具同时需要该子字段，工具的输入需求仍有效。

DOE 报告按 sink 保留候选及结论。输入评估、来源、推导、限制与相同引用列表各存一次，每项候选可链接到具体依据。HTML 与 Markdown 都以 UTF-8 分块写入临时文件，完整写入后再发布。中断后已经存在的文件须与重建字节摘要一致。查看历史分析时使用其原有协议和证据。

例如，Skill 读取 `a.a`、`b.b`、`c.c`，任务要求的输出字段只由前两者决定。源文审查确认这个关系后，反向求解器从该输出字段回传两个输入需求。若其余任务用途、必需动作和约束保持检查也都允许删除，输入评估才会列出 `c.c` 可删除的位置。正向记录仍能看到这次读取。若同一字段还控制另一个必需动作，该动作的证据会使字段得到保留。

离线验收包含注入语义答复、上轮保留材料的请求构造、字段必要性、共享与独立条件、入口来源与归属、历史读取和报告的引用完整性。上一个生产协议的 DOE v12 与敏感性 v10 结果可按原身份只读校验。报告体积基准分别记录候选数、两种格式的实际字节数、发布时间和 Python 分配峰值。
