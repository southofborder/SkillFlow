## 如何审查

在浏览器打开 `result/review/index.html`。页面离线加载已嵌入的数据，不连接模型服务，不执行 Skill 的脚本。

1. 从案例列表选择编号，先看反馈停止状态、实际选图轮次和标注状态。
2. 缩放 CFG，检查关键动作、分支条件、返回结果、禁止事项和实际保护操作。名称与约束只是图中记录的标签或声明，不能替代缺失的操作。
3. 点击操作，核对它的 `actor`、`roles`、`effects` 及各标签证据。证据验证说明引用真实存在，不说明模型推断必然正确。
4. 对照完整源文和语义核对差异，检查有没有漏掉过程、错绑结果或增加无依据行为。
5. 阅读单独标记的助手复核。助手复核不是用户确认，也不改写模型原始响应。

PNG 便于独立查看和分享；交互页保留矢量图用于放大和逐操作定位。一次动作可以对应多个主体、角色及效果。标注未决与图语义未决分别呈现。

## 状态的含义

| 状态 | 可以得出的结论 | 不能据此得出的结论 |
|---|---|---|
| `audit_passed` | 当前结构、保真、响应及覆盖检查通过；核对器的业务项全部判为保留 | 图已被证明与源文语义等价 |
| `unresolved` | 没有继续修复的明确差异，仅剩核对未决 | 核对通过 |
| `revision_limit` | 已用尽最多 3 次语义修复，仍有明确差异 | 末次图是正确图或最佳图 |
| 提取、保真或核对执行错误 | 对应阶段没有正常完成，原因保存在记录中 | Skill 本身错误，或图的语义一定错误 |
| 标注 `complete` | 所有真实 IR 均有格式及证据校验通过的四字段标注，无显式未决 | 标签推断全部正确，或数据安全 |
| 标注 `incomplete` | 标注响应合法，但存在明示未决 | 缺失信息已经被解决 |
| 标注 `invalid_response` / `execution_error` | 返回数据未被接受，或调用未正常完成 | 可以使用旧标签替代本次标注 |

标注绑定本次末次结构有效图，不要求该图已经得到 `audit_passed`。因此必须同时看两种状态；不能用标注完成掩盖图核对失败。
