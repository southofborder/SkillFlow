After the Party 的 21.67%–61.06% 加权灵敏度只适用于其精确版本匹配的 276 个候选池（人工抽查 180 个），不能外推为整个市场恶意检出率。[方法与评估范围](https://arxiv.org/html/2609.17274v2)

另外必须保留四组边界比较：

- [凭据泄露实证](https://arxiv.org/abs/2604.03070)已研究正常调试日志进入模型上下文的意外泄露；[MCPPrivacyDetector](https://arxiv.org/abs/2606.21338)已研究 return/log/raise 造成的隐式协议出口。因此“无恶意也泄露”和“没有 HTTP 也暴露”不能作新发现。
- [AgentRaft](https://arxiv.org/abs/2603.07557)与[ToolPrivacyBench](https://arxiv.org/abs/2606.28061)已覆盖用户意图、功能必要性及目的绑定的隐私边界。静态版仍需证明判定依据与精度，不能仅删除执行阶段。
- [ColluSkill/ChainGuard](https://arxiv.org/abs/2608.09732)已正面分析跨 Skill 组合；[SkillWatermark](https://arxiv.org/abs/2608.16026)提示秘密可经流量模式暴露。当前显式数据模型应如实限定范围。
- [SkillFortify v2](https://arxiv.org/abs/2603.00195)将信息流消融改报负结果：在其语料上没有比模式匹配增加检出。这是我们必须检验“复杂表示究竟增加什么”的直接提醒，并非所有信息流方法都无效。

Semia 的[公开实现](https://github.com/berabuddies/Semia)还有源行锚点、证据与运行清单等工程能力；[MalSkills](https://github.com/security-pride/MalSkills)也有公开代码。应固定实际版本开展复现，不能只比较论文摘要。Semia 的[证据对齐实现](https://github.com/berabuddies/Semia/blob/main/packages/semia-core/src/semia_core/evidence.py)是值得实验检查的切入点：文本定位存在和事实得到语义支持是不同问题；当前没有运行反例，不能据阅读断言其必然漏报。

**需要撤回或降级的旧定位。**

“静态＋环＋聚合＋必要性”的交集并不自动形成贡献。需要证明组合解决了现有方法实际失败的问题，并且收益足以覆盖新增复杂度。旧材料中“全市场规模化只有静态方法能做到”的措辞也过强；可比较实际分析覆盖、成本和运行条件，不应从类别直接推导规模能力。

旧记忆把“两个冗余动作，删去任一仍完成任务”解释成它们会被判必要，这个推理方向不成立。Wu SkillScope v3 的 Unnec 以保留核心流程且仍满足目标为条件；此情况反而可能被判不必要。v3 不再要求输出逐字相等。[SkillScope §2.2](https://arxiv.org/html/2605.05868v3#S2.SS2)、[§4.2](https://arxiv.org/html/2605.05868v3#S4.SS2)

同一个汇点含 `{credential, database, file}` 标签也不能直接证明联合隐私危害。至少必须核查：同一观察者能否获得这些内容；互斥路径是否可共同发生或跨次保留；标签是内容还是路径/句柄；组合是否增加可利用能力或推断信息；任务是否允许这个组合。旧 2,152 个候选汇点计数尚不能替代这些证据。单动作分析对某些组合风险可能不充分，但不能从旧反例推出具体竞争工具必然漏报。

**建议的主方向：让隐私结论对表示错误与未知有明确边界。**

候选问题是：在固定执行模型和观察者下，条件、作用域、值身份或执行主体的错误如何改变隐私结论；SkillFlow 能否在相同预算下减少这些错误，并在证据不足时避免给出无依据的安全结论？

该问题与现有资产吻合，但还需要三项实质结果：

1. **因果证据。** 对同一 Skill／图只改变一个经核实的安全事实，观察安全结论是否改变；同时记录反馈新增的错误。不能只统计图节点 F1 或核对器通过率。
2. **操作与观察语义。** 区分脚本内部读取后筛选再返回，与整个容器先回传模型再筛选；区分返回文件路径与返回文件正文；区分写盘和模型观察。现有论文已研究部分边界，我们需要证明跨 NL/工具边界的具体精度增益。
3. **未知进入下游。** 将候选依赖保留为可能性，将确定事实与未知分开。互斥结果不能被当成同时输入，未标 model_observe 不能被当成隔离证明。可以研究已证实/可能/无法判断的查询结果，或在明确有限语义下构建上下界；“没有发现”不能自动转换成“安全”。这套传播尚未实现，当前不能宣称健全性。

比如，同样写着“筛选日志后上传”，若工具先在本地筛选，模型可能只见筛后数据；若完整日志先进入模型再由模型筛选，上传前已经发生一次模型侧暴露。两者是否成立取决于具体运行规则。这个例子只是说明需建模的差异，**并非声称首次发现此类暴露**。

SkillSpec 已经把可选建议被强化、不可满足触发条件等问题列为残余误报来源。[SkillSpec §VI-B](https://arxiv.org/html/2609.06052v1#S6.SS2) 因而本文建议的贡献必须是可复现的改善方法和安全收益，不能只是重新命名错误类型。

Lean 的现有价值是明确且有限的：保证传给审查者的表示保持图事实。若要扩展理论贡献，应先给小型操作集合规定语义，再证明对应查询或传播性质。对完全相同的文本输出做“有/无证明”准确率消融没有意义；比较的是表示或校验机制，定理本身用于说明保证范围。

**建议先用约两周完成决定是否继续的验证，而不是继续扩充整个系统。**以下是工作建议，不是已执行实验，也不是统计显著性的预设样本量。

| 步骤 | 可交付结果 | 继续投入的依据 |
| --- | --- | --- |
| 第 1–3 天：固定问题与金标 | 定义一个具体暴露性质、观察者和执行假设；从现有反例与新取样真实包中确定第一批约 20 个不同来源案例；两人独立标注并仲裁 | 能辨认真实、重复发生的错误类型；不仅是措辞或 ID 不同 |
| 第 4–7 天：直接基线 | 固定 Semia 代码版本；加入同模型原文直接审计、图但无反馈、当前反馈版本。相关子问题再加入 MalSkills／SkillSpec／Wu SkillScope | 同源输入、可比输出、相同预算下确有可以解释的差异；无公开实现时如实标识复现状态 |
| 第 8–14 天：最小安全查询与消融 | 只实现所需的少量操作语义及传播；补充真实包并构造有/无风险、语义保持改写、单事实变更的配对样例 | 在独立案例上减少误报/漏报；能显示变化源自方法，而非更多调用或只保留成功样本 |

公平比较还须对齐威胁模型。Semia 的共享模型上下文及注入能力假设若与我们不同，减少传播边可能只是更换了分析对象，不能直接统计成修复其误报。需要分别报告在共同假设下的对照和在不同运行模型下的敏感性分析。

在一小部分案例中，应使用模拟秘密、受控工具桩与可观察轨迹验证实际边界，或取得可独立核实的执行证据。静态审计器本身可以免执行，但其效果评估仍可借助受控执行。没有这类证据时，结论应限定为“既定模型下的潜在暴露判定改善”，不能宣称真实泄露已证实。不能仅靠另一个 LLM 的判断给所有风险提供金标。

评估至少报告：已确认风险的精确率/召回率、未知比例、端到端可用率、每个有效结论的成本、重复运行变化、修复引入错误率。适合时报告配对置信区间或按 Skill／仓库聚类的 bootstrap；同一模板的六个变体、同一 Skill 的三次运行不能当成独立样本。现有开发与保留划分应保持，新案例按来源和模板家族隔离。

对形式保证和工程成功分别计数。坏 JSON、坏引文和网络失败不是语义漏报，但必须进入端到端可用率分母；报告条件性能时同时给覆盖率。未知不能排除后只展示漂亮 F1；也不能强行当作安全标签。不要将不同论文不同数据集的 F1 拼成排行榜。

初步继续标准可以是：在多个独立真实来源上出现至少三类可解释失误，且最小改动在公平预算下稳定减少错误，同时没有靠大幅增加未知或失败率取得优势。这个门槛只是决定扩大研究的实践标准，不保证论文录用。

如果收益只存在于当前手工模板、强直接 LLM 基线同样解决、复杂表示不改变安全结论，或完整流程成本与失败率无法接受，应停止扩大“全能隐私审计框架”。仍可根据证据质量收缩为语义错误基准、审计可靠性实证或可复核前端工具；这些同样要正面对比 SkillSpec、SkillConsist 与最新扫描器研究，不能承诺自动形成可发表结果。

当前建议是**保留 Skill-IR 基础，优先验证一个可证伪的小问题**。真正决定 SkillFlow 出路的证据，是现有强基线在真实案例上为什么错、我们如何使它少错，而不是给旧系统再增加几个功能标签。

**同日补充：粒度、路径级判断和非必要敏感暴露的正向差异。**

用户进一步指出：项目原意是沿完整数据路径判断非必要的敏感数据暴露，与一般危险行为扫描不同。复核旧文档确认这一点：[旧 DOE 说明](history/legacy-sfg-doe/packages/skill-doe-analyzer/README-CH.md)明确以单个 label 的完整源→汇流作为裁决单位，并结合沿途处理、接收方和任务依据。上文对整体流程重合的判断，不应被理解为这些判定维度没有价值。

| Semia 不区分敏感类型或来源 | 不能如此绝对描述。论文已有秘密名称、变量绑定与调用目标，只是通用保密传播采用一元标签。当前代码还区分 secret/sensitive_local/untrusted 等，并在泄露输出中保留 kind、src。可争取的是更细的业务敏感类别、字段、处理过程和目的相关必要性；仅加类别枚举仍可能只是扩展。 |
| SkillScope 不是静态，而我们静态 | 完整 SkillScope 是静态候选提取＋动态执行/消融回放的混合方法；它也有静态 LLM 判定消融。免执行是成立的部署与方法差异，但需要在共同任务上评价准确性、成本和覆盖，不能自动推出更优。 |
| 我们按路径判断，所以可能更准 | 原设计确实用路径上下文判断。需要区分“有见证路径”“判定消费路径历史”“保持可行路径条件”。Semia 已有前者；当前代码将 conditional 边并入通用 edge，主要值流查询不使用条件合取求可满足性。后两者仍有可验证空间。 |
| 非必要敏感暴露更符合真实用途 | 对数据最小化问题，这是合理而明确的范围：正常任务可以需要敏感数据，但不需要把全部数据交给所有接收方。此定义不穷尽未授权、滥用等其他隐私风险，也不是首次提出；AgentRaft 与 ToolPrivacyBench 已直接研究。 |

固定源码证据：[SDL](https://github.com/berabuddies/Semia/blob/379bc25fe99833eb185efe56a38fe15f0235799c/packages/semia-core/src/semia_core/rules/sdl/skill_description_lang.dl)、[类别枚举](https://github.com/berabuddies/Semia/blob/379bc25fe99833eb185efe56a38fe15f0235799c/packages/semia-core/src/semia_core/schema.py)、[传播与泄露查询](https://github.com/berabuddies/Semia/blob/379bc25fe99833eb185efe56a38fe15f0235799c/packages/semia-core/src/semia_core/rules/sdl/skill_dl_static_analysis.dl)。源码仍有单调用输入广泛影响输出、相邻调用输出广泛影响后继输入的近似，默认查询没有消费字段投影或脱敏合同；这些是机制对比，尚未验证实际漏报/误报。

更值得研究的粒度区别是：**动作有必要，不代表该动作携带的每个敏感字段都有必要。**例如发送订单确认邮件是必要动作，但附带客户内部备注可能不必要。只消融整个发送动作无法单独回答字段必要性；SkillScope 的授权判断也会读取动作对象与参数证据，因此不能据此宣称它必然漏报。应比较保留动作、删除/替换特定敏感字段后的判断，且把 AgentRaft 的字段级 DOE 作为直接先行工作。

路径级研究还有一个适合承接旧项目的实质问题：**哪些路径差异会改变暴露或必要性，因此必须保留；哪些差异可以合并并复用判断？**旧引擎使用代表路径和等价类压缩，现有新 IR 又接受有说明的保守候选；两者均不能自动证明路径敏感正确性。来源、授权条件、处理先后、接收方或任务分支不同，可能使相同 label/sink 的判定不同。可以在有限明确语义下验证合并条件，并实测精度与复杂度。

建议的候选定位为：**面向 Agent Skills 的任务相关静态数据最小化分析，以敏感数据的来源、沿途处理、路径条件和接收方为依据，定位必要动作中的非必要敏感数据暴露。**这是研究目标，不代表新传播已经实现、效果领先或首次提出该风险。
