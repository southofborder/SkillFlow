## 操作与效果的关系

源文包含可区分的多个动作，且先后或中间数据状态会改变后续处理、观察、写入或传输时，必须拆成多条 IR，明确引用所用的数据版本。例如：

```python
# 先本地删除，再发送：发送操作使用新结果
clean = local_remove_field(raw, "api_key")
send(clean)

# 先发送，再本地删除：发送操作仍使用原数据
send(raw)
clean = local_remove_field(raw, "api_key")
```

单个原子调用可以包含多种效果。例如模型读取原始输入再筛选，可以有 `model_observe → transform`；本地筛选后把结果回传模型，可以有 `transform → model_observe`。效果顺序不能代替后续对具体 Data 的绑定，也不能把已有观察从历史中抹去。

不按 opcode 拼写强制拆分，不展开代码或不透明函数内部，不因为标注了多个 effects 就增加 CFG 操作。源文没有支持的先后关系不能被捏造；执行模型假设产生的隐式观察仍在安全标注中表达。

## v2 效果与证据契约

profile 顶层仍只有 `actor`、`roles`、`effects`、`evidences`。actor 与 roles 去重；effects 是允许重复的字符串序列。例如有充分依据时，`["model_observe", "transform", "model_observe"]` 可表达两次不同阶段的观察，而不是重复列举同一个标签。

每条非空效果证据必须具有零起始 `effect_index`，与 `effects[effect_index]` 的标签一致。每次出现分别有证据；actor、roles 与空效果数组证据不使用索引。程序拒绝缺少位置证据、负数、布尔索引、越界与错配，不自动修复。证据可有多条，但其列表顺序不决定效果顺序。

顺序不明、并发或交错时，保留已知效果并填写 `unresolved(field="effects")`；报告不展示为已确定执行链，也不默认删减先于观察。没有新增人工确认步骤，本轮不实现后续的保守传播。

提取、核对、标注的指令正文及固定执行规则使用英文，要求模型理由使用中文。源文、代码、引文和受控文本保持原语言。共享解释契约和语义核对字段维持 v2 / v4，文本身份通过摘要绑定。
