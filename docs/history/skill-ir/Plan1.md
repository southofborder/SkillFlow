# 第一步实施方案：Skill-IR 结构规范、统一校验与核心证明

## 1. 当前结论与本轮目标

**第一步的工程主体已经实现，但按现在确定的形式化目标，还没有完成。** 本次核查的 147 项相关测试全部通过；同时发现完整性检查对内存对象修改后的字段规则重验不充分，需要修正。

本轮将 Skill-IR 定位为**服务静态分析的高层中间表示**，交付明确的结构规范、统一验证入口、可运行的参考检查器，以及限定核心性质的机器检查证明。允许有反例支持的必要调整，但不以增加字段或收紧操作名称代替语义准确性。

本轮只实施第一步。第二步通用语义回溯、第三步推理语义与传播另设里程碑；不引入 DOE，不执行 Skill，不重新调用提取 API。

## 2. 建立规范并统一验证入口

- 新增 `docs/Skill-IR结构规范与验证边界.md`，明确输入域、字段规则、基本块和控制边、结果定义与引用、根节点与可达性的含义。为每条规则建立“规范条款—实现—正反测试—证明覆盖”的对应表，并修正文档中的过时定位。
- 将规范分成两层：**Schema 合法性**负责字段、类型和取值约定；**结构良构性 `WF(G)`**负责编号、端点、终结、来源形状、局部定义顺序及跨块引用连通性。`WF` 使用独立的声明式定义，不能写成“检查器返回成功”。
- 保留当前有意允许的表达：单分支来源在合流后引用、回边引用、多根与独立行为片段、开放操作名称。明确自然语言条件、业务操作和约束的行为含义不由本轮结构定理证明；不强求 phi、显式循环或全部路径可执行。
- 统一 `ControlFlowGraph.validate_integrity()` 的承诺：对调用时对象进行完整字段与结构重验，合法返回 `True`，非法返回带定位信息的现有错误类型。编译、加载和需要接受 CFG 的导出入口使用同一完整校验边界；单独构造模型不等于完成全图验证。
- 修复已复现的两类问题：修改后重复的上下文声明、literal 上出现禁止字段。完整重验不得修改原对象，也不得通过先序列化删除字段来掩盖非法内容；快照必须区分默认字段与显式提供的字段，避免误拒合法对象。
- 本轮保持现有合法 CFG 的 JSON 格式和操作表达，不改生产提取 Prompt，不重写既有结果。过去因漏检被接受的非法内存状态应被明确拒绝。

## 3. 建立形式核心与机器证明

在 `packages/skill-ir/formal/` 建立独立项目，使用锁定的 [Lean 4.33.1](https://github.com/leanprover/lean4/releases/tag/v4.33.1) 工具链及其标准库；生产 Python 包不依赖 Lean。

交付内容包括：

- **核心模型与参考检查器。** 覆盖本轮 `WF` 所需的图结构和引用信息；业务操作名、自然语言条件、约束和源码作为不透明内容保留，不凭名称赋予执行语义。
- **检查器健全性与完备性证明。** 在规范规定的核心输入域内，证明 `check(G) = true ↔ WF(G)`。这里的“完备性”仅指结构规则，不指原文行为覆盖或程序正确性。
- **合法 ID 重命名保持性质。** 证明各结构标识命名空间内、保持命名规则的双射重命名，在同步更新定义、引用、入口和边端点后保持 `WF`。上下文键、资源名称和业务文字不随结构 ID 盲目替换。
- **实现对照入口。** 将同一输入快照交给 Python 校验器与形式核心参考检查器，比较接受／拒绝结果；发现差异时保存可重放反例。该入口独立运行，不加入生产提取的默认路径。

证明禁止使用 `sorry`、未完成占位证明、自设公理或跳过内核检查；记录定理依赖与工具链版本。

**保证边界必须写入交付说明：**机器证明覆盖形式核心及参考算法。Python 实现、JSON 解析和模型转换桥接通过差分与回归测试建立一致性证据，本轮不宣称它们已获得端到端机器证明。模型与 Python 在某批输入上结果一致，也不能扩大为所有输入都一致。

## 4. 测试与完成标准

采用现有回归、生成式差分测试和机器证明三类证据，各自承担明确职责：

- **规则正反例：**覆盖字段互斥、标识唯一、悬空引用、来源块形状、终结位置、局部先读后定义、无路径引用，以及本次发现的原地修改重验问题。验证失败不得改变输入对象。
- **合法边界：**保留 may 合流、回边、多根、独立片段，以及同端点不同条件的合法控制边；不得将宽松的分析表示误改成可执行语言的限制。
- **性质与差分测试：**检查合法 ID 重命名、无语义影响的块存储顺序变化、序列化往返，以及逐项破坏规则后的拒绝行为。使用固定种子和小图拓扑枚举，支持复现并缩减差异案例。
- **既有结果回归：**只读核验现有 30 份选定 CFG，对照两套检查器。保留 ZIP、PNG、原始分析、标注和评审；如果发现旧结果违反明确规则，报告实际差异，不通过静默改图让测试通过。
- **隔离验证：**没有 Lean、没有可用性分析模块时，生产编译和渲染仍能按原职责运行；完整研究验收则必须运行形式核心构建及差分检查。

只有以下条件全部满足，才将第一步标记为完成：

1. 每条规范规则均有实现与测试对应，证明覆盖和未覆盖范围清楚。
2. 已确认的完整重验缺口关闭，现有回归通过。
3. 两项核心定理完成机器检查，且没有占位证明。
4. 已执行的差分测试没有未解释的结果分歧。
5. 验收记录包含版本、输入摘要、命令和结果，可由他人复现。

## 5. 第二、三步的后续路线

**第二步：通用语义回溯。** 第一阶段验收后，再详细制定回溯方案。回译过程只消费 IR 及其中保留的信息，不读取原始 Skill 或外置标注；随后双向核对原文覆盖与无依据新增。以可定位的行为、来源绑定、条件和约束差异作为修正依据，不以整体相似度替代逐项验证。现有 30 份材料作为已审阅的回归资料；后续研究泛化结论需要新的独立留出材料。

**第三步：必要的推理语义与传播。** 在可靠的图和回溯证据基础上，明确操作解释、黑盒契约、条件与未知信息的处理方式，再构建独立传播分析。后续机器证明的目标是限定抽象模型中的收敛性及有明确前提的传播健全性，不将“值可用”自动解释为“被消费或外发”。

这三个阶段分别积累**结构规则的证明、原文忠实性的证据、传播推理的证明**。本轮先完成第一类，作为后两类工作的稳定基础。
