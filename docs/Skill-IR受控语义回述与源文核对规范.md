# Skill-IR 受控语义回述与源文核对规范（v5）

当前唯一流程：冻结 CFG → Lean 生成并核验受控文本 → 模型比较完整原文与受控文本 → 程序定位并记录建议。每案例一次逻辑核对。模型不读原始图、不生成回述，也没有独立的模型要求提取阶段。核对协议为 v5，解释契约为 `skill-ir-semantic-contract-v4`，受控打印与往返证明保持原样；统一规则见 [IR 解释契约与逐项核对](Skill-IR解释契约与逐项语义核对规范.md)。

## 1. 保证对象

输入来自原始 analysis 文件中的 CFG，并绑定原件 SHA-256。通过现有 Schema 与完整性校验后，以公开 `cfg.to_json()` 的规范化字段为保证对象；原件字节摘要另存。规范化前的空白、缺省字段拼写或文件排版不属于文本往返定理。

受控表示保留入口、上下文声明、块键/ID/名称/来源标记、每条操作的 ID/opcode/draft ID、按位置排列的输入输出、字面值、语义标签、边与条件、三级约束、完整 metadata。空容器、null、重复出现和列表顺序保留。块字典可以按键稳定排序；指令、操作数、约束与边列表不去重或重排。

固定中文字段是记录语法：名称是标签，约束是声明，条件是尚未求值的文字。没有记录条件文字不等于条件恒真；结果定义来源不等于在所有执行路径上已经产生；源码被保留不等于效果已显式建图。转换器不执行 Skill 或嵌入代码。

## 2. 形式化证明与程序边界

旧结构核心仅用于结构规范，不承担本轮全文保真。新富域保留全部明确字段，复杂 literal 与 metadata 以规范 JSON 文本作为不透明字符串入域。

Lean 是唯一权威打印器和解析器。证明包括实际字符文本的打印/解析往返、完整富图投影/恢复、字段分类与作用域/位置保持，以及按实际结果 identifier 关联定义的健全性。主性质是从实际受控文本解析并恢复得到原来的富图。解析不接收旁置原图或人工答案。

Python 的 Schema、规范 JSON、富域适配和进程协议属于工程边界。每次转换都从实际文本独立恢复公开 CFG，并作保留 JSON 类型的精确比较；不得用普通 Python 相等把 false 与 0、整数与浮点混为一谈。打印后、发送前分别核验文本、图、证据单元、定义链接、源码和二进制摘要。Python 不另写中文打印器。

证明构建及公理审计必须实际通过，无 sorry、占位公理或跳过内核检查。证书只说明当前输入通过衔接检查，不把对特定二进制的测试说成整个 Python 或 JSON 实现已被形式化证明。

## 3. 核对契约

模型得到完整源文件、行号和确定性段落索引、实际受控文本及编号索引。段落索引不筛选要求，不替代原文。外置预期、反例身份、修改位置、旧结果、原始图、图指针和内部证书不得进入模型 payload。

模型一次完成正向要求核对和反向内容核对。记录源文要求、实际表示、理由、依据、原文引文、受控编号和建议。正常响应固定为 `outcome="completed"`，五类判定为保留、遗漏、错转、无依据新增、内部冲突。业务项与背景项分开，背景项的“保留”不能计作业务语义通过。

七类检查点仅作为阅读提示：要求性质与作用域、动作与对象、数据来源与绑定、条件与例外、顺序与依赖、次数与终止、反向依据与一致性。取消核对项的强制类别、逐类表格和原子要求拆分；允许关联要求合并，但有局部差异不能将整项判为保留。这里的核对项粒度不替代 CFG 操作粒度：源文中可区分的有序动作，若中间数据版本影响后续处理、观察或传输，建图应分别表达动作及实际使用的版本；核对器应识别被合并后丢失的顺序和绑定。黑盒内部和执行模型隐含效果不得补造成源文操作。模型在同一次调用中检查自身结论与证据及其他发现的一致性。一个段落的编号已覆盖，不表示其中多个关系均已核对。

提示词指令与共享解释规则使用英文，明确要求模型理由使用中文。Skill、代码、原文引文以及 Lean 生成的中文受控文本保持原样；语言调整不改变受控事实、保守依赖规则或受控打印证明。规则及提示词摘要变化后，旧运行不能借新代码续跑或重新解释。

解释契约保留来源入口与取得值的分工。例如 `context_key=request` 可以标识 city 的逻辑来源，输出 `result` 标识取得值；这不单独证明整体读取、模型观察或整体外发。核对同时检查来源、目标字段或 getter、结果身份及其后续参数绑定，保留明确局部接口、隔离边界及源文明示的先读后选步骤。请求影响工具返回内容，不等于全部返回内容由请求参数构成；工具获取边界也不自动证明网络通信。提取 Prompt 已同步明确这些区分，不增加 IR 字段。宽读取及隐含观察仍在第二阶段标注，核对器不读取安全标注，也不根据执行假设要求新增源文动作。

`represented` 不再强制选择精度类别；明确采用保守依赖规则时附可选 `conservative` 说明，包括固定规则、已有候选事实编号、理由和精度损失。没有该说明不代表精确。保守只接受依赖精度问题，不因该精度不足记为未决，也不引发重新提取。它不能掩盖明确错绑、额外实参、动作遗漏或禁传违反。源文冲突、材料缺失或实际表示能力限制若阻止必要判断，使用独立 `outcome="cannot_assess"` 分支；它是 `semantic_failure`，不属于正常发现，不算通过，也不驱动猜测性修复。

模型仅引用已有受控编号；程序生成图位置。每项源文单元及受控单元都须有核对记录，覆盖编号齐全不是语义等价证明。错误引文、非法编号、缺少必要记录或坏 JSON 记为执行错误，不静默修复。不能完成必要判断时必须提供原因及真实的源文／受控定位；坏引文仍是格式或证据错误，不接受为合法失败说明。

建议定位已有操作或父容器。遗漏可以建议在某个返回前插入步骤，不编造不存在的证据编号。图内声明与操作的冲突可以被忠实回述，不能将它误算成回述保真失败。独立核对入口只记录建议；反馈入口按明确差异决定是否重新提取。程序校验定位、记录及已填写的保守候选，不证明模型语义判断正确。v5 删除 `unknown` 和 `unknown_reason`，不接受兼容别名。所有核对记录都在图外，原图 IR 不增加字段。

### 正常结果与语义失败分支

正常响应：`schema_version=5、contract_version=skill-ir-semantic-contract-v4、outcome=completed`，加既有 `findings、reviewed_source_unit_ids、reviewed_controlled_unit_ids、notes`。

失败响应只包含上述版本、`outcome=cannot_assess` 和 `failure={reason,source_refs,controlled_refs}`；至少一侧存在真实定位和依据，不允许同时返回 findings 或覆盖数组。程序校验材料和引文后抛出独立 `SemanticFailure`，运行器保存完整失败依据并停止，不进入修复。

未展开内容、契约认可的候选依赖、普通不透明操作和原文未保证运行成功，本身不是失败理由。能够忠实保留的开放描述正常核对。程序不根据文字关键词判定模型失败理由是否成立。完整正常结果若只有背景项，反馈决策同样为 `semantic_failure`，不能形成业务通过。

## 4. 固定实验与命令

本节的 30 图、F01 反例和首次七例套件沿用各自冻结来源，属于固定回归材料及历史实验安排。现行命令使用当前契约准备新目录；示例命令不授权用当前解释契约重放并改判既有历史运行。本次来源范围修正的三例完整链路另存 `experiments/propagation/runs/source-boundaries-v1-<时间戳>/`，不覆盖本节材料。

30 图仍使用 formal/fixtures/review30.json 的原始来源：001–006=N01–N06，007–012=Q01–Q06，013–018=F01–F06，019–024=D01–D06，025–030=R01–R06；F03 第3轮，其余第1轮。

F01 沿用原件及四个结构有效反例：archive 增加密钥、失败出口删除状态追加、重试成功返回首次结果、明确增加两秒等待。原始来源与人工预期不改写，预期只在核对完成后用于评测。

先在 formal 目录使用固定 Lean 工具链执行 `lake build`，构建受控打印器及证明；执行 `lake env lean ProofAudit.lean` 审计定理依赖。生产提取无需 Lean；独立回溯实验需要该打印器，缺失时明确失败，无旧打印器回退。

从仓库根目录使用：

```powershell
python -m skill_ir.backtrace prepare --suite semantics-v5-seven --run-dir packages/skill-ir/experiments/semantic_backtrace/runs/controlled-v5-seven
python -m skill_ir.backtrace run --run-dir packages/skill-ir/experiments/semantic_backtrace/runs/controlled-v5-seven --env-file .env
python -m skill_ir.backtrace replay --run-dir packages/skill-ir/experiments/semantic_backtrace/runs/controlled-v5-seven
```

`--renderer` 可显式指定受控打印器；`run --env-file` 沿用已有环境文件。prepare 默认核验30图及四个附加反例，不联网。默认套件 `f01-five` 保留 F01 五例；`semantics-v5-seven` 加入暂停批次 001、010 的第0轮实际图和对应冻结源文，共7次计划内逻辑调用。来源和图按固定摘要绑定，历史判断不进入输入。

请求官方 DeepSeek 的 `deepseek-v4-flash`，本轮使用600秒连接/阻塞读取等待。每例独立上下文，不补跑选优、不自动修复提示词、不截断输入。复用统一核对执行重试：仅已明确结束的暂态传输错误或不完整响应最多额外重试2次；完整响应中的格式或语义问题不重试，不确定请求不自动重发。逻辑核对、执行尝试、HTTP尝试分别记录。

单例转换或核对失败不阻断其他有效案例。中断后不再启动新请求，保存已经开始的调用。新版 replay 不创建客户端、不调用 API，也不修改原始调用记录。

## 5. 清理及验收

旧版运行与重放代码已从新接口范围移除，不建立归档代码包；历史输入、响应、报告、摘要、人工示例和诊断产物保留。新版命令明确拒绝旧运行版本，并绑定契约版本及摘要。历史材料不能用新版提示词或解析器重新解释成新实验结果。

新运行目录包含 inputs（完整源文及受控材料）、verification（30图转换）、calls（原始调用）、parsed（校验结果）、suggestions（逐例建议）和主报告。replay 结果另存。没有 PDF，不改变原有 dataset ZIP、result PNG 或评审意见。

工程验收包括证明构建、公理审计、实际文本往返、篡改拒绝、完整字段及引用保持、可组合语义项、可选说明和证据契约、输入隔离、固定套件调用数、中断/脱敏/离线回放和相关回归。方法验收逐项记录真实命中、漏报、误报、保守表示、无法完成判断或执行错误。外置证据匹配仅产生复核候选；助手复核不得冒充用户确认。

本轮不证明源文转换已完整、开放操作执行正确、文件写入成功、隐含副作用不存在或模型判断可靠。F01 是开发示范，五个案例不能支持泛化正确性或统计显著性结论。实际完成情况以新运行目录中的验证与验收记录为准。
