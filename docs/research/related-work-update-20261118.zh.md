# SkillFlow 相关项目更新：2026-11-18

本次更新接续 [2026-09-20 核查](../history/skill-ir/SkillFlow研究出路与相关工作更新-2026-09-20.md)，重点检索 9 月 20 日至 11 月 18 日新增工作，并重新检查主要旧基线的论文版本与公开实现。依据是作者论文、arXiv 版本记录和项目仓库；这是定向检索，不是穷尽综述。本文所有外部实验数字均为**作者报告**，不代表 SkillFlow 独立复现。日期均为 2026 年；版本抓取记录见 [sources.json](related-work-update-20261118.sources.json)。

**当前最直接的结构方法对照仍是 Semia；新增加的 SCS 必须进入直接竞争列表。** AgentSecGraph 补强了操作依赖、信任边界和 guard 证据的竞争；RuntimeTickets 则直接覆盖任务约束下的接收方、对象与累计发送量。因而“静态图＋敏感传播”“任务绑定＋确定性检查”“有源行证据”都不足以单独形成新贡献。SkillFlow 更需要同输入、同模型的实测证据，说明哪些表示或传播改进改变了正确的暴露判定。

## 9 月 20 日以后新增、需要优先纳入的工作

| [SCS / From Instructions to Exploits](https://arxiv.org/abs/2610.33489)，10-24 v1 | 将自然语言编译为受安全 API 限制的 Python 风格 IR；连接自然语言与代码的 PDG 为 xPDG，以 Trust–Sensitivity–Capability 模型传播安全属性。作者在 234 个人工核实 Skill、5 个 LLM 上比较；另以 400 个人工标注指令步骤检查编译正确性。 | 论文已核实；本轮未核实作者代码。 | **新增最直接静态方法对手。** “NL→IR→依赖图→确定性检测”已经有明确竞争；抽取正确性也不能仅用结构通过率替代。应继续寻找作者实现，优先级排在 Semia 之后，与 MalSkills 并列。 |
| [AgentSecGraph / Beyond Predefined Sinks](https://arxiv.org/abs/2610.03014)，10-02 v1 | 以敏感操作为中心构建 Security-ADG，加入来源／依赖、agent 相关性、信任边界、guard 和外部作用语义。67 个仓库、11 个生态；其候选规模与复现支持的安全行为是两层证据。 | 已核实公开 [AgentSecBench](https://github.com/A1LinLin1/AgentSecBench)，含分析器、标注、基线和微基准；本轮未安装运行。 | 可作**代码侧边界与防护证据**对照，不等同于完整 Skill 自然语言或任务字段必要性分析。它提示必须区分“到达敏感操作”和“造成安全风险”。 |
| [RuntimeTickets](https://arxiv.org/abs/2611.03772)，11-02 v1 | 模型从任务交付合同提出绑定 Skill 源行的安全义务；宿主批准后冻结，运行时确定性 gate 检查接收方、对象和累计数量，事后解码核验。作者在三个未修改 agent 框架的网络出口边界评估。 | 论文／摘要已核实；本轮未核实作者实现。 | **任务条件与数据最小化的新增近邻。** 与 SkillFlow 的静态诊断阶段不同，但不能把接收方＋负载＋任务必要性本身称为首次。作者的 0% overlook／overkill 限于其评测，不能外推为普遍保证。 |
| [The Devil Wears Markdown](https://arxiv.org/abs/2611.10830)，11-07 v1 | 融合静态告警、安全约束沙箱证据与模型推理，追踪证据来源。140 个留出样本含 80 恶意／60 正常；同推理后端消融中，加入动态证据后 F1 从 0.70 升至 0.85，再加入静态证据达 0.89。 | 论文已核实；本轮未核实作者代码。 | 动态证据可降低误报的强提醒。**系统级胜负不能隔离模型和架构作用**，论文摘要也明确这一限制；我们的对照应分别给出同模型实验和原生配置实验。 |
| [Why Static Skill Inconsistencies Do Not Equate to Runtime Risks](https://arxiv.org/abs/2610.18927)，10-13 v1 | 审计 575 个 Skill，得到 1,182 个人工核实不一致；构造 49 个可执行任务，在三种模型和 NoSkill／OriginalSkill／FixedSkill 条件下分析 441 条轨迹。 | 论文与版本已核实；本轮未核实作者工具。 | 主要是**评价方法警示**：静态不一致数量不能直接换算成执行风险或性能损失。SkillFlow 的审查发现数、传播覆盖数、DOE 成功结论必须分别报告。 |
| [Beyond Maliciousness](https://arxiv.org/abs/2610.19264)，10-13 v1 | 全包静态检查、依赖来源检查、沙箱执行与轨迹评估结合，度量安装后能力暴露。覆盖两个市场的 6,309 条 listing，区分能力暴露与恶意意图。 | 作者 [Metano 页面](https://metano.ai/resources/beyond-maliciousness) 链接 SkillTracer 服务；本轮未确认开放实现。 | “正常 Skill 也可能拥有过大能力”不是空白。能力存在、具体任务必要性、真实数据泄露是三个不同判定对象；该工作适合作为测量背景，不能直接与 DOE 分数合并。 |

此外，跨会话制品传播的 [SkillRelayBench / SkillRelayGuard](https://arxiv.org/abs/2610.13227)（10-09 v1）和工具更新信任缺口 [ETUDE](https://arxiv.org/abs/2611.01976)（11-01 v1）扩大了威胁边界。前者研究文件／配置等持久制品跨会话传递，后者研究工具实现更新后旧信任不再有效。本轮只核实摘要与版本；它们属于范围边界补充，不能被本轮单包、固定版本的静态复刻宣称覆盖。

## 对当前复刻与论文定位的具体约束

1. **先回答共同问题。** Semia 原生输出是安全风险，SkillFlow 的目标包含任务所需敏感使用与额外暴露；应先建立共同可比的泄露／敏感边界子集，再单独比较任务与字段必要性。不支持某类判定要记为不适用或能力范围缺口，不能机械记为漏报。
2. **保持共同材料及可见性。** 同模型同输入是第一条实验轨道；还要记录实际发送给模型的文件、裁剪／排除、模型上下文、迭代预算与失败状态。源包相同但实际审查材料不同，不等于有效输入相同。Semia 原生配置复现是另一轨道，不能混为一个分数。
3. **对齐执行／威胁模型。** 显式工具参数、共享模型上下文、日志／文件和隐式流分别标注。删除保守传播边可能改变假设，不能直接算成减少误报。源码位置存在也不证明语义得到源码支持。
4. **分层计分并保留未决。** 分开统计前端接受／覆盖、源文忠实度、边界和字段定位、必要／额外暴露裁决、失败与 unknown、时延／调用／公开 token。正常必要使用是误报评估的必需部分；仅有恶意样本不足以评价最小化判断。
5. **不把旧 GA4 partial 当优势证据。** 已封存运行中的边界到达率、通过的离线测试或审查数量不证明语义正确，更不证明超过 Semia。本轮应保留原有失败和未决，新增对照结果另行存放。

现阶段可检验的贡献假设是：在共同执行假设下，明确的结果身份、接收方依赖、操作语义与任务需求能否减少真实的错误暴露结论，并能否保留足够覆盖和可接受成本。SCS、Semia 与运行时近邻的存在使这一假设需要实验验证；“更细的 IR／更多合同／更多检查”本身不能替代证据。

## 检索与复核边界

检索使用 Semia、AgentRaft、AgentSecGraph、MalSkills、SkillConsist、agent skills/static analysis/privacy 等名称与主题，补查 2610／2611 新稿，随后以 arXiv 页面、作者仓库和作者项目页核对。arXiv 标题与版本历史另外从原站抓取到 sources.json；不使用搜索结果中旧摘要覆盖论文现行版本。新发现中，SCS、Devil、RuntimeTickets 等目前是摘要与版本层面的核实，本文不宣称已经逐段复审其方法正文或完成工具复现。公开仓库状态也不等于可在本机无修改运行；实验接入结果应以独立复刻日志为准。
