# SkillFlow 统一抽象运行时契约

当前流程是：**完整 Skill 与 CFG → 统一抽象运行时契约 → 一次联合标注处理方式及字段关系 → 程序编译观察 → 确定性传播**。所有 Skill 共用一份契约，不为每个 Skill 选择运行时，也不要求逐例动态验证。

权威英文运行时规则与有限操作清单位于 [`runtime_contract.py`](../../src/skillflow/propagation/contracts/runtime_contract.py)，当前版本为 `skillflow-abstract-runtime-v12`。`runtime_contract()` 返回隔离副本；`runtime_contract_binding(model)` 返回版本与完整契约（规则和操作清单）的规范化 SHA-256。模型材料完整提供这份契约，证据使用独立 `rule_id` 与真实 EM 编号，不由模型填写 basis 或 quote。类型模式和实现约束实际可接受的表示及执行；文字规则说明其语义和源文依据义务，不单独构成可执行语义证明。当前入口见[版本导航](../current-version.md)，内层处理规格及编译细节见[字段关系与观察编译](SkillFlow-字段关系与观察编译.md)。

## 1. 规则与保证边界

规则区分显式事实与保守默认。默认描述契约下的静态可能行为，不是实际执行的测量，也不是“所有 Agent 必然如此”的断言。收窄范围、局部处理和隔离例外需要源文、代码或接口依据。

| 编号 | 规则 | 适用边界 |
|---|---|---|
| EM01 | 来源范围默认 | 从整体取得字段时保留整体与字段关系。目标名、执行主体或 getter 式名称不能证明局部接口；明确机制才能限定获取／返回范围。不编造其他字段、敏感性或无关资源。 |
| EM02 | 工具返回默认 | 未明确隔离时保留返回内容进入模型的可能性。适用对象是返回版本，而非工具内部所有扫描内容。本地扫描整体、仅回传一个字段时不能直接推导整体观察。 |
| EM03 | 模型可见边界 | 内容进入模型请求构成观察，不证明模型理解或记住内容。缺少隔离且内容用于 Agent 处理时应用可能观察默认；纯调度不能证明观察。 |
| EM04 | 数据版本与明确机制 | 模型处理原输入与本地处理后仅回传结果不同。凭据句柄不等于明文；后来删减不能撤销早先观察，transform 也不证明脱敏。 |
| EM05 | 声明不是保护动作 | 禁止传递或只需某字段，不自动实现筛选或隔离。契约只作用于有依据的现有动作，不能制造无关来源或业务操作。 |
| EM06 | 交互边界独立 | 工具名称和 LLM 参与不证明网络，普通 return 不证明面向用户。可能观察整体不扩大真实调用参数。真实冲突和次序不明仍保留。 |
| EM07 | 上下文写入 | 只有改变后续可读上下文内容／绑定才是 context_write。结果登记不自动构成写入；原样保存不自动 transform，删除不自动读取旧内容。 |
| EM08 | 地址与值身份 | 没有明确缩减则保留相关范围。possible 依赖不等于明文包含。address_kind 默认 identified；只有确实未知的地址关系才声明 unidentified，并给具体原因和物理源文依据。同类未知地址保守别名／弱更新，名字前缀没有别名语义。登记 Data 不自动形成交付。 |
| EM09 | 获取与计算不同 | 检索返回保留获取边界、请求输入及可能依赖。网络明确使用 remote/net_receive；网络未定的工具获取使用 tool/无标签 receive。纯计算仍是 compute。 |
| EM10 | 处理模式的确定性编译 | 模型标注 model/local/default，程序按实际引用插入观察。省略或 null operator 表示未知；显式执行者若存在，model 模式须包含 llm。flat wire 不填写 operator，程序只从显式 model 派生 llm；default 观察不推断执行者。local 要有依据及明确 returns，编译不证明模式判断正确。 |
| EM11 | 元素作用域与筛选 | filter_items 保留可能成员身份。for_each 以 occurrence 关联字段和参数；yield/output 形成保序映射集合，空与未知集合分开，同值重复成员不合并。其词法 body 与 EM17 的显式嵌套 CFG 循环分别遵循已有支持域；不引入任意逐成员共享状态或通用异常执行。yield 不等于模型观察，空集合无成员作用。 |
| EM12 | 接收范围与留存默认 | 位置新增 access_scope/retention。工具部署未说明保留外部接收可能性但不补网络标签；上下文默认任务内临时；文件默认任务内持久，明确临时和清理机制才能降低留存；模型、远端和用户默认另一接收主体。 |
| EM13 | 交付与 sink 分类 | tool 请求交付与返回获取分别表达。程序编译观察后按边界属性生成六类 sink 和固定暴露等级；任务内部临时流动、删除和普通 return 不虚构内容交付，等级不表示敏感性或 DOE。 |
| EM14 | 可选请求成员 | 布尔控制决定原字段值是否成为对象成员；控制与载荷分开，同一控制共享决定，条件观察沿用相同条件。 |
| EM15 | 请求交付与获取 | call 展开时按明确坐标生成配对身份，重复相同参数也能分开；独立操作仍须同一 IR／作用域／边界及有序请求引用唯一对应。获取复用实际交付版本，不按名称或 FIFO 猜测。 |
| EM16 | 统一抽象粒度 | 纯局部计算可不透明；真实获取、交付、可选保存、初始化版本和条件返回须保留边界。调用摘要保留正常／失败候选、凭据创建来源和有限状态作用，不将未知内容当作无法分析。 |
| EM17 | 有限循环摘要 | 保留实际前驱、成员 occurrence、条件边及接收者配对；未知次数、递归结构和受限状态关系不伪装成精确执行。 |
| EM18 | 普通保存默认 | 源文要求保存但未指定更新方式时，省略 mode 展开为 replace；明确 append／delete 等源语义优先。默认不冒称原文明示覆盖。 |

### 有限操作契约覆盖什么

`operation_contract` 与规则一起完整提供，包括 18 行操作／结构清单：

- 14 个原子操作：read、receive、deliver、write、select_part、exclude_parts、update_fields、build、compute、filter_items、merge、member、branch、append。
- flat `call`：展开为保持真实调用身份和请求／响应配对的 deliver 与 receive。
- 3 种结构：processing、for_each、cases；各自保留已有模式、作用域和返回义务。

每行声明输入输出域、身份／别名关系、信息属性和副作用；共同义务说明失败局部性及源文依据。
类型模式仍决定字段、数量、引用、顺序和支持边界。已知选字段、构造和覆盖使用确定性操作，
不能改成不透明 compute 来逃避真实依赖。14 个结构化需求表达式操作符为
ref、literal、field、present、count、not、eq、ne、lt、le、gt、ge、and、or；
它们的实际版本和条件仍按原表达式模式核验，不构成新的执行器。

这里穷尽的是系统支持的有限词汇，不是任意 Skill 程序、外部库、工具接口或全部可能运行情形。
清单覆盖和模式通过不证明源文已完整、忠实地建模。源文关系超出支持域时，应指出具体操作、
输入／输出范围、依据及缺少的关系；不能用泛化的“黑盒”替代理由，也不能虚构输入或删除真实副作用。

### 内容未知、地址未知与局部失败

调用参数、异常载荷、调用结果或成员值的内容未展开时，只要来源可定位，就保持该来源及 occurrence 身份。
只有地址关系本身确实未知才使用 `address_kind=unidentified`，同时给出 `address_reason`
和物理源文依据；这类地址与同 kind 的位置保守别名并采用弱写入。`symbolic:` 仅是名字内容，
旧前缀声明在新协议下须显式选择地址策略。程序检查结构／引用，源文审查判断理由是否充分。

支持的局部类型／数据域错误保留原错误、实际输入及 IR／操作坐标，回滚失败尝试，沿实际依赖限制后续范围。
独立已处理记录继续有效，但部分成功候选伴随的失败诊断仍限制 DOE。对象不能因传播困难而被当作集合。
未知引用、内部不变量及完整性错误不通过宽泛捕获变成局部成功，资源限制也单独保留。
`infeasible` 需要实际路径排除证明；`not_reached`、`not_solved`、失败或缺少记录不等于没有需求。

## 2. 读取、处理与观察分别表达

| 已知事实／标注 | 程序处理 |
|---|---|
| 未说明局部机制，从容器取得字段供 Agent 处理 | default 模式保留相关整体获取；read 后观察取得版本，select_part 连接目标字段。不能声称原文明示了整体观察。 |
| 明确本地扫描整体，只回传一个字段 | local 模式内部读取不生成观察；明确返回字段才在段末被观察。 |
| 模型处理已经取得的数据 | model 模式在首次使用前观察段外输入；同段生成的中间结果不算新的外部输入或额外模型调用。 |
| 工具取得响应 | model/default 中 receive 后观察响应，不因取得响应就同时观察请求参数。 |
| 明确本地删减，只回传清理结果 | local 的 returns 引用新版本；不补原版本观察。 |
| 模型先看原数据，随后删减 | 先前观察保留原版本；中间计算结果不回写早先事件。 |
| 明确凭据代理不回传凭据 | local 的 returns 可为空或只含有依据的句柄，不能把句柄变成密钥明文。 |
| 仅参与调度 | 不因 operator 有 llm 就制造数据；观察仍须有处理模式与具体值引用。 |

同一处理段中相同外部符号引用去重；不同处理段及不同取得／返回版本分别保留。此去重是记录同一抽象处理边界，不推断模型实际调用次数。顺序使用 `order=fixed/partial`。partial 保留编译生成的必要先后约束并计算候选排列，不能借数组位置断言先保护后观察。模型输入观察先于处理、read/receive 先于对应观察、本地段全部操作先于回传观察；不同处理段可在原子操作之间交错。

## 3. 各阶段职责

CFG 提取与源文核对只保留原文行为和约束。逻辑来源不等于实际整体读取；局部接口不能丢失；运行时默认观察不补造成 CFG 操作。它们不新增 IR 字段，也不读取安全标注答案。

联合标注读取完整源文、CFG 与契约，输出处理规格，不自行输出 `model_observe`。它必须判断模式、局部机制、字段路径和数据关系；名称或 opcode 不能替代判断。指令和理由使用英文，引文保留原语言。默认、opaque、possible 和可求值的 partial 均正常完成。当前七调用入口提交支持的事实和具体局部缺口，不使用整份 cannot_assess 结束标注；未决范围不能由空业务结果冒充完成。历史独立入口的失败材料保留原样。

编译器检查原始结构、编号和引文，按类型规则插入观察，建立 wire、内层原始规格与编译位置的映射，再检查编译结构。它不解释自由文本理由，也不能证明 local 依据充分、model 判断真实或源文已经被完整覆盖。省略 reason 时只补中性引用说明；default 观察和模型接收方都不自动增加执行主体。sink 清单由程序按实际交付及边界规则生成。

模型标注位置访问范围与留存性质，程序再从具体交付和非删除写入生成 sink 清单及 exposure_level；清单由实际操作及边界性质派生。边界默认、明确例外和六类等级见[Sink 边界主规范](SkillFlow-Sink边界与固定分级.md)，不在这里另建一套分类规则。任务内部上下文写入仍传播，但不自动成为暴露 sink；工具参数交付和工具返回后的观察分别绑定。

传播器执行编译后的规格，不追加 LLM 调用，不按 opcode 补关系。稳定后的记录是静态可能性，不是执行日志。`complete` 不代表行为必然发生、语义完整或不存在 DOE。

## 4. 版本与身份

标注材料保存全文，标注运行清单保存契约绑定：

```json
"runtime_contract": {
  "version": "skillflow-abstract-runtime-v12",
  "sha256": "实际冻结规则与有限操作清单的规范化摘要"
}
```

完整契约保存在标注材料；传播引用对应上游运行，不复制另一份契约。完整运行加载同时核验原始响应、编译结果、映射与摘要；只验证编译结构不等于验证编译来源。普通业务读取须符合相应支持协议，重新求解还需源码身份一致。旧记录不迁移、不重新计算摘要掩盖变化。

当前运行时为 v12，profile v24，processing compiler／mapping v15，传播运行 v22；完整入口与验收状态见[版本导航](../current-version.md)。独立表示契约材料已移除，Schema 和共用格式说明承载格式职责；有限操作清单复用这些现有能力。Data v6 保留有限循环、选择、累计及 mapped_collection 关系；旧材料不迁移、不重新标记。

`abstract-runtime-v1-*` 三例试验及当时的 `run_runtime_pilot.py` 调度属于 v1 历史材料。当前调度已经更新，不能用新契约重解释旧模型响应；先前处理段试验使用 v2，实际结果以相应运行材料为准。历史一轮经明确批准只原位替换 `processing-v1-20260928-204710` 内三例派生产物，保留经核验的选定 CFG，并建立新运行身份；这不构成旧响应的迁移或重新解释。

集中验证包括：模式边界、获取与请求区分、本地返回版本、段内中间值去重、逐元素参数配对、引文与摘要篡改拒绝、零 API 重放。它验证程序规则；模型实测另行报告模式误判、字段关系错误和明确失败，不以编译成功替代语义正确性。

## 可选参数与请求关联

EM14 规定可选对象成员引用原字段值，布尔条件只决定加入或省略，不成为请求明文。成员条件为 false 时不消费该值；抽象布尔保留两种形状。同一条件的多个成员共用决定。先前整体观察仍保留。

EM15 规定交付与获取明确配对并复用实际交付的数据版本。call 由程序生成精确配对 ID；其余独立操作按同一 IR／作用域／边界和一致有序请求引用唯一匹配。不按名字或 FIFO 猜测；歧义明确失败。规则不承诺采用 JSON 作为网络序列化格式。

v5 收紧网络机制证据，并补齐上述条件消费、观察与请求复用；Data 保持 v4。完整规范见[Sink 标注收紧与可选参数](SkillFlow-Sink标注收紧与可选参数.md)。

## 通用显式循环

EM17 约定有限静态定义和关系摘要：模型提供合流、成员、边选择及实际处理，程序生成循环和 occurrence 身份。显式嵌套 CFG 循环与结构化 for_each 的具体能力边界分开；未知次数、递归尾部及精确累计位置不被改写成已知值。局部域不支持保留具体范围，独立分支继续。完整设计与离线证据见 [通用循环设计](../doe/general-loop-analysis.md)。
