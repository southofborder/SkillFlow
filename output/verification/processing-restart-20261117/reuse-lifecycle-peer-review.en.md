# Read-only peer review: accepted-upstream reuse

Reviewed the new `online-ga4-processing-restart-20261117` preparation, lifecycle guard, controller and accounting helper source after the transport agent declared it stable. No helpers, stage APIs, validators, models, Skill code, donor replay or tests were executed by this reviewer. No production or lifecycle files were edited. The reviewer found no unresolved blocking defect in the inspected implementation.

The route explicitly creates a new owner. It copies only complete source, accepted initial Task/flow/graph stage artifacts and the initial canonical CFG/certificate. It excludes downstream answers and all parent native transport files. Operational locks, reports, replay output and Task execution boundary are excluded from the immutable inherited inventory, permitting fresh operational records only in the new owner. Parent origins, original prompts, response bodies, timestamps and recorded counts remain intact in the copied evidence.

Preparation binds the fixed closed parent's implementation/source/configuration, selected initial Task/CFG, accepted first-attempt chains and closure/replay evidence. It records exact inherited hashes and separately records parent upstream cost. The new source/stage references resolve under the copied owner. A controller factory refuses initial Task, flow and graph completion before any native client construction; fresh downstream and the existing bounded revision stages remain available. This is inherited initial material, not three newly sampled upstream answers.

The unchanged runner still visits and verifies cached upstream jobs in the new owner and deterministically reconstructs its canonical CFG. The frozen guard compares the inherited inventory, including exact `graph/initial.json` bytes, before any new native request and before/after the sole new-owner replay. Thus a different reconstructed initial CFG cannot silently become processing input. This is not donor execution: no donor runner, backend or replay is invoked by these helpers. Ordinary Task loading reconstructs the local copied request chain; it should not be described as doing no validation at all.

Accounting explicitly separates the configured seven-stage schedule into three inherited initial stages and four fresh normal stages. The ordinary guided logical count retains inherited records, while `restart-accounting.json` reports inherited and new logical counts separately. New transport metrics enumerate the initially empty new transport tree. Parent native/token counters are stored under `parent_upstream_cost_not_new` and are not added to the new totals. When no controller outcome is available, new logical count remains unknown rather than being invented.

The existing structural, semantic repair, two-worker and transport budgets remain unchanged. A shared repair may subsequently revise a domain under the existing policy; retaining the initial CFG must not later be misreported as proof that the final selected CFG can never change. Final reporting must identify the actual selected bundle and distinguish abstract record reach from semantic correctness, as in the donor audit.

Root's separate synthetic integration and the helper author's lifecycle receipts are the executable evidence; this peer review is source inspection, not an additional test run. The preserved receipts are `restart-integration-initial.xml` and `lifecycle-accounting.xml`. No real launch was performed by this reviewer.
