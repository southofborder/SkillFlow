# 首份 processing 答复与纠错范围

首份新答复被结构校验拒绝，共 14 条诊断，尚不能将其中任何契约称为已接受的语义关系。主代理记录 native 正常退出、请求区间耗时 1,376.830 秒；该数值不是纯生成耗时。

这次模型确实使用了共享输出：先给完整 payload，最后只给一份含 194 个定义的 shared_values。原始模型文本 152,926 字符；紧凑 wire 为 152,087 字符，精确展开后的紧凑 payload 为 467,453 字符；response.json 容器为 178,778 字节。它们是同一答复的不同表示，不能混作 token、耗时或语义通过证据。保存的校验结果没有重复键或共享引用错误。

覆盖错误是重复归类，并非漏掉 IR：487 条 modeled 与 4 条 unmodeled 的并集恰好覆盖 489 条 IR，其中 ir_011、ir_436 同时出现在两类中。这两处缺口说明没有表达控制台格式化输出；另两条 unmodeled 为 ir_289、ir_295，描述 JavaScript undefined。答复共有 19 个 processing_gaps，还涉及条件时钟读取、稀疏数组空洞、保存文件的调用对应关系和未实现的 Markdown 后续。这些仍是待源文审查的模型声明。

另 13 条错误分别落在 ir_134、140、310、313、314、316、328、331、333、345、348、350、459 的 evidences。它们的 local processing 只引用 EM16/EM17，没有给出该具体操作的源文或 CFG 机制定位。运行时规则说明允许的表达方式，不能单独代替具体机制依据。

实际 a002 是完整替换答复。全局 `/ir_semantics` 覆盖错误横跨 modeled/unmodeled，现有记录纠错策略无法把所有错误定位成单条可替换记录，因此按严格回退路径要求完整对象。这不代表每条 IR 都需要语义修改。纠错输入为 599,855 字符、600,262 字节，完整保留展开后的首份候选、全部 14 条诊断、原始逻辑输入和完整源文。通用提示中的 task 一词没有带入 Task 对象。

127 个 location 均采用默认 identified，没有显式 unidentified 声明。异常位置使用具体调用或来源名称，例如 ir_455 的读取异常与 ir_457 的解析异常；未知异常内容因此不会自动变成全局别名。但 writtenFile 和按类别/操作命名的保存位置是否正确保留每次调用的路径与接收方关系，仍须源文审查；ir_449 缺口本身已经承认汇总位置不能证明物理文件独立。

答复含 87 份 compute demand_transfer 和 221 份接口输入契约（218 个 call、3 个 deliver）。87 份 compute 契约都只有一条整体 value 输出规则，非空输出字段选择器为 0。标量输出可能适合整体规则；对于 ir_016 设置对象等复合输出，整体结果所需环境字段的并集，不能直接证明某个子字段分别需要哪些输入。确定性选择和构造仍有作用，但不能据此宣称语义契约已完成逐输出字段映射。当前尚无已接受源文审查或后续 Task 需求结果。
