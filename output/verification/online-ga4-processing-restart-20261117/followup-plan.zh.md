# 本轮结果支持的后续修改方案（尚未实施）

本轮保留原 CFG、冻结代码并重跑 processing，已经结案。以下是结果驱动的通用修复建议，不是新模型运行、额外回放或生产修改的执行记录。

1. **先修审查纠错表达能力与交付失败后的局部保留。**当前既有跨 finding/check 冲突，又缺少 231 个已知契约槽。纠错协议应区分已存在记录的关联替换、明确缺失槽的新增；保持全量库存、源文与原答复的可验证绑定。输出合并后仍严格校验全体记录、必要性依据、覆盖和冲突。纠错输入要对包含适配器的完整交付做无损共享／引用处理；不能截断源文、漏掉契约或提高上限掩盖问题。若纠错交付在启动前失败，对已保存完整首答运行同一套严格局部隔离：仅保留独立有效记录，把缺项、冲突及具体受影响范围留下。不得把作者自标 accepted 直接当成核验通过。

2. **修正未知内容与未知地址的混淆，并局部化执行错误。**五个异常来源的 `symbolic:` 名称触发同种位置的宽泛别名。异常值未知不意味着其来源位置未知，应为明确发生点建立正确的来源身份，并核验未知地址声明的依据。保留真正未知地址的保守别名语义和对象／集合严格校验。另将某操作的数据类型错误定位到操作、输入 Data ID、发生点及实际后继范围，避免未到达的独立部分被全局异常一并停止。尚未执行的分支不能表述为已经证明不可行；coverage 应保留未到达的具体原因。

3. **补足已知复合输出的字段契约与真实观察记录。**明确对象构造应优先使用现有确定性构造操作；不透明计算根据该操作的源文输出结构给出字段规则，不能由本次 Task 反向污染 processing。Task-correspondence 则独立检查指标、分组和成员配对等输出义务，不能只保留 shape 代替实际内容。修正源文确实读取的 filters/orderBy、console 输出和客户端接收方身份的遗漏。整值和 truth 规则不能冒充字段级覆盖。

建议离线验收直接覆盖本轮错误边界：分散的缺失审查槽与冲突一起纠错；完整交付超限时严格保留独立有效检查；已知异常来源不污染 URL 数组；真正未知地址仍保持保守别名；一处集合类型错误不阻断无关分区；执行中止后的 not_reached 不伪称路径不可行；inspection 与 metadata 的输出子字段只回传相应输入，同时保留原始读与观察。继续沿用七次正常请求、两个 worker 和现有预算；不放宽校验、不截断源文。离线通过与后续线上运行应分别报告，不能用测试数量替代真实源文覆盖。

本次重跑没有改动生产代码，因此其较快局部纠错和较差传播覆盖不能归因于一次新的生产修复。差异来自同一输入下重新生成的 processing、后续材料及其触发的既有路径；一次重跑不足以给出总体准确率、稳定性或性能改进结论。
