# Finite review correction and bound local retention

This is an interim offline implementation note. It does not authorize or report a model run, a historical replay, Skill execution, or complete GA4 semantic acceptance.

`review_correction.py` adds `ReviewCorrectionStrategy(material, fallback)`, instantiated by the fragment source-review runner. The original complete source-review material remains the authority. The strategy binds the exact candidate, diagnostics, material, obligation inventory, selected records and dependent obligations by canonical digests. Missing slots are the difference between the program's complete obligation inventory and the distinct authored obligation IDs. Unknown, missing or duplicate authored identities, ambiguous ownership and unsupported global diagnostics retain the existing complete correction strategy. Ordinary existing-record corrections without missing obligations or cross-record conflicts keep their previous strategy.

For finite corrections, diagnostic owners select existing finding/check records. Actual target ancestry closes both sides of finding/check conflicts, including connections through missing checks and currently invalid or nonaccepted checks. The response may replace only supplied records and insert checks only for supplied missing obligation IDs. An existing check cannot change its obligation identity. Duplicate replacements, duplicate insertions, invented IDs, table deletion and changes to unselected records are rejected. The full merged candidate always goes through the existing source, target, scope, coverage and consistency validator. An incomplete correction may still be isolated after its existing budget is exhausted; omission never means acceptance.

All original source and contract inputs remain in the prompt. Only unaffected prior review records are omitted from correction delivery; their exact values remain in the immutable original answer and are reused by the host. Selected record IDs and complete values use parallel arrays so the existing column-table grammar can remove repeated field names exactly. Missing coverage messages use the complete inventory's positions plus the original message prefix, code, path and diagnostic positions; an exact inverse check prevents changed diagnostics. Repeated known IDs are referenced by inventory positions rather than copied again. This is a generic display and correction policy, with no GA4-specific rule, operation name, count or source special case in production code.

`source_review.py` can retain usable local records when the second, existing correction delivery ends with `ModelRequestFailure` or `InputTooLarge`. It requires a complete first response envelope, the exact two-attempt response chain, the immutable first response and validation, the second request's previous-response binding, a checked error transport record and no second response. Unknown process state, integrity faults, recording failures and user interruption do not take this path. Ordinary strict isolation revalidates the original complete candidate against the exact material. The result is `partial`, never a completed review; the original `request_failure` and `failure_call` remain explicit, and `delivery_retention` binds artifacts and the isolation result. Missing/invalid/conflicting scopes remain blocked. No usable records means the result stays `request_failure`.

The existing auditable JSON normalization is also rederived from the original first response. Its exact receipt and validation digest must match, and the normalized candidate must equal the response chain's candidate. When present, `normalization.json` is included in the retention proof. Independent peer review exposed a raw-extra-closer regression before this fix; its failed receipt remains preserved. This does not extend the normalization policy.

The complete runtime contract must stay visible: review may need a supported alternative operation to diagnose an incorrect current representation. Filtering the vocabulary to operations already used would obscure precisely those alternatives. The new measurement therefore substitutes the entire current runtime v12 contract, including its operation inventory.

With the old complete runtime contract the delivery is 1,039,522 characters. With only the complete current runtime v12 substituted it is 1,045,496 characters, including the unchanged 212-character adapter envelope: 3,080 below the unchanged 1,048,576-character limit. Unchanged input fields are compared after exact display expansion. The historical files remain hash-identical. This concrete fit does not guarantee arbitrary future material will fit; the existing complete-delivery prestart limit and strict local retention still apply.
