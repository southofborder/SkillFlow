# Accepted upstream material proof

The public `describe_accepted_upstream`, `prepare_from_accepted_cfg` and `load_accepted_upstream` APIs are unchanged. Imported Task, flow, CFG, source and their original producer manifests retain their bytes and identities; only the new owner and its downstream work use the current producer.

The new `accepted_stage_reader.py` is a pure artifact reader for flow/CFG. It does not invoke `run_step`, a response-chain runner or a model client. It accepts only supported step v13/v14, structural correction v5, normalization v1 and the exact corresponding CFG correction identities. It checks the successful result shape; the one- or two-attempt limit; exact ordering; request-kind, prompt and previous-attempt linkage; complete call/transport agreement; response hashes; auditable normalization; correction rendering and permissions; the recorded merged candidate; and complete validation evidence. The current strict stage validator derives the final value, which must equal the cached document/candidate. Unsupported old correction evidence fails explicitly rather than being reinterpreted. The selected CFG must also equal the compiled accepted candidate.

Every selected flow/graph context must identify its actual source owner, whose complete snapshot must equal the selected source. Its dependency list must name that source manifest and, for graph, the exact selected flow result. Imported Task checks its sealed producer, unchanged Task v5 policy, source and structural request/transport chain before copying. Full Task semantic reading is performed only on the new copy. If that final copy-only verification fails, the new preparation records `preparation-failure.json` and a failed result; no native request is started.

Source trees are copied completely, including legitimate filenames that resemble infrastructure reports or replay folders. Stage-only reports, locks and replay artifacts remain excluded from selected stage infrastructure. Every copied ancestor receipt and its complete bound file inventory is retained; all references stay within the declared owner. Lineage is bounded to eight inherited levels. Parent directories in metadata are informational and are never followed as alternate source locations. Selected graphs with additional failed-stage recovery dependencies are currently rejected explicitly before child creation; the current donor's initial CFG does not have that unsupported extra dependency.

They include current and synthetic v13 first answers, valid normalization, an actual existing-record correction, cache spoofing, wrong states/protocols, request and transport contradictions, missing/extra call evidence, exact flow ownership, source preservation and multiple inheritance. That fixture was separated into a direct source-copy regression; complete-pipeline source preservation still covers `report.md`, `execution-boundary.json` and `replay/note.md`. No claim is made that this unrelated source-manifest limitation was fixed.
