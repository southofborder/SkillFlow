# 审查有限纠错与有证据的局部保留

本说明记录离线实现与阶段性证据，不表示已启动新模型实验，也不表示 GA4 已获得完整语义验收。历史运行和原始失败材料保持不变。

新纠错策略直接绑定源文审查材料、完整原始答复、诊断、义务清单和允许修改的记录。缺项由程序清单减去已提交的唯一义务 ID 得到，不从模型文字猜测。现有错误记录与冲突记录按真实目标的父子关系形成闭包；缺失检查和当前未通过的检查也参与闭包。模型只能替换这些已有记录，或补齐列出的已知义务；不能改变已有检查的义务 ID、删除表、修改未授权记录或创建新的义务。合并后仍执行原有完整校验。未知 ID、重复 ID、无法定位的全局错误等继续走原有完整纠错路径，不放宽验收。

纠错输入继续包含全部源文、annotation 和契约。无关且未修改的旧审查记录可不重复发送，但它们仍完整保存在原始答复中，且由摘要绑定后原样合并。选中的记录以路径数组和值数组一一对应，复用既有无损列表编码；缺项诊断利用完整清单位置和原始公共句式表达，并校验能精确恢复每条原诊断。所有这些规则针对任意 Skill，生产代码没有 GA4 名称、固定数量或特定操作的分支。

若唯一一次纠错请求发生有明确结束状态的 `ModelRequestFailure` 或 `InputTooLarge`，程序现在检查首次完整答复、首次校验、两次请求的关联、失败传输记录和文件摘要，然后用原有严格局部隔离重新检查首次答复。仅合格的记录进入 `partial` 结果；缺项、错误和冲突仍保持阻断。原始 `request_failure` 和具体失败调用单独保留，新的保留证据绑定输入和产物。初次请求失败、不完整答复、没有任何可用记录、状态未知、完整性错误、记录失败或用户中断都不能冒充可保留的完整审查。

系统已有的有限 JSON 规范化也必须从原始首次答复重新推导，并与保存的规范化凭证、校验摘要和候选逐一吻合；存在凭证时，它也纳入保留证据。独立复查发现了原始答复多一个右括号时的保留失败，该失败回执已保留，修复没有扩大规范化规则。

运行时契约仍完整交付。审查需要判断“当前表示错误时，系统是否已有正确的操作可选”；仅展示当前已使用的操作，会隐藏可用于纠错的其他受支持语义。因此测量使用了完整的当前 v12 运行时契约及其操作清单。

`review-render-measurement-02.json` 记录了只进行 JSON 读取和提示渲染的测量，没有执行历史候选校验、编译、后端、运行器或回放。16 份源文件、684 项义务和 2,540 个范围全部保留，源文尾部逐字节相同。纠错涉及 40 条已有记录和 231 个补齐位置。保留旧运行时契约时，完整交付为 1,039,522 字符；仅替换为完整当前 v12 运行时契约后，为 1,045,496 字符，包含原有 212 字符封装，比 1,048,576 上限少 3,080 字符。这个具体材料能够容纳，不代表任意大小的未来输入都能无损压到上限内；原有完整请求长度检查和有依据的局部保留仍不可省略。

阶段性离线结果不能相加：最新 `review-focused-05.xml` 45 项新测试通过，覆盖传递闭包、保留审查后生成和重新验证 DOE 契约材料、记录失败、规范化凭证与回放。独立契约仍可用、缺失契约仍不可用。`review-focused-03.xml` 92 项通过，包含之前的失败阶段策略及明确拒绝 v5/v6 的测试；`review-retention-doe-01.xml` 18 项通过。兼容测试曾有两条旧断言，分别针对显示键名和 v6 身份，已取得对应通过记录；另一组 95 项通过、1 条旧 guided-v16 身份断言失败，更新为当前 v17 后该模块 13 项全部通过。早期候选摘要与显示断言失败的 XML 也保留，未覆盖。以上不是一次全仓库验收；父任务负责完整 guided 修复链集成和最终验收。

当前审查身份为 `skillflow-document-source-review-fragment-v7`。七个正常阶段、两个 worker、一次结构纠错、一次共享修复、原有超时及传输重试预算均未由这次实现增加。
