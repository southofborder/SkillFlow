# 地址身份与有限运行时契约：离线说明

本记录只覆盖离线实现、合成回归和有限范围复核。没有执行 Skill、调用模型、重新分析历史运行，也不代表 GA4 已成功。历史运行材料保持原样。

现在用显式 `address_kind` 区分两件事：默认 `identified` 表示来源地址已知，即使内容未知；`unidentified` 表示地址关系本身确实未知。名字只作标识，不再通过 `symbolic:` 前缀决定别名。调用参数、异常值、工具返回值和成员值只要来源明确，就保留各自身份。真正未知的地址仍与同类位置保守别名，包含 CFG 隐式上下文槽；其写入仍是弱更新。

旧运行时文字已说明“值未知”和“地址未知”不同，但此前实现只检查名字前缀，未把区别落实到模式约束。新协议下，旧前缀声明必须明确选择地址策略；`unidentified` 必须同时给出具体原因和物理源文依据。程序验证字段和引用，源文审查判断理由是否成立，不能把有引用等同于语义正确。

同一地址判断用于解释器、强写入判定、活跃位置及 processing 缺口传播。Data 不可变身份和对象／集合类型保护保持严格。字段经过 flat、raw 和 compiled 三层完整保留。运行时契约 v12、profile v24 及父代理统一升级的下游身份明确区分新语义，不迁移或重新解释冻结旧产物。

运行时契约补入有限、封闭的支持操作清单，复用已有模式和解释器：18 行涵盖 14 个原子操作、call 以及 processing／for_each／cases 三种结构，同时列出全部 14 个结构化需求表达式操作符。内容包括输入输出类型、身份与别名、信息属性、副作用以及共用的失败范围和源文依据义务。测试将清单与真实模式判别集合逐项比较。紧凑清单为 5,553 字符，完整随契约提供；没有新增另一个执行器。

因此，需要穷尽的是系统有限的“支持词汇”，无法穷尽任意 Skill 的所有程序行为和外部工具语义。超出支持能力时仍应给出具体局部缺口，不能靠选择一个熟悉操作名虚构语义。

本代理最终受影响范围验证 `location-runtime-affected-final.xml` 为 256 通过、0 失败，并非全仓测试。涵盖来源独立性、原始读取保留、真实未知地址、弱写入、FIFO／LIFO、严格集合保护、证据约束、编译保留及契约清单。早期新测试夹具有 8 个不合法上下文获取拓扑问题，改为真实独立来源块后通过；另有 2 条旧版本常量断言，随已授权的新协议明确升级。早期失败凭据均保留，未放宽生产校验。

对局部执行失败实现的独立复核发现并由其负责人修复了两点：封闭集合布局错误需要精确的类型标记；已知为假的结果／输入条件不应消费不存在的可选值。当前实现保留未知引用和程序错误的失败边界，失败 IR 回滚后保留独立观察证据，并沿实际数据和控制关系传递缺口。控制缺口只在可证明的有限汇合点解除。本次检查范围内未再发现阻断问题，不作所有程序均正确的保证。

源文审查保留路径还发现一个通用问题：a001 的完整原答复经过既有“单个多余右括号”规范化后有效，但 a002 交付失败时，保留逻辑重新解析原始字符串，反而抛出第二次 JSON 错误。负责人现已按原规则重新推导规范化结果，核对规范化凭据及哈希，保留原始响应和原始请求失败，并对同一候选执行严格局部隔离。初次失败见 `review-retention-peer-first.xml`；原测试不改动，修复后 `review-retention-peer-final.xml` 通过，且验证合成零调用重放不改原始文件。

有限审查纠错保留完整源文、原始输入清单和材料身份；缺失槽来自当前程序清单，已有记录权限包含实际冲突闭包。未知、全局或歧义问题仍回退为完整答复。合并后继续完整严格验证，补入检查不等于接受检查。交付失败后的保留仅限绑定同一材料的完整旧答复，并继续使用原局部隔离规则；缺失／错误检查不会因此获准，无法定位的源文指控也不能为通过校验而静默删除。修复规范化问题后，本次有限复核未发现其他阻断项。
