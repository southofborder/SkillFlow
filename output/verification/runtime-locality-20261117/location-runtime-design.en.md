# Explicit address identity and finite runtime operation contracts

This is an offline implementation and bounded peer-review report. It does not execute a Skill, call a model, rerun a historical analysis, or claim a successful GA4 result. Previous run artifacts remain unchanged.

Unknown content no longer changes a source's address identity. A location has an explicit `address_kind`: `identified` by default, or `unidentified` when its address relation is genuinely unknown. Names are opaque identifiers. Caller arguments, exception values, call results and member values with known provenance keep their own identities even when their contents are unavailable. Explicitly unidentified locations still conservatively alias every location of the same kind, including implicit CFG context slots, and their writes remain weak.

The old runtime prose already distinguished unknown content from unknown addresses; the implementation's `symbolic:` prefix test did not enforce that distinction. The new schema removes that second, implicit naming language. A legacy prefixed declaration requires an explicit policy under the new profile. `unidentified` also requires a specific address reason and physical source evidence. Schema checks provenance shape and existing reference validation checks locations; source review must decide whether the claimed unknown address is justified. Evidence syntax alone is not semantic proof.

The shared address helper is used by interpreter aliases, strong-write classification, liveness and processing-gap locality. Ordinary immutable Data identity and strict object/collection guards are preserved. The location fields survive flat annotation, raw annotation and compiled profile generation. Runtime contract v12 and profile v24, together with the parent's downstream protocol updates, distinguish these semantics; frozen old artifacts are not migrated or reinterpreted.

The runtime contract now contains a compact, closed inventory of supported operations, generated from the existing vocabulary rather than adding an execution engine. Its 18 rows cover 14 atomic operations, the flat call form, and processing/for_each/cases structures. The inventory records input/output domains, identity and alias behavior, information properties and effects, plus shared failure/source-evidence obligations. All 14 structured demand-expression operators are named too. Tests compare these sets with the actual typed schemas. The compact inventory is 5,553 characters and remains part of the complete delivered contract. This exhausts the supported vocabulary, not arbitrary Skill programs or external tool semantics. Unsupported source behavior still needs an explicit located gap; a familiar operation name does not justify invented semantics.

The final owned affected-scope receipt is `location-runtime-affected-final.xml`: 256 passed, zero failed. It covers distinct source arguments and exceptions, retained original reads, explicit dynamic addresses, weak writes, same-kind alias limits, FIFO/LIFO, strict collection shape, source-evidence requirements, schema/compiler preservation, runtime identity and finite operation coverage. This is not a whole-repository test result. Earlier receipts remain: the first behavioral receipt contained eight errors in the newly authored fixture's context-acquisition topology, corrected by using real separate source blocks; the first compiler receipt had two obsolete profile/compiler-version assertions, updated under the explicit protocol change. Neither required weakening production validation.

The bounded review of the separate local-failure implementation found two issues that its owner fixed: explicit closed collection-layout errors needed a typed domain marker, and a concrete false input/result guard should not consume an unavailable optional payload. The current implementation preserves unknown reference/programming failures as fatal, rolls back failed IR mutations, retains detached failed-attempt observations, carries unavailable data/control through actual dependencies, and discharges branch control only at a proven finite reconvergence. No further blocker was found in the inspected paths. This is a scoped review, not a proof for every program.

The independent review of source-review correction found one additional defect: when the existing normalizer removes a single extra trailing object closer from a complete a001 response, a later ended a002 delivery failure reparsed the raw response and raised a second JSON error. The owner now rederives the unchanged normalization policy, checks the exact saved receipt and its validation hash, binds the normalization artifact, and isolates the normalized candidate while preserving the raw response and original request failure. `review-retention-peer-first.xml` preserves the observed failure; the unchanged peer regression passes in `review-retention-peer-final.xml` and verifies immutable zero-call synthetic replay.

Finite review correction retains the complete source, original input inventory and material identity. Missing slots come from the current program inventory; existing-record permissions include actual finding/check conflict closure. Unknown/global or ambiguous scope keeps the full-response fallback. The complete merged result is still strictly validated; insertion is not acceptance. The failure-retention path accepts only a complete prior envelope bound to an ended typed correction failure and the same material, then uses the ordinary local isolation rules. It does not make absent or invalid checks accepted, and unrepresentable source allegations cannot be silently removed. No remaining blocker was found in that bounded review after the normalization fix.
