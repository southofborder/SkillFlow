# `google-search` 组会讲稿

## 约一分钟

这个 Skill 从环境变量读取 `GOOGLE_API_KEY`，使用 Google Custom Search 完成查询。图左上是线上提取的任务要求 R6，要求通过环境变量提供凭据。中间蓝色绑定是演示里补上的 `R_search`，把保持有效搜索请求的需求落到调用的 `params.key` 上。

先看绿色箭头。语义标注把读取的密钥记作数据版本 `K`，并说明构造请求时 `params.key` 取这个版本。前向传播据此算出，Google 收到的这一个请求中，`key` 确实来自这个环境变量。

再看紫色虚线。需求从请求的 `params.key` 出发，反向进入构造操作。构造规则指出这个字段只取自密钥输入，于是需求继续回到 `K` 的读取处。这个推导只针对这一次请求的这个字段。

右下角是另一个边界。若 HTTP 错误中的响应 URL 仍带 `key`，脚本原样打印异常文本时也会输出它。报告失败可以保留状态码和原因，并省去诊断 URL 里的密钥。同一个值在请求和错误输出上，应当分别判断它对各次交付是否必要。
