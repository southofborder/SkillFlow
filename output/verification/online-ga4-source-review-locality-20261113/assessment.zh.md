# 源文审查局部隔离：本轮 GA4 验收结论

通用修复和离线验收已完成。本轮 GA4 实际验证了完整材料送审、严格局部隔离，以及有效问题进入既有修复流程。**整轮分析仍失败：修订 processing 达到 2700 秒进程总时限，尚未进入传播与 DOE。**唯一一次零调用回放匹配，实现全程未变；未再启动其他实验。

## 三条定位为何纠错后仍失败

旧 Schema 分别描述 `kind` 和 `actual`，却没有展示它们的对应关系和 missing-field 路径非空要求。首答把“缺字段”写成“缺整个参数”，运行时先报第一条规则；纠错改成输入槽路径 `[]` 后，才触发第二条隐藏规则。原来的记录替换格式也不能把无法建立 SDK 字段定位的问题改写到其他合法审查表。

源文确立了 `limit` 的请求字段，但没有确立 `filters` 和 `orderBy` 对应的 SDK 字段编码。修复不猜字段名、不把空路径放行：将类型关系和非空路径直接写入模型可见 Schema，提供实际操作输入／输出坐标说明，并在需要改换表达位置时使用原预算内的一次完整答复纠错。

旧流程在逐契约验证前整体解析失败，随后凭据消费和修复路由又只接受 complete，导致局部错误使整份材料失效。新流程逐记录严格核验，再核对完整 inventory、引用和冲突，保存不可变候选及隔离账本。需求计算、全部输入评估和删除影响检查共用定位到实际操作及请求／响应配对的阻碍；无效记录不会变成接受，也不会因为漏行而默认为“不需要”。

## 局部错误没有再使全体契约失效

首答有 5 条范围记录错误和 27 对跨记录冲突。一次纠错解决了这些问题，但新引入一条 scope ID 拼写错误。两次答复仍记为 structural_invalid，审查保持 partial，不能描述为完整审查通过。

这条错误只阻断 `ir_260` 配对的请求／响应两项义务，共 6 个范围。其余 **273 条可用检查、922 个范围**保留自身状态：880 accepted、36 rejected、6 unresolved。物理保留的 274 条检查中有一条配对阻断行，不能计入可用检查。14 条普通 finding 和 35 条契约派生 finding，共 **49 条有效问题**实际进入原有一轮共享修复。

纠错答复还给出了 `ir_110` 原生输入 0 的 `["limit"]` 定位，明确仅报告零值导致请求字段省略，未宣称已知道服务端零值输出行为。filters／orderBy 继续作为 Task 和映射限制保留。该调用的 receiver 关系仍被接口范围审查拒绝；结构合法定位不证明操作完整忠实或语义结论已完全成立，详见英文审查边界报告。

## 整轮失败、覆盖与用量

最终选择仍为初始 679 条 IR：633 条保留建模、2 条源文未建模、44 条校验隔离。13 个远程位置和 25 个保存位置均有表示，但没有传播可达证据。修订 Task 有 58 项要求，修订 CFG 有 770 条 IR；它们未形成完整修订 annotation 或复审，不能与初始选定材料混用。

修订 processing 在约 24 分半时发生服务端断流，随后出现连接重置和内部请求超时，最终于 11 月 14 日 00:26:00 达到 **2700.032 秒进程时限**。终止原因是进程总超时，不是已证实的建连超时；公开日志不足以把整段耗时归于某一种原因。外层没有重试。

控制器于 00:27:01 关闭。分析用时 13,603.668 秒，唯一回放 60.492 秒、结果匹配、新增调用为零。实际 15 次 native 启动＝7 次正常＋5 次结构纠错＋同一轮语义修复中的 3 次阶段调用，两个 worker 及原预算不变。14 次完成请求的已知公开用量为 **2,862,874 tokens**，失败请求用量未知；内部失败尝试的未报告用量也不能算零。

本轮没有最终契约凭据、传播结果、input assessments 或 DOE 结果，没有建立原始输入可删除结论。这不是“没有 DOE”，也不是完整分析成功。完整证据见 [英文报告](assessment.en.md)、[汇总](run-summary.json)和本目录各项审计。单次运行与回放授权已使用完毕，历史材料全部保留。
