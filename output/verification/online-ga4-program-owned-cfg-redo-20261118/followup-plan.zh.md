# 根据替代轮结果的后续方案

1. 给 processing 下游阶段加通用无损交付。让敏感性和 Task 对应共用已有的共享值与列式编码。编码输入保持为结构化的 processing 和 CFG 对象，附上源文位置映射、表达式引用、阶段所需的 Task 及修订材料。完整源文仍作为独立源文区交付，模型输出继续通过原有严格校验。以实际 1,107,518 字符输入做往返回归，逐项验证处理契约、字段、引用、缺口和 16 份源文。 [体积审计](sensitivity-size-audit.json)
2. 在可并行的下游阶段提交前，用与适配器一致的 Unicode 字符口径对最终交付完成本地预检。把超限的分区大小和校验位置写入结果，阻止已知不可完成的批次消耗并行请求。用本轮超限和一组正常并行的离线注入样例验证，保持七阶段、两个 worker、现有纠错和共享修订预算。 [请求审计](final-request-audit.json)
3. 为纠错回应保存逐槽位状态，区分提交、有效应用、缺项和拒绝。保留六个未填写的绑定路径及各自的验证错误；把程序可证明的引用改名与需要源文决定的 producer 绑定分开验收。缓存命中与初始化分支属于真实语义，不能用邻近变量补齐。 [纠错应用审计](processing-scope-audit.json)
4. 从已有公开事件生成主请求的类型化终止原因。将本地进程截止、TLS 断开、容量退避、HTTP 解码失败和提交前超限分别绑定到调用回执。离线覆盖「只有辅助模型目录超时」及真实主流失败，验证辅助日志不会误触发外层重试。现有样本已经覆盖一次进程截止和一次较小的纠错交付成功返回，无需用额外模型探针验证规则。 [首次实验](../online-ga4-program-owned-cfg-20261118/assessment.zh.md) · [替代轮请求审计](final-request-audit.json)
