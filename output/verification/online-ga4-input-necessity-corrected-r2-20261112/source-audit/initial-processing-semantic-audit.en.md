# Initial processing semantic audit

**Provisional:** this inspects the rejected initial candidate. The bounded correction and later source review may supersede it. No deletion or DOE conclusion is established.

The candidate contains 115 demand-transfer contracts and 26 tool contracts. Its output-rule histogram is descriptive only: scalar whole-output rules and deterministic operations are not errors merely for lacking subfield rules.

## Focused source-backed checks

- **PROC-SEM-01 — supported_relation — Consumer-specific settings fields preserve actual acquisitions.** The property, site, credential-creation, save and listing call-site computations contain exact field rules. ir_066 separates propertyId from resultsDir; its former input needs only GA4_PROPERTY_ID while the latter needs cwd and explicitly no environment fields. ir_076 deterministically selects propertyId and builds the wrapper. Actual env/cwd reads are retained, so semantic narrowing has not erased those forward acquisitions. Next check: Review the field relations and all uses before judging any slot/range deletable. This is candidate relation quality, not a selected or reviewed deletion result.
- **PROC-SEM-02 — specific_output_rule_gap_risk — Validation object has a whole rule but its consumers select valid.** Opaque validation producers ir_035/045/055 have only output={property:value}; immediate consumers ir_036/046/056 select valid and branch on it. If these required guards produce a field/truth demand, no exact rule for valid exists. Likewise ir_024 requests truth of three settings fields from ir_023, whose settings-object computation has only a whole-value rule. These are concrete producer-consumer mismatches, not a claim that every whole-value rule is erroneous. Next check: After selection/review, inspect the actual demanded selectors. Add/review exact relations through the authorized semantic process or retain localized output-contract gaps; do not repurpose the whole-output rule as a precise valid/field rule.
- **PROC-SEM-03 — scope_watchpoint — Selective metadata and inspection output rules.** ir_346/358 correctly exclude the other metadata collection for their whole wrapper output. Their contracts still lack exact output paths dimensions or metrics and finer entry fields; this matters only if such partial outputs are demanded. ir_415 similarly has only a whole base-projection rule. In contrast, ir_551 explicitly supplies an indexStatus output rule, and ir_553 uses deterministic selection/expression/build for status/verdict. The latter is a positive selective-consumer example. Next check: Check selected demand paths and preserve deterministic rules. Whole wrappers demanded as whole may use their existing rule; partial fields require corresponding rules. Do not infer remote response projection merely from local field exclusion.
- **PROC-SEM-04 — source_dependency_coverage_risk — Internal saves collapse wrapper and path dependencies.** Every one of the 25 save_result call-site records reduces to write(input0, saved). CFG category/operation/optional-extra inputs are not referenced by these processing records; save-time settings, clock, wrapper and path construction are not expanded there. The shared saved location refers to the public saver ir_077 input1 rather than each call-specific path. The standalone saveResult body does model its wrapper, but that alone does not supply all separate invocation dependencies. Next check: Demand and deletion assessment must not treat category/operation/extra as irrelevant merely because call-site processing omitted them. Check per-call wrapper/payload/path and how the authored saved-location gap applies to all 25 uses.
- **PROC-SEM-05 — interface_evidence_review_required — Several tool reasons establish actual arguments rather than independent necessity.** ir_171 and ir_273 include public query-interface references in addition to the call construction. By contrast, several constructors, realtime calls, metadata and inspection contracts cite only actual argument construction, with reasons such as Constructor arguments, Request only sends name, or Exact request. Such evidence establishes what was passed; the final source review must separately establish why each required range is necessary. The shared auth contract marks the entire two-scope list required for both service constructors without a separate per-service scope rationale. Next check: Check the semantic interface obligation, including field scopes and literal lists, rather than approving from operand presence. This audit does not claim every code-only reference is invalid; source semantics can establish an interface relation when the rationale actually explains it.
- **PROC-SEM-06 — conditional_necessity_concern — Type-conditioned save labels receive inconsistent precision.** ir_173 explicitly identifies a type-conditioned value-transfer gap for retaining a string or undefined. ir_248 performs the analogous string-or-custom operation but marks the whole input value required, even while saying nonstring object fields are not copied. On the DateRange-object branch, startDate/endDate do not determine custom; type does. A whole-value sufficient rule does not by itself demonstrate field necessity on that branch. Next check: Review conditional field scope using supported deterministic structure or a justified local gap. Do not turn the object branch into a whole-dateRange requirement merely to avoid uncertainty.
- **PROC-SEM-07 — mixed_gap_quality — Concrete limits versus runtime-unknown explanations.** The dynamic-slice gap names the missing end-index-dependent input selector and affected values; the label gap names the type-conditioned relation. Both are specific expressiveness claims that review must verify. The cd-status gap instead requests the concrete invocation path, resolved access outcome and cd result because directory access can fail. Unknown runtime outcomes alone do not explain why static input necessity cannot be decided, so this reason needs stronger relation-level justification. Next check: Do not reject all gaps categorically or accept detailed wording automatically. Verify the claimed representational limits and keep each gap local; do not require execution merely to decide static necessity.
- **PROC-SEM-08 — source_error_review_pending — Ignored filters and ordering remain source errors to check at review.** Processing preserves the actual reads of filters/orderBy and does not invent their transmission. Their source-declared behavior remains missing. Typed source_input_findings belong to the later source-review material, which is not available here; absence from this processing fragment is not itself a schema or semantic error. Next check: Verify final review reports the missing required behavior/input at the actual request boundary and preserves both the actual read fact and task obligation. A no-use finding alone must not be presented as successful filtered/ordered reporting.
