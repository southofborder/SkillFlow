Implemented `src/skillflow/document_guided/fragment_wire.py` and integrated it in `fragments.py` (fragment identity v6). The optional self-contained response envelope is `skillflow-processing-json-v1`, with exact shared JSON values, explicit references, literal marker escaping and a complete logical payload. Plain complete processing responses remain accepted. There are no templates, substituted parameters, prior-artifact references or implicit missing-record reuse.

Before allocating expanded containers, the codec measures expanded character count, node count and depth. It validates every definition, including unused ones, and rejects undefined references, cycles, excessive reference indirection, nonfinite numbers, duplicate keys, malformed markers and expansion limits. Every occurrence gets independently allocated containers. Limits are representation guards, not model time/token/repair budget changes.

Existing schema, complete current-IR coverage, evidence, semantic contracts and actual-operation validators run against the expanded logical fragment. Processing-only parser, correction selection, correction merge and salvage use the same expansion. Representation failures require structural correction or failure; they cannot turn into semantic facts or silently retained local records. Full correction uses the expanded candidate both in its fallback and the joint packed correction context. Raw provider response artifacts remain unchanged; accepted `value.json` and correction `merged-candidate.json` bind the logical result. No `annotation_wire.py` edit was needed: assembly already consumes the returned logical processing fragment and its existing compiled mapping.
