# Backend r3：GA4 与三个小 Skill 线上验证

**这一轮已经结束，但 GA4 仍未走通。001 和 010 完成了生成图的传播；013 只完成部分传播。三个小 Skill 都保存了 DOE 产物，但没有一个形成完整、可行动的 DOE 结论。** 有用的结果主要是实际数据来源、字段、接收方和响应配对证据，以及具体的前端阻断定位。

本次是四个全新运行，依次为 GA4、001 conditional-notification、010 catalog-query、013 source-fetch-with-fallback。均使用 `gpt-6.1-sol / high / openai`、最多两个 worker、正常七调用及原有纠正／修复预算。GA4 使用完整 16 文件源包；四例源包与上一轮逐字相同，全部材料重新生成。四个控制器及各自唯一一次零调用重放均已关闭，重放全部匹配。运行期间实现、提示词与源包保持不变。

## 剩余问题具体在哪一层

### GA4：接口默认值处理缺陷，尚未测试到新后端

processing 的 22 个 cases 候选中，3 个 `local_error / throw` 候选省略了允许省略的 `segments`。类型默认值是空列表，提示词也写为可选；程序使用 `exclude_unset=True` 导出后又直接读 `case['segments']`，触发 `KeyError`。第一次不安全访问在冻结 `annotation_wire.py:501`，后续还有同类访问。

这属于程序接口实现错误，不是模型遗漏必填字段，也不是循环状态爆炸。相关文件与暂停的 v9 版本逐字一致，缺陷早于 r3。processing 的纠正额度并未耗尽；该异常走工程错误分支，没有进入结构纠正。整份 processing 答案的后续合法性尚未验证，不能从这个直接原因推断修复后一定全部成功。原答、失败回执和匹配的失败重放均保留。

### 001：传播配对正确，任务限制和审查归属仍有缺口

实际 notify 请求只构造 recipient/body，分别来自同一成员的 recipient 和原始 summary；没有添加 access_token 字段，也没有虚构 summary 重写。计数写入也有实际版本关系，9 个抽象候选不表示实际处理了 9 条记录。

但是 R6 把禁止发送 token 留在文字缺口里，误称没有词法 `for_each` 就无法表达。现有接口已有 task-scope `forbid_information`，可以指向原始集合的 `each/access_token`。末尾审查发现了遗漏，却把 owner 归为 sensitivity；禁止交付约束属于任务对应／realizations。这个接口可表达性判断基于静态类型核查，没有编译替代声明。

源文还确实没有定义“processed records”应按检查、选中还是通知计数，也未明确满足资格条件是否必选。这些歧义与遗漏的限制一起使需求不完整。**问题已从主流程传播截断转到需求／限制表达和未决范围处理；仍不能把全部 38 条未决说成无 DOE。**

### 010：关键值关系已贯通，约束定位仍易写错

四种可选参数组合全部保留，缺省字段不会变成 null。每个请求候选与自己的响应配对，保存的是该响应的 `total`，返回的是同一响应完整 `items`。普通保存采用公开约定的 replace 默认，并未把该默认说成源文明示。

任务对应第一次纠正先处理 R8 缺 gap；随后才暴露 R4/R6 条件定位错误：模型引用 compute 的 output，而已规范化的 presence 表达式位于 operation self。对应 realization 被隔离为验证缺口，独立的有效操作需求仍保存。最终 13 个适用 seed 目标在 9 条要求上有推导，保存边界有实际 total 的精确值需求；但删除禁止、返回接收方等要求仍未完全建立。没有敏感声明本身不是错误。

### 013：不必要的公共写入输出再次造成 CFG／processing 不对齐

四个状态 append IR 声明了“追加后的整份文件”公共输出，而这些输出没有任何 CFG 消费者；源码只要求追加状态。现有 write/append 已能保存状态变化，但没有一个 local result 可绑定到这些额外公共输出。processing 为避免把状态文本冒充整份文件，最终把四条写入全标成未建模，连带阻断四个 return。

因此，这次并不是后端缺少 append 能力。最小的表示方向是保留 append 副作用、去掉源码与消费者都不需要的公共写入结果；没有必要增加调用栈、文件重读或假 compute。这个方向没有在本轮替换候选执行。源文审查返回空 findings，错过了应归 CFG 的修复机会。R3 另有规范化表达式引用错误。

已经计算的部分仍有价值：首次与重试 fast 响应身份不同；两个 fast 请求使用相应 source_id 与 FAST_KEY，archive 只收到原始 source_id。实际 append、return 和全局约束没有完成，不能据此宣布完整凭据禁止要求成立。

## 交付与下一步优先项

1. GA4 的可选字段默认值要由程序一致落实；不应花模型纠正调用补一个可省略的空数组。
2. CFG 的公共输出应对应真实后续用值；013 的 append 应保持已有副作用语义，避免无用的整文件输出义务。
3. 任务对应使用正确的规范化表达式目标；源文审查对这些具体缺口应识别正确归属，不能把 gap 或空 findings 当作问题解决。

这些是本次结果支持的后续优先方向，本轮没有修改实现、替换答案或追加采样。旧暂停进程和旧 heartbeat 保持暂停。
