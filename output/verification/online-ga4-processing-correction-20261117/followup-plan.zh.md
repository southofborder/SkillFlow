# 基于本轮结果的后续修改方案（未实施）

本轮没有发生原生进程超时。主要阻碍是独立诊断被串行门控隐藏、失败阶段目标约定
不一致，以及缺少有效 CFG 时无法进入共享修订。下一轮修改应针对这三个通用边界，
继续保留七次正常请求、两个 worker、每阶段一次纠错和一次共享修订，不增加逐 IR 调用、
源文截断、契约省略、额外探针或历史重放。

1. **在唯一纠错前汇总安全可执行的独立 CFG 检查。**

   将严格解析／可用形状检查与诊断收集区分开。对身份明确、结构足以编译的原始候选，
   收集 wire preflight 和编译器诊断后，再决定是否接受及纠错范围。不能先在 dispatch
   检查处退出，使两个已经存在的循环错误到第二次验证才出现。不得虚构缺失输入、猜测
   语义默认值或把不完整投影作为 accepted CFG；不能安全检查的范围必须记录具体阻碍。

   保留原始诊断、顺序／身份映射、原始候选摘要和完整源文。若根级错误同时包含分支输入
   与端点问题，当前“仅端点级联”的完整归属证明不能冒用：要么保留整份纠错回退，要么
   为每类实际问题分别增加类型明确的归属，全部验证后才授予依赖范围权限。不能删去根级
   错误来伪装局部性。权限仍由实际 SCC、生产者、前驱及保持不变的边界计算，合并后整图
   重验。需允许修改循环的真实 skip／keep carry 生产位置，不只循环头。

   离线验收应在独立合成候选中同时放入缺失分支输入、两处循环自引用及真正缺失端点：
   初次诊断完整；一次纠错能修复前几项；真实缺失端点和无法证明的混合根级问题仍拒绝
   局部放行。再覆盖旧候选、归属错位、范围外修改及全部原始诊断保留。

2. **用同一份明确政策生成失败阶段目标、提示和校验。**

   本轮提示宣称实际失败阶段可用 `stage:<owner>`，但索引只为 annotation 的三个 owner
   创建阶段目标。应从实际保存的失败材料生成允许的阶段条目，明确 runner 阶段名称与
   finding domain 的对应关系，并绑定 source、失败答复／诊断及阶段身份。只接受真实
   失败材料支持的目标，不能新增一个无条件接受任意 `stage:*` 的正则规则，也不能猜测别名。

   提示展示与 validator 必须使用同一个目标库存。若当前政策根本无法表达某条真实发现，
   明确指出材料／表示缺口，并选择既有纠错形式中能够表达的路径；不能要求模型删除发现、
   指向无关 Task 或用空 replacements 假装修正。继续保留独立有效发现及原始被隔离记录。

   离线验收覆盖 Task／flow／graph／annotation 阶段的真实失败与未失败情况、未知目标、
   假冒阶段、目标材料过期、修正后可以定位的发现，以及无法表达时的明确隔离。保留本轮
   “5 条有效 Task＋1 条无有效定位的 CFG”形状作为独立合成回归，不能重放本轮。

3. **把缺少有效 CFG 的恢复作为显式修订政策，独立实现和验证。**

   仅修正目标名字不能改变 `runner.py:566-572` 的入口条件。建议在 source 与所需上游
   材料仍完整时，允许既有一次共享修订选择失败的 CFG 阶段，从完整源文、有效 flow、
   原始失败候选及诊断重建；失败候选只是修订证据，不能先变成 accepted CFG。
   新 CFG 通过全部严格检查后，才沿依赖闭包生成 processing、映射、敏感性和复审。
   Task 与 processing 的隔离职责保持不变，独立有效 Task 发现按同一轮既有修订政策处理。

   若不采用此恢复政策，就应明确承认“CFG 一次纠错耗尽即没有共享恢复入口”，而不是把
   未用的共享预算描述为本可自动执行。无论选哪种，终态、审查范围和预算记录必须一致。
   验收覆盖失败 CFG 恢复成功／再次失败、上游材料缺失、一次共享预算耗尽、身份绑定、
   依赖片段重建及零调用回放。不得悄悄追加第二次结构纠错或第二轮共享修订。

这些改动若实施，应升级受影响的 guided／step／fragment、source-review 及修订决策
身份，保留旧产物和本轮失败记录。离线验证仍需注入答复完成整条流程，并记录初始失败
和修正回执。当前运行与其唯一回放已关闭；本文件没有实施以上修改，也没有授权新实验。
未来线上验证应使用新的明确授权和新目录，不继续或改写本轮。
