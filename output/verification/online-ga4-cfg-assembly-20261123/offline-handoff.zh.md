# 从失败的 GA4 草图到 processing 的离线验收

把上轮保存的正常 Task、flow 和 CFG 原答注入一个临时运行。沿用完整的 16 文件源文，使用真实 CFG 编译器、本机 Lean 校验器和正常的 processing 请求入口。唯一一次 CFG 纠错使用人工给定的六项语义答复。processing 客户端收到并核对实际输入后结束测试，真实模型调用为零。[验收收据](saved-draft-acceptance.json)

| 检查位置 | 验收结果 |
|---|---|
| 上轮原答 | 117 个块、223 个普通操作。25 个纯控制块直接归类，18 个混合块自动拆分。 |
| 剩余六个块 | 同一次纠错授权了六个块。四个接收操作分别保留调用参数和先前选定的结果；工作流在原调用和文件读取位置分别获取上下文；查询块把排序约束绑定到实际查询。 |
| 原始观测与控制流 | 输入版本、字段、源码位置、动作顺序、出口和 165 条控制边逐项核对。39 次原始上下文读取均保留。程序拆块生成 18 个无条件跳转。 |
| 编译与 Lean | 143 个物理块、372 条 IR。Lean 对 2,666 个单元及 341 条派生关联完成往返校验，证书与传给 processing 的图摘要一致。 |
| 正常 processing 入口 | 实际收到 372 个必填 IR 标识、完整源文、flow 和运行时契约；解码后的 CFG 与已选图逐字段相符。包含适配器前缀的提交体为 481,872 个字符。 |

程序生成的 18 个跳转均无操作数、无输出和源码副作用。纠错后有 229 个普通操作。比原答多出的六项是四处已选结果的本地绑定，以及工作流中两次原始上下文读取的显式表达。验收将每个受修订块的调用、接收、写入、读取、交付和上下文键按执行次序与原答比对。这个测试覆盖 CFG 到 processing 的交接，传播与字段删除的线上表现由新实验度量。

在已安装本项目和本机 Lean 校验器的环境运行跨机回归：

```shell
python -m pytest -q tests/document_guided/test_cfg_assembly_handoff.py
```

本机有完整的上轮答复时，可运行同一交接检查并在标准输出读取结果：

```shell
python -B output/verification/online-ga4-cfg-assembly-20261123/verify_saved_draft.py
```

小型回归自带输入，独立于历史运行目录；完整样例从指定历史目录读取 Task、flow、CFG 原答和源文，并记录其摘要。两项验收都在临时目录构图，不修改旧运行材料。
