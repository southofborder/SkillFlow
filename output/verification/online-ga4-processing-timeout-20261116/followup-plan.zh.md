# 根据本轮 GA4 结果提出的后续修改方案

本文件是方案，不是已实施或再次上线的结果。本轮在初始 processing 纠错阶段失败，尚未进入源文审查或语义修订。保持七次正常请求、两个 worker、每阶段一次结构纠错、一次共享语义修订、2700 秒时限和现有传输预算；完整源文、全部契约、严格校验及 Task v5 隔离继续作为约束。

1. **先补齐输出协议说明与代码的缺口。** 将 codec 接受的完整语法集中定义，并供初始 processing、结构纠错、完整回退、局部替换和语义修订共同引用。明确根键及每个 JSON 成员只能出现一次；只允许一个 `shared_values`；名称必须匹配 `v(?:0|[1-9][0-9]*)`；引用、字面量转义、无环性、未使用定义校验及完整展开后的 IR/契约覆盖都要说明。现有提示只展示 `v0`，没有把命名规则说明白，这是本轮暴露的实现缺口。禁止用宽松解析、自动改名或后一张表覆盖前一张表来“修好”答复。

2. **让模型一次写出完整共享表。** 建议给出 `format → payload → shared_values` 的完整多值示例：先写完整 payload 及前向引用，再写唯一的最终定义表。当前 codec 已不要求根键顺序，不需要更改接受语义。示例覆盖嵌套引用和字面量转义；明示补充定义必须纳入同一张表，不得追加第二张表。它针对本轮“表—payload—第二张表”的事实，是减少表示错误的候选措施，尚不能保证成功率或耗时改善。

3. **让现有一次纠错获得完整的确定性格式诊断。** 严格解析仍立即拒绝重复键；另以有界、只读的原始对象对扫描补充可独立证明的重复表位置、非法标识符和引用形式问题。使用原回答摘要、字符位置及重复出现序号，不能把重复键伪装成唯一 JSON Pointer。扫描不选择表、不合并、不生成可用候选、不运行歧义对象的语义校验，也不触发局部隔离。只在同一纠错请求中提供精确计数、有限例子和覆盖限制，原回答及源文仍完整提供。若语法损坏或扫描边界不足，保持严格拒绝与完整替换。这样可避免一次纠错只看到最外层错误，修完后才发现提示未交代的下一条规则。

4. **另行修复 CFG 诊断的因果定位和纠错范围。** 本轮两个循环头的读前定义错误，使两个块无法进入规范图，进而产生根级缺边端点诊断，最终要求重写整张图。后续应保留全部原始诊断，同时标记“主错误—派生错误”的有类型因果关系，按真正的生产者、前驱和循环携带关系构造修复闭包。实际纠错修改了两个头块和两个主体块；仅两个诊断根的 1250 字符不是充分修复范围，也不是可承诺的节省量。保留完整只读上下文、合并后整图严格校验；需要新拓扑、无法解释的全局错误或闭包不充分时仍完整替换。不得压掉根级错误后直接通过校验。

5. **再评估纯变换的表示粒度，保护实际调用边界。** 本轮纯 `.filter/.map` 的显式循环增加了版本携带和纠错负担。可在已有 IR 能力内，为无副作用的局部集合变换提供通用粒度指导；获取、保存、远程请求和真正的逐成员副作用仍独立保留。需要同时保留真实读取、数量、存在性、条件、成员配对及输出字段的需求关系，不能为缩小图而删除语义。本项优先级低于协议与纠错问题，也不应预设所有循环都可折叠。

离线验收应增加能检出这次真实缺口的用例，而不只是成功 fixture：所有 processing 请求路径都包含同一明确语法；相同、互补、冲突的重复表均拒绝；描述性名称及前导零名称拒绝；payload 在前的合法前向引用、嵌套引用和转义可精确展开；坏候选完整进入纠错；原始对象对诊断不会产生可用 candidate 或放宽接受条件。图诊断用本轮“两个主错误加派生缺端点”的结构做独立回归，并覆盖真实的全局错误及不充分闭包，保证必须完整替换时不会误判为局部。继续做注入答复的七请求、双 worker、完整校验、成功/失败回放和预算不变检查。

网络方面，本轮能证明三次内部采样重试和最终总时限，不能证明 900 秒闲置超时、纯生成耗时或失败用量。保留公开事件观测、总时限及不额外重试超时的策略。已有原 bundle 的语义修订失败仍按本轮已实现的范围保留机制处理；初始 processing 没有有效 bundle 时必须停下，不能制造字段删除或 DOE 结论。后续评估分别衡量输入字符、有效输出率、纠错范围、网络事件和可见用量，不把一次重跑当作受控速度对照。

具体新证据见 [英文评估](assessment.en.md)、[对象对诊断设计](processing-pair-diagnostic-followup.en.md) 和 [处理答复审计](processing-initial-response-audit.en.md)。本轮唯一的新运行和回放已经结束；上述方案没有触发第二轮调用。
