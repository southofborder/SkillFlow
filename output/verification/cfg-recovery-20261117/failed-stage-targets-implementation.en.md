# Explicit failed-stage source-review targets

The failed-stage target contract now has one program-owned policy used by material preparation, prompt display, finding validation and correction diagnostics. `stage:task` belongs to Task; `stage:flow` and `stage:graph` belong to CFG. Processing, task-correspondence and sensitivity retain their exact annotation-stage IDs and owners. There is no `stage:cfg` alias, spelling normalization or acceptance by prefix.

Only an actual structural or semantic failure can create a stage target. The three upstream stages require an original-stage evidence envelope with matching stage, failure status, source-table hash and complete material hash. The root-owned material collector verifies the immutable request/response/validation/owner references. The review target binds the complete supplied failure and source; it does not open artifacts or promote a failed candidate into an accepted CFG or Task. Existing annotation failure fixtures remain compatible through complete failure/source bindings, while any supplied evidence envelope is checked. Missing, skipped, request-failed, partial and unknown stage names produce explicit unavailable reasons.

The compact/shared prompt carries every permitted stage ID, domain and owner in `failed_stage_targets.targets`. A key in `stage_failures` alone grants no target. Failed-stage findings require original-source references and retain the existing Task objection and annotation ownership rules. Ordinary finding validation rederives only the referenced failure target, so unrelated valid records remain usable when a particular binding is stale.

The correction diagnostic distinguishes an incorrect locator in a representable domain from an allegation for which no actual same-domain target exists. An incorrect locator can be explicitly corrected to a listed ID. For an unrepresentable allegation, the existing correction strategy rejects deletion or an unrelated-domain replacement, retains the original invalid record and allows strict local isolation to retain its valid siblings. This adds no model request, repair round, response section or validator exception. A failed-stage ID has no inferred slash-parent.

The current source-review fragment identity is `skillflow-document-source-review-fragment-v6`; downstream input-contract acceptance requires that same version. The target and failure-material identities are `skillflow-failed-stage-review-targets-v1` and `skillflow-failed-stage-material-v1`. The legacy source-review identity is unchanged. Previous artifacts retain their original identities, and a new test explicitly rejects a v5 response at current contract acceptance.

The previous failure was a latent program contract gap, not evidence that the last processing change broke review locality. The preserved run's source-review file hashes to `659ed2f4330ff3c6c50841e5d685c5ba096f492ec6fd53308b7a55f987d72db4`, exactly matching the pre-change baseline. Its prompt advertised an actual failed-stage form, but target construction intersected failures only with the three annotation owners. Five Task findings were still retained and only the CFG record was quarantined. Separately, the old shared-repair gate required an accepted graph, so fixing the target name alone could not have enabled recovery. The root-owned recovery change addresses that independent gate.
