# Independent recovery and failed-material provenance review

Reviewed the new failed-stage material, shared-repair admission, missing-CFG runner path and fatal-frontier reconstruction. All execution below used fresh synthetic fixtures; no historical analysis/model/Skill run or historical replay was used.

Three actionable findings were reported and resolved before this focused receipt:

1. Fatal replay previously classified every structural/semantic stage exception as `structural_failure`, despite checking the actual receipt status first. Root corrected the status mapping.
2. If a revision Task request failed before the revision graph owner was prepared, the fatal frontier did not verify `audit/failed-stages/graph.json` or `audit/shared-repair-decision.json`. Fresh tests demonstrated that deleting or changing either file escaped replay rejection. Root added bound audit inventory and independent failure/admission reconstruction.
3. `capture_failed_stage` allowed an absent completed transport receipt because its artifact inventory treated transport as optional. A fresh direct-capture regression demonstrated that this produced apparently bound material after transport deletion. The capture helper now verifies the complete provenance before constructing evidence.

The capture API remains unchanged. It checks the sealed guided/source/stage manifests, exact frozen source files, stage kind/configuration, physical source owner and actual phase dependencies. Task preparation remains source-only. It checks the original chain protocol, contiguous call order, existing one-correction limit and result-to-chain binding by constructing a read-only ResponseChain without running its validator. Every attempt requires an intact completed transport, request identity, exact call/prompt/response, predecessor hashes and recorded normalization/merged-candidate hashes. SavedResponseClient is used solely as an immutable-record reader; no client is created and no answer is semantically revalidated during capture.

All per-attempt validation diagnostics remain in the material, along with their digests and artifact references. This retains earlier CFG errors when a later correction is malformed. Admission rejects malformed or rehashed inconsistent envelopes, mismatched terminal validation, incomplete references, invalid raw/candidate hashes, and statuses other than the actual two-attempt structural failure. Failed candidates remain explicitly `accepted:false` and cannot become CFG or annotation values.

Final focused receipt: `cfg-recovery-provenance-final.xml`, **78/78 passed**: 18 independent peer cases, six full recovery integration cases, and 54 admission cases. The integration cases exercise missing CFG → source review → the existing shared graph rebuild → processing/mapping/sensitivity → re-review → propagation/DOE → zero-call replay. The independent peer cases exercise Task failure before any revision graph owner, graph failure after observed Task completion, and graph failure before Task completion. They also reject missing/changed failure and decision artifacts, response/merged/validation/request/transport tampering, wrong physical source/dependency owners, altered source text, wrong stage kind, rebound call order and a rehashed detached transport response.

Earlier receipts remain preserved: `cfg-recovery-peer-01.xml` had three passes/four audit-binding failures; `cfg-recovery-peer-02.xml` had seven passes/five failures including missing transport; `cfg-recovery-peer-03.xml` passed its then-current twelve cases. These are focused regressions, not a claim of one all-green whole-repository execution. Production edits are stable pending root's final affected-scope acceptance and freeze.
