# Shared-repair admission and failure-target peer review

The current runner admits missing-CFG recovery only when the source-only Task and flow are accepted, the required graph has a source-bound terminal structural rejection, and the normal source review completed or retained valid local records. Semantic capability failures, request failures, skipped stages, missing prerequisites, stale source/material bindings and unavailable reviews do not open this path. An empty completed review does not invent a semantic finding: the rejected required CFG itself is the recorded reason to spend the existing shared round. The decision names the source, review and failure hashes and retains the one-round budget.

The original-bundle path still uses validated source-review findings. When a complete original annotation exists, request failure during repair retains its original Task, graph, annotation and review together. When none exists, a repair request failure remains fatal; the runner does not synthesize an original bundle. A new bundle reaches backend selection only after assembly. The two-worker scheduler and one structural correction per stage remain unchanged.

Failed-stage review targets name failure evidence rather than accepted values. The exact stage/domain policy and correction guard are consistent with admission: semantic failures can be source-reviewed without being eligible for missing-CFG structural recovery. A correction cannot delete an allegation merely because its domain has no honest target, or move it to unrelated Task content. Strict terminal isolation preserves the invalid record and independently validated siblings.

The fatal-frontier path binds the failure-material inventory and repair-admission receipt. Its zero-call verification reconstructs observed failure material, validates the original review, recomputes admission and checks the selected stage dependencies. An aborted sibling is not retroactively counted as an observed review failure. The new revision graph binds the exact rejected-original material as a dependency. This review was static; no historical frontier or model request was executed.

One targeted unit counterexample exposed a conservative-check gap: a rehashed envelope could carry a terminal attempt validation inconsistent with its top-level terminal validation. The material owner fixed this by preserving every attempt's complete validation, binding its digest, validating attempt shapes/statuses and requiring exact terminal consistency. The check also verifies response/candidate hashes and rejects malformed evidence without filesystem calls. Complete original diagnostics remain available when a later correction is malformed. No historical run is claimed to have contained this synthetic malformed envelope.

The final focused receipt `shared-repair-admission-targets-final.xml` passes 105 cases: 54 admission cases plus 51 target/correction cases. It covers missing Task/flow, nonstructural failure states, unavailable review, stale/malformed bindings, mismatched terminal evidence, locally retained Task findings, ordinary original-bundle behavior and exact target correction/isolation. These are overlapping scoped tests, not final aggregate or whole-repository acceptance.

Earlier receipts remain unchanged: `shared-repair-admission-first.xml` passed 43 cases before the added malformed scenarios; `shared-repair-admission-malformed-first.xml` recorded 53 failures during concurrent changes to the decision payload and evidence shape; `shared-repair-admission-malformed-second.xml` recorded 52 passes and the terminal-consistency failure. The final receipt is the passing replacement for those cases. The accompanying [JSON record](shared-repair-admission-peer.json) hashes each receipt and the reviewed implementation. No production file was edited by this peer-review follow-up.
