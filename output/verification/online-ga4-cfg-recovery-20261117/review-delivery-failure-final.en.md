# Closed-run review delivery failure and unused shared repair

This report concerns the closed original run `document-guided-ga4-cfg-recovery-high-20261117-135205`. The newly authorized processing-onward descendant is separate. This audit only reads saved artifacts and frozen code; it does not implement a fix or launch anything.

The failure was the adapter's character limit before the correction request started, not a network or generation timeout. The first review prompt was 883,026 characters before the 212-character adapter envelope. It returned an answer. The correction prompt was 1,055,579 characters, or **1,055,791 delivered**, exceeding the 1,048,576 limit by **7,215**. No native process or second review response exists for that request. These facts are recorded in `review/calls/review/a002/call.json` and `review/result.json`.

Both prompts preserved the complete 16-file source. Their 180,842-character source suffixes are identical. Independent expansion of the saved display shows that every base logical section is also identical across the two prompts. The displayed Task and annotation match the saved review inputs, apart from display-only origin metadata. The inventory contains **451 contracts/obligations: 106 compute and 345 tool**, covering **1,738 scopes**. Every obligation and scope ID remains present. Thus 106 counts only compute contracts, not the whole review inventory. The correction also includes the complete first answer and all 18 grouped diagnostics.

The first answer authored 17 findings—two Task, six CFG and nine annotation—and 451 checks, of which it labeled 403 accepted and 48 rejected. Those labels are not accepted review results. The saved validation has 15 malformed scope-check records and 34 finding/acceptance conflicts, grouped into three conflict diagnostics. One concrete malformed group combines a `rule` and an input `remainder` while assigning `affected_scope_ids` to the entire group. The validator permits such affected links only from wide rule/interface/output scopes; the input remainder cannot inherit the same link. The current error message names only the record, so a more exact subject/target diagnostic would help correction without weakening the rule.

Any `input_contract_review_conflict` currently selects whole-review correction (`fragments.py:659–664`), because the finding or the implicated check may need changing. Exact shared-value and column-table packing already ran. Adding the whole prior review candidate and correction context increased the core prompt by 172,553 characters. This is a remaining complete-correction size case, not omitted source or disabled compression.

The request-failure handler sets `review=null`. Strict record isolation currently runs after structural-correction exhaustion, but not when a later correction request fails to deliver (`source_review.py:733–763`). Consequently no retained validated findings were exposed to shared repair. `audit/shared-repair-decision.json` records `eligible=false` and the explicit unavailable-review barrier. The missing-CFG recovery path does not apply: Task, CFG and annotation were accepted, and there is no graph failure material. The original annotation continued to partial backend/DOE analysis; no shared repair was used. This audit does not calculate how many first-answer records could have survived isolation.

Bounded general follow-ups, proposed only:

1. Extend existing-record correction to a proven conflict closure containing each malformed check, conflicting finding and paired check. Keep all original source, annotation and contract inventory; reuse untouched review records with exact bindings and validate the complete merged response. Unexplained cross-section defects still require whole replacement. Preflight the final delivery including its adapter envelope.
2. On correction delivery failure, consider retaining independently valid records from the prior immutable returned answer through the existing strict isolation mechanism. Preserve every conflict/barrier and the delivery failure separately. No-answer cases remain unavailable; only validated records can enter the existing shared round.
3. Give scope errors exact group/subject/target IDs and kinds, and add complete-delivery regressions for these conflict shapes. Do not truncate source, omit contracts, auto-delete findings, raise budgets or assume that shaving this one 7,215-character excess solves future cases.
