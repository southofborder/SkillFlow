# 基于已关闭父运行的后续方案：仅建议

本文件只提出通用改进，不修改代码、不执行模型，不追补父运行结论。父运行已经关闭；用户新授权的 processing-onward 运行另行记录，使用保留的 Task、flow、CFG 和当前实现。新运行与下面尚未实施的代码方案必须分开陈述。

## 1. 优先解决完整审查纠错超限

本次首答审查有 15 个错误 scope 记录，以及 34 处检查/finding 冲突。现有任一冲突都会请求整份审查替换，完整首答和全部诊断使核心提示增加 172,553 字符；共享压缩后交付仍为 1,055,791 字符，超过上限 7,215。仅针对 GA4 再省几千字符，不能保证后续规模。

建议把现有局部替换扩展为**有证明的冲突闭包**：显式列出错误检查、相冲突的 finding、配对检查及相互引用范围，并把原始候选、全部源文、完整 Task/CFG/annotation 与契约清单绑定。只允许替换闭包内已有记录，闭包外逐字保留，合并后完整校验。无法解释的全局错误、缺失所有权或跨范围影响仍回退完整替换，不猜测正确检查、不自动删除异议。

同时在最终适配器封装后做准确大小预检，报告核心字符、封装字符和超限差额。仍保持七个正常语义阶段、两个 worker、单次结构纠错和原共享修复预算，不分拆增加模型请求、不截断源文或候选、不遗漏契约。

离线验收应包含这次混合 scope 主体错误、多 finding/检查冲突、配对影响闭包、不相干记录不变、过期候选哈希、错误引用、全局回退，以及完整封装后的规模边界。目标是通用完整性和纠错范围正确，不是拟合这次字符数。

## 2. 请求失败时保留前次答复中独立有效的审查记录

当前仅在结构纠错耗尽后局部隔离；若纠错请求超限或确定结束的交付失败，则 review 直接为空，即使前次答复已经存在。本次因此没有任何已接受契约检查，已有共享修复无法使用。

建议在严格限定的“已有完整前次答复、后续请求确定失败”情况下，复用现有严格隔离机制。必须保持源文、CFG、annotation、候选与 review 身份一致，保留全部冲突、隔离范围及传输失败。只有独立通过结构和关联校验的记录可以作为局部审查材料；不能把未验证的 403 个“accepted”作者标签直接当成通过。没有答复、来源不完整、身份不符、完整性错误及用户中止不能借此继续。

仍沿现有共享修复准入规则处理可用 findings，不额外增加轮次。未完成的范围必须保留具体阻碍；不能把无有效 findings 当作整份审查通过。应覆盖局部失败不扩大、成对范围仍隔离、修订后旧审查不可复用、无答复继续拒绝等回归。

## 3. 让 scope 诊断精确指出主体、目标和类型

本次错误组把 rule 与 remainder 共用 affected_scope_ids。目标 ID 真实存在，但 remainder 主体不能使用宽范围链接。仅报“Wide review barriers must reference actual input-information scopes”容易使模型误以为目标不存在。

建议诊断携带记录路径、scope-group 路径、实际主体 ID/类型、目标 ID/类型，以及被违反的关系规则；保留原错误，不降低校验。初始、局部纠错、完整替换提示使用同一规则描述。离线验证正确 rule→输入关系接受，输入主体错误继承关系拒绝，混合组准确拆分定位。

## 4. 补充契约的输出子字段关系和接收方依赖

当前 106 个不透明 compute 契约全部只有整值输出规则；实际 `ir_285` 需求包含多个 indexStatus 子字段。应按输出语义生成各字段所需输入；复合需求取并集，不能用整值规则冒充任何子字段的精确规则。结构化 build/select/expression 的确定性关系仍优先。已审查输入要求既要充分，也要有必要性证据；无需需求的字段只有在全部适用用途汇总后才能判删除。

13 个直接远程调用虽均有发送/接收记录，源文客户端/凭据身份未明确绑定到远程接收方。应保留真实句柄、其缓存/构造设置版本与当前 property/site 的区别，避免把模型漏画的依赖误判为 Skill 多取信息。七处 realtime/metadata 的源文操作可以在现有 IR 内明确表达，但不能只写在 prose 中或给工具接口虚构零环境依赖。保持 request/response 和同一成员配对；接口当前实参不能自行证明必要性。

这些都需要源文审查确认，不能把父运行的静态发现直接改成可删除结论。若真实输入缺失或字段用错，应报告现状，不伪造正确字段使分析通过。

## 5. 保留可观察事实与结论边界

父运行已保留 options.filters/orderBy 的实际读取，虽然请求没有发送它们；对应任务义务仍存在。后续应继续把真实观察、源文语义错误和任务必要性分别记录。21 条 blocked、五条 unmodeled、13 条无源文确认的 wrong_input 与缺失总结链条均需具体定位，不能因边界记录达到 13/25/7 就宣称完整正确。

验收应报告：接受的契约/范围数、局部未决的具体理由、实际到达的源文边界、接收方和路径绑定、非敏感输入评估、可删除修改及保持证明。所有不确定性必须有范围、关系、位置、阻断原因和解决条件。禁止把 no_excess_established 写成“安全”或“全部字段必要”，也不从单个 GA4 推导精确率、普遍优势或纯生成速度提升。
