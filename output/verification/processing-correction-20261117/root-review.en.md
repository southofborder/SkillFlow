# Root integration review

The task baseline already contained substantial uncommitted work. Acceptance
compares the current implementation with the captured content inventory, not
with Git HEAD, and separately checks all 488 protected historical files. No
historical response is used to generate the new offline test candidates.

The integration keeps the strict parser/codec as the sole processing acceptance
path. A raw pair scan runs only after rejection. Its grouped evidence does not
return a candidate, select among duplicated tables, resolve references or grant
partial acceptance. The rejected raw response is still saved unchanged. Full
grammar is appended by the correction strategy itself, so a short custom base
prompt or a matching marker inside source text cannot omit it. The final wording
allows only the selected slots actually being replaced, matching existing merge
behavior; final merged coverage remains mandatory.

CFG compiler context supplements existing diagnostics. An observed constructor
failure must exactly match the rederived rejected-block endpoint issue set before
causal ownership is issued. The diagnostic-only graph is never selected. Source
copying can change the compiler input digest, so the online adapter separately
binds the original raw candidate. The correction selector validates that binding,
owner locations and original messages, then records actual cycle, producer and
predecessor relationships. Complete candidate/source context is retained. The
merger rederives permissions from the current original and original diagnostics;
scope mutation, stale ownership, block identity changes and edits outside the
allowed records are rejected. Complete post-merge CFG validation still detects
defects at unmodified consumers. Unexplained global or topology defects keep the
existing full-response correction.

The unchanged wire grammar remains v1. Guided run v15, step v12 and fragments
v7 distinguish the changed prompts, diagnostics and correction protocol. Seven
normal requests, two workers, one structural correction per stage and one shared
semantic repair remain configured. The previous transport timeout, retry policy
and complete source/review behavior are unchanged.

Independent peer review covered both the scanner and CFG paths. Root reviewed
the sole new lifecycle helper: an explicit root owner, fresh namespace, immutable
preparation/acceptance bindings, exact source inventory, pinned CLI and frozen
implementation are checked before dispatch and each native start. The controller
alone owns terminal replay, refuses unconfirmed child-exit receipts and compares
the complete start/PID inventory before and after replay. Root still must observe
actual recorded PID absence at closure. Fake lifecycle tests do not launch the
real CLI. No preparation or launch precedes the final offline acceptance seal.

Final execution and exact hashes are recorded in offline-acceptance.json when
the final affected-scope execution has passed. Earlier overlapping receipts and
the initial outdated prompt-suffix assertion failure remain preserved. This is
not a whole-repository test claim and does not establish real GA4 completion or
model latency improvement.
