# Scoped source-review and lifecycle implementation

This is offline implementation evidence after the original four-case batch and its cost/provenance audits were sealed. No real model call, Skill execution, probe, original-run resume or additional replay was performed.

The current source-review fragment is v4; its immutable input-contract receipt is v2. Guided run v11, step/annotation v10 and formal DOE format v9 distinguish the changed acceptance contract from the original measured run. Task remains v5.

The receipt derives the expected operation obligations independently of supplied attachments. Every expected operation needs exactly one decision, including an explicit rejected missing attachment. Accepted contract checks certify the finite scope inventory; nonaccepted checks must provide a complete, duplicate-free partition of accepted, rejected and unresolved scopes. An unresolved scope requires a typed local barrier with missing fact, resolution requirement and valid source evidence. Generic-only wording is rejected as a structural floor; neither wording validation nor receipt hashes prove semantic truth.

Input ranges, explicit unresolved ranges, remainders, output rules and complete-output decompositions have separate scope identities. Wide barriers have no implicit whole-input effect. Any affected input scope must be explicitly named and independently marked nonaccepted. Program-generated scoped repair findings do not revoke unrelated accepted scopes, including the paired response when request and response share a flat call target. Independently authored overlapping representation defects remain incompatible with acceptance.

The compact review inventory exposes the implemented `if_present` semantics: unconditional presence knowledge and the requested information when present. No redundant presence row is required. Optional acquisition projections have one decision per exact request-response pair and authored capability row, with no whole-to-descendant or implicit union capability inference.

Source-established missing/wrong-input findings remain a separate typed table. Their source references and exact operation placements are revalidated when the receipt is built and loaded. They do not add missing Data or arguments, rewrite actual inputs, invent Task seeds, or themselves request a representation repair. A faithful dependency description may coexist with a known source invocation error; downstream source-error impact handling remains separate.

The existing repair ownership, seven normal semantic requests, structural-correction limits, shared semantic repair budget and source/Task/mapping/sensitivity isolation are preserved. The final selected review is bound to the actual frozen source, Task, CFG, raw annotation, compiled annotation, mapping and obligation inventory. Formal DOE persists this receipt and rechecks it without making a model request or rerunning demand merely to validate references.

The narrow Task/review guidance clarification preserves clear source-stated duties when only implementation/interface encoding is unspecified, while retaining genuine conflicting or competing source interpretations. It changes no Task schema or global issue policy.
